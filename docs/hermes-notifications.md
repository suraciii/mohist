# Hermes Notifications

Hermes notifications tell users when long-running Work needs attention. Mohist
sends important Issue and Workflow events to a chat platform such as Telegram
or Weixin.

## Product Commitments

- Mohist decides when to notify and writes the complete message.
- Hermes delivers the message to the selected chat destination.
- The Web Inbox remains the complete history. Notifications are not replayed.
- Delivery failure never blocks or changes Issue, Workflow, AgentJob, or
  Approval state.
- Every notification identifies the Issue and gives a next action when one
  exists.
- Failure messages give a short reason, never a stack trace.
- Four event types are enabled by default. `issue_started` is disabled by
  default.

## Notification Events

The default-on events are:

- an Approval Point waits for a decision;
- a Workflow fails and blocks the Issue;
- an Issue completes;
- an Agent response fails to handle its work.

`issue_started` is off by default because the user normally started the work.

Each notification includes the Issue number and title. A suggested command
includes the Issue number, for example `approve 42`, so the recipient needs no
conversation context.

## Setup

### Enable the Hermes Webhook Listener

Hermes must expose its webhook platform before Mohist can create a
subscription. Add a top-level `platforms.webhook` block to
`~/.hermes/config.yaml`; do not place it under `gateway.platforms`:

```yaml
platforms:
  webhook:
    enabled: true
    extra:
      host: "127.0.0.1"
      port: 8644
      secret: "<platform-level secret>"
```

Restart Hermes and check the listener:

```bash
hermes gateway restart
curl http://127.0.0.1:8644/health
```

The listener secret protects the Hermes webhook platform. It is not the
subscription secret that Mohist uses.

### Connect Mohist

Run the guided setup command:

```bash
mo notification setup --platform telegram
```

The guide checks the local listener, generates a subscription secret, writes
Mohist notification configuration, and prints the matching Hermes subscription
command. Run that command to complete the connection:

```bash
hermes webhook subscribe mohist \
  --deliver telegram \
  --deliver-only \
  --secret "<subscription-level secret printed by setup>" \
  --prompt '{body}'
```

`--deliver-only` is required because Mohist has already rendered the complete
message. It prevents an Agent or LLM from rewriting the notification. The
subscription secret must match the value generated by Mohist. Do not use the
platform-level secret from `config.yaml`.

Weixin has no default receiving chat. Specify its chat ID explicitly:

```bash
mo notification setup --platform weixin --deliver-chat-id "<your WeChat chat ID>"
```

Reload Server after writing the configuration:

```bash
mo update server
```

For an end-to-end check, drive an Issue to an Approval Point or completion and
verify that the chat platform receives the notification.

If setup cannot reach Hermes, check `hermes gateway status` and the health URL.
If Hermes accepts a request but no message arrives, verify `--deliver-only`,
the subscription secret, and an explicit `--deliver-chat-id` for platforms
without a home channel.

## Failure Recovery

A suggested action maps directly to a recovery command. For example:

```text literal
mo run retry --issue 42
mo run approve --issue 42
mo run request-changes --issue 42 --message "describe the required changes"
```

Use `mo run retry --issue 42` after a failed Issue. Use `mo run approve --issue 42`
after an Approval Point, or use `mo run request-changes` when the Workflow
defines Feedback Tasks. See [Troubleshooting](troubleshooting.md) for
the complete recovery map.

## Weixin Delivery Window

Weixin permits a Bot to push messages only for a limited period after the user
last sent it a message, approximately 48 hours in current practice. After the
window closes, delivery may fail even when Weixin reports a rate-limit error.
This is why Telegram is the recommended default for completion notifications.
Use Weixin during an active conversation. Sending a message reopens the window.

## Implementation Gaps

There is no command surface for per-event toggles, such as enabling the
default-off `issue_started` notification. Rerun the guide or edit Server
configuration manually to change the defaults.

The architectural boundary, HTTP payload, signature, and failure-isolation
contracts are in [Hermes Webhook](../design/hermes-webhook.md).
