# Feature Specifications

Specifications are organized by subdomain and feature. Read a feature's
`spec.md` for its behavior and acceptance scenarios. Read its optional
`design.md` for mechanisms and implementation contracts. The
[domain analysis](../design/domain-analysis.md) explains ownership boundaries.

To understand runtime status, start with
[Session execution evidence](session/execution-evidence/spec.md). It links to
the Runner confirmation source and the activity presentation that consumes it.

Feature specifications not yet organized here remain in the
[product documentation](../docs/README.md) and
[design documentation](../design/README.md). There is one authoritative body
for each rule, not a copy in each location.
