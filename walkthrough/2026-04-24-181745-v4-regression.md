## 发现的问题

### 问题 #1: Build 完成 task 状态检查时序 bug [严重]
- **现象**: Build 阶段完成后所有 tasks.json 中所有 task 都 passes=True，但 issue 报错 "Build completed with 1 failed task(s)"
- **根因**: 推测是 build 完成时的 task 状态检查在 task 最终更新前执行了。agent 在执行每个 task 后检查 passes，在某个 task 暂时为 False 时记录了错误，之后 task 被 agent 更新为 True，但错误已经写入
- **证据**: 两次 issue (#1 和 #2) 都复现了完全相同的行为。tasks.json 最终状态全是 True，但 approvalState 记录了 error
- **建议**: 检查 build 完成逻辑，确保读取 tasks.json 的最终状态而非中间状态

### 问题 #2: Build 失败后 stage 回退到 draft [严重]
- **现象**: Build 阶段失败后 issue.stage 从 "build" 回退到 "draft"
- **根因**: 未定位。可能是在错误处理中硬编码了 stage=draft
- **证据**: 两次 issue 都观察到 `issue.stage="draft"` + `approvalState.stage="build"` 的不一致
- **建议**: 工作流应单向推进。失败应保持在当前 stage 或设为专门的 error stage，不应回退

### 问题 #3: Agent 超时未生效 [严重]
- **现象**: 单个 opencode 进程运行超过 48 分钟（issue #1）和 40 分钟（issue #2），远超默认 30 分钟超时
- **根因**: 未定位。可能是超时计时器未正确启动，或 agent spawn 方式绕过了超时逻辑
- **证据**: 同一个 opencode 进程 PID 持续运行数十分钟
- **建议**: 检查 agent runner 的超时机制是否正确应用于 build 阶段

### 问题 #4: `resume --skip-to-review` 导致死锁 [严重]
- **现象**: `mo issue resume --skip-to-review` 设置 stage=review 但不创建审批点，也不启动 self-review agent
- **根因**: resume 命令只修改了 stage/status 但没有触发 review pipeline
- **证据**: stage=review, status=active，但 approve 报 "No pending gate"，start 报 "not in draft stage"
- **建议**: resume --skip-to-review 需要触发 review 阶段的完整流程，或在没有 agent 时直接创建审批点

### 问题 #5: Agent 不提交代码到 git [中等]
- **现象**: Build 完成后 worktree 中所有新文件都是 untracked (??)，没有 git commit
- **根因**: opencode agent 可能未被指示或无法执行 git commit
- **证据**: `git log` 只有 initial commit，`git status` 全是 `??`
- **建议**: Agent 或 build pipeline 应在完成 task 后提交代码

### 问题 #6: reopen 语义不匹配 [低]
- **现象**: `mo issue start` 对 blocked issue 建议运行 `mo issue reopen`，但 reopen 的帮助说明是 "Reopen a closed issue"
- **根因**: reopen 被复用于 blocked 和 closed 两种状态
- **建议**: 添加 `mo issue unblock` 命令，或更新 reopen 的帮助文档

### 问题 #7: Volume 权限导致日志收集失败 [低]
- **现象**: collect-logs.sh 无法写入 /app/results/（Permission denied）
- **根因**: 主机目录 uid=1000(surac)，容器内 motest uid=1001
- **证据**: `podman exec` 执行 collect-logs.sh 报 Permission denied
- **建议**: 使用 `--uidmap` 或在 Dockerfile 中统一 uid，或在 entrypoint 中 chmod

### 问题 #8: 容器停止需要 SIGKILL [低]
- **现象**: `podman stop` 的 SIGTERM 在 10 秒内未能停止容器
- **根因**: sleep infinity 可能不响应 SIGTERM，或 zombie 进程阻塞了信号传递
- **证据**: podman 输出 "StopSignal SIGTERM failed... resorting to SIGKILL"
- **建议**: 使用 `sleep infinity & wait` 或添加 signal handler

## 可观测性改进建议

1. **Build 阶段进度**: 无法查看 agent 正在执行哪个 task、task 的详细错误信息。建议添加 `mo issue show <N> --verbose` 显示 task 进度
2. **Agent 日志**: `mo issue logs <N>` 返回 "No logs found"。Agent 运行时应有实时日志可查
3. **`mo issue logs` 缺少分页**: 只有 `--follow`，缺少 `--lines`/`--limit` 选项
4. **Build 耗时统计**: 无法知道每个 task 的执行耗时
5. **Agent 当前行为**: 无法通过 API 查看 agent 正在执行什么操作（文件读写、命令执行等）
