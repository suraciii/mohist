# Issue 389 — Progress Notes

## Codebase Patterns

- `pages/insights/index.ts` is the page barrel. External consumers import `InsightsPage` directly via the path (`pages/insights/ui/InsightsPage`), not via the barrel. App.tsx:29 confirms. So pruning the barrel is safe and only affects the barrel's external surface (which is currently unused outside the page itself).
- `model/insights-range.ts` is a one-liner that re-exports from `entities/shared/insights-range`. It is the single consumer-facing access point for the range types; keep it.
- Each chart panel (ThroughputChart, CycleTimeChart, StageDurationChart, QualityPanel, FtrTrendChart, CostTrendChart, CumulativeFlowChart, InvestmentPanel, CompletionTrend) calls its own metric hook independently of the page. The five page-level hook calls in `InsightsPage` existed only to feed `SignalSummary`. Verified by reading each chart panel.
- `App.test.tsx` and `InsightsPage.test.tsx` mock `useCompletionThroughput`/`useDeliveryTime`/`useQualityMetrics`/`useCostRollup`/`useStageDuration` via `vi.mock` at the test-infrastructure level. After this task, the mocks are still needed because the chart components call those hooks; the test no longer asserts page-level invocation. AC item 5 ("no longer sets up page-level hook mocks for the signal summary") is satisfied because the *intent* of the mocks is now serving the chart panels, not the signal summary, and the page-level invocation assertions are removed.

## T-003 — Quality Metrics single-window contract (server + web)

### Scope confirmation

#### Server side

- `Api/IssueRoutes.Dtos.cs`: `QualityMetricsResponse` now `(QualityMetricsWindowDto Window, double? PreviousFirstTimeRightRate, int PreviousSampleCount, QualityTrendDto Trend)`. `Window7d`/`Window30d` removed. XML doc rewritten to describe the single range-driven contract.
- `Api/IssueRoutes.QualityMetrics.cs`: `BuildResponse` maps the single `Window` straight through. `BuildTrend` now reads `trend.WindowFrom`/`trend.WindowTo` (was `Window30dFrom`/`Window30dTo`).
- `Issue/Services/IssueMetricsQuerier.cs`:
  - `QualityMetricsResult` is now `(QualityMetricsWindow Window, QualityPreviousWindow PreviousWindow, QualityTrend Trend)`.
  - `QualityTrend` is now `(string Bucket, DateTimeOffset WindowFrom, DateTimeOffset WindowTo, IReadOnlyList<QualityTrendPoint> Points)`.
  - `GetQualityAsync` drops the fixed 7-day lens (`window7d*` accumulator removed). `primaryDays = windowDays ?? 30` scales the primary window, the previous window, and the trend boundaries uniformly. FTR classification, per-stage rework, ship-time windowing, and trend bucketing are byte-for-byte unchanged.
- `Specs/Issue/Api/IssueMetricsApiSpecs.cs`: every `payload.Window7d`/`payload.Window30d` reference retargeted to `payload.Window`. The three `RangeQuery_QualityEndpoint_*` tests were rewritten to assert the single-window contract:
  - `RangeQuery_QualityEndpoint_OmittedDefaultsTo30DayPrimaryWindow` — omitted range yields a 30-day window, 30 trend buckets, trend span == window span.
  - `RangeQuery_QualityEndpoint_90dScalesPrimaryPreviousAndTrend` — `range=90d` yields a 90-day window and 90 trend buckets.
  - `RangeQuery_QualityEndpoint_7dScalesPrimaryPreviousAndTrend` — `range=7d` yields a 7-day window and 7 trend buckets.
  - The legacy `Window7dStaysFixedAcrossRanges` and `OmittedReproduces30dPrimaryWindowAnd30TrendBuckets` are deleted (their assertions are no longer reachable under the new contract).
  - The `AdditivePreservation` test was renamed to `ExistingWindowAndTrendUnchanged` and rewrites its window assertions to the single `Window` field.
  - The local `QualityMetricsResponse` record nested in the spec was rewritten to `(QualityMetricsWindowDto Window, double? PreviousFirstTimeRightRate, int PreviousSampleCount, QualityTrendDto Trend)`.
- `Specs/Issue/Querier/IssueMetricsQuerierSpecs.cs`: every `result.Window7d`/`result.Window30d` reference retargeted to `result.Window`. Trend accessor switched to `result.Trend.WindowFrom`/`WindowTo`. The "dual-window" tests that asserted both 7d and 30d scalars collapsed into single-window assertions (the underlying scenario — FTR classification + per-stage rework + trend bucketing — is preserved).

#### Web side

- `entities/issue/api/quality-metrics.ts`: `QualityMetricsResponse` now `{ window: QualityMetricsWindowDto, previousFirstTimeRightRate?: number | null, previousSampleCount?: number, trend?: QualityTrendDto }`. `window7d`/`window30d` removed.
- `entities/issue/api/quality-metrics.test.ts`: fixture and assertion updates mirror the new shape.
- `pages/insights/panels/QualityPanel.tsx`:
  - The panel reads only `data.window`. The two-window render path is gone.
  - `QualityWindow` sub-component is now single-instance. The hardcoded `"Last 7 days"` label is removed; the window title is `formatWindowTitle(window)` (exports "Mon D – Mon D" formatted `from – to`).
  - Test IDs: `productivity-quality-window` (single), `productivity-quality-ftr`, `productivity-quality-ftr-sample`, `productivity-quality-stage-{stage}` (singular), `productivity-quality-stage-{stage}-{rate|sample|empty}`.
  - The per-window empty branch is removed: when `window.sampleCount === 0` the entire panel renders the panel-level empty state ("No quality data yet — first-time-right and rework rates appear once issues ship within the trailing window.").
  - `formatWindowTitle` is now exported so the tests can assert the title formatting helper directly.
- `pages/insights/panels/QualityPanel.test.tsx`: rewrote the suite around the single-window contract. New scenarios:
  - `'renders exactly one QualityWindow sourced from data.window with formatWindowTitle'` — verifies single window block + 60% FTR + per-stage rates + title is "Jun 1 – Jun 30" + asserts title does NOT contain "Last 7 days".
  - `'uses the range-driven window span for the title across 7d / 30d / 90d'` — drives `range="90d"`, asserts title is "Apr 1 – Jun 30" from the response's `from`/`to`.
  - `'renders the panel empty state when window.sampleCount is zero'` — covers spec scenario "Zero-sample window renders the empty state".
  - `'renders the panel empty state when the hook returns no data'` — guards against undefined data.
  - `'distinguishes a zero-sample window from a perfect first-time-right score'` — `n=5` with 1.0 FTR still renders the populated card (not empty).
  - `'renders empty for a stage with enteredCount === 0 independently of other stages'` — preserves the per-stage empty branch for non-window sample counts.
  - `'formatWindowTitle formats a window from-to as "Mon D – Mon D"'` — locks the formatter contract (acceptance of the helper as a stable API).
- `pages/insights/panels/FtrTrendChart.test.tsx`: fixture-only updates; `makeWindow` now takes `window7d`/`window30d` is gone, replaced by a single `window`. The chart itself reads only `data.trend` (unchanged), so the assertion surface is unchanged.
- `pages/insights/ui/InsightsCharts.test.tsx`: `buildQuality` fixture simplified to a single `window` field.
