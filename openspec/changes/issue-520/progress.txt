## Codebase Patterns

- AgentJobGrain persists lifecycle state through Orleans IPersistentState and mirrors a relational read model; terminal transitions are centralized in EnterTerminalStateAsync.
- Agent keys use `projectId:agentId` via GrainKey.Agent.
- Agent definitions are read through AgentQuerier, which returns MaxConcurrentRuns live from the Agent store.
- Full npm test currently reaches all .NET projects successfully, but workspace JavaScript checks fail because node_modules tooling (`tsx`, `tsc`) is not installed.

## T-002

- Follow-up reservations on idle AgentSessions now acquire the shared per-agent gate before persistence and runner delivery; busy-session follow-ups remain per-session serial and do not acquire a new permit.
- Follow-up permits are stored on the pending lease and released when the matching idle `session.activity` clears the lease, or when the reservation is abandoned/expired. A failed persistence or runner delivery also abandons and releases the permit.
- At the gate limit, follow-up acquisition throws `FollowupConcurrencyLimitException`; the API returns HTTP 409 with code `concurrency_limit`, leaves no input persisted, and remains distinct from HTTP 503 `runner_unavailable`.
- The focused follow-up spec fixture builds successfully, but the current Orleans 10 in-process test host cannot resolve server grain implementations (`Could not find an implementation for interface ...`), matching the existing session-grain spec baseline. Solution build and unit/architecture tests remain usable.

## Review Fixes

- Concurrency permits now retain their Job or follow-up Session owner. Reconciliation verifies each persisted permit against the mirrored AgentJob state or the persisted Session lease before pruning it, so a running execution is no longer discarded as an orphan.
- A launch that cannot obtain a Runner or slot now releases its permit before entering dispatch backoff. Pending work therefore does not inflate `activeRuns` or turn a runner/capacity wait into a per-Agent concurrency wait.
- Added Spec coverage for a running Job and an active follow-up lease surviving reconciliation, plus a no-Runner launch under a finite per-Agent limit leaving no active permit.
- Focused SpecTests command did not accept the legacy VSTest filter under Microsoft.Testing.Platform and ran the full collection; a repeat full SpecTests run passed (3333 tests).
- Readiness setup responses now return the concrete Agent detail path (`/agents/{agentId}`), which is the existing profile edit surface. Both Web entry points render that path as a project-scoped link; the readiness unit test asserts the concrete response.
- Split Agent detail readiness/availability coverage into its own 5-test file. The original file is below the 500-line budget, `check:test-boundaries` passes, and the Web suite passes (5162 passed, 1 skipped).
- Updated `GenericFollowupEndpoint_TerminalActivityStaysFollowable` to complete its owning AgentJob through the Runner rather than only injecting a Session idle event. A terminal Session no longer escapes a still-running Job's concurrency permit; the corrected focused spec passes.
