## Codebase Patterns

- The dead state we're removing is `TaskProgressMap` (a `Map<string, TaskProgressEntry>`) + `LoopProgress` declared in `entities/coder-session/model/types.ts`. These are **distinct** from `TaskProgress` (singular, `{ completed, total }`) which lives on `AgentActivity`/`AgentProgress` and is used by `SessionCard`, `activity-cards`, `PulseZone`, `CompactSessionCard`, and inside `useSessionTimeline.ts:344-345` via `progress.taskProgress`. The two share a name fragment but are unrelated types; only the `TaskProgressMap` is dead state. Future tasks grepping must distinguish.
- `TaskProgressPanel` is an `export function` from `SessionTimeline.tsx` with parameter type `{ tasks: Array<{ taskId; status; error? }>; loopProgress: LoopProgress | null }` — `LoopProgress` import must remain in `SessionTimeline.tsx` even after dropping it from `SessionTimelineProps` (the panel itself still uses it). `TaskStatusIcon` is local (no `export`) and only used inside `TaskProgressPanel`.
- `useSessionTimeline.ts` exports many shared types/helpers (`Round`, `RecoveryEvent`, `RecoveryStatus`, `PlanStep`, `PlanProgress`, `ContextHealthState`, `ContextHealthStatus`, `CompactionEntry`, `deriveToolCallTitle`, `reconstructRoundsFromEvents`, `BASE_PLAN_STEPS`, `toContextHealthStatus`, `mapLivenessToRecoveryStatus`) that are imported by `SessionTimeline.tsx`, `PlanProgressPanel.tsx`, and tests via the deep path `../model/useSessionTimeline`. When T-003 moves them to `session-timeline-reducer.ts`, it must re-export them from the hook module (design D7) to avoid changing import paths.
- Test fixtures for `SessionTimeline` consistently use `isLive={false}` followed by the dead-state props; future test maintenance should leave the props-positioning simple (no extra blank lines between unrelated attributes).

## T-002 — Add event-wiring integration tests before reducer extraction

All 39 tests pass (22 pre-existing + 17 new); `npm run typecheck -w packages/web` green.
- Test pin current (pre-extraction) hook behavior. Each test is a regression net that the subsequent reducer extraction (T-003) must not break.
- Coverage map (all asserted via the resulting hook state — `rounds` / `recoveryStatus` / `planProgress` / `contextHealth`):
  - `plan_round_start`: appends a round, marks the matching step running, appends a new step when `roundType` is not in `BASE_PLAN_STEPS`, drops events with wrong `issueId` or wrong `coderSessionId`.
  - `plan_round_complete`: stamps `duration` + `verdict`, marks step `failed` on `FAIL` / `completed` on `PASS`, appends `auto-fix` + `re-self-review` pending steps on `self-review FAIL` (each at most once across repeated FAILs).
  - `coder_recovery_status`: sets `recoveryStatus` from event, appends to last round's `recoveryEvents`, clears `recoveryStatus` to `null` on `recovered` (and the round event is still appended).
  - `session.liveness`: `probing → recovering`, `running → recovered`, `failed → failed`; ordered `attempt` fallback `activeProbeVersion → satisfiedProbeVersion → probeVersion → 1`; `failureReason` used when set; `recoveryStatus` cleared on `failed`.
  - `compaction_event`: appends `CompactionEntry` to last round's `compactions`, resets `contextHealth.contextWindowUsed = contextWindowUsedAfter` and `contextHealth.status = null`.
  - `com.mohist.agent-session.context-compacted`: same compaction semantics as `compaction_event` but gates on `detail.issueId === issueId` only (not `isCurrentSessionEvent`); synthesizes a placeholder `Compaction` round when no round exists.
  - `com.mohist.agent-session.context-health-updated`: applies server-provided values verbatim (gates on `issueId` only).
  - `tool_call.started` → `updated` → `completed` (live path): `started` creates entry, `updated` with `state: 'timeout'` maps to `failed` via `toToolCallEntryState` and re-clones the in-place-mutated ref entry into the round's `toolCalls`; `completed` mutates the ref entry and replaces in the round's `toolCalls`. Round's `toolCalls` length stays at 1 (no duplicate appends on update).
  - `plan_session_update` coalescing: two events dispatched within 100ms → agentText stays empty until the setTimeout+rAF cascade fires (advance 120ms covers setTimeout(100) + rAF(16)) → agentText becomes the concatenation (`'hello world'`), proving a single `setRounds` flush consumed the batch.
  - `plan_session_update` rAF branch: after the first flush at t≈116, advancing to t≈316 + dispatching one more event takes the rAF branch (elapsed ≥ 100ms); the second delta is applied within 30ms (one rAF tick), not 116ms, proving the elapsed-since-last-flush branch selection.
- Codebase patterns and gotchas discovered:
  - **`vi.advanceTimersByTime` boundary for the rAF polyfill**: the test env polyfills `requestAnimationFrame` as `setTimeout(..., 16)` (see `tests/setup.ts:60`). With `vi.useFakeTimers()`, the rAF needs ~28-30ms of advance to fire — 20-25ms is not enough even though the underlying setTimeout delay is 16ms. The first-flush cadence test uses 120ms (setTimeout 100 + rAF ~16 + 4ms buffer); the rAF-branch test uses 30ms to assert the second flush happens in one rAF tick.
  - **`vi.runAllTimers` is unsafe here**: the hook uses `useQuery({ refetchInterval: 5000 })` for `getAgentStatus`, and `vi.runAllTimers` will keep firing the refetch setTimeout forever (the 10k-timer vitest cap is hit, throwing "Aborting after running 10000 timers"). Always use bounded `advanceTimersByTime` for this hook.
  - **Live `tool_call.*` handler does NOT call `deriveToolCallTitle`** — only the batched path inside `flushPlanBuffer` does. The live path stores `detail.title` verbatim, so the test asserts `title: 'read'` for the `tool_call.started` event with `title: 'read', rawInput: { file_path: ... }`. Future reducer-extraction (T-003) must preserve this asymmetry (or fix it deliberately as a separate change).
  - **`compaction_event` vs `com.mohist.agent-session.context-compacted` scoping differ**: the legacy `compaction_event` uses `isCurrentSessionEvent` (session-bound), while the new `com.mohist.agent-session.context-compacted` uses `detail.issueId === issueId` only. Tests use `coderSessionId: 'coder-1', acpSessionId: 'acp-1'` for the legacy path and `issueId: '123'` for the new path.
  - **`session.liveness` clears `recoveryStatus` AFTER the round's `recoveryEvents` append** — the test for `failed` asserts `recoveryStatus === null` AND the round has the `failed` event. If the implementation reordered these, the test would catch it.
  - **`afterEach(vi.useRealTimers)` is mandatory** in this test group: `beforeEach(vi.useFakeTimers())` + a `setTimeout`-using `useQuery` would otherwise leak fake timers to the next test in the file (the original `describe('useSessionTimeline context health events', ...)` block uses real timers).
- The reducer extraction (T-003) target surface is now test-pinned. Future T-003 must keep every assertion in this block green after the move to `model/session-timeline-reducer.ts`.
