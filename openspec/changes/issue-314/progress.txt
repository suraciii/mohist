## Codebase Patterns

- The dead state we're removing is `TaskProgressMap` (a `Map<string, TaskProgressEntry>`) + `LoopProgress` declared in `entities/coder-session/model/types.ts`. These are **distinct** from `TaskProgress` (singular, `{ completed, total }`) which lives on `AgentActivity`/`AgentProgress` and is used by `SessionCard`, `activity-cards`, `PulseZone`, `CompactSessionCard`, and inside `useSessionTimeline.ts:344-345` via `progress.taskProgress`. The two share a name fragment but are unrelated types; only the `TaskProgressMap` is dead state. Future tasks grepping must distinguish.
- `TaskProgressPanel` is an `export function` from `SessionTimeline.tsx` with parameter type `{ tasks: Array<{ taskId; status; error? }>; loopProgress: LoopProgress | null }` — `LoopProgress` import must remain in `SessionTimeline.tsx` even after dropping it from `SessionTimelineProps` (the panel itself still uses it). `TaskStatusIcon` is local (no `export`) and only used inside `TaskProgressPanel`.
- `useSessionTimeline.ts` exports many shared types/helpers (`Round`, `RecoveryEvent`, `RecoveryStatus`, `PlanStep`, `PlanProgress`, `ContextHealthState`, `ContextHealthStatus`, `CompactionEntry`, `deriveToolCallTitle`, `reconstructRoundsFromEvents`, `BASE_PLAN_STEPS`, `toContextHealthStatus`, `mapLivenessToRecoveryStatus`) that are imported by `SessionTimeline.tsx`, `PlanProgressPanel.tsx`, and tests via the deep path `../model/useSessionTimeline`. When T-003 moves them to `session-timeline-reducer.ts`, it must re-export them from the hook module (design D7) to avoid changing import paths.
- Test fixtures for `SessionTimeline` consistently use `isLive={false}` followed by the dead-state props; future test maintenance should leave the props-positioning simple (no extra blank lines between unrelated attributes).
