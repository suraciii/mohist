## Codebase Patterns

### FSD / widget structure
- `packages/web/src/widgets/<widget>/` has `model/`, `ui/`, optional `index.ts` barrel.
- Public barrel at `index.ts` re-exports stable symbols (e.g. `projectTurn`, `useSessionTranscript`, `SessionTranscriptLayout`).
- Model modules contain pure domain logic; UI modules contain React components.
- `model/transcript-tool-utils.ts` already owns patch *parsing* (`parsePatchOperations`, `parseEditInput`, `parseEditWriteChanges`); `model/diff-builder.ts` is the new home for patch *diff-building* (the companion half). Both belong in model — the split-brain at the model/UI layer boundary is what T-001 fixes.

### Diff types
- `FileBlock`, `DiffLine`, etc. live in `packages/web/src/widgets/issue-changed-files/model/diffModel.ts`.
- `parseDiff`, `isLargeDiff` are also there. session-transcript imports them cross-widget for the diff rendering components.

### Test patterns
- Tests use `vitest` + `describe/it/expect` style.
- Pure model tests live as `<name>.test.ts` next to the source.
- Render/harness tests use `@testing-library/react` and `// @vitest-environment jsdom`.
- Current transcript widget had only one test file: `model/useSessionTranscript.test.tsx` (cover the hook, no diff calc coverage before T-001).

### Tooling
- Typecheck: `npm run typecheck -w packages/web` (`tsc -b`).
- Tests: `npm run test:run -w packages/web` (`vitest run`).
- tsconfig is strict with `noUnusedLocals` and `noUnusedParameters`.

### Branch
- Workflow branch is `mohist/run-wr_d034710a05a74df984095723e87b2df0`; commit on this branch only.

Workaround: either pick a command that is unique to the bash command pre (e.g. `echo hi`), or use `getAllByText` / `container.querySelector('pre')?.textContent`. The baseline test passes `input: JSON.stringify({ description: ... })` so `showExpandableDetails` is true and the inner `DelegationContentView` renders.
- `DiffContentView` "Show raw" toggle only renders when `hasDiff` is true, which requires the diff-text-resolution chain to succeed (metadataDiff / rawOutput / rawInput containing `---` for parseDiff, OR `normalizedName === 'edit'|'write'` with parseable input for buildDiffFromEdit, OR `normalizedName === 'apply_patch'` with patchText for buildDiffFromPatchText). `parseDiff` itself only produces blocks when the input starts with `diff --git a/... b/...`, so a `rawDetail` with just `--- a/...` + `+++ b/...` will NOT trigger the toggle.
