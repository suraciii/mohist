## Why

Workflow Inline Agent execution still rides on the Agent Client Protocol: a spawned OpenCode ACP process, ACP session/event semantics, a quiet-threshold liveness probe, log-file heuristics, CLI model parsing, and private compaction metadata. The `mohist/opencode` Action that issue #408 landed is only a bridge that validates the new input contract and then delegates back into this ACP runtime. With the #407 identity/command contract and the #408 Action/completion contract now in place, the Workflow execution path can finally call OpenCode directly through the surfaces its own Web/TUI use, eliminating the fragile indirect layer. This is the runtime half of epic 46 and must land so the bridge stops being the real execution path.

## What Changes

- Replace the Workflow-source execution backend with a deep `OpenCodeRuntime` module that drives `@opencode-ai/sdk/v2` directly: turn execution via `client.session.prompt()` (awaited for completion), Follow-up via `promptAsync()`, Compact via `summarize()`, Interrupt via `abort()`, Reset via `create()`, and state reconciliation via `get`/`messages`/`status`, with live display fed by one `client.global.event()` subscription. Callers see only Mohist-owned request/result types; no SDK DTO leaks past the boundary.
- Pin `@opencode-ai/sdk/v2` and smoke-verify the asserted call surface (the mature `client.session.*` namespace plus read-only `client.v2.model.list()` / `client.v2.provider.list()`) against a real OpenCode before implementation proceeds; do not call the currently-unavailable `client.v2.session.wait()` / `client.v2.session.compact()`.
- Each Runner maintains a single shared OpenCode Server, Client, and global event subscription. **BREAKING**: the Runner gates *all* new work on OpenCode health plus a readable model catalog; on Server exit or unreadable catalog it stops claiming new work and emits actionable diagnostics, resuming only after both re-pass. During the transition this readiness gate also covers AgentJob work that still runs on ACP until #410.
- Load the model catalog structurally via `client.v2.provider.list()` and `client.v2.model.list()` (replacing `opencode models --verbose` parsing) for configuration hints; final model legality and defaults stay OpenCode's judgment.
- Honour the #408 Action contract from the runtime side: `prompt`/`session`/`options` only, `options.model` split at the first `/` with `options.variant` as a sibling, unknown `options` keys ignored and recorded as diagnostics (not failures) to backstop persisted legacy `vars.agent`, and type-invalid `model`/`variant` returned as actionable input errors.
- **BREAKING**: Remove ACP liveness probing, OpenCode log-file scanning, CLI model parsing, and private ACP compaction metadata from the Workflow path. The sole backstop for a hanging turn is the executor-owned layered timeout (existing defaults): on deadline the runtime aborts the turn and the work fails; `OpenCodeRuntime` performs no silent detection.
- Supply the turn's final assistant text as the private turn fact so the Workflow task executor can evaluate `path: _output` expect markers; `OpenCodeRuntime` never synthesizes the `{ promise }` output (the executor does, per #408).
- Fulfil the #407 Session-command contract for Workflow source over the native SDK: Compact keeps the binding, Reset is guarded by the expected-binding check and appends lineage, Follow-up/Cancel route through the Mohist-owned request/result shape, the `operationId` dedup journal is honoured, and missing/conflict/unavailable results map to `summarize`/`create`/`abort` outcomes.
- On Runner restart or event reconnect, continue routing and reconcile state from the persisted AgentSession binding plus a `get/messages/status` snapshot; add no V2 history cursor, deterministic Prompt ID, or replay state.
- Surface actionable, user-visible errors with recovery suggestions when permissions are unsatisfied, the Runtime Session is missing, OpenCode is incompatible, or the process exits.
- Scope boundary: ACP cleanup is limited to the Workflow source. `mohist/acp-agent`, the shared ACP connection, the generic/AgentJob session strategy, and the `@agentclientprotocol/sdk` dependency remain registered and available for the Mohist Agent AgentJob path until #410; Agent-source Session ACP traces and final dependency removal are #410's responsibility. No `mohist/agent` Action, no Pi abstraction, no feature flag/alias/fallback, and no OpenCode CLI install/version lock by Mohist.

## Capabilities

- `opencode-runtime`: The deep `OpenCodeRuntime` module boundary — shared OpenCode Server/Client/global-event lifecycle, readiness check (health plus catalog load) and the readiness contract the Runner host gates work on, encapsulation of all SDK DTOs behind Mohist-owned request/result types, error normalization into actionable diagnostics, and the pinned, smoke-verified `@opencode-ai/sdk/v2` call surface.
- `opencode-turn-execution`: Work-owned turn execution for the Workflow Inline Agent path — create/resume the Runtime Session, apply `model`/`variant`, run and await `client.session.prompt()` for completion, emit the final-assistant-text turn fact for `_output` evaluation, and rely solely on the executor-owned layered timeout (abort on deadline) with no ACP liveness probe, no `client.v2.session.wait()`, and no early or duplicate completion on event loss; restart/reconnect reconciliation via the persisted binding and `get/messages/status` without V2 replay state.
- `opencode-session-operations`: Session commands over the native SDK for the Workflow source — Follow-up `promptAsync()`, Compact `summarize()`, Cancel `abort()`, Reset `create()` under the #407 expected-binding guard, the `operationId` dedup journal, and the `missing`/`conflict`/`unavailable` result taxonomy, with Workflow-source Session state and diagnostics exposing no ACP identity.
- `opencode-model-catalog`: Structured provider/model discovery via `client.v2.provider.list()` and `client.v2.model.list()` replacing CLI parsing, first-slash `options.model` parsing with `options.variant` as sibling, tolerance of unknown `options` keys with diagnostics, and actionable errors for type-invalid `model`/`variant`.

## Impact

- **Runner runtime** (`packages/runner/src/runtime/`): new `OpenCodeRuntime` module; `host.ts` replaces ACP connection initialization with OpenCode Server/Client start, readiness gate, and poll gating (transitionally also gating pre-#410 AgentJob work); `acp-session-command.ts` drives Workflow-source Compact/Reset via `summarize`/`create`. `opencode-models.ts` (CLI parsing) and `opencode-log-diagnostics.ts` (log heuristics) are retired for the Workflow path; `acp-connection.ts` and `acp-command.ts` stay for the AgentJob path until #410.
- **Runner Actions** (`packages/runner/src/actions/`): `opencode.ts` switches from the ACP bridge to `OpenCodeRuntime`; `registry.ts` keeps both Actions registered (`mohist/opencode` now native, `mohist/acp-agent` retained for AgentJob). The Workflow session strategies in `acp/session-strategies.ts` and the Workflow-path usage of `acp/liveness.ts`, `acp/compaction.ts`, `acp/model-resolution.ts`, and `acp/session-events.ts` are retired; the generic/AgentJob strategy remains on ACP until #410.
- **Runner dependencies** (`packages/runner/package.json`): add pinned `@opencode-ai/sdk/v2` (smoke-verified); retain `@agentclientprotocol/sdk` until #410.
- **Server** (`packages/server/src/Mohist.Server/`): built-in profiles already use `mohist/opencode` (#408) and the model regex already does first-slash splitting (#408 D8); Workflow-source Session state and diagnostics must not surface ACP Action or ACP Session identity. AgentSession binding fields (`runtime`, `runtimeSessionId`) are already in place from #407.
- **Web / CLI**: Workflow-source Session views must not expose ACP identity (largely satisfied by the #407 wire rename); full removal of `type`/liveness config keys and remaining ACP terms across API/CLI/Web is deferred to #410.
- **Testing**: default Runner tests must not start a real OpenCode process or touch network/process/fs/clock; inject a fake `OpenCodeRuntime` or fake SDK Server/Client factory. Coverage required for input expansion, multi-slash model, shared-runtime/separate-work identity, physical-session reuse/rotation, model/variant non-rotation, global event routing, prompt completion/interruption/no-replay, async Follow-up, native Compact/Reset, restart routing, and permission/missing-session/incompat/process-exit failures.
- **Compatibility**: persisted Workflow-source bindings carrying legacy ACP identity are treated as "current Runtime Session missing" and resolved by an explicit Reset prompt; no stored-data rewrite, alias, or fallback is provided. The AgentJob path and its ACP dependency are intentionally untouched in this change.
