## Codebase Patterns

- **Scope-of-test collection**: `MohistIntegration` (xunit `IClassFixture`-style collection) wires up `MohistIntegrationFixture` which boots a real `WebApplicationFactory<Program>` + Orleans silo + in-memory SQLite EF. Fast/cheap enough for the default `npm test`.
- **Test traits convention**: every spec carries `[Trait(Traits.Speed.Name, Traits.Speed.Integration)]` + one or more `[Trait(Traits.Sut.Name, Traits.Sut.X)]` (Agent/Api/Workflow etc.). Speed gates the test selector (`Speed=Unit|Grain|Integration|Service`), Sut gates the bounded context.
- **HttpClient helpers**: `_fixture.Client.PostAsJsonAsync/GetAsync/...`, plus `ApiTestClient.GetDataAsync<T>`, `PostOkAsync`, `PatchOkAsync`, `PostDataAsync<T>` (which unwraps `ApiResponse<T>` envelope). For manual envelopes (non-success) use the raw `PostAsJsonAsync` directly and read `ReadFromJsonAsync<JsonElement>`.
- **GenericAgentSessionMetadata key conventions** (already extended by this task): `mohist.io/agent-id`, `mohist.io/agent-name`, `mohist.io/agent-launch/{issue-number|epic-number|repository|workspace-path}`, plus the new `mohist.io/trigger/event-id` + `mohist.io/trigger/subscription-id`. Sessions queryable via `AgentSessionQuery` + `AgentSessionQueryMetadataKeys.ProjectId` / `SourceKind = "agent-launch"`.
- **Scoped lifetime follows `IssueQuerier` pattern**: concrete `AgentLauncher : IScopedService`, interface forward-registered in `MohistServiceRegistration` as `services.AddScoped<IAgentLauncher>(sp => sp.GetRequiredService<AgentLauncher>())`. Bus-side handlers resolve via `IServiceScopeFactory` (same pattern as `InboxProjectionHandler`).
- **Architecture rules exception noted** — Agent joined `domainsWithKnownCycles = { Issue, Workflow, Sessions, Runner, Agent }`. Justification: `AgentGrain → AgentQuerier (Services)` for `ToInfo` projection, and the shared `AgentLauncher (Services) → IAgentJobGrain (Grains)` for `SubmitAsync`. Both directional, both legitimate. If Agent ever moves its projection path out of `AgentGrain` (e.g. into a dedicated `AgentProjectionGrain`), the cycle closes and this exception can be removed.

## T-001 → T-003 hand-off notes

- T-003 dispatch handler will resolve `IAgentLauncher` via `IServiceScopeFactory` (same pattern as `InboxProjectionHandler` resolving `IInboxSubscriptionStore`).
- The handler MUST invoke the launcher as:
    ```
    await launcher.LaunchAsync(
        agent,
        renderedResponsePrompt,
        new AgentLaunchContext(ProjectId: projectId /* nothing else */),
        triggerLabels: new Dictionary<string, string>(StringComparer.Ordinal)
        {
            [GenericAgentSessionMetadata.TriggerEventId] = cloudEvent.Id,
            [GenericAgentSessionMetadata.TriggerSubscriptionId] = subscription.Id,
        });
    ```
- The `AgentJobInput` contract — `AgentInstructions: agent.Instructions, AgentConfig: agent.AgentConfig?.Clone()` — preserves the two-layer prompt composition (Agent identity + rendered ResponsePrompt → `Prompt`).
- The subscription's `Rendered ResponsePrompt` replaces the manual `prompt`; everything else (workspace path, project id, session metadata) is identical. The session metadata carries the two trigger labels; manual launches do not.
