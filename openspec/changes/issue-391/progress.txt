## Codebase Patterns

- **Scope-of-test collection**: `MohistIntegration` (xunit `IClassFixture`-style collection) wires up `MohistIntegrationFixture` which boots a real `WebApplicationFactory<Program>` + Orleans silo + in-memory SQLite EF. Fast/cheap enough for the default `npm test`.
- **Test traits convention**: every spec carries `[Trait(Traits.Speed.Name, Traits.Speed.Integration)]` + one or more `[Trait(Traits.Sut.Name, Traits.Sut.X)]` (Agent/Api/Workflow etc.). Speed gates the test selector (`Speed=Unit|Grain|Integration|Service`), Sut gates the bounded context.
- **HttpClient helpers**: `_fixture.Client.PostAsJsonAsync/GetAsync/...`, plus `ApiTestClient.GetDataAsync<T>`, `PostOkAsync`, `PatchOkAsync`, `PostDataAsync<T>` (which unwraps `ApiResponse<T>` envelope). For manual envelopes (non-success) use the raw `PostAsJsonAsync` directly and read `ReadFromJsonAsync<JsonElement>`.
- **GenericAgentSessionMetadata key conventions** (already extended by this task): `mohist.io/agent-id`, `mohist.io/agent-name`, `mohist.io/agent-launch/{issue-number|epic-number|repository|workspace-path}`, plus the new `mohist.io/trigger/event-id` + `mohist.io/trigger/subscription-id`. Sessions queryable via `AgentSessionQuery` + `AgentSessionQueryMetadataKeys.ProjectId` / `SourceKind = "agent-launch"`.
- **Scoped lifetime follows `IssueQuerier` pattern**: concrete `AgentLauncher : IScopedService`, interface forward-registered in `MohistServiceRegistration` as `services.AddScoped<IAgentLauncher>(sp => sp.GetRequiredService<AgentLauncher>())`. Bus-side handlers resolve via `IServiceScopeFactory` (same pattern as `InboxProjectionHandler`).
- **Architecture rules exception noted** — Agent joined `domainsWithKnownCycles = { Issue, Workflow, Sessions, Runner, Agent }`. Justification: `AgentGrain → AgentQuerier (Services)` for `ToInfo` projection, and the shared `AgentLauncher (Services) → IAgentJobGrain (Grains)` for `SubmitAsync`. Both directional, both legitimate. If Agent ever moves its projection path out of `AgentGrain` (e.g. into a dedicated `AgentProjectionGrain`), the cycle closes and this exception can be removed.

**Gotchas / decisions recorded**:
- **SQLite DateTimeOffset ordering**: `ListByAgentAsync` / `ListByProjectAsync` materialize the candidate set then `OrderByDescending(UpdatedAt).ThenBy(Id, Ordinal)` in memory — SQLite cannot `ORDER BY DateTimeOffset` (same pattern as `InboxQuerier.cs:39-55`). Subscription volume per Agent/Project is small, so this pass is cheap; the `(ProjectId, AgentId)` compound index still narrows the SQL predicate efficiently.
- **Idempotent status transitions**: `Archive`/`Restore` check the current `Status` and either bump `UpdatedAt` (true transition) or no-op return the row. Spec acceptance requires "identity and fields SHALL be preserved across both transitions" — the idempotency check makes repeated toggles a noop rather than advancing the timestamp spuriously.
- **`UpdateAsync` field set**: HTTP `PATCH` is bound via a custom `BindAsync` that returns an `IReadOnlySet<string>` of field names that were literally present in the JSON body. This lets the route distinguish "not provided" from "explicitly null". `priority: null` is honoured as a clear-to-default; absence of `priority` keeps the stored value.
- **Spec endpoint** integrates with the project's `ApiTestClient.GetDataAsync<T>`/`PostDataAsync<T>`/`PatchDataAsync<T>` helpers — same shape as `AgentDefinitionApiSpecs.cs`.
- **No FK to `Agents` table**: agents are stored as JSON-blob rows (`AgentRow.State`), so a real FK can't be defined. The store enforces ownership by carrying `(ProjectId, AgentId)` and the route layer enforces project/agent scope at lookup time. This matches the existing `Agent` aggregate shape (no schema FK exists for `Project` either).
- **Status filter payload normalization**: `null`/empty `Source`/`Subject` strings are normalized to `null` at the route layer so the persistence layer can rely on a single representation ("null = no constraint").

The algorithm is deterministic: group by `AgentId` (Ordinal), each group picks the highest-priority subscription (ties by Id Ordinal), then groups are compared by their max-priority (ties broken by the smallest winning-subscription Id Ordinal).
- `CloudEventTypeMatcher` was extracted so the type-pattern algorithm is now defined once and consumed by both `InMemoryEventBus` (live dispatch) and `SubscriptionFilter` (post-filter per subscription).
