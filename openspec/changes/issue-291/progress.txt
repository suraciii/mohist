# Issue-291 Progress

## T-001 (2026-07-05) — `runCommand` per-command timeout primitive

### What landed
- `packages/runner/src/system/timeout-signal.ts` — extracted `timeoutSignal`
  from `actions/registry.ts:190` to a shared low-level module so `system/process.ts`
  can import it without a cycle. Single implementation, shared by
  `core/script`, `mohist/acp-agent`, and `runCommand`.
- `packages/runner/src/actions/registry.ts` — now imports `timeoutSignal`
  from `system/timeout-signal.ts`; behavior identical.
- `packages/runner/src/system/process.ts` — `CommandResult` gained optional
  `status?: "timeout"` + `timeoutMs?: number` fields (absent on normal exit
  ⇒ byte-identical result). `CommandLineOptions` gained `timeoutMs?: number`.
  `runCommand` layers `timeoutSignal(parent, options.timeoutMs)` when
  `timeoutMs > 0`, switches `spawn` to `detached: true`, and on abort
  (timeout OR parent signal) calls `killProcess` to group-kill helper
  processes. On timeout: structured result + captured output + sentinel
  `Command timed out after Ns` in stderr. Parent abort: rejects (today).
  `killProcess` hardened to group-kill detached children via `process.kill(-pid)`
  with POSIX guard + ESRCH/EINVAL fallback (direct `child.kill` on Windows).
- `packages/runner/tests/system-process-timeout.spec.ts` — 7 new tests,
  all under fake `setTimeout` (real setImmediate for I/O). 343 ms total.

### Gotchas worth recording for downstream tasks (T-002 etc.)

- **Vitest `advanceTimersByTimeAsync(N)` takes N ms of real wall-clock.**
  Inside `vi.useFakeTimers({ toFake: ['setTimeout'] })` it's
  sinon's `tickAsync` which uses `originalSetTimeout` per chunk.
  So a `timeoutMs` of 5000 in a test = 5 s real wait. Tests
  must use tiny `timeoutMs` (50–100 ms) to stay under the 500 ms
  spec budget.
- **Fake-only-setTimeout is the right mode for `runCommand` tests.**
  `vi.useFakeTimers()` (default) fakes `setImmediate` too, which
  starves the parent's pipe read. With `{ toFake: ['setTimeout'] }`,
  `setImmediate` is real and pipes flow. Helper:
  `await yieldRealTime(N)` spins on `setImmediate` until
  `Date.now()` advances N ms — used to let child output reach the
  parent before the timer fires.
- **Detached spawn does NOT need `unref()`.** Parent still awaits
  `close`; unref would race the spawn-error path. (Spec: `killProcess`
  reap-after-grace SIGKILL is explicitly deferred to Open Questions.)
- **`AbortError` race on Node's `abortChildProcess`:** when the
  layered signal aborts, Node internally calls
  `abortChildProcess → child.kill(sig) → emit('error', AbortError)`
  AND our `error` listener fires. To avoid a stray AbortError from
  rejecting the timeout path, classify lazily via
  `effectiveSignal.reason instanceof Error && /Timed out after/.test(...)`
  (not a captured `timedOut` boolean) — the reason is set BEFORE any
  listener runs, so no race.
- **`killProcess` is called from `effectiveSignal.addEventListener('abort', ...)`.**
  Both the timer-fired (reason = timeout Error) and parent-abort
  (reason = parent.reason) paths trigger it. On the parent-abort path
  `effectiveSignal.reason` carries the parent's reason, so `wasTimeout()`
  is false ⇒ the `error` listener rejects (today's behavior preserved).
- **Helper-spawn-by-child test layout:** child writes
  `parent=<pid> helper=<pid>` to stdout via an inline `node -e` script
  with `onLine` capturing both. After the timeout, both PIDs must be
  reaped (`process.kill(pid, 0)` throws ESRCH). Verified on Linux.
- **Test budget:** all 7 tests in `system-process-timeout.spec.ts`
  run in ~340 ms. Well under the 500 ms spec target. Total runner
  suite (931 tests) runs in ~8 s.
## T-002 (2026-07-05) — Network-command-timeout policy + structured retry-safe failure path

### What landed
- `packages/runner/src/actions/git.ts` — exported `NETWORK_COMMAND_TIMEOUT_MS = 120_000` as the single source of the network default. Extended `GitOptions` with `timeoutMs?: number`; `git()` forwards it into `CommandLineOptions.timeoutMs` (works whether or not a sink is present).
- `packages/runner/src/runtime/workspace.ts` — applied `timeoutMs: NETWORK_COMMAND_TIMEOUT_MS` to `cloneFresh` (`git clone`) and `verifyBaseBranch` (`git ls-remote`). All other workspace.ts runCommand call sites (rev-parse, checkout, rebase/merge/cherry-pick --abort, reset, fsck, cat-file, show-ref, ls-tree, remote get-url) keep NO timeoutMs — they are local-only and the design explicitly excludes them.
- `packages/runner/src/actions/push.ts` — added `networkOptions(context)` helper that pairs the sink with `timeoutMs: NETWORK_COMMAND_TIMEOUT_MS`; applied to `push` and `resolveRemoteTip`'s `ls-remote` probe. `rev-parse` keeps NO timeoutMs.
- `packages/runner/src/actions/rebase.ts` — same pattern: `networkOptions(context)` for the `fetch <remote> <baseBranch>` call only. All `rev-parse`, `rebase`, `status`, `add`, `commit`, `reset`, `diff`, `merge-base`, `branch` calls keep NO timeoutMs.
- `packages/runner/src/actions/create-github-pr.ts` — applied network timeout to `push --force-with-lease`, `fetch <remote> <target>` (via `networkGitOptions` threaded into `resolveBaseSha`), and the entire gh precheck + `gh pr list` / `edit` / `create` chain (via `networkGhOptions`). `rev-parse <remote>/<target>` keeps NO timeoutMs.
- `packages/runner/src/actions/{mark,merge}-github-pr.ts`, `github-pr-status.ts` — updated `ghLineOptions` to always include `timeoutMs: NETWORK_COMMAND_TIMEOUT_MS` since every gh call in these actions is a network call.
- `packages/runner/src/actions/github-pr-runtime.ts` — unchanged in body; the precheck just forwards the caller-supplied options to `gh()`, so the network timeout flows through transparently when callers pass `networkGhOptions`.

### Test additions (16 new tests across 7 spec files, all < 500 ms each)

- `tests/github-pr-status.spec.ts` — `NetworkGhPrView_ReceivesTimeoutMs`, `GhPrViewTimeout_SurfacesStepNameAndDuration` (the action's existing failure path — it does NOT call `classifyGhFailure` — surfaces the captured output and step in the JSON `steps` array).

### Gotchas worth recording

- **`runCommand`'s 6th arg is `options`, NOT a separate `env` slot.** When writing fake
  `GitRunner`s the signature is `(workDir, args, signal, options?)`. Earlier I wrote
  `(workDir, args, signal, _env, options)` like the `GhRunner` — TypeScript accepts the
  overload but `options?.timeoutMs` resolves to `undefined` because the fake receives
  `undefined` for the 4th param (the actual `options`). Use the 4-arg form for `GitRunner`
  fakes.
- **`git.ts`'s runner contract widened to include `status?: "timeout"` and `timeoutMs?: number`**
  on the return type. The existing `installGit` helpers in push.spec.ts / rebase.spec.ts
  / create-github-pr.spec.ts use the seam type declared in each action file. Adding the
  two new optional fields is backward-compatible: existing fakes that return
  `{ success, stdout, stderr, exitCode, combinedOutput }` still type-check. The new
  D4-shaped fakes that add `status: "timeout"` + `timeoutMs` exercise the classifier
  path without invoking `runCommand`.
- **`GitRunner` seam signature in `actions/push.ts` and `actions/rebase.ts` is a local
  type, not derived from `typeof git()`**, so the return-type widening had to be done
  in both files manually. `create-github-pr.ts` does the same.
- **Test fake arrays are now module-scope (`gitCalls`, `ghCalls`)** in
  `create-github-pr.spec.ts`, `github-pr-status.spec.ts`, `mark-github-pr-ready.spec.ts`,
  `merge-github-pr.spec.ts` — `afterEach` clears them. Existing tests that declared
  local `gitCalls: string[]` arrays still work because the variable shadowing is
  per-block. The new tests assert against the module-scope arrays.
- **`github-pr-status.ts` does not call `classifyGhFailure`** — its failure path surfaces
  the raw gh output directly. A timeout test for this action therefore asserts the
  captured stderr contains `timed out` and the existing `steps[]` entry carries the
  right exit code, rather than asserting `failureKind`. The other delivery actions DO
  call `classifyGhFailure` and pick up the unchanged `retry-safe` arm.
- **Action-level seam type for `GhRunner` (`actions/github-pr-runtime.ts:6`,
  `actions/github-pr-status.ts:6`) is `typeof runCommand`**, so the 6-arg signature is
  `(command, args, workDir, signal, env?, options?)`. fakes that want to record
  `options.timeoutMs` must take 6 args.
- **No per-command budget table.** The acceptance criteria explicitly forbids it; one
  shared constant covers clone/fetch/ls-remote/push/gh-pr-list/edit/create/precheck.
  If clones regress on slow links, raise `NETWORK_COMMAND_TIMEOUT_MS` rather than add
  a per-command knob (Non-Goal from the proposal).
- **Test budget for the new tests:** all 16 new tests run in well under 500 ms each;
  the full runner suite (948 tests, up from 931) completes in ~8.5 s.
