## T-002 — 提取 git 输出解析器到 git-parsers.ts 并补单元测试

- Created `packages/runner/src/server/git-parsers.ts` exporting the five pure parsers verbatim from `runner-signalr.ts`:
  - `parseDiffFiles(numstat, fullDiff)` → per-file `{ file, additions, deletions, diff, isBinary }` array (binary line `-\t-\t…` → `additions=0`, `deletions=0`, `isBinary=true`; non-binary ints parsed via `parseInt` defaulting to 0; blank / short-tab lines skipped).
  - `splitDiffByFile(diff)` → `Record<b/path, joined patch>`; empty/whitespace input → `{}`; preamble before first `diff --git` header dropped by `flush()` (currentPath stays null).
  - `parseCommits(log)` → empty for empty/whitespace input; splits on `\n`, drops lines with fewer than 5 tab fields, returns `{ hash, shortHash, message, author, date, files: [] }` in field order.
  - `parseAheadBehind(output)` → `[ahead, behind]` from `behind\tahead` tab split; `[0, 0]` on anything that isn't exactly 2 tab fields (empty / single field / 3+ fields / non-integer).
  - `parseNumstatTotal(numstat)` → `{ filesChanged, additions, deletions }` aggregated with the same binary rule.
- `packages/runner/src/server/runner-signalr.ts` (772 → 701 lines) now `import { parseAheadBehind, parseCommits, parseDiffFiles, parseNumstatTotal } from "./git-parsers.js"`. All 5 handler call sites unchanged (line numbers shifted; behavior byte-identical). Other helpers (`git`, `isGitWorkTree`, `resolveWorkspaceQuery`, `isUnderRunnerRoot`, `resolveSessionTarget`) remain in `runner-signalr.ts` — extracted by later tasks per design.md D2.
- Created `packages/runner/tests/git-parsers.spec.ts` — 24 direct unit tests grouped by parser, each scenario mirrors the corresponding WHEN/THEN clause in `specs/workspace-git-queries/spec.md` ("Numstat parsers tolerate binary entries and malformed lines" + "Ahead/behind and commit parsers tolerate malformed output") plus the "Per-file diff is keyed by the b/ path" requirement. Covers: binary line → 0/0/isBinary, malformed/empty lines skipped, `parseNumstatTotal` aggregation (3\t1\ta.txt + -\t-\tb.bin → {filesChanged:2, additions:3, deletions:1}), `parseAheadBehind` well-formed vs malformed → [0,0], `parseCommits` drops short lines and returns [] on empty input, `splitDiffByFile` b/ path key behavior unchanged.
- Verification:
  - `npm run typecheck -w packages/runner` → clean (no unused-import warnings; treat-warnings-as-errors would have caught it).
  - `npm test -w packages/runner -- git-parsers.spec` → 24 / 24 pass in 5ms (well under unit <50ms target).
  - `npm test -w packages/runner` → 948 / 948 pass across 70 test files (was 924 / 69 before T-002). `runner-signalr.spec.ts` / `runner-signalr-workflow-status.spec.ts` / `workspace-registry-integration.spec.ts` unchanged and still green — no existing test had to import any of the five parsers (they were previously not exported).
- Zero behavior change at the call site: every existing git handler in `runner-signalr.ts` was updated mechanically (only the import changed; the parser calls themselves were untouched).
- For downstream tasks: the test file deliberately uses the parser-only import path (`from "../src/server/git-parsers.js"`) so future work (P5/P6 git handler direct tests in `runner-signalr.spec.ts`, T-007's `workspace-git-handlers.ts`) can keep importing from the canonical location without depending on `runner-signalr.ts` re-exports. If reviewers prefer the design.md D4 "re-export setters from runner-signalr" pattern for parsers too, that's a zero-cost follow-up.
