## Codebase Patterns

- `TranscriptAccumulator.EventTypes` is the canonical allow-list for AgentSession runtime ingress and transcript persistence.
- Terminal AgentJob delivery is persisted as `TranscriptPartTypes.SessionActivity`; its `operationId`/delivery id is the transcript correlation key, so duplicate runtime delivery remains one part while `RawEventCount` records both observations.
- Project and Issue AgentOps feeds query persisted `session.activity` parts directly. The Issue feed additionally requires routed AgentJob lineage and a canonical `agent-job:{id}:terminal` delivery id.

## T-002

- `TRANSCRIPT_EVENT_TYPES` no longer carries `session.closed`, `session.followup_completed`, or `session.followup_failed`; the three names are also excluded from the typed `AgentDetailEventMap`. The canonical-event-types test now asserts both the current transcript catalogue and an explicit exclusion of the three retired names.
- `isSessionClosedEvent` predicate is gone; the transcript chat/compact views now close a turn and set terminal status from `session.activity` with `activity: 'idle'`. Failure detail still arrives through `session.liveness` with `status: 'failed'`; `coder_session_status_changed` / `coder_recovery_status` continue to carry recovery surfaces.
- The activity-feed event classifier (`agentSessionEventInfo` + `AGENT_SESSION_EVENT_TYPES`) now treats `session.activity` as the canonical AgentSession event, keeping the existing `status`-based attention routing for completed/failed/timeout/cancelled outcomes and the Session navigation target.
- Test fixtures that named the retired events for terminal signalling were migrated to the equivalent current event (`session.activity` for terminal completion, `session.liveness` for failure). `events-hub-subscription.spec.tsx` and `live-task-cloud-event.spec.tsx` now assert subscription/routing against `session.activity` and explicitly exclude the retired names.
