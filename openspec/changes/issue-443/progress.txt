# issue-443 progress

## Task T-001: Implement structured Workflow Action output end to end

## Codebase Patterns

- Runner `ActionResult.output` was `string | null`; converted to/from JSON at every consumer.
- `WorkItemResult.output` was `string | null` and was JSON.stringified over the runner report HTTP wire.
- Server `WorkResult.Output: string?`, `TaskReport.Output: string?`, `RunnerReportRequest.Output: string?`.
- `WorkflowWorkLifecycle.ParseOutputToJsonElement` wrapped unparseable strings as JSON strings; now removed.
- `WorkflowStatusMapper.MapTasks` re-serialized `t.Output` to a string via `JSON.Serialize(t.Output.Value)`; now passes the element directly.
- `WorkflowItemTranslator.TranslateTaskResultAsync` passed `result.Output` (string) to `TaskReport.Output`; now validates object-or-null and canonicalizes JSON null.
- `WorkflowItemTranslator.TranslateChecksResult` used `WorkflowDispatchHelpers.ParseCheckResults(result.Output)` which expected a JSON-string of an array; now consumes `JsonElement?`.
- Server `WorkResult` carries `Output: JsonElement?`.
- `AgentJobExecutor.projectTurnToWorkItemResult` JSON.stringified an object; now returns the object directly.
- `core/process` now returns `{ stdout: trimmed, exitCode: number }`.
- `TaskRun.Output` was already `JsonElement?`. We now assign directly without `ParseOutputToJsonElement`.
- Web `WorkflowTimelineTask.output` is to become `Record<string, unknown> | null`.
- `parseTimelineTaskOutput` and `parseTaskOutput` are to be removed.
- `pr-delivery.ts: parseJson` accepts strings or objects — kept for backward test compat with object-valued outputs.
- `recovery.ts: safeParseObject` reads `result.output` as string — now consumes structured output directly.

## Runner changes done

- Core types: `ActionResult.output: JsonObject | null`. `WorkItemResult.output: JsonValue | null`.
- `action-result.ts`: `succeed(output: JsonObject | null)`. New `validateActionOutputShape(output)` rejects strings, arrays, scalars, cyclic objects, non-finite numbers, undefined/function/bigint with the existing `unexpected-error` code and an actionable message.
- `executor.ts`: validates action output at the boundary, produces `failAction(...)` with `unexpected-error` before completion/recovery/setVars when the shape is invalid. `projectTaskOutput` preserves structured output; `mohist/opencode` projects a `{ promise }` object. Surfaces `result.output` directly.
- `check-execution.ts`: emits the structured result-row array (`JsonValue`), with passing rows carrying object-or-null `output`. Validates each row's Action output shape and reports `unexpected-error` per invalid check.
- `set-vars.ts`: traverses the `ActionResult.output` object directly; missing paths and null output fail the task atomically (no partial patch).
- `recovery.ts`: `failureContext.output` is now the structured value (object-or-null), no `safeParseObject`.
- `artifact-capture.ts`: `actionProducedArtifacts` reads the structured output object directly.
- `output-capture.ts`: traverses the structured output object.
- All built-in Action producers return objects directly: `core/process` → `{ stdout, exitCode }`; `core/script`, `core/artifact-exists`, `core/marker`, `merge-ready`, `core/process`, `mohist/push`, `mohist/rebase`, `mohist/rebase-status`, `mohist/openspec-*`, `mohist/archive-change`, `mohist/create-github-pr`, `mohist/mark-github-pr-ready`, `mohist/merge-github-pr`, `mohist/github-pr-status`, `mohist/opencode`, `mohist/workspace-prepare` — no more `JSON.stringify` of public success output.

## Decisions / gotchas

- The ActionResult type stays narrower (`JsonObject | null`) than the shared `WorkItemResult.output` (`JsonValue | null`) per the proposal — checks emit arrays, AgentJobs emit their own non-Action shapes.
- `ActionResult` validation runs immediately after `stripRunnerPrivateFacts` and before `evaluateCompletion`/`tryRecovery`/`captureAndUploadArtifactsForWork`/`applySetVarsForWork`. The runner keeps `output` on the failed result as `null` so recovery context doesn't accidentally match on an invalidated output.
- `AgentJobTerminalResult.Output` remains `string?` (domain contract). The AgentJob adapter converts inbound JsonElement object/array to raw text at the server-side AgentJob boundary so its terminal output keeps the existing shape without crossing the Workflow Action contract.
- Feedback summary extraction is one Action-specific adapter: only `core/process` task's `output.stdout` becomes the resolution summary. Every other Action yields null summary (still resolves the feedback).
- `capturedOutputs` is intentionally not wired into the server (Runner proposal explicitly says not); we keep the runner-local field to keep the Web StageStateRead path unchanged.
