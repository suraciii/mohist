## Codebase Patterns

- The `IAgentConnectionProviderCleanup` interface is the established seam for cascading provider rows on Connection delete. Each child store implements `DeleteForConnectionAsync` and is forward-registered in `MohistServiceRegistration.cs:106-111` so the cascade loop in `AgentConnectionStore.DeleteProviderRecordsAsync` resolves the same scoped instance. New child stores MUST be added there (now 7 forward-registrations).
- The channel ingress (`HandleChannelIngressAsync`) uses a single equality check that is now consolidated into `SlackConnectionAccessDecider.EvaluateAsync`. The decider is read once per ingress and reused at all five owner-check sites via a local `decision` variable.
- `AgentConnectionRow` has both a `LastHeartbeatAt` style nullable `string?` and a `string` (with default) AccessPolicy. The migration uses the `HasDefaultValue(AccessPolicyKind.OwnerOnly)` pattern, and the snapshot needs `HasDefaultValue("owner_only")` to match the model exactly (string form, not constant name).
- `MohistDbContextModelSnapshot` must mirror the runtime model exactly or `IMigrationsModelDiffer` returns `AlterColumnOperation` (default-value differences) and `AddCheckConstraintOperation` (missing check constraints) that abort Migrate().
- `SlackConnectionAccessDecider` takes `IDbContextFactory<MohistDbContext>` for future use (T-002 needs it for live users.info) but the T-001 owner_only + DM branches do not use it. Keep the parameter for the upcoming T-002 wiring.
- Test classes in `Mohist.Server.SpecTests/Specs/Slack/` MUST end with `Specs` or `Collection` (arch test enforced). I initially named a unit-style test `SlackConnectionAccessDeciderTests` and the arch test caught it.
- Spec test classes that don't need IAsyncLifetime (and own their resources with a constructor + `IDisposable`) work fine; some specs in the codebase use `IAsyncLifetime` but it's not required.
- The `SlackOwnerClaimService` constructor now takes `SlackConnectionAccessDecider` (5th positional parameter). All test sites that instantiate it directly (e.g. `SlackOwnerClaimSpecs`, `SlackOwnerTransferSpecs`) must be updated.
- Arch test rule `ServerSourceComments_DoNotIntroduceNewIssueSpecDesignPathReferences_BeyondBaseline` blocks issue/openspec references in production code comments. Pattern: `issue-\d+|T-\d{3}|design/[^*\s]+\.md|openspec/`. Do not put such references in `.cs` comments.
- For `IAsyncLifetime`-based test classes, the initialize runs before each test method. The constructor-based approach is more reliable for tests that need a single fresh fixture.
