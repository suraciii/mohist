## Why

A long Mohist session runs to dozens of tool calls and tens of thousands of pixels. When a reader returns with a question — "where did it fail?", "what files did it touch?" — the only answers today are pure scrolling, or a bare count ("Tool errors detected · 2") pinned to the top of the page that links to nothing. #427 already gave every turn and every tool row a stable, locatable anchor (`data-turn-id`, `data-turn-index`, `data-tool-call-id`, `data-tool-state`) and deliberately deleted the old half-broken `TurnTocRail`/`TranscriptToolbar` to make room; #428 proved the click-to-jump pattern (`CurrentActivityBar` locating a row via `CSS.escape` + `querySelector('[data-tool-call-id=…]')`) + `scrollIntoView`). This issue mounts the navigation surface those anchors were built for: a mini timeline that marks key events and jumps to them, an error prompt that goes straight to the failing call, and rendering tuned so a long transcript scrolls and expands without visible jank. It is purely additive — it consumes existing anchors and existing display data, and adds no new event protocol, data model, or liveness gate.

## What Changes

- **The session gains a mini timeline.** A compact navigation surface (rail or bar — exact placement is a design decision) plots the session as a sequence of nodes: turn boundaries plus, within and across turns, event markers for **failed tool calls** (red), **file-changing tool calls** (green), and **exploratory read-only calls** (gray). Activating any node locates the corresponding row via its existing anchor and scrolls it into view.
- **The mini timeline works for single-turn long sessions too.** When there is only one turn, nodes are derived from events (not turn boundaries), so a one-turn session still gets useful navigation rather than a single dot.
- **Event markers descend into context groups.** Because #427 collapses consecutive exploratory calls into a `context-group` row, an event inside such a group still maps to the underlying `toolCallId`; locating the target row also expands its containing group when needed so the target is on screen.
- **The session-level tool-error evidence bar becomes the entry point for error navigation.** The existing `SessionErrorsEvidence` bar (`data-testid="session-errors-region"`, `data-tool-error-count`) currently shows a count and links to nothing. It becomes activatable: a click jumps to the first failed tool call (located via `[data-tool-state="failed"]`), scrolls it into view, and applies a transient highlight so the reader sees exactly where they landed. When there is more than one error, the bar offers a "next error" affordance to iterate failures in document order. The count and category display are unchanged.
- **Locating a target applies a transient highlight.** Both the mini timeline and the error bar, on locating a row, apply a short-lived highlight to the target so the reader's eye lands on it after the scroll. The highlight is dismissable (escape / click elsewhere / next jump) and decorative to assistive tech.
- **Long transcripts render at row/turn granularity, not container granularity.** Today the whole `role="log"` container carries a single `content-visibility: auto`; this issue pushes the visibility/lazy-render strategy down to the per-turn or per-tool-row level so scrolling and expanding rows in a 10k+ pixel transcript is smooth. The detail-expansion contract of a row is unchanged; only the off-screen rendering strategy changes.
- **No change to the transcript data model, event protocol, or liveness gate.** No new fields on `DisplayTurn`/`DisplayToolPart`/`DisplayContextGroupPart`; no new SSE event types; no change to `useSessionTranscript` reducers; the error bar still reads `meta.eventSummary.toolErrorCount` / `meta.eventSummary.failureCategory`. All new behavior is presentation derived from existing data.

## Capabilities

- `transcript-mini-timeline`: The compact session navigation surface — turn nodes plus within-turn event markers (failed tool / file change / exploratory read), each activatable to locate the corresponding row. Requires meaningful behavior for both multi-turn and single-turn (event-derived) sessions, and correct descent into `context-group` rows so an event inside a group locates the underlying tool call rather than the group wrapper.
- `transcript-error-jump`: Making the session-level tool-error evidence bar activatable to jump to the first failed tool call, iterate through subsequent failures in document order, and surface a transient highlight on the located row. Requires preserving the existing count/category display and operating purely off the existing `[data-tool-state="failed"]` anchor.
- `transcript-jump-highlight`: The transient visual highlight applied to a transcript row after a scroll-to-locate, consumed by both the mini timeline and the error jump. Requires the highlight to be short-lived, dismissable, decoupled from any specific launcher, and invisible to assistive tech as a decorative cue.
- `transcript-render-performance`: The rendering strategy that keeps scrolling and row expansion smooth on long (10k+ pixel) transcripts. Requires visibility/lazy-rendering decisions to be made at the turn or tool-row granularity rather than the whole transcript container, with no change to the detail-expansion contract of a row.

## Impact

- **Web (`packages/web/src/widgets/session-transcript/`)** — primary surface, presentation layer only:
  - A new mini-timeline component (e.g. `ui/MiniTimeline.tsx`) and a model helper projecting `displayTurns` → event nodes (failed / file-change / exploratory read), descending into `context-group` parts. Reuses the `CurrentActivityBar` locate pattern (`CSS.escape` + `querySelector` + `scrollIntoView`) against the existing `data-tool-call-id` / `data-turn-id` anchors.
  - A new transient-highlight affordance (hook or component applied to a located row) consumed by both the mini timeline and the error jump. Any timer MUST be time-injectable per `design/testing.md` (reuse the `useNow` seam #428 established).
  - `ui/AssistantParts.tsx` `ErrorPartView` gains a locatable id so individual error parts can be jump targets too (failed tool rows already carry `data-tool-state="failed"`).
  - `ui/TurnList.tsx` and/or `ui/SessionTranscriptLayout.tsx` — move the `content-visibility: auto` (or equivalent lazy-render strategy) from the whole container down to per-turn or per-tool-row granularity. Row expansion behavior is unchanged.
- **Web (`packages/web/src/pages/session/ui/SessionDetailShell.tsx`)** — `SessionErrorsEvidence` becomes activatable; a click handler locates the first `[data-tool-state="failed"]` and triggers the shared locate+highlight flow. Mounts the mini timeline (placement — the existing `siblingSidebar` slot vs. a transcript-internal rail — is a design decision). No new data-source fields: `displayTurns`, `meta.eventSummary.toolErrorCount`, `meta.eventSummary.failureCategory`, and `scrollContainerRef` are all already on `SessionDataSourceResult` / the shell.
- **Tests (`packages/web`)** — new unit/spec coverage for: event-node projection (failed / file-change / exploratory read, incl. inside context groups), mini-timeline activation locating the right row, single-turn vs. multi-turn node derivation, error-bar activation + next-error iteration + transient highlight, and large-document rendering strategy (asserted via fake strategy / count of rendered rows, not wall-clock timing — per `design/testing.md` no `elapsed < N` assertions). The liveness gate (#426), the row anchor (#427), and the live-tool-duration (#428) are owned by their issues and not re-tested here beyond consumption.
- **Server / Runner / CLI / events / protocol / dependencies**: none.
- **Risk (low)**: purely additive presentation; consumes the stable anchors established by #427 and the locate pattern proven by #428 without modifying either; mitigated by keeping all new behavior client-side and derived from existing display data.
