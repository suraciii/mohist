### F1. A canceled delivery leaves the queued turn permanently claimed until activation changes

`AgentSessionFollowupDispatcher` persists a `Dispatching` claim before calling the Runner ([AgentSessionFollowupDispatcher.cs:32](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Api/AgentSessionFollowupDispatcher.cs:32)), but releases it only when delivery returns an unsuccessful result ([AgentSessionFollowupDispatcher.cs:49](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Api/AgentSessionFollowupDispatcher.cs:49)). The SignalR delivery implementation instead rethrows request cancellation ([RunnerFollowupDeliveryDispatcher.cs:79](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Runner/Services/SignalR/RunnerFollowupDeliveryDispatcher.cs:79)). The turn therefore remains `queued` but claimed; a same-key retry correctly reports that it should redeliver, yet `BeginNextFollowupDispatchAsync` refuses the still-claimed turn ([AgentSessionGrain.cs:462](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Grains/AgentSessionGrain.cs:462), [AgentSessionGrain.cs:510](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Grains/AgentSessionGrain.cs:510)). The only reclamation is during a later activation ([AgentSessionGrain.cs:72](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Grains/AgentSessionGrain.cs:72)).

Reproduce by holding `ReceiveFollowup`, aborting the POST after the claim is stored, and retrying the same idempotency key without deactivating the grain. The retry returns the original identity but cannot redeliver, violating D9 and the retry acceptance criteria. Make interrupted delivery independently recoverable before an in-process retry, or keep dispatch alive independently of HTTP cancellation, and cover this path with an API/spec test.

### F2. An in-flight delivery claim changes a queued turn from "join" to "new turn"

The claim deliberately leaves the selected turn observable as `queued` ([AgentSessionGrain.cs:514](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Grains/AgentSessionGrain.cs:514)), but `ChooseFollowupTurnForAssignment` excludes a queued turn whenever its lease has `Dispatching = true` ([AgentSession.Transitions.cs:810](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Domain/AgentSession.Transitions.cs:810)). A distinct input accepted after the first turn has been claimed but before the Runtime emits `session.input` therefore gets a new turn ([AgentSession.Transitions.cs:720](/home/szf/.mohist/projects/workspaces/wr_523a0d94be64409990d59c564f3f550a/packages/server/src/Mohist.Server/Sessions/Domain/AgentSession.Transitions.cs:720)), instead of appending to the existing queued turn in submission order as D3 requires.

Reproduce by holding the first Runner invocation after its claim is committed, then submit a second idempotency key. Both inputs are accepted, but the status-visible queued turn is split into two turns solely because delivery is in flight. Preserve the queued-turn assignment rule independently of the transient delivery reservation, and add a concurrency spec that holds delivery while submitting the second input.
