## Why

The unified session page (`UnifiedSessionPage` + `widgets/session-transcript`) replaced the earlier issue-scoped coder-session UI, but the superseded layer was never removed. Today `widgets/coder-session` still ships a complete dead component chain (SessionCard family, SessionTimeline, PlanProgressPanel, compaction entries, its own `useSessionTimeline`/`session-timeline-reducer`), `entities/session` still ships SessionEvent chat/compact/timeline view projections whose only consumer is that dead chain, and `entities/coder-session`/`entities/agent` still export issue-scoped and generic session client functions no production code calls. On top of that, `pages/session/data/SessionDataSource.ts` re-declares the data hook's return shape as a hand-written interface that has already drifted (fields no consumer reads), so the session page's data contract is maintained twice. This dead surface slows every session change, keeps obsolete API shapes alive as if they were alternates, and violates the repo rule of removing obsolete paths instead of keeping them.

## What Changes

- Delete the dead `widgets/coder-session` component chain: `SessionCard.tsx` (ActiveSessionCard / RecentCard / WaitingCard), `model/anomaly.tsx`, `SessionTimeline.tsx`, `PlanProgressPanel.tsx`, `session-health/CompactionTimelineEntry.tsx`, `session-health/CompactionCompactSummary.tsx`, `model/useSessionTimeline.ts`, and `model/session-timeline-reducer.ts`. Keep the still-consumed exports (activity events, usage snapshot, SessionFollowupComposer, SessionRecoveryActions, ContextHealthBar, UsageSnapshotLabel).
- Delete the SessionEvent view projections in `entities/session`: `model/view.ts` (`viewSessionEvents`), `model/view/{chat,compact,timeline,helpers}.ts`, the `SessionEvent` / `SessionView*` type family, and their re-exports (`index.ts`, `@x/session-view.ts`). The live timeline projection (`model/timeline/*`, used by `widgets/session-transcript`) stays untouched.
- Delete session data-layer code with no production consumers: `useCoderSessions`, `useFollowupMutation` + `postFollowup`, `useStopSessionMutation` + `stopSession`, and the issue-scoped client functions `getCoderSessions`, `getAgentSessionMetadata`, `getAgentSessionTranscript`, `getAgentSessionEvents` in `entities/coder-session`; `canRecoverSession` / `deriveSessionActivity` in `sessionActivity.ts`; `buildGenericSessionMetadata.ts` in `pages/session/data`; and the duplicated generic-session summary/transcript client functions and hooks (`getGenericSessionSummary`, `useGenericSessionSummary`, `getGenericSessionTranscript`, `useGenericSessionTranscript`, their query options, `GenericAgentSessionSummaryDto`) in `entities/agent`. Types used only by deleted code are removed with it.
- Replace the hand-written `SessionDataSourceResult` / `SessionTurnControlHandle` interfaces with the concrete return type of `useUnifiedSessionDataSource` (inferred, not re-declared), so `SessionDetailShell` and tests consume the hook's actual shape and fields without consumers disappear from the contract.
- Remove tests that cover deleted code only, and prune slice public APIs (`index.ts`) of the removed exports.
- No user-visible behavior changes, no server/runner API changes, no dependency changes.

## Capabilities

- `session-detail-data-source`: The session detail page's single data path — the unified session data hook whose inferred concrete return type is the contract between `pages/session/data` and `SessionDetailShell`; covers that web has exactly one session-detail data source (unified session summary/transcript + generic followup/turn control) with no parallel hand-written interface and no orphaned issue-scoped or generic session client duplicates.
- `session-transcript-timeline`: The surviving production session presentation projection — session turns and live events reduced to timeline facts, items, and grouped entries (`entities/session/model/timeline` consumed by `widgets/session-transcript`); covers that this is the only session-event projection in web after the SessionEvent chat/compact/timeline view builders and their types are removed.

## Impact

- **`packages/web` only.** Touched slices: `widgets/coder-session` (component deletions plus index pruning), `entities/session` (view projection deletion, `@x/session-view.ts`), `entities/coder-session` (hooks, client functions, activity helpers, types), `entities/agent` (generic session summary/transcript duplicates), `pages/session` (data source typing, `buildGenericSessionMetadata.ts` removal).
- **Tests:** delete unit/dom tests of removed code (SessionCard, SessionTimeline, session-health compaction views, session view projections, dead hooks and client functions); `SessionDetailShell` tests switch their `data` prop to the concrete hook return type.
- **APIs/dependencies:** none — server endpoints, runner, and CLI are untouched; deleted web client functions simply stop existing (their server routes remain for other consumers).
- **Risk:** low — deletions are provably unconsumed in production; the only behavioral surface is the session page data contract, which becomes stricter (unused optional fields fall away with the interface).
