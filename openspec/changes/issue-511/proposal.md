## Why

A review surfaced a batch of problems that share one property: **the fix is unique and needs no design judgment** — they are scattered "we know what to do, just nobody did it" debt. Left alone they actively mislead readers (a dead event-dispatch path that looks load-bearing, a class named for a concept it no longer touches, control flow keyed on English exception text) or silently rot (38 comment references to issue numbers and design paths, one already pointing at a file that does not exist). Each item is mechanical on its own, but bundling them cuts coordination cost and — for the two most likely to recur (comment-number references, the status word table) — pays for gatekeeper tests that turn red the moment the debt tries to come back.

## What Changes

- **Remove the dead WorkflowGrain event-dispatch path.** `IWorkflowGrainContext.DispatchEvent`, its `WorkflowGrain.On` implementation (19 branches all returning `Task.CompletedTask`), the `WorkflowWorkLifecycle` loop that feeds it, and the `reason` parameter threaded through `CommitAsync` for that loop are deleted. No behavior is lost — the path produces nothing.
- **Remove the production test backdoor.** `WorkflowGrain.BindProfileForTest` (a settable delegate that lets production code bypass `IWorkflowProfileReferenceCoordinatorGrain`) is deleted; its single test consumer switches to registering a fake coordinator grain in the test cluster. This closes the hole `architecture.md`'s "no production bypass of the coordinator" ArchTest is meant to cover.
- **Stop using exception message text as a contract.** Profile-resolution failure now throws a typed exception carrying a decidable reason; `CommitAsync` branches on the type, not on `ex.Message.Contains("no current definition")`. Changing a word no longer silently changes control flow.
- **Correct misleading names.**
  - `WorkflowRunProfileManager` → `WorkflowRunVariablesStore` (it reads/writes Run-scoped Variables, never a Profile; `docs/workflow-profiles.md` already says Variables are not part of the Profile). Methods drop the Profile wording; the `WorkflowRunProfileRow` / `WorkflowRunProfiles` table is either renamed with a migration or the misnomer is documented in `design/` as a deliberate keep.
  - `FrontendStatus` → a name that states the wire-format contract it actually defines (e.g. `WireStatus`) — the CLI consumes this table too, and it describes a line format, not a frontend.
- **Make the status word table exhaustive by construction.** `FrontendStatus(string)` is split into one typed entry per enum (`WorkflowRunStatus`, `StageRunStatus`, `TaskRunStatus`, `StageCheckStatus` — the issue body's `CheckRunStatus` is a misnomer), each a switch expression; the `ToLowerInvariant()` fallback is deleted. Adding a new enum value without a mapping is now a compile error, not a silent `inprogress`. The four hand-written web unions (`WorkflowRunStatus`, `WorkflowStageRunStatus`, `StageStateStatus`, `WorkflowRecoverySummary`) each gain a comment naming the server enum they track; `WorkflowStageRunStatus` currently lacks `completed` (which server `StageRunStatus` emits) and is reconciled as part of this change.
- **Ban issue/spec/design references in C# comments.** A new ArchTest forbids `issue-\d+`, `T-\d{3}`, `design/*.md` paths, and `openspec/` in C# comments, gated by a frozen baseline of the current 38 violations across 26 files (the same ratchet pattern as `spec-file-size-baseline.json`) that may only shrink. The baseline is then cleared to zero so the test becomes a hard ban. The migration comment pointing at the non-existent `design/workflow/scheduling.md` gets its schema decision written inline (or removed), and the `UnifiedSessionRoutes` T-005 remark is verified against actual CLI usage and rewritten as a fact (CLI still uses `agent-sessions/{sessionId}`).
- **Two micro-cleanups.** `EventDispatcherService.Backoff` becomes `private` (retry cadence is observed through `DispatchAsync` + `FakeTimeProvider`); the `WorkflowProfileManager.ResolveLayeredVariablesAsync` pass-through wrapper is inlined at its single call site.

External behavior is unchanged: Workflow state progression, event output, the API and CLI command surface, and the literal wire-format status values all stay byte-identical. Profile-resolution-failure user-facing error text is unchanged.

## Capabilities

- `workflow-grain-production-contract`: WorkflowGrain carries no test-only seams in production code and no dead event-dispatch path — `DispatchEvent`/`On` and the `BindProfileForTest` delegate are gone, and profile-resolution failure is classified by exception **type** (not message text) so control flow survives any wording change. The contract the coordinator-bypass ArchTest promises becomes real.
- `workflow-run-variables-store`: The Run-scoped Variables persistence entry point is named for what it does (`…VariablesStore`, per `conventions.md`'s `Store` suffix for resource persistence), its methods drop Profile wording, and the backing table is either renamed with a migration or its misnomer is recorded in `design/` as a deliberate decision (never silently left). No change to the persisted shape or API surface.
- `status-wire-mapping`: The wire-format status mapping is exhaustive by construction — one typed switch entry per server enum (`WorkflowRunStatus`, `StageRunStatus`, `TaskRunStatus`, `StageCheckStatus`), no `string` input, no `ToLowerInvariant()` fallback, every value producing kebab-case — and each web union names the server enum it tracks (with `WorkflowStageRunStatus` reconciled to include `completed`). Existing wire values are preserved verbatim.
- `comment-reference-ban`: C# source comments must not contain `issue-…`, `T-…`, `design/*.md`, or `openspec/` references, enforced by an ArchTest using a baseline ratchet (frozen at today's 38 hits, shrink-only) that is driven to zero and then becomes a hard ban. The dangling `scheduling.md` migration reference and the `UnifiedSessionRoutes` T-005 remark are resolved as part of clearing the baseline.

## Impact

- **Server — Workflow grain & lifecycle** (`packages/server/src/Mohist.Server/Workflow/Grains/`): `WorkflowGrain.cs` (delete `On`, `DispatchEvent` impl, `BindProfileForTest`; type the resolution-failure exception; drop `reason` from `CommitAsync`), `IWorkflowGrainContext.cs` (delete `DispatchEvent`), `WorkflowWorkLifecycle.cs` (delete the dispatch loop at `:128`).
- **Server — profile coordination** (`IWorkflowProfileReferenceCoordinatorGrain` + the fake grain registration hook in the test cluster): the single `WorkflowGrainStateSaveFailureSpecs.cs` consumer of `BindProfileForTest` switches to a registered fake coordinator.
- **Server — variables store** (`packages/server/src/Mohist.Server/Workflow/Services/WorkflowRunProfileManager.cs`; 14 files / ~33 occurrences across `packages/server`): rename to `WorkflowRunVariablesStore`; decision on `WorkflowRunProfileRow` / `WorkflowRunProfiles` table rename (EF Core migration if taken, else a `design/` note).
- **Server — status mapping** (`WorkflowStatusMapper.cs`, `WorkflowStatusMapperFrontendStatusTests.cs`, route/view call sites in `Api/WorkflowRoutes.cs`): typed per-enum entries, `WireStatus` rename, per-enum exhaustive spec.
- **Web** (`packages/web/src/entities/issue/model/`): `workflow-run.ts`, `stage-state.ts`, `recovery.ts` unions gain a server-authoritative-source comment; values unchanged (verified by typecheck + test).
- **Server — ArchTests** (`packages/server/tests/Mohist.Server.ArchTests/`): new comment-reference-ban test + baseline JSON (mirrors `spec-file-size-baseline.json`); existing coordinator-bypass rule now has real teeth.
- **Server — misc** (`Infrastructure/Events/EventDispatcherService.cs`, `Workflow/Services/WorkflowProfileManager.cs`): `Backoff` → private; `ResolveLayeredVariablesAsync` inlined.
- **CLI / runner / API command surface / wire format**: unchanged; no new commands, routes, or dependencies.
- **Verification**: server full suite (unit + spec + ArchTests); web typecheck + test. Risk is `medium` — each edit is mechanical but the rename and comment cleanup span many files, so they land in independently reviewable groups (A–E).
