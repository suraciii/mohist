## Tier-weight Markers

- `StatusHeadline` carries `data-tier-weight="status-header"` (the heaviest: sticky + semantic fill + icon + border).
- `reading-flow` carries `data-tier-weight="reading-flow"` (medium weight).
- `reference-rail` carries `data-tier-weight="reference-rail"` (lightest: CardSection substrate + muted tokens).
- All flow-block sections (description, comments, commits, diff-files) carry `data-tier-weight="reading-flow"` for cross-block consistency.
- The spec assertion "reading-flow is visually lighter than the status headline and heavier than the reference rail" is tested by mapping the three `data-tier-weight` values to a numeric order (3 / 2 / 1) and asserting the inequality chain.

## Collapsible Key-Signal Behavior

- Description: presence (heading "Description") + leading-text hint (`description-preview-hint`) above the markdown body. The hint is gated on stripped body length > 320 chars so the body content and the hint do not visually duplicate when content is short.
- Diff-files: scale line (`diff-files-scale`) with file count, additions, and deletions is always rendered. Zero-state shows "No files changed yet" so the absence of changes is also signal, not a vanished block.

## Decisions Settled in T-002

- **Per-block chrome rule**: description/comments/commits → no card wrapper, just heading + content (content-forward). diff-summary-banner → flat block (no fill/border). diff-files section → flat block with always-visible scale line.
- **Preview hint gating**: only show when stripped body length exceeds 320 chars. Avoids duplicate-text issues in jsdom-based tests and keeps the hint semantically a "long-content signal."
- **Tier weight ordering**: numeric map {status-header: 3, reading-flow: 2, reference-rail: 1} is asserted via `data-tier-weight` and compared by ordering the three tier containers. This is more stable than asserting per-class chrome and survives future visual refinements.
