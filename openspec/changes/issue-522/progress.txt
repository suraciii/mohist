## Codebase Patterns

- AgentSession child records are persisted in the grain state snapshot; Orleans serialization requires arrays for single-item InputIds values rather than collection-expression read-only lists.
- Follow-up reservations distinguish joining an active turn from starting an idle turn. Only idle-start follow-ups mint and persist a new input/turn pair before Runner dispatch.
- Explicit Runner rejection cleans up the pre-dispatch queued follow-up record so existing retry behavior remains intact; uncertain dispatch failures retain the record.

## verify:fix-ci (round 1)

- Reproduced the host hang by running `Mohist.Server.SpecTests.Specs.Sessions.GenericAgentSessionCancelApiSpecs` directly: the first `Cancel_QueuedTurnWithoutRunner_ReturnsCancelledAndPreservesRecords` test never returned. The hang actually lives at the start of `CreateQueuedSessionForCancelAsync`: `record.OpendAsync` → `Checkpoint` → `RecordFollowupTurnAsync` → `persistence.WaitAsync()`. The probe's `WaitAsync` waits for the next `IAgentSessionPersistenceObserver.Report`, which only fires from `PersistCallback`, which only fires when a persistence timer is registered and `_stateDirty`/`_transcript.HasPending`/`PendingTranscriptEvidence` is non-empty.
- `RecordFollowupTurn` returns an empty events list for a brand-new input/turn, so the grain took the early-return branch (`_stateStore.SaveAsync(...) ; return;`) without setting dirty or ensuring the persist timer — `persistence.WaitAsync` hung forever. The empty-events path also existed on `CancelTurnAsync`, `MarkTurnExecutingAsync`, `MarkTurnTerminalAsync`, `AbandonFollowupTurnAsync`, and `MarkInitialTurnTerminalAsync`, but only `RecordFollowupTurnAsync` had a test setup that depended on the persistence cycle.
- Targeted fix: keep the original early-return shape on those six methods (it is the right no-event path), but in `RecordFollowupTurnAsync`'s empty-events branch mark state dirty and `EnsurePersistenceTimer()` so the next `PersistCallback` tick reports the cycle. `AppendEventsAsync` already does this on its event-bearing path; this closes the symmetric no-event path used by the cancel/stop test helper. Filing the dirty/timer on every empty commit (the broader alternative) regressed `AgentSessionRecoveryGrainSpecs.Reset_StaleExpectedBinding_RejectsWithoutMutation` because the persist timer's mandatory re-save raced into the assertion window — a targeted fix avoids coupling unrelated save-count assertions to the persist cycle.
- The cancel/stop API tests `Stop_ExecutingTurnSendsTurnTargetAndReturnsStopped` and `Stop_UnconfirmedReplySurfacesUnknownAndInterruptFlag` surfaced a second pre-existing test defect once they stopped hanging: `CreateCanonicalSessionForCancelAsync` registered the runner via `IRunnerGrain.RegisterAsync` but never registered a SignalR connection in `RunnerConnectionTracker`, so `connections.GetConnectionId(target.RunnerId)` returned null and the stop route returned 503 `runner_unavailable`. Added `tracker.Register(_runnerId, $"{_runnerId}-conn")` next to the runner registration so the stop-route's `runnerHub.Clients.Client(runnerId)` resolves to the `RecordingRunnerHubContext` proxy and the test-set `SetInvocationResponse` actually routes the reply.
- Validation: focused class run, all 7 cancel/stop tests pass in ~5s; full Server Spec suite passes 3334/3334 in 77s; UnitTests 1535; CLI 1447; Runner 1444; Web 5155; ArchTests 35. No `.gitignore` or assertion-weakening changes; the only edits are the dirty/timer fix in `RecordFollowupTurnAsync` and the missing `tracker.Register` in `GenericAgentSessionCancelApiTestSupport`.
