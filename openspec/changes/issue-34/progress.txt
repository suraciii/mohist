# issue-34 progress

## Codebase Patterns (read first)

- `ILoggerProvider`/`ILogger` wiring convention: register a singleton of the provider class AND register it as `ILoggerProvider` on the application service collection. The framework's `AddLogging` enumerates `ILoggerProvider` from DI and wires it into the `LoggerFactory` automatically. There is no `AddProvider(Func<IServiceProvider, ILoggerProvider>)` overload in `Microsoft.Extensions.Logging` 10.x — calling `builder.AddProvider(sp => ...)` does not compile.
- `IEnvironmentVariableProvider` is in the `System` namespace (from the `EnvironmentAbstractions` NuGet), not `EnvironmentAbstractions`. Existing code uses no `using` directive for it.
- `ISingletonService` lives in `Mohist.Server.Infrastructure.Hosting`. Marking a class with it is enough to get the conventional `AddMohistConventionalServices` to register it as itself with singleton lifetime; explicit `services.AddSingleton<T>()` is still needed when other registrations depend on it (e.g. `ILoggerProvider`).
- `MohistIntegrationFixture` redirects filesystem concerns to per-run temp dirs in `ConfigureWebHost` and cleans them in `DisposeAsync`; the existing `RunnerRoot` and `ArtifactStorageRoot` pattern is the right seam to follow for any new redirectable directory.
- `JSON.Options` (`Mohist.Server.Infrastructure.JSON`) is the single shared `JsonSerializerOptions` for the entire API pipeline. Always serialize through it so the on-disk file and the API response have identical formatting.
- `SystemInfoService` advertises the `Logs` path. The advertised path is now consumed from `ILogPathResolver` so the `SystemPaths.Logs` field and the real file logger target are guaranteed to agree.
- `MohistWebApplicationFactory` constructor signature is part of the public test surface — `EventPublishingIntegrationFixture` (a separate `WebApplicationFactory<Program>` subclass) chains `base(...)` and broke when the constructor gained a new positional parameter. Add a new parameter at the end of the ctor and update both subclasses; do not reorder.

## T-002 — Typed /api/logs/tail contract

Files added (under `packages/server/src/Mohist.Server/Api/`):
- `LogsRouteContracts.cs` — `LogEntry` (level/time/service/message/raw) and `LogTailResponse` (lines, cursor, nextCursor, source, truncated, reset, unavailable, expectedLocation, reason) record types. Every nullable property carries `[property: JsonIgnore(Condition = JsonIgnoreCondition.Never)]` so the project-wide `JSON.Options` setting `DefaultIgnoreCondition = WhenWritingNull` does **not** strip nulls off the wire — the spec mandates every agreed field be present (as `null` when absent) so the Web client never sees `undefined`. Internal `LogEntryProjection.Project(rawLine)` parses each NDJSON line into the agreed shape and degrades non-JSON lines to `message=raw` with null level/time/service.

Files modified:
- `Api/LogsRoutes.cs` — rewritten. Consumes `ILogPathResolver` (T-001) and reads `server.log` directly with the newest-`*.log` glob retained as a transitional discovery fallback. `reset=true` on first read (no cursor) **or** when the supplied cursor > file length (rotation/truncation, restarting from byte 0). `truncated=true` when the line/byte cap hits before EOF. Both `cursor` and `nextCursor` carry the same byte offset (null at EOF and when unavailable). `reason` is populated when rotation is detected ("rotated or truncated since the previous read; view replaced."). `source` is the active file name (`server.log`) so the Web renders the `File:` line.

Tests added (under `packages/server/tests/Mohist.Server.Tests/Specs/Api/`):
- `LogsRouteSpecs.cs` — ten cases via `MohistIntegrationFixture`: missing-directory unavailable (with `expectedLocation`); directory present but server.log missing unavailable; first-read response shape (every field present); line-cap truncation + cursor advance + non-truncation EOF; rotation reset (cursor > fileLength, `reason` set); available-but-empty **not** reported as unavailable; non-JSON line degrades to `message=raw` + null structured fields; mixed JSON/non-JSON list (no raw strings mixed in); record written through `FileLoggerProvider` round-trips through the tail projection with no field loss; `source` reflects the active log file name.

Gotchas:
- **Cursor math must be manual, not `stream.Position`.** `StreamReader.ReadLineAsync()` reads ahead into its internal buffer, so `BaseStream.Position` jumps past the actual line position whenever the file fits in a single buffer read. The fix: `nextCursor = startPosition + bytesRead` where `bytesRead` accumulates `Encoding.UTF8.GetByteCount(line) + 1` per line. Using `stream.Position` produces an over-advanced cursor that puts the next read inside the previous line's tail (test fails with `expected "line 3", actual "}"`).
- **BOM breaks cursor math when tests use `File.WriteAllLinesAsync` with default `Encoding.UTF8`.** Default `Encoding.UTF8` has `emitUtf8Identifier = true` and `WriteAllLinesAsync` writes a 3-byte BOM (`EF BB BF`) at the head of the file. `StreamReader` auto-detects and skips it, but `bytesRead` doesn't see it — cursor math goes off by 3. Tests that seed log files via `File.WriteAllLinesAsync` must pass `new UTF8Encoding(encoderShouldEmitUTF8Identifier: false)`. The production `FileLoggerProvider` already uses that encoding, so production is fine.
- **`[JsonIgnore(Condition = JsonIgnoreCondition.Never)]` overrides `DefaultIgnoreCondition = WhenWritingNull` per property.** This is the only way to keep the global null-stripping behavior for the rest of the API while emitting `null` for the always-present log-tail fields. Apply via `[property: JsonIgnore(...)]` on each positional record parameter.
- **The singleton `FileLoggerProvider` in DI holds an open `FileStream` to a file path that can be deleted by other tests.** Other tests in the `LogsRouteSpecs` collection call `ResetState()` (which deletes the fixture's logs directory). After deletion, the provider's `_writer` is still bound to the original inode (Linux unlink semantics) — subsequent writes go to the unreachable inode, not the file at the path. For the FileLogger round-trip test, the fix is to instantiate a **fresh** `FileLoggerProvider` pointed at a private temp directory, write a record through it, then `File.Copy(freshProvider.LogFilePath, fixture's server.log)` so the route (which reads through the singleton resolver) sees the record. Calling `LogInformation` on the DI singleton in this test is a trap.
- **Integration tests should be tagged `Speed=Integration`, `Sut=Api`.** The `LogsRouteSpecs` class is annotated with `[Collection("MohistIntegration")]` and every test carries the two trait attributes — matches `TaskLogRouteSpecs.cs` and other route-spec files.

Gotchas:
- **`vi.useFakeTimers()` must be called *before* `renderHook`**, not after. With fake timers, microtasks still resolve, but `waitFor` polls via `setTimeout` (faked), so it hangs unless the test advances the clock. For tests that only need the initial fetch to settle, prefer `await act(async () => { await Promise.resolve(); await Promise.resolve() })` to flush microtasks over `waitFor` — no fake timers needed and the assertion is immediate. Use fake timers only for tests that advance `POLL_INTERVAL` or exercise the visibility-gated tick.
- **The `getLogTail` mock has to be defined via `vi.hoisted`**, not as a top-level `vi.fn()`, because `vi.mock` factories are hoisted above the surrounding top-level statements. A top-level `const mock = vi.fn()` followed by `vi.mock('./api', () => ({ getLogTail: mock }))` ends up with the factory capturing `undefined`.
- **`refresh()` does NOT reset the stored cursor** — preserving the original hook's behavior. After the first poll, `cursorRef.current` holds `nextCursor`, and `refresh()` re-fires `fetchLogs()` which uses `cursorRef.current == null` to decide whether to omit the cursor. This means: after the very first fetch (where `cursorRef` is still `null`), refresh re-fires without a cursor → server returns `reset=true` → view replaced. After any subsequent fetch (where `cursorRef` is a byte offset), refresh re-fires with that offset → server returns `reset=false` → appended. This matches what a user expects from a "refresh" button when they have been tailing live: it re-fetches the current tail position.
- **`MAX_ENTRIES = 2000` trim drops the oldest when total > 2000.** A test that combines 1500 + 1500 entries ends up with `[b1-1000 … b1-1499, b2-0 … b2-1499]` (2000 entries), not `[b1-500 …]`. Easy off-by-`MAX_ENTRIES/2` mistake.
- **`document.visibilityState` is read-only in jsdom.** Tests that toggle visibility must use `Object.defineProperty(document, 'visibilityState', { configurable: true, get: () => 'hidden' })` and dispatch a `'visibilitychange'` event manually; `document.visibilityState = 'hidden'` would throw or silently fail.
