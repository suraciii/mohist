T-001 (Live-ticking duration on running tool rows) — completed 2026-07-18

## Codebase Patterns

- Tool row duration rendering lives at `packages/web/src/widgets/session-transcript/ui/tool-views/index.tsx:129` (`formatElapsed(part.startedAt, part.completedAt ?? undefined)`), and the JSX block was historically gated on `!isRunning` (line 294 originally).
- ActivityPage (`packages/web/src/pages/activity/ui/ActivityPage.tsx:133-161`) is the existing precedent for injectable clock: `now?: number` prop, `setInterval(1000)` otherwise.
- `DisplayToolPart.status` ∈ `pending | running | completed | failed | cancelled`; `isRunning` is derived as `status === 'running' || status === 'pending'` — used in many places, do not redefine.
- `TurnList`/`TurnItem`/`AssistantParts` chain forms the rendering pipeline; new props must thread through the chain (TurnList→TurnItem→AssistantParts→ToolRowView, plus ContextGroupView for grouped tools).
- Vitest config uses `isolate: false`, project `jsdom` for `*.spec.tsx`; setup file restores `vi.useRealTimers()` in `afterEach`. So each test file/suite must call `vi.useFakeTimers()` itself and `vi.useRealTimers()` in afterEach.
- Test pattern for fake timers + React renderHook: `act(() => { vi.advanceTimersByTime(N) })`. Existing examples: `CopyFullTextButton.test.tsx:248`, `useSessionTimeline.dom.test.ts:330`.
- The existing `tool-row-view.spec.tsx` has a hard assertion that running rows render no duration when `now` is omitted — that contract is preserved because `liveDuration` only renders when `now !== undefined`.
- Tool rows already carry a stable `data-tool-call-id` anchor (set by `ToolRowView` in `ui/tool-views/index.tsx:233`). New consumers (e.g. the current-activity bar) locate the row by querying `[data-tool-call-id="..."]`; no parallel ref registry needed.
- The transcript scroll container is the `scrollContainerRef` div in `SessionDetailShell.tsx:366` (`data-testid="session-transcript-scroll-container"`); `SessionTranscriptLayout` receives it as `scrollContainerRef?: RefObject<HTMLElement | null>` and threads it to keyboard-nav. The same ref is the natural lookup scope for the bar's `[data-tool-call-id]` query.
- Existing "sticky" elements in the transcript region use `position: sticky` (e.g. the recovery bar in `SessionDetailShell.tsx:379` uses `sticky top-9 z-20`). The new bar mirrors that with `sticky bottom-0 z-10` so it pins inside the same scroll container without consuming layout space outside the scroll region.

## Implementation notes

- Added `widgets/session-transcript/model/use-now.ts` with `{ intervalMs, now?, enabled? }` API. `enabled` (default true) controls whether the interval runs; passing `enabled: false` returns `undefined` and skips the interval — this lets the layout gate ticking on `isRunning`. When `now` is provided, no interval is started (matches ActivityPage convention).
- Added `formatElapsedNow(startedAt, nowMs)` next to `formatElapsed` in `model/format-duration.ts`. Returns null for missing/unparseable/negative/non-finite inputs (same defensive shape as `formatElapsed`). Unit-tested with fixed timestamps.
- `ToolRowView` now takes optional `now?: number`. Computes `liveDuration = isRunning && now !== undefined ? formatElapsedNow(...) : null`; `duration = liveDuration ?? finalizedDuration`. JSX now renders duration when `(!isRunning || liveDuration)`, tagged `data-duration-mode="live"` vs `"frozen"` so tests can distinguish without polluting the testid.
- `SessionTranscriptLayout` calls `useNow({ intervalMs: 1000, enabled: isRunning, now: providedNow })` and threads the resulting `now` to `TurnList`. Only in-progress tool rows (status pending/running) receive the `now` prop in `AssistantParts` and `ContextGroupView`; terminal rows are passed `undefined` so `React.memo(ToolRowView)` stays effective (D2).
- When `isRunning` flips false, `useNow`'s effect dependency cleanup tears the interval down and the layout starts passing `now = undefined` to all rows; in-progress rows drop the live duration (matches spec scenario "Ticking stops when the session ends mid-tool" → row reverts to no duration).
- Layout exposes `now?: number` prop so tests can inject a fixed timestamp; the ActivityPage precedent (`pages/activity/ui/ActivityPage.tsx:139`) calls this `now`.
- Added `widgets/session-transcript/model/select-active-tool-call.ts`: pure `selectActiveToolCall(turns)` walks `assistantParts` in order (including tools nested inside `context-group` parts) and returns the last tool with status `pending`/`running`, or `null`. Last-match tiebreak is deterministic. Unit-tested with 9 cases (empty, no tools, all terminal, single in-progress, pending vs running, deterministic last-match, skip-over-terminal, nested-in-context-group, mixed top-level + nested).
- Added `widgets/session-transcript/ui/CurrentActivityBar.tsx`: `position: sticky; bottom: 0` bar rendered as the last child inside the layout's scroll content. Shows a `RunningIndicator` dot, the active tool's `deriveVerbLedTitle(...)` result, and the live duration via `formatElapsedNow`. Activation (button click or Enter/Space keydown) queries `scrollContainerRef.current` for `[data-tool-call-id="<id>"]` (CSS-escaped) and calls `scrollIntoView({ block: 'center' })`. Bar is `data-testid="transcript-current-activity-bar"` with `data-active-tool-call-id` for tests; the jump button is a separate testid; the duration is tagged `data-duration-mode="live"`.
- `SessionTranscriptLayout` now also reads `activeTool = isRunning ? selectActiveToolCall(turns) : null` and mounts `<CurrentActivityBar>` as the last sibling inside the column when `activeTool`, the layout's resolved `now`, and `scrollContainerRef` are all present. The selector is gated on `isRunning` so the bar disappears when the session ends even mid-tool.
- Tool-call-id lookup uses `CSS.escape(toolCallId)` because the id is a free-form server-supplied string that may contain `.`/`:`/`[` (e.g. `tc.with:weird[chars]`). The selector's data attribute is set by `ToolRowView` as-is, so the bar must escape on the consumer side.

## Gotchas

- `vi.advanceTimersByTime(N)` only fires intervals if the fake timers are configured. Setup file's afterEach runs `vi.useRealTimers()`, so each test must opt back into fake timers (typically via `beforeEach`).
- Initial render of a running tool row at `now === startedAt` produces `"0ms"` (sub-second), not `"0.0s"` — `formatDuration` switches at 1000ms. Tests for the layout use `vi.advanceTimersByTime(1000+)` to reach the seconds tier.
- For the test `does not start any interval when there are no turns`: the layout's `useNow` call is unconditional (rules-of-hooks), so the interval still starts. Rewrote the test to assert the interval is torn down on unmount instead.
- `enabled` was added to the hook signature even though the spec doesn't list it — needed to satisfy D1 ("the interval only runs while isRunning is true"). Layout passes `enabled: isRunning`.
- `jsdom` has no layout engine, so `position: sticky` cannot be asserted in jsdom. Current-activity bar tests assert the `sticky bottom-0` Tailwind classes are present in `className`, plus presence/absence/data attributes, and call `scrollIntoView` on the target row. True sticky behavior is deferred to the browser track (per the design note in D5).
- `deriveVerbLedTitle(...)` for a `read` tool without a `filePath`/`input` target produces `"Reading…"` (trailing-ellipsis mode for in-progress without a target). Tests for the bar use a JSON `input` like `{ filePath: 'src/foo.ts' }` to assert a target-form verb-led title. The verb family strips the path to its basename, so a `filePath` of `'src/foo.ts'` renders as `'Reading foo.ts'`.
- The bar's `aria-label` includes the verb and target so screen readers announce "Jump to <verb> <target>". The button itself is `<Button>` (the project's `variant="ghost"` shadcn-style primitive) with `type="button"` to avoid form-submit semantics.
- The bar is intentionally a child of the same flex column that hosts the `TurnList`, not a sibling of the scroll container. This keeps it inside the `data-scrollable` subtree so `position: sticky; bottom: 0` resolves against the scroll container (the nearest scrolling ancestor), matching the layout in D5.
- The re-targeting test verifies that swapping which tool call is the "active" one (different `toolCallId`) causes the next click to scroll the new row — this exercises both the selector's last-match tiebreak and the `data-tool-call-id` anchor lookup.
