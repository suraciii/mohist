## Codebase Patterns

- Runner action tests live next to source under `packages/runner/tests/`; each describe block is `mohist/<action-name>` and uses `mkdtemp` + `mkdir`/`writeFile` to build isolated change dirs.
- `ActionContext` is shaped via local helpers (`context`, `artifactsContext`, `archiveContext`) defined at the bottom of `openspec.spec.ts`. The artifacts helper takes `(workDir, changeDir, extra?)`.
- Existing `openspecArtifactsAction` accumulates all missing paths (does not stop at the first) and emits structured `{ kind: "openspec-artifacts", changeDir, present, missing }` plus a human-readable failure message listing every missing path.
- Wrong-kind detection (file vs directory) lives in `isPresentOfKind` (`packages/runner/src/actions/openspec.ts:518`); it already treats a path of the wrong kind as missing, so flipping specs/ from "optional" to "required" reuses it for free.

## T-001 Discoveries

- The action's previous three-entry set silently permitted a missing `specs/` directory. Appending `{ path: join(changeDir, "specs"), kind: "directory" }` between `proposal.md` and `design.md` is the only implementation change needed for T-001.
- The github-pr server spec (`MohistPrIssueWorkflowProfileSpecs.cs:260`) already binds `plan-artifacts` to `mohist/openspec-artifacts`. T-001 tightens github-pr immediately but its plan stage always produces `specs/`, so no in-flight run breaks. The T-002 server-side consolidation of `mohist-local.workflow.yaml` is what gives local the previously-implicit specs gate.
- `core/artifact-exists` stays registered (D4) — do not remove. T-001 touches only `openspec.ts` + `openspec.spec.ts`.
- Wrong-kind coverage: added two tests — one for a directory required as a file (`specs` is a file) and one for a file required as a directory (`proposal.md` is a directory). The empty-changeDir case was updated to expect all four entries in `output.missing`.

## T-002 Discoveries

- Local YAML edit is the four-line removal + a five-line mirror of `mohist-github-pr.workflow.yaml:127-132` (name/title/uses/with changeDir/repair chain untouched). The local check now binds `plan-artifacts` to `mohist/openspec-artifacts` exactly the way github-pr already does.
- The new server spec `LocalWorkflowDefinition_PlanStage_HasSingleOpenspecArtifactsCheck` lives next to its github-pr counterpart in `MohistPrIssueWorkflowProfileSpecs.cs` (a single class file houses both built-in profile cases) and asserts: exactly three checks in `["plan-artifacts", "self-review-passed", "health"]` order, the consolidated check binds `changeDir: ${{ openspecChangeDir }}`, none of the four per-artifact names are present, `self-review-passed` is `core/marker`, and `health` is `core/script` running `git diff --check`. Mirrors the spec scenarios "Local plan stage declares exactly one artifact gate", "Per-artifact artifact-exists dispatches are removed", and "Plan stage retains three distinct gates".
- `VariableScopeSpecs.cs:251` model used to inline four `core/artifact-exists` checks; updated to a single `plan-artifacts` (`mohist/openspec-artifacts`, `changeDir: ${{ openspecChangeDir }}`) plus the unchanged `self-review-passed` and `health` entries. The class file itself is `WorkflowVariableSpecs` (inside `Foundation/VariableScopeSpecs.cs`), test lives at `MohistWorkflowUsesCoreActionsForGenericChecks` and now asserts the dispatched `With` contains `mohist/openspec-artifacts` instead of `core/artifact-exists` — the test's intent ("workflow uses core actions for generic checks") is preserved with one fewer core action in play.
- Spec assertion approach taken from `MohistPrIssueWorkflowProfileSpecs.cs:785` (the existing `ReadStringWith(check, "changeDir")` helper) rather than rolling a new helper — keeps the new test reading like the counterpart test.
