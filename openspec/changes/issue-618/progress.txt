## Codebase Patterns
- Ordinary Slack DM ingress persists an inbox route, launches through `IAgentLauncher.LaunchConnectionAsync`, sets the route Session and `SlackDmSessionMappingStore`, then uses `AcceptFollowupAsync` plus `AgentSessionFollowupDispatcher` for later messages.
- `AgentSlackExecutionContext` is built from durable Session input provenance and the Runner injects the pinned collaboration Skill for every Slack execution. Manager uses the synthetic `__mohist_slack_manager__` project and Enrollment id as the Slack owner/connection identity.
- Inbox identity is `(ConnectionId, SlackMessageIdentity)` and Manager uses Enrollment id as `ConnectionId`; the mapping stores workspace and actor facts and is read with a workspace-bound lookup for Manager ingress.
- Slack terminal delivery must finalize liveness only. Assistant output is not a reply source; Manager terminal envelopes now omit the extracted `assistantText` value entirely.

## T-003 Decisions
- Manager credentials are issued only while assembling the Server poll response from a Manager Slack anchor. The durable `WorkDispatch`, AgentJob ledger, Session state, Slack context, and Runner journal never gain a credential field.
- `ManagerExecutionLeaseStore` retains only SHA-256 hashes plus immutable origin, actor/Enrollment, execution, epoch, scope, issue, expiry, and active metadata. `ManagerDeploymentEpoch` invalidates the store on graceful shutdown and rejects older values after a restart; store or epoch unavailability fails closed.
- The Runner consumes the response-only grant into a per-work in-memory wrapper. Its private broker exposes the matching management or reply value only to the scoped `mo` launcher; generic commands inherit a broker locator and private PATH but no bearer. Pi uses the pinned SDK Bash operations hook, and Manager OpenCode turns create a separate server/client process with the same non-secret boundary environment.
- Manager CLI transport selects `MOHIST_MANAGER_MANAGEMENT_TOKEN` or `MOHIST_MANAGER_REPLY_TOKEN` by request path and never falls back to an operator credential. Runner capability registration/gating requires grant, epoch, broker, Pi, isolated OpenCode, and redaction support.
- Epoch changes abort Manager turns and dispose brokers/runtimes; acknowledged AgentJob reports revoke both lease records for the work identity. Final Runner outputs, runtime events, task logs, exceptions, and terminal messages are passed through the Manager redactor.

## T-004 Decisions
- Manager CLI reply sends are a separate `manager.reply` capability. Manager mode routes `mo slack message send` to `/api/slack-manager/reply`; the existing project-scoped Connection reply route remains unchanged for ordinary callers.
- Manager reply validation is lease-bound and durable: the route compares the requested conversation/thread and optional full-anchor fields with the immutable lease origin, then requires the matching active Enrollment, accepted Manager inbox origin, and Enrollment/workspace/actor/Session DM mapping before any outbox write.
- `SlackManagerReplyAnchor` carries the validated origin into `SlackOutboxStore.EnqueueManagerAgentReplyAsync`. The outbox uses the synthetic Manager project, `OwnerKind.Manager`, Enrollment id, and the stable origin-derived progress dispatch ref. A pending progress row is promoted in place; repeated sends return the same terminal row without appending text. A missing progress row receives a Manager-owned terminal row so fast replies still share terminal convergence.
- Manager ingress persists receipt before Session dispatch and queues working state before invoking the launcher/follow-up path. The working projection queues receipt removal first, so fast completion and adapter redelivery cannot leave a receipt as the final visible state or show working before the receipt transition.
- Terminal reaction mutations are idempotent by stable phase dispatch refs. Terminal payloads carry non-user-visible `terminalStatus` metadata so `unknown` remains distinguishable for operator/recovery handling; terminal delivery still never reads assistant text or authors fallback text.

## Review Round 3 Repair (manual, review budget exhausted)
Round-3 FAIL terminated the run's automated review budget, so the three findings were fixed directly on the run branch and the check stage is rerun from these commits.

- Finding 1 (unauthenticated Manager command proxy): the broker no longer accepts arbitrary `mo` arguments. Every request must resolve through the new `manager-capability-surface` mirror of `ManagerCapabilityCatalog` (same vocabulary as CLI manager-mode admission, including the bare-invocation and `--help` bypasses the CLI itself applies before its allowlist), the declared `kind` must match the resolved capability family, the child runs only in the boundary-frozen working directory (caller cwd ignored, launcher no longer sends it), one credential-bearing child may run at a time, and each kind has a bounded request budget (reply 5 / management 64, configurable). The file documents why same-user caller authentication is unachievable (no SO_PEERCRED in Node; every launcher-held value is equally readable by the model shell) and why the enforceable boundary is credential non-exposure plus capability confinement, with the Server still enforcing lease origin, route allowlist, and anchor validation. Fixing this exposed a real pre-existing bug: `net.Server` defaults to `allowHalfOpen=false`, so the admitted proxy path never delivered a response at all (the previous tests only exercised the refused shape); the broker now runs with `allowHalfOpen=true`.
- Finding 2 (disposal left token-bearing children alive): spawned CLI children are tracked; disposal SIGTERMs them, waits a bounded configurable grace, escalates unconditionally to SIGKILL (`killed` merely records that a signal was sent), awaits exit, destroys broker sockets, closes the broker, and only then removes the boundary directory. Another real bug surfaced: the SIGKILL escalation previously never fired because `!child.killed` gated it.
- Finding 3 (Runner-loss left Manager recovery without a fresh turn): `AgentJobGrain.MarkUnknownAsync(reason, recoveryDeadlineAt)` — the path `RunnerGrain.CloseoutLostAsync` drives — now delivers the pending initial terminal and creates the single Manager recovery turn for Manager inputs, mirroring the report/timeout paths; `EnsureManagerRecoveryAsync`'s existing guard keeps repeated transitions idempotent.
