## Codebase Patterns

- The web project uses **Vitest + Testing Library + jsdom** with `// @vitest-environment jsdom` directive at the top of test files.
- For the agent module, the pattern is: tests live next to the file (`*.test.tsx`), mock the entity module with `vi.hoisted` + `vi.mock`, render inside `QueryClientProvider` + `ProjectProvider` + `MemoryRouter`/`Routes`.
- Widget-level components (e.g. `AgentProfileEditor`) are stubbed via `vi.mock('../../../widgets/.../AgentProfileEditor', () => ({ AgentProfileEditor: ({ open }) => open ? <div data-testid="agent-profile-editor" /> : null }))`. The stub mirrors the real testid so list/detail specs can assert open/close wiring without dragging in the real editor's query deps.
- `tsconfig.json` enables `noUnusedLocals: true`, so any local variable / hook call whose return is never used must be removed (not just imports). `useNavigate`/`useProjectPath` calls in a function body that no longer use their return trip this check — even though the import line is still consumed by sibling components in the same file.
- `AgentProfileEditor` is the universal "agent create + edit" Dialog widget. `agent={null}` is create mode (`isEditing=false`, `useCreateAgent`, navigates to detail page on success). `agent={...}` is edit mode. The create branch already invalidates `['agents']` (`queries.ts:78`) and `navigate`s on success — callers should NOT also navigate.
