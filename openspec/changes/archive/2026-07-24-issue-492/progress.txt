## Codebase Patterns
- OpenCode SDK session calls use `{ sessionID, directory }` plus `{ throwOnError: true }`, matching `runtime/opencode/turn.ts`.
- Runtime resolve results carry the physical active-turn snapshot: OpenCode derives it from `session.status` (`undefined`/`idle` is idle), while Pi reads the cached handle's `isStreaming` getter.
- `BindingProbeResult` represents presence as `{ ok: true, activeTurn }`; only a failed probe with `kind === "missing-session"` authorizes candidate creation.
- The runtime-event outbox is the only activity-settlement channel for the runner side; the grain's `ApplyRuntimeEventToDomain → ParseActivity` path settles `active`/`unknown → idle` (and other transitions) when the fact carries a `runtimeSessionId` matching the current binding. `AppendEventsAsync(..., requireCurrentRuntimeBinding: true)` discards facts whose binding was superseded.
- Cancel does NOT consult `outbox.ready()` — the comment on `registerCancelHandler` calls out the design rule that cancel must remain available while the durable snapshot is being recovered. Enqueue failures are logged via `console.error` and swallowed; the cancel reply always reflects what the runtime honestly reported.
