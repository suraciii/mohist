## Codebase Patterns

- `packages/web/src/entities/issue/model/` is the canonical home for Issue-domain pure-logic modules. Existing siblings (`labels.ts`, `rebase-events.ts`, `timeline-events.ts`, `live-task.tsx`) are co-located with `*.test.ts` files when they exist. New Issue-domain pure logic belongs here, re-exported through `packages/web/src/entities/issue/index.ts`.
- `packages/web/src/entities/issue/index.ts` is the entity public-API barrel. It mixes value, hook, and model re-exports; new Issue-domain exports (functions and types) are added here. `AttentionItem` (type), `deriveAttentionItems`, and `isIntegrateFailure` follow that pattern.
- The `Issue`, `IssueHealth`, `IssueStatus`, `WorkflowStage` types/enums live in `packages/web/src/entities/issue/model/types.ts` and are re-exported through `entities/issue/index.ts` via `export * from './model/types'`. Always import these via the entity barrel from inside the entity layer.
- `AgentStatus` is defined in `packages/web/src/entities/agent/model/types.ts` but the `entities/agent` barrel does not currently re-export it as a type. Imports of the type use `import type { AgentStatus } from '.../entities/agent'` (the original widget pattern); this works because of `isolatedModules` resolution but is an existing wart — do not fix it from this task.
- `tsconfig.json` for `packages/web` enables `noUnusedParameters: true` and `noUnusedLocals: true`. Unused parameters must use a leading underscore (e.g. `_agentStatus`) to be ignored.
- vitest is the test framework for `packages/web`; `vitest.config` lives inside `vite.config.ts`. Run a single file with `npx vitest run <path>` from `packages/web/`.
- Pre-existing test failures (live-task-cloud-event, events-hub-subscription, AgentSettingsSection, settings-visual-accessibility-evidence, EpicListPage, settings a11y) are present on the branch and unrelated to attention derivation. Do not attempt to fix them as part of attention work.
