## Why

After #409 retired the Workflow-source ACP bridge behind the deep `OpenCodeRuntime` module, exactly one execution path still spawns `opencode acp` and speaks Agent Client Protocol: the Mohist Agent AgentJob. Both the manual launch (`mo agent session launch`) and the event-subscription dispatch funnel into an `AgentJobInput` that hard-codes `Uses: "mohist/acp-agent"` and ships a `with.agent` payload, which the runner resolves through `@agentclientprotocol/sdk`, ACP liveness probes, ACP private compaction metadata, and a parallel generic session strategy. The issue-level `agentConfig` surface still carries the ACP-era keys (`type`, `livenessQuietThresholdMs`, `probeTimeoutMs`) end-to-end, and `acpSessionId` terminology survives in tests, doc-comments, and a web milestone classifier. With #407 (canonical AgentSession + command contract) and #409 (shared OpenCodeRuntime) both landed, this is the moment to route the AgentJob through the same runtime as Workflow, make the AgentJob the sole authority over its own terminal state, and delete the last ACP code path, dependency, and configuration keys — no fallback, no alias.

## What Changes

- Migrate AgentJob execution from the `mohist/acp-agent` ACP bridge to an **Agent-owned OpenCode execution request** that calls the shared `OpenCodeRuntime.runTurn` deep module directly. The runner no longer gates `openCodeRuntime` off for `ownerKind === "agent-job"`; the AgentJob receives the same runtime handle as the Workflow source. This is **not** a new `mohist/agent` Action and **not** a dispatch through the `mohist/opencode` Action contract — Workflow Action input/output/recovery changes must not affect Mohist Agent launch.
- Manual launch (`mo agent session launch`, `POST /agents/{ref}/sessions`) and event-subscription dispatch (`AgentSubscriptionDispatchHandler`) continue to share one launch pipeline that opens a canonical AgentSession (`runtime: "opencode"`), mints the AgentJob, and dispatches the Agent-owned execution request. Event ↔ subscription ↔ AgentJob ↔ AgentSession stay bidirectionally traceable through stable source labels.
- The AgentJob captures the resolved Agent snapshot (instructions, model/variant, prompt) at launch time; editing, disabling, or archiving the Agent during a running job does not change the in-flight request. AgentJob records `pending → running → completed | failed` plus its own terminal result (`AgentJobGrain.ReportResultAsync` is the sole terminal authority); AgentSession transcript/usage/runtime-lineage events never transition the AgentJob to terminal.
- Named Agent Follow-up / Compact / Reset / Cancel continue to use the unified AgentSession model from #407 over the OpenCode runtime — Compact keeps the binding, Reset is expected-binding guarded, missing current Runtime Session fails explicitly with a Reset hint.
- **BREAKING**: Remove the `@agentclientprotocol/sdk` dependency from `packages/runner/package.json`, delete the `mohist/acp-agent` Action and the entire `actions/acp/` tree (`process.ts`, `liveness.ts`, `compaction.ts`, `model-resolution.ts`, `session-events.ts`, `agent-config.ts`, `session-strategies.ts`), retire `runtime/acp-connection.ts`, `runtime/acp-command.ts`, `runtime/acp-session-command.ts` and their tests, drop `ActionContext.acpSessionManager` / `acpConnection`, and rework `server/session-target.ts`, `server/followup-handler.ts`, `server/cancel-handler.ts`, and `server/followup-failure-outbox.ts` to target the OpenCode runtime. No feature flag, compatibility alias, or ACP fallback remains.
- **BREAKING**: Converge the issue-level `agentConfig` surface to `model` + `variant` (plus `stageModels` / `stageModelVariants`). `type`, `livenessQuietThresholdMs`, `probeTimeoutMs`, and other ACP/liveness keys are removed from the API DTOs, CLI `--agent-config` schema, and Web forms; `IssueVariableBuilder` stops emitting legacy `vars.agent` keys. Already-persisted legacy keys in `vars.agent` are tolerated by the `mohist/opencode` `unknownKeys` diagnostic path landed in #409 and are not rewritten.
- **BREAKING**: Workflow profiles, translators, serializers, and `TaskRun` classification no longer recognise `mohist/acp-agent`; a profile that still names it fails at dispatch with an actionable error (the Action no longer exists). `IsInlineAgentUses` collapses to `mohist/opencode` only.
- **Legacy transition (no data rewrite)**: historically ACP-bound AgentSessions (legacy `runtime`/`runtimeSessionId` bindings, historical Compact/Reset rotation records) remain queryable and auditable; Session operations on them fail explicitly with a Reset hint. A WorkflowRun started before cutover does not auto-migrate; subsequent agent task dispatches on it fail with an actionable error and recover by rerunning the affected stage.
- Remove every remaining `acpSessionId` / ACP term from runner handlers, server doc-comments, web milestone classifier (`isAcpAgentTask`), and the `MOHIST_AGENT_ARGS` env surface; rename the ACP scenario in `specs/workflow-agent/spec.md`; close the gap sections in `design/agent-execution.md` and `design/runtimes/opencode.md`.

## Capabilities

- `agent-job-execution`: The AgentJob execution contract — the AgentJob owns its terminal state (`pending → running → completed | failed` + result reported by `AgentJobGrain.ReportResultAsync`); execution drives the shared `OpenCodeRuntime.runTurn` directly via an Agent-owned request built from the launch-time-fixed Agent snapshot (instructions, model/variant, prompt); Agent edits during the run never mutate the in-flight request; AgentSession events (transcript, usage, lineage) never transition the AgentJob to terminal; Workflow Action name/input/recovery contract changes do not affect launch. Explicitly not a `mohist/agent` Action and not a `mohist/opencode` Action dispatch.
- `agent-launch-unification`: The single launch pipeline shared by manual and event-subscription entries — both resolve a stable Agent identity, open the canonical AgentSession (`runtime: "opencode"`), compose the launch-time-fixed snapshot, submit the AgentJob, and dispatch the Agent-owned execution request with stable source labels (trigger event id, subscription id, agent id) so event ↔ subscription ↔ AgentJob ↔ AgentSession are bidirectionally traceable.
- `issue-agent-config`: The converged issue-level AgentConfig surface across API/CLI/Web — inputs accept only `model`, `variant`, `stageModels`, `stageModelVariants`; `type` and ACP liveness keys (`livenessQuietThresholdMs`, `probeTimeoutMs`, `sessionStartTimeoutMs`, …) are rejected; the persisted `vars.agent` write path stops producing legacy keys; already-persisted legacy keys are ignored + diagnosed by the `mohist/opencode` runtime, not rewritten or migrated.
- `acp-removal`: Final ACP removal and legacy-transition behaviour — delete `@agentclientprotocol/sdk`, the `mohist/acp-agent` Action and `actions/acp/` tree, shared `AcpSessionManager` / `SharedAcpConnection`, ACP liveness / log scanning / private compaction metadata / `.opencode` lockfile cleanup, and every remaining `acpSessionId` wire/Server/Web term; drop the transitional AgentJob readiness-gate caveat (both sources now gate on OpenCode health + catalog); legacy ACP-bound AgentSessions fail Session operations explicitly with a Reset hint and stay queryable; pre-cutover WorkflowRuns do not auto-migrate and their subsequent agent task dispatches fail with an actionable, rerun-recoverable error.
