## Codebase Patterns

### Convention: namespace 跟目录走
仓库既有约定是 namespace 严格按目录物理对齐（`Sessions/Services/AgentSessionQuery.cs`
→ `namespace Mohist.Server.Sessions.Services`）。本次迁移遵循此约定：5 个 Services 文件
走 `Mohist.Server.Sessions.Services`，1 个 DTO 文件走 `Mohist.Server.Sessions`。

### Convention: 领域反向 using 严格受 spec 约束
横向叶子域 `Sessions/` 目录树下不应含 `using Mohist.Server.Workflow.*` 形式的 using
引入（spec line 29）。全限定名（如 `Mohist.Server.Workflow.Domain.Run.TaskRunStatus.Running`）
是豁免项，不算反向依赖（spec line 31）。check 阶段判定用 `^using\s+Mohist\.Server\.Workflow\.`
锚定 using 语句，避免误报 D2 故意保留的 FQN。

### Convention: Architecture test FeatureDirectories_ShouldOnlyContainDomainGrainsAndServices
`packages/server/tests/Mohist.Server.Tests/Architecture/ArchitectureRules.cs:157` 强制
feature 根目录（Agent/Epic/Issue/Project/Runner/Sessions/Workflow）只能包含 Domain/Grains/Services。
本次迁移把 `AgentSessionReadModels.cs` 放到 `Sessions/`（按 spec D1）会触发该规则；
本任务同步把架构测试扩展了一个白名单（`allowedFeatureRootFiles`）允许 `AgentSessionReadModels.cs`
作为 CQRS 读侧 DTO 文件直接位于 feature 根。规则扩展后 `FeatureDirectories_ShouldOnlyContainDomainGrainsAndServices`
测试绿。

### Convention: DI 注册走 Scrutor 按接口扫描
`Mohist.Server.Infrastructure.Hosting.ServiceCollectionExtensions.cs:34` 通过
`IScopedService`/`ISingletonService` 接口 + 程序集扫描注册，namespace 改写对 DI 透明。
`MigratedServicesRegistrationSpecs.cs:84` 仍正确验证 `AgentSessionQuerier` 注册为 Scoped。

## Decisions & Gotchas

### Gotcha 1: `using Mohist.Server.Workflow.Domain.Run;` 实际并非完全冗余
self-review (item-1) 与 design D2 都基于"line 1550 已用 FQN"判定该 using 冗余。但实测发现：
- `IsSessionAssociatedWithRun(WorkflowRun run, ...)` 形参（line 1541）
- 多处 bare cref：`WorkflowRun`、`TaskRun`（lines 21, 22, 1527, 1530, 1531, 1536）
均依赖此 using。删除 using 必须把上述全部改 FQN，否则编译失败（TreatWarningsAsErrors）。
本任务已将这些 bare 引用全部改为 `Mohist.Server.Workflow.Domain.Run.WorkflowRun` 等 FQN。

### Gotcha 2: 多处文件原本就有 `using Mohist.Server.Sessions.Services;`
替换 `using Mohist.Server.Workflow.Services.Sessions;` 时如文件原本就有前者则产生
CS0105 重复 using。涉及 11 个文件（5 个 src、6 个 test）需要手工删除冗余：
- src: `AgentSessionLaunchRoutes.cs`、`WorkflowActivityQuerier.cs`、`WorkflowSessionHealthService.cs`、
  `WorkflowGrain.cs`、`RunnerRoutes.cs`
- test: `AgentSessionActivityVisibilitySpecs.cs`、`AgentSessionContextAssociationApiSpecs.cs`、
  `AgentSessionQuerySpecs.cs`、`AgentSessionReadApiSpecs.cs`、`AgentSessionRecoveryDomainSpecs.cs`、
  `GenericAgentSessionCancelApiSpecs.cs`、`GenericAgentSessionFollowupApiSpecs.cs`、
  `GenericAgentSessionSummarySpecs.cs`、`WorkflowRetrySessionHealthGuardSpecs.cs`、
  `MigratedServicesRegistrationSpecs.cs`、`AgentSessionLaunchRoutesSpecs.cs`

### Gotcha 3: `AgentRoutes.cs` 还需要额外的 `using Mohist.Server.Sessions;`
该文件除了 Services 命名空间下的 `AgentSessionQuerier` 还引用 DTO（如 `AgentCostMetricDto`、
`ActivityWaitingCardDto`、`AgentCostRollupDto`）—— 这些 DTO 现位于 `Mohist.Server.Sessions`
（而非 `.Services`），需额外添加 `using Mohist.Server.Sessions;`。
DTO 跨 namespace 调用是 spec D1 的设计意图（DTO 层与 Services 层分离）。

### Gotcha 4: `AgentSessionReadModels.cs:424` 还有一处 bare cref 需要修复
该处 `<see cref="AgentSessionQuerier.GetCostWindowedAsync"/>` 在迁前因同 namespace
解析正常；迁后 `AgentSessionReadModels.cs` 位于 `Mohist.Server.Sessions`，与
`AgentSessionQuerier`（`Mohist.Server.Sessions.Services`）不同 namespace，必须改为
`<see cref="Sessions.Services.AgentSessionQuerier.GetCostWindowedAsync"/>`。
D4 任务描述只点名 line 248，但 line 424 同样需修复以满足 TreatWarningsAsErrors（CS1574）。

### Gotcha 5: `SessionTranscriptBuilder.cs` 需调整 using
迁前 `using Mohist.Server.Sessions.Services;` 为冗余自引用（同 namespace），迁后变成有效引用。
但同时文件现需要 `using Mohist.Server.Sessions;` 以访问 DTO 类型（`AgentSessionTranscriptResponse`
等）。本任务已替换为 `using Mohist.Server.Sessions;`、删除冗余自引用 using。

### Gotcha 6: 一个 test 文件用 FQN 而非 using
`SessionFollowupApiSpecs.cs:156` 用的是 `GetRequiredService<Mohist.Server.Workflow.Services.Sessions.AgentSessionQuerier>()`
FQN 而非 using。grep 锚定 `using ...` 时漏检。修改时直接改 FQN 字符串而非 using。
