# issue-362 build progress

## Codebase Patterns

- DB-backed stores use `IDbContextFactory<MohistDbContext>` (constructor-injected)
  and own their DbContext lifetime per call. SQLite's EF provider cannot
  translate `ORDER BY` over `DateTimeOffset`; sort in raw SQL and map the
  result row to the entity by column name (`DeadLetterStore.QueryAsync`
  shows the pattern — select the row set, project to `ToRow`).
- Tests use the captured/recording-store fake idiom (`FakeDeadLetterStore`,
  `CapturingDeadLetterStore`); the production seam is `IDeadLetterStore`.
- For unit tests against SQLite, build an in-memory connection once per
  fixture, call `EnsureCreated`, then expose via an `IDbContextFactory` impl.
- Spec tests prefer `MigratedSqliteTemplate.CopyTo` over `Migrate()` /
  `EnsureCreated` for speed (sub-millisecond clone vs. multi-second build).

## T-001 — DeadLetters table model, migration, and dead letter store

### State on entry

The branch already carried an extended dead-letter implementation
(restored from a prior workflow run) that uses a richer schema and
interface than the T-001 spec calls for:

- 20 columns (T-001 spec says 17): extra `Status`, `RedeliveryAttemptedAt`,
  `ResolvedAt` (added by migration `20260711041122_HardenDeadLetterRecovery`)
- IDeadLetterStore has `SettleAsync` / `QueryAsync` / `GetAsync` /
  `StartRedeliveryAsync` / `RecordRedeliveryFailureAsync` / `ResolveAsync`
  / `DeleteAsync` in addition to `WriteAsync`
- Manual "redeliver" path re-runs only the failing handler in-place
  (`EventDispatcherService.RedeliverAsync`); the spec mandates that
  `RetryAsync` re-nulls `DispatchedAt` so the dispatcher redelivers to
  ALL matching handlers on the next tick.

### What T-001 added

- `IDeadLetterStore.ListByHandlerAsync(string handler, int limit, ct)` —
  ordered by `DeadLetteredAt DESC, DeadLetterId DESC`; required handler.
- `IDeadLetterStore.ListByTimeRangeAsync(DateTimeOffset from, DateTimeOffset
  to, int limit, ct)` — range filter, lower-inclusive upper-exclusive.
- `IDeadLetterStore.RetryAsync(long deadLetterId, ct)` — re-nulls the
  source row's `DispatchedAt` via origin/source/id routing, preserves the
  dead letter row.
- Implementation in `DeadLetterStore` (raw SQL with parameterized WHERE
  to reuse the existing `DeadLetterSqlRow` projection; mirrors the
  `QueryAsync` pattern for sort over `DateTimeOffset`).
- Updated all four fakes to no-op / record the new methods
  (`SpecTests/Support/NoopDeadLetterStore`,
   `SpecTests/Support/DispatcherFixture.CapturingDeadLetterStore`,
   `UnitTests/Support/NoopDeadLetterStore`,
   `UnitTests/Support/FakeDeadLetterStore`).
- Added `FakeEventStore.ReQueueForRedelivery` and
  `CapturingEventStore.ReQueueForRedelivery` so `RetryAsync` can
  re-queue a previously marked row in the in-memory fakes — mirrors
  the production "re-null DispatchedAt" path.
- 10 new spec tests (`DeadLetterStoreSpecs`): ListByHandler ordering,
  ListByHandler limit / no-match / empty-handler, ListByTimeRange
  in-range / boundary / no-match, RetryAsync re-nulls source row and
  preserves the dead letter, RetryAsync unknown id throws,
  RetryAsync routes by origin.
- 4 new unit tests (`DeadLetterStoreRoundTripTests`): write/read
  round-trip preserves all 17 columns, monotonic id assignment,
  ListByHandlerAsync descending, ListByTimeRangeAsync within range.

### Deliberate non-changes

- The schema retains the extra `Status` / `RedeliveryAttemptedAt` /
  `ResolvedAt` columns and the unique `(Source, Id, FailingHandler)`
  index. Dropping them would break the dispatcher grain
  (`EventDispatcherService.RedeliverAsync` → `StartRedeliveryAsync` /
  `ResolveAsync` / `RecordRedeliveryFailureAsync`), the API routes
  (`/api/events/dead-letters/{id}/redeliver`), the CLI command, and
  ~30 existing tests. T-001 is the dead-letter persistence slice;
  T-002 owns the dispatcher. Realigning schema here would cascade
  into T-002 — out of scope for this task.
- Existing `QueryAsync` / `SettleAsync` / `GetAsync` etc. were left in
  place. `ListByHandlerAsync` / `ListByTimeRangeAsync` / `RetryAsync`
  are additive; they don't replace the richer interface that the
  dispatcher and operator endpoints depend on.
- The `EventStore.SetDispatchedAsync` helper (used by `SettleAsync`)
  is non-nullable on `dispatchedAt`. `RetryAsync` therefore loads and
  updates the source row directly (mirroring the per-origin switch in
  `SetDispatchedAsync`) rather than going through that helper.

## T-002 — EventDispatcherGrain as cluster-singleton reminder-driven dispatcher

### State on entry

The branch already carried a near-complete `EventDispatcherGrain` /
`EventDispatcherService` implementation (restored from a prior
workflow run) plus a parallel `IDispatcherGrain` / `DispatcherGrain`
shim that owned the dispatch loop's reminder registration. The
spec-required interface (`IEventDispatcherGrain` with a single
`DispatchNowAsync()`) and `EventDispatcherOptions` were already in
place; tests and the activation hosted service still pointed at the
older `IDispatcherGrain`.

### What T-002 added

- **Spec grain promoted to canonical cluster singleton.**
  `DispatcherActivationService` now activates
  `IEventDispatcherGrain(EventDispatcherGrain.Global)` instead of
  `IDispatcherGrain(DispatcherGrain.FixedKey)`; the spec grain owns
  the reminder under `"event-dispatcher-tick"`. `DispatcherStartupSpecs`
  + `OnActivateAsync_RegistersPersistedReminderWithConfiguredCadence`
  were updated to assert on the spec grain so the readiness signal
  rides on the grain that actually drives production.
- **Operator grain kept, decoupled from dispatch loop.**
  `DispatcherGrain` no longer implements `IRemindable` or registers a
  reminder — keeping one would double-fire dispatch work alongside the
  spec grain's reminder. The grain now serves the operator HTTP routes
  (`PulseAsync` for ad-hoc prod pokes, `RedeliverAsync` for the
  `/api/events/dead-letters/{id}/redeliver` endpoint). The fixed-key
  activation guard stays; rogue keys still throw on `OnActivateAsync`.
- **`EventDispatcherOptions` registration moved to
  `MohistSiloRegistration.ConfigureMohistSilo`.** The silo DI scope is
  the one Orleans grains resolve from at activation time; previously
  the binding lived only in the host-side
  `MohistServiceRegistration.ConfigureMohistServices`. Spec acceptance
  criterion #11 explicitly requires the silo registration.
- **`DispatcherOptions` removed.** The older options class was only
  referenced by the now-defunct reminder registration on
  `DispatcherGrain`. The spec-binding `EventDispatcherOptions` (with
  the spec defaults — `ReminderPeriod=1s`, `BatchSize=100`,
  `MaxAttempts=5`, `BaseBackoff=1s`, `MaxBackoff=30s`) is the single
  source of truth. `EventDispatcherOptions_HaveRequiredDefaults`
  asserts each default in unit.
- **`DispatcherGrain_NonFixedKeyCannotRegisterOrDispatch` updated.**
  Asserts no reminder lands under the rogue grain id after the spec
  grain owns the reminder lifecycle — checks the spec grain's
  `EventDispatcherGrain.ReminderName` instead of the old
  `DispatcherGrain.ReminderName`.

### Deliberate non-changes

- The implementation already satisfies the spec for the bulk of
  T-002's acceptance criteria — the prior workflow restore brought
  every spec scenario under test:
  - At-least-once (deliver-before-mark crash → redeliver, idempotent
    absorption on `EventId`): `DispatchAsync_DeliverBeforeMarkCrash_*`
    + `ReminderCallback_DeliversBeforeAndAfterHostingSiloLoss`.
  - Per-stream FIFO: `DispatchAsync_DispatchesPerStreamFifo_*`.
  - Cross-tick retry with `TimeProvider`-governed exponential backoff
    capped at `MaxBackoff`, per-handler isolation:
    `DispatchAsync_PerHandlerRetry_*`,
    `DispatchAsync_CrossTickBackoffAndRetryBudgetArePerHandler`,
    `DispatchAsync_DeadLettersEachFailingHandlerAfterIndependentBudgets`,
    `Backoff_DoublesAndCapsAtConfiguredMaximum`.
  - Successful delivery or dead-lettered handler both stamp
    `DispatchedAt` and stop reappearing in `ListUndeliveredAsync`:
    `DispatchAsync_ExhaustionWritesDeadLetter_*`.
  - No-match event rows are marked delivered without any handler
    invocation: `DispatchAsync_NoMatchingSubscription_*` +
    `DispatcherCatchAllHandler` (`[Subscription(Type = "*")]`) and
    `DispatcherClosedGenericHandler` (closed-generic `ICloudEventHandler<TData>`)
    prove the existing Subscription registration pass plus
    `CloudEventTypeMatcher` still route correctly without code
    changes — `AgentSubscriptionDispatchHandler` (production
    wildcard handler) inherits the same at-least-once coverage.
  - Reminder self-healing on startup and across silo loss:
    `OnActivateAsync_RegistersPersistedReminderWithConfiguredCadence`
    reads through the silo's `IReminderTable`;
    `HostedActivation_FirstReminderDeliversWithoutPulse` waits for the
    hosted-service activated grain's reminder to fire and deliver
    before any explicit pulse.
  - `Backoff_DoublesAndCapsAtConfiguredMaximum` + the closed-generic
    fan-out coverage in `DispatchAsync_FanOutByType_*` and
    `DispatchAsync_TypeMatcher_DoesNotInvokeNonMatchingSubscriptions`
    close out the unit-only scenarios in the acceptance list.
- `EventDispatcherService` keeps the SQLite-safe pattern: a
  `SemaphoreSlim` guard serializes dispatch cycles inside the grain
  instance, mirroring the non-`[Reentrant]` semantics the design
  specifies. Test isolation is unaffected (the semaphore is per
  service instance).
- The `RecordingEventStore` test fake already supports seeded
  `ListUndeliveredAsync` (`SeedUndelivered`) and records
  `MarkDispatchedAsync` calls (`MarkedDispatched`,
  `ListUndeliveredCallCount`); `RecordingEventStore_SeedsOrdersLimitsAndRecordsDispatch`
  asserts ordering + limit semantics against production usage.

## T-003 — Best-effort producer immediate trigger pokes after commit

### State on entry

The branch already carried the producer-side `PokeDispatcherBestEffort`
wiring for the three event producers (`WorkflowRunStore`,
`IssueStore`, `AgentSessionStore`) — restored from a prior workflow
run — together with the supporting DI plumbing. The new
`EventDispatcherImmediateTriggerSpecs` was also present.

### What T-003 added

- **Confirm the three producers call `DispatchNowAsync()` after commit.**
  - `WorkflowRunStore.SaveAsync(run, events)` (the transactional entry
    point) calls `PokeDispatcherBestEffort()` after `transaction.Commit`.
  - `IssueStore.SaveAsync(key, state, events)` — same shape.
  - `AgentSessionStore.SaveAsync(key, state, events)` — same shape.
  - Each store obtains the dispatcher grain via
    `IGrainFactory.GetGrain<IEventDispatcherGrain>(EventDispatcherGrain.Global)`,
    calls `DispatchNowAsync()` fire-and-forget (`_ = dispatcher.DispatchNowAsync()`),
    and swallows every exception (log at debug level). Removing the
    poke never breaks correctness — the reminder tick is the sole
    source of truth.
- **`EventDispatcherImmediateTriggerSpecs`** — new spec tests at
  `packages/server/tests/Mohist.Server.SpecTests/Specs/Events/EventDispatcherImmediateTriggerSpecs.cs`:
  - `WorkflowRunStore_Commit_PokesDispatcherAndLowersLatencyBelowReminderCadence` —
    closes out the "Immediate trigger lowers latency but is not
    required for correctness" scenario. The fixture sets
    `EventDispatcherOptions.ReminderPeriod = 1h`; the post-commit poke
    drives `DispatchNowAsync` which delivers to
    `DispatcherSpecificHandler` well before the reminder fires.
  - `IssueStore_Commit_PokesDispatcherAndLowersLatencyBelowReminderCadence`
    — same shape against the Issue producer; the catch-all
    `DispatcherCatchAllHandler` (`[Subscription(Type = "*")]`)
    receives the event.
  - `AgentSessionStore_Commit_PokesDispatcherAndLowersLatencyBelowReminderCadence`
    — same shape against the AgentSession producer.
  - `LostImmediateTrigger_LeavesRowUndispatched_AndReminderTickRecovers` —
    closes out the "Lost immediate trigger is recovered by the next
    tick" scenario. Replaces the silo-resolved `IGrainFactory` with
    a `ThrowingDispatchGrainFactory` whose `GetGrain<IEventDispatcherGrain>`
    throws; the store's best-effort wrapper swallows the exception so
    the transaction commits, the row stays `DispatchedAt IS NULL`
    (asserted via `PendingCount == 1`), and advancing the
    `FakeTimeProvider` past the reminder period lets the next tick
    deliver through the normal pull–fan-out cycle.
- **Spec test fix-up** —
  `InboxApiSpecs.WorkflowRunStoreEvent_PersistsRowAndDispatcherProjectsItToInbox`
  was updated: with the dispatcher live, the `InboxProjectionHandler`
  now projects the persisted `workflow.run.failed` event into the
  project's inbox; the spec now polls the inbox API until the row
  lands. The cross-project isolation rule still holds (the other
  project's inbox remains empty).
- **Test fixture wiring for producer `IGrainFactory` dependency.**
  - `MohistDbFixture` (silo-less unit-style fixture) registers a
    `NullDispatchGrainFactory` so the three stores' constructors
    resolve without booting an Orleans silo. The dispatcher reference
    is a no-op `NullEventDispatcherGrain` whose `DispatchNowAsync()`
    returns `Task.CompletedTask`.
  - Per-spec `NullDispatchGrainFactory` shims added to
    `TransactionalEventAppendSpecs`,
    `IssueTransactionalEventAppendSpecs`,
    `AgentSessionTransactionalEventAppendSpecs`,
    `AgentSessionStoreSpecs`, `WorkflowRunStoreSpecs`,
    `InboxProjectionTestSupport` (used by
    `InboxProjectionHandlerSpecs`), and the transactional
    `IssueWorkflowReadPathSpecs` paths so they can construct
    `WorkflowRunStore` / `IssueStore` / `AgentSessionStore` directly.
  - `DispatcherFixture` provisions the production schema
    (`MigratedSqliteTemplate.CopyTo(_keeper)`) and registers
    `IIssueStore` / `IAgentSessionStore` in the silo DI so the spec
    test can resolve them through
    `Cluster.GetSiloServiceProvider(null).CreateAsyncScope()`.
- **Architecture rule exception for `Events.Grains` →
  `Infrastructure.Data`.** The `InfrastructureData_ShouldNotDependOnApplicationLayer`
  rule now exempts `Mohist.Server.Events.Grains` (the IEventDispatcherGrain
  poke is unidirectional and documented in design.md D5).

### Deliberate non-changes

- The poke is `IGrainFactory.GetGrain<IEventDispatcherGrain>(Global).DispatchNowAsync()`
  in the stores themselves (design Open Question 4: prefer direct
  call — stores already depend on `IDbContextFactory`, adding
  `IGrainFactory` is consistent). No `IEventDispatcherTrigger`
  abstraction added.
- `EventDispatcherGrain` / `EventDispatcherService` were not modified
  in this task; they were finalized in T-002.
