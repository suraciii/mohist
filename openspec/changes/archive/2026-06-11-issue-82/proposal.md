## Why

Mohist's SignalR realtime push is end-to-end broken. The frontend opens the `/hubs/events` connection but never calls `SetSubscriptionsAsync` / `SubscribeAsync`, so every connection's subscription set is empty and `UserNotificationDispatcher` filters out every emit. The backend also emits CloudEvents 1.0.2 reverse-DNS names (e.g. `com.mohist.workflow.stage.started`) while the frontend's `LiveTaskProvider` switches on legacy snake_case names (e.g. `stage_changed`) that no producer ever sends. Finally, agent-session transcript events (`coder_text_chunk`, `ralph_task_update`, `agent_liveness_status`, `agent_session_terminal`, …) are written to `AgentSessionRuntimeEvents` by the runner → server ingestion path but have no realtime path to the Web at all — they are observation data, not domain events, so they do not (and should not) flow through `IEventPublisher` / `EventBridge`. As a result, the kanban never auto-refreshes, the approval toast never appears, the rebase-conflict indicator is stuck, and the live task timer never ticks. Users only see partial state through the 5-second `/api/projects/{ref}/agent/activity` / `agent/status` / `workflow/status` polls. Issue 82 closes the three breaks without changing the workflow domain model or hard-mixing transcript observation events into the domain-event bus.

## What Changes

- **Web subscribes on connect.** `useEventsConnection` (`packages/web/src/shared/api/events-hub.ts`) builds the full list of event types the Web consumes (legacy snake_case names from `LiveTaskProvider` + `AGENT_DETAIL_EVENTS`) and invokes `connection.invoke('SetSubscriptionsAsync', [...])` after the SignalR `start()` resolves and again on every `onreconnected`. `SetSubscriptionsAsync` is idempotent, so re-invoking on reconnect is safe and resilient to the hub's replay-on-reconnect behaviour.
- **Server tolerates an empty subscription set on first open.** `MohistHub.OnConnectedAsync` no longer treats "the grain is empty" as the default — it now also accepts the client's first `SetSubscriptionsAsync` call as the source of truth, and keeps the registry/grain in sync from then on. The dispatcher is unchanged: it continues to filter by per-connection subscription set.
- **Reverse-DNS names reach the Web.** The Web's `unwrapEnvelope` already extracts the CloudEvents `type`; the fix is to add a reverse-DNS → legacy-snake_case alias map in `EventMap` / `EventName` and `AGENT_DETAIL_EVENTS`, or to teach the provider's switch to match the new names directly. We choose the latter: extend the existing `EventMap` / `AGENT_DETAIL_EVENTS` to include the reverse-DNS names alongside the legacy ones, so both producers (new reverse-DNS) and any unmigrated producer (legacy) reach the same downstream handler. New Web switch arms are added for `com.mohist.workflow.stage.started`/`completed`/`failed`, `com.mohist.workflow.stage.approval-requested`/`approval-resolved`, `com.mohist.workflow.run.*`, `com.mohist.issue.*`, `com.mohist.agent-session.started`/`completed`/`failed`/`cancelled`/`status-changed`, and they map to the same cache invalidation and toast logic as the legacy cases.
- **Agent session domain events enter the CloudEventBus.** Add `BusType` mappings to `AgentSessionEventSerializer` for `AgentSessionStarted` / `AgentSessionCompleted` / `AgentSessionFailed` / `AgentSessionCancelled` / `AgentSessionStatusChanged` (using the existing `EventCatalog.ReverseDns.AgentSession*` constants). `AgentSessionGrain.AppendRuntimeEventsAsync` publishes the corresponding domain event via `IEventPublisher` exactly once when the session transitions to a new terminal or status-changed state, after the row is persisted. This is the lifecycle branch, not the per-chunk observation branch.
- **New non-domain event channel for transcript events.** A new `ITranscriptEventPublisher` interface plus an in-process implementation exposes a single `PublishAsync(TranscriptEnvelope)` method. The implementation wraps a SignalR method (`OnTranscriptEvent`) on `IEventsClient` and is registered in DI. The subscription/filter logic reuses the existing `ConnectionSubscriptionRegistry`: connections that subscribed to a transcript event type (via the same `SetSubscriptionsAsync` mechanism) get it. `AgentSessionGrain.AppendRuntimeEventsAsync` now publishes each `coder_text_chunk` / `coder_thought_chunk` / `coder_tool_call` / `ralph_task_update` / `ralph_loop_progress` / `agent_liveness_status` / `agent_usage_update` / `agent_session_model_resolved` row through the new publisher, in addition to persisting the row. The runner → server REST endpoint shape is unchanged.
- **ActivityPage Waiting list has data.** `AgentRoutes.MapGet("/activity", ...)` now reads the same set of "issue currently paused on an approval gate" the Web already polls in the 5-second fallback (`IssueGrain` query for `InProgress` issues whose current stage is `AwaitingApproval`), and passes it to `AgentSessionQuerier.GetActivityAsync` so the `Waiting` section stops being always-empty.
- **Frontend polls are kept as a fallback.** The 5-second `agent/activity`, `agent/status`, and `workflow/status` polls are NOT removed. They are the safety net when SignalR is unavailable or when the connection's subscription set is still being negotiated.
- **No breaking changes.** All new CloudEvents `type` strings are new and additive. All new SignalR hub methods (none new — only new behaviour) and client invocations match existing JSON wire shapes. The legacy snake_case names in `EventCatalog` are kept (per the explicit non-goal "do not clean up EventCatalog"); they are now also subscribed to by the Web so any legacy producer that still exists still works. The reverse-DNS names get their own switch arms so new producers also work.

## Capabilities

### New Capabilities
- `signalr-realtime-push`: end-to-end contract for the SignalR realtime push layer — server emits CloudEvents 1.0.2 reverse-DNS events for workflow / issue / agent-session domain changes, the Web subscribes via `SetSubscriptionsAsync` on connect/reconnect, and the Web matches both legacy snake_case and reverse-DNS names to the same downstream handlers. Covers the lifecycle events the dispatcher must deliver and the connection-lifecycle expectations for replay-on-reconnect.

### Modified Capabilities
- `event-bus`: the in-process `IEventPublisher` + `EventBridge` path remains the channel for **domain** events; add agent-session lifecycle events (`AgentSessionStarted` / `Completed` / `Failed` / `Cancelled` / `StatusChanged`) as bus types via the existing `EventCatalog.ReverseDns.AgentSession*` constants so they reach `EventBridge` and the Web. Transcript / observation events (`coder_text_chunk`, `coder_tool_call`, `ralph_task_update`, `agent_liveness_status`, `agent_usage_update`, `agent_session_model_resolved`, `agent_session_terminal` for live view) explicitly DO NOT flow through this bus — they flow through a separate non-domain channel.
- `coder-session-tracking`: the runner → server transcript ingestion path (`/api/runner/{runnerId}/sessions/{projectId}/{workflowRunId}/{sessionName}/events` → `AgentSessionGrain.AppendRuntimeEventsAsync`) SHALL forward observation events to the Web via a new non-domain realtime channel in addition to persisting the `AgentSessionRuntimeEvents` row. The `AgentSession*` domain events emitted when the session transitions to a lifecycle state SHALL ALSO be published to the CloudEventBus so live clients see lifecycle changes. The persisted row shape and the `toolCall` / `toolError` / `resolvedModel` / `failureCategory` projections are unchanged.
- `web-ui`: the Web's `useEventsConnection` SHALL call `connection.invoke('SetSubscriptionsAsync', [...])` with the union of `EventName` and `AGENT_DETAIL_EVENTS` after `start()` resolves and on every `onreconnected` callback; the `LiveTaskProvider` switch SHALL handle the new reverse-DNS event names by mapping them to the same invalidation/toast logic that the legacy snake_case arms already use. The `ActivityPage` Waiting list SHALL display issues that the server now includes in the activity response's `waiting` array.

## Impact

- **Server: hub / dispatcher / registration** (`packages/server/src/Mohist.Server/Events/Hub/MohistHub.cs`, `Events/Hub/EventBridge.cs`, `Infrastructure/Events/UserNotificationDispatcher.cs`, `Infrastructure/Hosting/MohistServiceRegistration.cs`): add a new `OnTranscriptEvent` method on `IEventsClient`, expose a new `ITranscriptEventPublisher` interface + implementation, register it in DI, and have the dispatcher also fan out transcript events. Keep the existing domain-event flow intact.
- **Server: agent session grain** (`packages/server/src/Mohist.Server/Sessions/Grains/AgentSessionGrain.cs`): for each appended runtime event, after persisting the row, forward the observation event via the new `ITranscriptEventPublisher`; for `agent_liveness_status`, `agent_session_terminal`, and `agent_session_model_resolved`, additionally publish a domain event via `IEventPublisher` when the state transition is meaningful (lifecycle boundaries only, deduplicated against the already-emitted domain event).
- **Server: agent session serializer** (`packages/server/src/Mohist.Server/Infrastructure/Events/AgentSessionEventSerializer.cs`): add `BusType` mapping for the lifecycle event variants using the existing `EventCatalog.ReverseDns.AgentSession*` constants.
- **Server: API** (`packages/server/src/Mohist.Server/Api/AgentRoutes.cs`, `packages/server/src/Mohist.Server/Sessions/Services/AgentSessionQuerier.cs`, `packages/server/src/Mohist.Server/Sessions/Services/AgentSessionQuerier.cs`): `/api/projects/{ref}/agent/activity` now accepts a `waiting` array (built from `IssueGrain` queries for `InProgress` issues paused on an approval gate, plus a `question_pending` flag from existing `ask_user` tables if present). The querier passes that array through to `GetActivityAsync` which is already shaped to accept it. No DTO shape change.
- **Web: events hub** (`packages/web/src/shared/api/events-hub.ts`): add `connection.onreconnected` handler that re-invokes `SetSubscriptionsAsync` with the canonical event-type list. Resolve the canonical list from a single helper so `LiveTaskProvider` and the new behaviour share one source of truth.
- **Web: live task provider** (`packages/web/src/app/providers/LiveTaskProvider.tsx`): extend the switch (or a small alias map) to handle reverse-DNS event names for the same logical cases — workflow stage transitions, approval requested/resolved, agent session lifecycle, issue lifecycle.
- **Web: event maps** (`packages/web/src/entities/issue/@x/events.ts`, `packages/web/src/entities/agent/model/events.ts`): add the reverse-DNS names to the union types so the TypeScript switch exhausts the new arms.
- **Web: ActivityPage** (`packages/web/src/pages/activity/ui/ActivityPage.tsx`): no structural change. It already consumes `waitingCards` from `useActivityCards`; once the server returns the `waiting` array, the section populates.
- **Tests**: extend `Mohist.Server.Tests/Specs/Events` to cover (a) `EventBridge` delivers a reverse-DNS event to a connection that subscribed to its legacy alias and the reverse-DNS name; (b) `ITranscriptEventPublisher` delivers an appended transcript event to a subscribed connection; (c) `AgentSessionGrain` emits at most one lifecycle domain event per transition. Add Web unit test asserting `useEventsConnection` calls `invoke('SetSubscriptionsAsync', [...])` after start.
- **Backwards compatibility**: All new bus types are added additively; existing wire shapes for runner → server and server → Web are unchanged. The Web adds new switch arms but keeps the legacy ones so any unmigrated producer still works. The 5-second poll fallback is preserved.
