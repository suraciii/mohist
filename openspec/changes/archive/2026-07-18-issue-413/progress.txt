## Codebase Patterns

- T-001: The transport-independent matcher lives under `Infrastructure/Events/Matching` and accepts only the `EventMatchInput` interface. CloudEvent adaptation remains for T-002.
- T-001: Compilation tokenizes and parses once into immutable record AST nodes. Regex instances are created eagerly with the caller-provided timeout; runtime regex failures return false locally.
- T-001: General evaluation failures flow through `IEventMatchFailureSink`, which is the structured log + counter integration seam; failures in either evaluation or the sink never propagate.
- T-001 verification: focused matcher suite passes 21 tests in 25ms; `dotnet build Mohist.sln --no-restore -p:SkipWebBuild=true` passes with zero warnings; full `npm test` passed Unit/Arch/CLI but had one unrelated pre-existing flaky `SessionFollowupApiSpecs` failure, and that exact test passed immediately when rerun alone.
- T-002: `CloudEventEventMatchInput` is the CloudEvent→EventMatchInput adapter — core fields (type/source/subject) read first, then extensions; missing values return "" and `Has` reflects key presence for extensions and core fields independently.
- T-002: `IEventTailSource` is registered as a singleton alias of the concrete `EventTailSource` (`AddSingleton<IEventTailSource>(sp => sp.GetRequiredService<...EventTailSource>()`) so the Subscription handler activation and the test fake resolve to the same contract surface.
- T-002: The `[Subscription(Type = "com.mohist.*")]` `EventTailSource` handler is non-blocking: it `TryWrite`s into per-tail bounded `Channel<CloudEvent>` instances and silently drops on a full channel; it never awaits the channel writer, so the dispatcher fan-out is unblocked even if every tail is stalled.
- T-002: Project isolation is enforced before matcher evaluation (`event.projectid` must equal the tail's resolved project id; an absent projectid is a drop). This is the strict line that the shared dispatcher gate deliberately does NOT take.
- T-002: The `/api/projects/{ref}/events/tail` endpoint compiles the expression exactly once before opening the stream (single authority). On compile failure it returns 400 with a structured `{ message, location }` body and never opens the stream. The endpoint reuses the existing `ProjectResolutionEndpointFilter` for project lookup.
- T-002: Server specs (SpecTests) drive the endpoint exclusively via the `IEventTailSource` fake (`InMemoryEventTailSource`) registered in `MohistIntegrationFixture`. No real `[Subscription]` dispatcher and no wall-clock waits — NDJSON lines are pulled off the source's per-test queue.
- T-003: `NdjsonStream` is the CLI's first non-buffered HTTP reader (`HttpClient.SendAsync` with `HttpCompletionOption.ResponseHeadersRead` + a `StreamReader.ReadLineAsync` loop that flushes each line). It is shared, not duplicated for `events tail`. On a 400 it parses the structured `{error, details:{offset,line,column}}` body the server returns (per T-002) and prints the location to stderr before any line is emitted.
- T-003: The CLI does NOT compile the expression locally — per design D6, `?match=` is forwarded verbatim and the server's 400 is the validation result. The CLI's only local check is project resolution (fails fast with `NoActiveProjectMessage` without contacting the server when none).
- T-003: Cancellation is `Console.CancelKeyPress` → local `CancellationTokenSource.Cancel()` → `HttpClient.SendAsync(token)`. Tests inject the token via `EventCommands.TailCancellationOverride` (a static seam) — the override path skips the console hook entirely so tests do not touch a real `ConsoleCancelEventArgs` (the public constructor is internal in net11.0).
- T-003: The `RecordingHttpHandler` was extended with `Ndjson(IEnumerable<string>)` (uses an internal `AsyncLineQueue` + a custom `Stream` over the IAsyncEnumerable) and `MatchCompileError(...)` (returns the server's structured 400 body). The fake stream is read once by the consumer and exposes EOF when the queue is empty — no `Task.Yield` / `Task.Delay` needed in tests.
- T-003: The `event` → `events` rename touches `MohistCliCommands.Event.cs:10` (top-level noun), the existing dead-letter subtree relocates verbatim under `events`, and `MohistCliCommands.cs:26` registration is unchanged in shape. Existing dead-letter specs were retargeted to the plural noun (10 tests pass unchanged). `CliRootCommandShapeTests.LegacyEventNoun_FailsToResolveAndExitsNonZero` is the root-shape regression gate for the singular-noun removal.
- T-003 verification: focused `CliEventsTailCommandSpecs` covers 8 cases — NDJSON lines on stdout, ?match= forwarding, 400-with-location stderr exit, no-project local failure (with and without --match), --project override, cancellation/release on the response token, and `mo event tail` parse failure. Total CLI suite: 942 tests pass; full `dotnet build Mohist.sln --no-restore -p:SkipWebBuild=true` is zero-warning; runner typecheck + web typecheck + web test:run + 1494 server unit + 27 arch all green.
