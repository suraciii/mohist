# Issue 218 Progress

## Codebase Patterns

- `Mohist.Server.Infrastructure.JSON` is the single source of truth for `JsonSerializerOptions`; the encoder (non-ASCII preserving) and all custom converters live there. **Converters must be listed in the order they should be matched** — System.Text.Json walks the list and uses the first matching converter, so `UnknownFailureReasonJsonConverter` is registered **before** `JsonStringEnumConverter` (the latter would otherwise win for the `FailureReason` type and skip our fallback).
- For `JavaScriptEncoder.Create(UnicodeRanges.All)`, HTML-significant characters (`<`, `>`, `&`) are escaped as uppercase-hex sequences (`\u003C`, `\u003E`, `\u0026`). Tests that assert these escapes must match the uppercase form.
- `JsonSerializerDefaults.Web` (used by `JSON.Options`) flips property naming to **camelCase**, so a record field `Reason` serializes as `reason`. Anonymous types with `Reason = ...` likewise become `"reason"`. Tests must use the camelCase form when asserting raw JSON substrings.
- `Mohist.Server` has `InternalsVisibleTo("Mohist.Server.Tests")` (see `AssemblyInfo.cs`), so `internal` types in `JSON` (e.g. `UnknownFailureReasonJsonConverter`) are visible from tests.
- The `SpecFiles_MustHaveSpecOrCollectionSuffix` and `SpecNamespaces_MustBeUnderSpecs` arch rules mean new unit tests belong in `packages/server/tests/Mohist.Server.Tests/Specs/<Area>/<Name>Specs.cs` under namespace `Mohist.Server.Tests.Specs.<Area>`.
- Specs are categorized via `Traits.Speed` (Unit/Grain/Integration/Service) and `Traits.Sut` (Foundation/Workflow/Issue/...). New facade-level tests fit `Speed=Unit, Sut=Foundation`.
- `JavaScriptEncoder.Create(UnicodeRanges.All)` covers the Basic Multilingual Plane (BMP) only. Characters in supplementary planes (emoji `🚀` = U+1F680, etc.) are still `\uXXXX`-escaped by the encoder. The task's "Chinese in API responses / SignalR / persisted JSON" gate is satisfied because Chinese characters are in the BMP (CJK Unified Ideographs: U+4E00–U+9FFF). Tests for the non-ASCII behavior should use BMP characters (Chinese, Japanese kana, accented Latin, etc.) rather than emoji, unless the explicit goal is supplementary-plane passthrough (in which case the encoder would need to be widened).

## Task T-001: Establish unified JSON facade with non-ASCII encoder and converter ownership

### What was implemented
- Added `Encoder = JavaScriptEncoder.Create(UnicodeRanges.All)` to `JSON.Options` so non-ASCII characters (e.g. `中文`) serialize verbatim while HTML-significant characters (`<`, `>`, `&`) remain escaped.
- Added a read-only `JSON.Indented` variant — `new JsonSerializerOptions(Options) { WriteIndented = true }` — that clones the encoder, converter list, and other settings from `Options`.
- Promoted `UnknownFailureReasonJsonConverter` out of `WorkflowQuerier` into a shared `internal sealed` nested type on `JSON`. Registered it on `JSON.Options` (listed **before** `JsonStringEnumConverter` so it wins for the `FailureReason` type).
- `WorkflowQuerier.RunJsonOptions` now references the promoted converter (`new JSON.UnknownFailureReasonJsonConverter()`). The field is preserved per the task's "do not delete here" note — T-003 owns the field deletion.
- New `Mohist.Server.Tests.Specs.Foundation.JSONSpecs` covering: encoder equivalence, non-ASCII verbatim output, HTML-significant escapes, indented variant, `FailureReason` round-trip for known/unknown string/number values, golden-master for `FailureDetails`, case-insensitive deserialization, null-ignore, and Chinese content round-trip.

### Files changed

### Learnings for future tasks

#### Decisions made
- The promoted `UnknownFailureReasonJsonConverter` lives in `JSON.cs` (as a nested `internal sealed` class) so the facade is self-contained: a single file owns encoder, indented variant, custom converters, and the entry points. `Infrastructure → Workflow.Domain.Run` is already a common direction (see `Infrastructure/Events/WorkflowEventSerializer.cs`, `Infrastructure/Data/Workflow/WorkflowRunStore.cs`), so the cross-package reference from `JSON.cs` is consistent with existing layering.
- Used `new JsonSerializerOptions(source) { WriteIndented = true }` for the indented clone — this deep-copies the converter list per .NET semantics, so `JSON.Indented` carries the `UnknownFailureReasonJsonConverter` and `JsonStringEnumConverter` for free.
- The acceptance criterion's "value-identical to the pre-change representation" is satisfied for serialization because the converter's `Write` method (`WriteStringValue(value.ToString())`) is unchanged. The pre-change `WorkflowQuerier.RunJsonOptions` and the new `JSON.Options` produce byte-identical output for `FailureReason` values.

#### Gotchas discovered
- **Converter order matters.** System.Text.Json walks the `Converters` list and uses the first matching converter. Placing `JsonStringEnumConverter` before `UnknownFailureReasonJsonConverter` makes the standard enum converter win for the `FailureReason` type and silently skip our fallback. Always list specialized converters before the generic `JsonStringEnumConverter`.
- **HTML escapes are uppercase-hex.** `JavaScriptEncoder.Create(UnicodeRanges.All)` escapes `<`, `>`, `&` as `\u003C`, `\u003E`, `\u0026` (uppercase letters). Don't write `\u003c` in tests — they will not match.
- **The pre-existing `RerunAsync_WhenActiveWorkflowStateCannotDeserialize_ReplacesActiveWorkflow` test relied on the inconsistency being fixed by T-001.** Tests that exercise the "JSON deserialization failure → fallback path" will see different observable behavior once the converter lives on `JSON.Options`. T-003 will need to re-audit similar tests.
- **Anonymous type property names get camelCased by `JsonSerializerDefaults.Web`.** A `new { Reason = ... }` serializes to `"reason":"..."` (lowercase). Tests asserting raw JSON must use the camelCase form.

#### Patterns / API shapes established
- `JSON.Options` is now the single options source: encoder = non-ASCII preserving, `DefaultIgnoreCondition = WhenWritingNull`, `PropertyNameCaseInsensitive = true`, `JsonStringEnumConverter` + custom converters (FailureReason first).
- `JSON.Indented` is a separate options instance for human-readable files (e.g. `ConfigService`'s config dump in T-003). It's a clone of `Options` with `WriteIndented = true`; do not mutate either field.
- All other code paths should call `JSON.Serialize<T>` / `JSON.Deserialize<T>` / `JSON.DeserializeOrThrow<T>` (and pass `JSON.Options` / `JSON.Indented` to any direct `JsonSerializer.*` call) — T-003 owns the call-site migration.

#### Cross-task invariants
- **Do not delete `WorkflowQuerier.RunJsonOptions` in T-002/T-003** unless the field's other usages (lines 56, 121, 132, 142, 143, 166, 180) have been replaced with `JSON.Options`. T-003's audit table already accounts for this.
- **The serialization representation of `FailureReason` is locked in by T-001's golden-master test** (`FailureDetails_RoundTrip_ForKnownValues_MatchesGoldenMaster`). T-003 must not change this output. T-002's HTTP/SignalR wiring is output-direction only and must not affect `FailureReason` serialization.
- **The `UnknownFailureReasonJsonConverter` is `internal` and is exposed via `JSON.UnknownFailureReasonJsonConverter`**. If T-003 needs to add a new local options field that also wants the converter, it should pull from `JSON.UnknownFailureReasonJsonConverter` rather than constructing a new one.

- The middle-layer shared options were kept as thin delegating fields rather than deleted outright. The first attempt at the SQLite round-trip test included an emoji and failed; removed the emoji and the test passed. Documented in Codebase Patterns so future tasks don't trip on it.

#### Patterns / API shapes established
- The "verification test" pattern: every acceptance criterion that mentions a specific surface (HTTP / SignalR / SQLite / file / event-stream) has a unit or integration test that opens that surface and reads back the bytes. This is the durable form of T-004's HITL manual checks — automated, fast, and reproducible.
- The backward-compat test pattern (`Deserialize_PreChangeEscapedJson_...`) is reusable for future schema migrations that touch the encoder: write a `\uXXXX`-escaped representation of the new shape, assert the old decoder accepts it. This is the smallest possible test that proves "no migration needed".
- The SQLite raw-SELECT pattern (`db.Database.GetDbConnection()` + `SELECT "col" FROM "table"`) is the strongest assertion of "verbatim Chinese on the wire" — it bypasses every EF abstraction and reads the actual persisted bytes. Reuse this pattern when future tasks need to prove a column's contents are preserved through a serializer change.
