## T-006: 实现失败处理和重试逻辑
Timestamp: 2026-04-08T18:42:00Z

### What was done
- Added `FailureCategory` type: 'ac_not_met' | 'environment' | 'dependency' | 'timeout'
- Implemented `categorizeFailure()` function with pattern matching to classify errors
- Created `FAILURE_CATEGORY_CONFIGS` with category-specific retry limits:
  - AC not met: max 3 attempts (retryable)
  - Environment: max 2 attempts (retryable)
  - Dependency: max 1 attempt (NOT retryable)
  - Timeout: max 1 attempt (NOT retryable)
- Added `onAskUser` callback to `RalphExecutorContext` for pausing and asking user intervention
- Implemented `storeFailureLearning()` to record failures with category and adjustments
- Modified `runRalphLoop()` to:
  - Categorize each failure using `categorizeFailure()`
  - Apply category-specific max attempts
  - Call `onAskUser` for non-retryable failures (dependency, timeout)
  - Call `onAskUser` when max retries exceeded
  - Store learning on every failure
  - Return `paused: true` in result when paused for user intervention
- Added comprehensive unit tests for `categorizeFailure()` and configs

### Learnings
- Used `Math.min(maxRetries, categoryConfig.maxAttempts)` to respect both global and category-specific limits
- Prefixed unused `_error` parameter with underscore to satisfy lint
- Added `path` import that was missing
