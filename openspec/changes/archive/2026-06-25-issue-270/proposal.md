## Why

The current `mohist/pr` workflow couples PR lifecycle, branch sync, and failure
recovery through ad-hoc mechanisms (`ready-github-pr`, `verifyTask`, hidden
stage checks). This makes PR state transitions, retries, and merge recovery
inconsistent and hard to debug. We need a single explicit task graph with a
unified `onFailure` + `retry: self` recovery model so PR state, repair, rebase,
and merge recovery all flow through one predictable, debuggable lifecycle.

## What Changes

- **BREAKING**: Rename the built-in workflow profile from `mohist/pr` to
  `mohist/github-pr`.
- Open the draft GitHub PR as the **last plan-stage task** (`open-draft-pr`),
  after `self-review`, once all plan artifacts are ready.
- **BREAKING**: Remove the `verifyTask` concept entirely. `CheckFailureRepair`
  no longer carries a `VerifyTask` field; `WorkflowYamlSerializer` no longer
  parses `verifyTask`. Repair verification is expressed through task-level
  `onFailure`.
- **BREAKING**: Replace the combined `ready-github-pr` action with two separate
  actions:
  - `mohist/mark-github-pr-ready` — only marks a draft PR ready, idempotent.
  - `mohist/push` — explicit branch sync to the remote PR head, supports
    `forceWithLease` after rebase.
- Add task-level `failIf` on `expect.markers`: when the matched marker equals
  `failIf`, the task is marked failed. The `errorCode` is defined by the
  action's own output, not generated by the engine.
- Add `retry: self` to `onFailure` cases: the engine appends a fresh attempt of
  the original failed task after recovery tasks, preserving the original
  `onFailure`.
- Support nested `onFailure` on recovery tasks (resolved at failure time,
  non-recursive), e.g. rebase conflict → `recover:resolve-rebase-conflicts`.
- Restructure the check stage to: `ai-review` (`failIf: FAIL` + auto-fix +
  `retry: self`) → `push` → `mark-pr-ready`. Remove `health`, `review-passed`,
  and `merge-ready` checks; keep only the read-only `github-pr-status` check.
- Restructure the integrate stage to: `spec-sync` → `archive-change` → `push`
  → `merge-pr` (squash merge after waiting for PR checks).
- `merge-pr.onFailure` declares two recoverable cases:
  - `base-moved`: `recover:rebase` (`conflictMode: task`) → `recover:push` →
    `retry: self`. Does not re-mark ready.
  - `pr-checks-failed`: `recover:fix-pr-checks` → `recover:push` →
    `retry: self`.
- `mohist/rebase` with `conflictMode: task` returns
  `output.failureKind: conflict` and leaves the rebase in progress when
  conflicts occur; an explicit `recover:resolve-rebase-conflicts` agent task
  resolves and completes it.
- All task prompts use named references (`${{ prompts.xxx }}`); no inline
  prompt strings in workflow YAML.
- Task IDs drop stage prefixes (`plan:`, `check:`, `integrate:`); recovery
  tasks use the `recover:` prefix.
- Consolidate the four `core/artifact-exists` plan checks into a single
  `mohist/openspec-artifacts` check (`changeDir` only).

## Capabilities

### New Capabilities
- `workflow-failure-recovery`: Task-level `onFailure` recovery model —
  `failIf` marker matching, `retry: self` re-enqueue of the failed task with
  preserved `onFailure`, nested recovery task `onFailure` (resolved at failure
  time, non-recursive), and the engine contract that recovery reads only the
  failed task's action output via generic JSON-path matching.

### Modified Capabilities
- `pr-first-workflow`: The profile is renamed `mohist/pr` → `mohist/github-pr`;
  actions renamed (`create-pull-request` → `create-github-pr`,
  `merge-pull-request` → `merge-github-pr`); the draft PR is opened as the last
  plan-stage task; `ready-github-pr` is split into `mark-github-pr-ready` +
  `push`; stage checks are reduced to the read-only `github-pr-status`; the
  `pr-checks-failed` contract changes from "no auto-fix" to explicit declared
  recovery; the `base-moved` recovery path replaces "update PR" with an
  explicit `push`; the plan checks collapse to `mohist/openspec-artifacts`.
- `issue-workflow-profile`: References to `mohist/pr` in read-surface and
  startup-resolution scenarios are updated to `mohist/github-pr`.

## Impact

- **Server (C#)**: `CheckFailureRepair` domain record loses `VerifyTask`;
  `WorkflowYamlSerializer` drops `verifyTask` parsing; workflow engine adds
  `failIf` evaluation, `retry: self` re-enqueue, and nested `onFailure`
  resolution; built-in workflow catalog ships `mohist/github-pr`.
- **Runner (TypeScript)**: Action registration/naming —
  `mohist/create-github-pr`, `mohist/mark-github-pr-ready`, `mohist/push`,
  `mohist/merge-github-pr`; `mohist/rebase` gains `conflictMode: task` with
  `output.failureKind: conflict` semantics; merge action returns
  `errorCode: base-moved` / `errorCode: pr-checks-failed` action-owned JSON.
- **Tests**: Coverage for workflow ordering, action names, `failIf`, `onFailure`
  + `retry: self`, nested `onFailure` (rebase conflict), `base-moved` and
  `pr-checks-failed` recovery, and `verifyTask` removal.
- **APIs/Data**: Any persisted `mohist/pr` profile references on existing
  issues/runs must still resolve (rename is breaking at the profile-id level).
- **Docs/Specs**: `openspec/specs/pr-first-workflow` and
  `openspec/specs/issue-workflow-profile` delta specs; new
  `openspec/specs/workflow-failure-recovery` spec.
