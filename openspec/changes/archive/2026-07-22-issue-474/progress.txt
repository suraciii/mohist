## Codebase Patterns

- Workflow Definition YAML is parsed through `WorkflowYamlSerializer`; task-level `artifacts`, `recovery`, and `setVars` remain valid executable fields.
- Built-in workflow files are pure behavior assets. Profile names and descriptions belong to `WorkflowProfileCatalog`.
- Project and issue workflow persistence keeps the existing storage keys and stores a `WorkflowProfile` envelope in the existing template column.
- Startup and later stage loads resolve through `WorkflowProfileManager`; the selected profile id is used for `WorkflowStructure` because pure Definitions do not own identity.

## T-001 Decisions

- Direct Definition YAML/JSON rejects only the known removed fields and stage `variables`; broad unknown-field validation remains outside this task.
- `FromProfileYaml` is an API/persistence boundary for existing custom-profile input. It separates profile metadata before passing the remaining document through the pure Definition parser.
- `WorkflowProfileDataUpgrader` converts old persisted definition rows once, preserving project/template and issue identities. Rows with embedded variables fail with a diagnostic containing the profile identity and variable paths.
- Effective variable resolution no longer patches Definition/global-config variables. Issue/Run default initialization and remaining variable behavior are reserved for T-002.

## T-002 Decisions

- `VariableBundle` gains `DefaultVars` and `DefaultStages` fields that mirror the explicit `Vars` and `Stages` trees but carry initialization-default markers. `Patch` and `ToJson` round-trip both trees; `HasExplicitContent` and `HasDefaultContent` make bundle-shape branching explicit at the call site.
- Effective Variable resolution merges defaults → Project → Issue → explicit Run top-level values (and the same order for selected-stage overlays). The defaults layer sits at the bottom of the resource precedence stack so explicit Project, Issue, and stage writes always win; once an explicit write covers a default key the marker is cleared and the explicit value follows the standard precedence.
- `WorkflowRunProfileRow` gains a `DefaultVariables` JSON column alongside `Variables`. The two columns separate explicit values from marked defaults so an explicit write (setVars / PUT / PATCH) can clear only the affected default keys without touching unrelated markers.
- `WorkflowRunProfileManager.EnsureArchiveDefaultAsync(workflowRunId)` is the WorkflowRun-creation entry point. It is idempotent, never overwrites an explicit `archive` value, and is called from `IssueGrain.PrepareWorkflowStartContextAsync` after the issue bundle is persisted but before the run becomes dispatchable.
- `IssueVariableBuilder.BuildContextBundle` now accepts the issue's existing bundle and seeds `vars.agent = {}` only when the existing issue does not already define an `agent` key. Explicit user-chosen agent configurations are preserved across repeated start attempts.
- `WorkflowProfileManager.ResolveConfiguredVariablesAsync` consults only Project, Issue, and WorkflowRun resources. `ConfigService.GetVariables()` is no longer read on the effective-Variables path. Profile parsing and Definition loading cannot contribute variables.
- `VariableBundle.ClearDefaultsCoveredByExplicit(explicitOverlay)` strips default keys that the supplied explicit overlay also writes, leaving unrelated default keys (and stages) intact. The caller passes the freshly-merged explicit bundle so the marker-clear semantics match the new top-level value.
- `VariableBundle.ResolveStageVars(stage)` assumes the caller's `Vars` and `Stages` trees already have defaults merged in at the bottom (the resolver merges them before constructing the bundle it returns). The method then overlays the merged selected-stage tree on top of the merged top-level tree. Direct calls that bypass `ResolveConfiguredVariablesAsync` (the unit tests) build the tree with defaults baked in to match the resolution-path shape.

## CI Repair

- The failed verify reproduced as 196 SpecTests failing because test persistence serialized bare Definitions while the migrated loader requires Profile envelopes; old YAML fixtures also retained forbidden Definition metadata and Variables.
- The production root cause was an additional serializer defect: `WorkflowDefinition` has a legacy in-process constructor, so `System.Text.Json` could not deserialize the pure Definition from a Profile envelope. `WorkflowYamlSerializer.FromJson` now parses the allowed `stages` and `approval` fields explicitly and rejects stage Variables in JSON as well.
- Spec persistence helpers now write Profile envelopes, metadata assertions use Profile assets, and stage-agent scenarios seed Issue Variables with stage overlays.
