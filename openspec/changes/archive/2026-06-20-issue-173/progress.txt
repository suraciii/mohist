## Codebase Patterns

- Epic domain aggregate uses a `sealed partial class Epic` split across `Epic.cs` (fields/properties) and `Epic.Transitions.cs` (factory + transition methods + helpers).
- Domain events use C# union type `EpicEvent`; new events are added as records to the union in `Events/EpicEvent.cs`. No new event type was needed for Pause/Resume — they reuse `EpicStatusChanged`.
- The `EpicGrain` has its own `StatusName`/`ParseStatus` static helpers (alias on domain `EpicStatus` enum) separate from the domain's `ToStatusName`. Both maps must be kept in sync.
- Domain exceptions follow the pattern: message in constructor, minimal properties for the consumer (e.g., `EpicId`, string status names). Follow the `EpicAlreadyTerminalException` shape.
- Tests use `[Trait(Traits.Speed.Name, Traits.Speed.Unit)]` and `[Trait(Traits.Sut.Name, Traits.Sut.Epic)]` for categorization. Unit tests avoid integration fixtures.
- The `NewActiveEpic()` factory helper in spec files creates a canonical test Epic.
- `EpicProgress.IsTerminal` is a static predicate on `EpicStatus`; it stays `Done | Closed` only.
- EpicGrain's `MapToRow`/`Materialize`/`ToDto` are the canonical write/read paths. Any new field must be threaded through all three.
- DTO constructor args follow a specific position order: Id, Number, Title, Description, Priority, Status, CreatedAt, UpdatedAt, then extras like Progress or PauseReason. Keep this order consistent.
- EF migrations without `dotnet ef` tool: create migration `.cs` (with `Up`/`Down`), `.Designer.cs` (full `BuildTargetModel` snapshot), and update `MohistDbContextModelSnapshot.cs`.
- API routes for lifecycle actions resolve the Epic by either id or number (parity with existing done/close). Use `int.TryParse(id, out var number)` to detect numeric segments and call `GetByNumberAsync` accordingly.
- API spec tests parse error responses via `ReadFromJsonAsync<ConflictEnvelope>` (lightweight record with Success, Code, Error); not the full `ApiResponse<T>` envelope.
- Frontend EpicListPage tests use `vi.hoisted()` for mock factories and mock `useEpics`/`useCreateEpic` at the module level. Test data follows the `EpicWithProgress` shape. Section ordering is tested by checking heading DOM order via `screen.getAllByRole('heading', { level: 2 })`.
- Frontend `EpicStatus` enum defines the canonical status order; list group sections mirror it (Active, Paused, Done, Closed).
- Paused EpicCards use `opacity-60 hover:opacity-80` for de-emphasis vs active cards' `hover:border-muted-foreground/30`.

## Task T-001: Epic aggregate: add Paused status with Pause/Resume transitions and MarkDone guard

- What was implemented:
  - Added `Paused` member to `EpicStatus` enum (`EpicStatus.cs`).
  - Added `EpicPausedCannotMarkDoneException` to `EpicLifecycleExceptions.cs`.
  - Added `_pauseReason` field and `PauseReason` property to `Epic.cs`.
  - Added `Pause(string? reason, DateTime? now)` method: idempotent on already-paused, throws `EpicAlreadyTerminalException` from `done|closed`, sets status to `Paused`, persists reason, records `EpicStatusChanged`.
  - Added `Resume(DateTime? now)` method: no-op if not paused, sets status back to `Active`, clears reason, records `EpicStatusChanged`.
  - Added explicit `Paused` guard at the top of `MarkDone`: throws `EpicPausedCannotMarkDoneException` before the existing `EnsureNotTerminal`/`undelivered` checks.
  - Added `Paused` branch to `ToStatusName` in `Epic.Transitions.cs`.
  - Added `Paused` branches to `StatusName` and `ParseStatus` in `EpicGrain.cs`.
  - `EnsureNotTerminal` stays unchanged (only blocks `done|closed`).
  - `EpicProgress.IsTerminal` stays unchanged (returns false for `Paused`).
  - No new event type — Pause/Resume emit only `EpicStatusChanged`.
  - Domain unit tests added for: pause from active (reason/link preservation/event), pause idempotent, pause from done/closed throws terminal, resume from paused (clears reason/event), resume no-op on active, MarkDone on paused throws `EpicPausedCannotMarkDoneException`, Close from paused allowed, pause without reason, IsTerminal on Paused returns false.

- **Learnings for future tasks:**
  - Decisions made: Pause/Resume emit only `EpicStatusChanged` (not `EpicClosed`), so the grain's `ApplyPendingEvents` unbind side-effect cannot fire. Close from paused is allowed via existing `EnsureNotTerminal` which doesn't block paused.
  - Gotchas discovered: `EpicGrain.cs` has its own `StatusName`/`ParseStatus` maps (using `EpicStatusEnum` alias for `EpicStatus`) that must be updated in parallel with the domain `ToStatusName`. Forgot to also check this; caught during implementation.
  - Patterns / API shapes established: Pause is idempotent (mirrors `LinkIssue` duplicate pattern). Resume is no-op on non-paused (safe under retries). The Paused guard in `MarkDone` goes before `EnsureNotTerminal` so it fires first and gives a clear error.
