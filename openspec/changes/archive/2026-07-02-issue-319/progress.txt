# Issue 319 — working memory

## Codebase Patterns

- Web workspace (`packages/web`) uses **Vitest** with `jsdom` env; tests live next to source as `*.test.ts` / `*.test.tsx` (e.g. `format-compact.test.ts`, `IssueCard.test.tsx`). Run via `cd packages/web && npx vitest run` — running at monorepo root mis-resolves the `tests/setup.ts` path.
- `npm run typecheck -w packages/web` runs `tsc -b`; the root monorepo `npm test` script also runs `dotnet test`, so prefer the per-workspace commands when iterating on Web.
- Shared color helpers live in `packages/web/src/shared/lib/label-colors.ts`. They are pure, side-effect-free — easy to unit-test with no React/jsdom setup.
- `getPriorityStyle`'s return type is `{bg, text}` and is consumed by destructuring (`const style = getPriorityStyle(p); style.bg / style.text`) in 6 call sites (IssueCard, KanbanBoard, both dialogs, IssueDetailPage/pills). Keep the shape stable to avoid a blast radius.
- For cross-file min-w-0 containment chains that are too heavy to fully mount in jsdom, mixing a `render()` of the affected React components with a `fs.readFileSync` of an unrelated source file is fine — regex-parse the inner div's className attributes from the source string.

## T-001 — Priority strip color + dedup chip palette

- `getPriorityStripColor(priority)` returns hexes for `p0..p4` (red-600 / orange-600 / yellow-600 / green-600 / gray-500) — all visually distinct; falls back to the gray for null / undefined / unknown (including empty string and `p9`).
- `PRIORITY_COLORS` chip map was deduped (p0 and p1 used to share the same `#fee2e2 / #dc2626` pair — also below AA contrast at ~3.5:1). New pairs use Tailwind `-100` bg + `-900` text family (`#7f1d1d`, `#7c2d12`, `#713f12`, `#14532d`, `#1f2937`). All five pairs clear 4.5:1 by a wide margin.
- `getStripColor` (label-based) untouched per task notes; it remains the generic helper for label-driven strips elsewhere.
- `getRiskStyle` (`RISK_COLORS` in the same file) was deliberately NOT touched — out of scope for T-001; the design.md only calls out priority pills for this task, and Risk chips are a separate concern (would belong in T-004 if needed).
- Test file `packages/web/src/shared/lib/label-colors.test.ts` computes WCAG contrast via sRGB relative luminance inline (no external dep). 14 tests pass; the full 241-file suite still green.

## Gotchas

- The chip text hexes had to drop 2-3 lightness steps (e.g. `red-600 #dc2626` → `red-900 #7f1d1d`) to clear AA on the `-100` background — keeping the soft-tint look while being compliant.
- `getPriorityStyle` return shape stays `{bg, text}` (no `strip` field) so all 6 existing call sites stay type-compatible — the strip is sourced via the separate `getPriorityStripColor` function T-004 will call.

## T-003 — Remove per-column sort controls

- `StageColumn.tsx`: dropped the per-column sort button group (the `onSortChange && sort` block) and removed `sort` / `onSortChange` from the `Props` interface; also removed the now-orphaned `sortOptions` local array. `KanbanBoard.tsx`: removed the two corresponding props from the `<StageColumn>` call site. - "changing the global sort drives the sort order of every column" sets up 4 issues across Backlog and InProgress with mixed priority / number / updatedAt and asserts the card order in BOTH columns reorders after each global sort click (priority → number → updated). This pins the spec scenario "A single sort state drives all columns".

## T-004 — Converge IssueCard top row, AA text, priority strip

- **Workflow profile → hover-only**: the always-visible chip (`bg-gray-100 text-gray-700`) is gone. The value moved to a `title` attribute on the issue-number span (`data-testid="issue-number"`, with `title="Workflow profile: <id>"`). The inspectable data hook (the new `IssueCard.test.tsx` tests use this) lives on a sibling span with `class="sr-only"` `aria-hidden="true"` and `data-testid="issue-card-workflow-profile"` / `data-workflow-profile="<id>"` — fully invisible to sighted users but the DOM and tests can still reach it.
- **Stage fold**: when `getStatusIndicator()` returns non-null, a single `<StatusPill>` renders with the full format `${indicatorLabel} · ${stageLabel} ${progressLabel}` (e.g. `Running · Build 2/5`). When progress is null the suffix drops to `${indicatorLabel} · ${stageLabel}` (no standalone `${completed}/${total}` is ever rendered). When no status pill applies, the lone `<WorkflowStagePill>` + `<WorkflowStageProgressIndicator>` still render (preserves "still renders stage pill standalone when no status pill applies"). The `getStatusIndicator` derivation logic was untouched (visual-layer-only Non-Goal).
- **Auxiliary text AA**: `text-muted-foreground/70` is gone — issue number, timestamp, the "+N" labels-truncated count, and the archive button now use full-opacity `text-muted-foreground`/`text-foreground` as appropriate. The blocker-reason and blocked-reason lines also moved to `-800` amber/red (`text-amber-800` / `text-red-800`) for better margin.
- **StatusPill AA**: every StatusPill variant's text color was darkened one Tailwind step (`-700` → `-800`) to widen the margin above 4.5:1 against its `-100` bg. Computed via OKLCH→sRGB for Tailwind v4's actual rendered color: blocked 6.85, cancelled 8.32, approval 6.36, running 7.23, waiting 6.84, drift 6.43. The pairs are exported as `STATUS_PILL_PAIRS` so a colocated `StatusPill.contrast.test.ts` asserts the >=4.5:1 invariant in CI.
- **Priority strip**: `style={{ borderLeftColor: getStripColor(issue.labels) }}` → `getPriorityStripColor(issue.priority)` (one-line swap; `getStripColor` stays untouched for other potential call sites).
- **New test files**:
  - `IssueCard.test.tsx` rewritten to cover: workflow-profile visibility (sr-only data hook + hover title), priority-strip p0..p4 distinctness, default top-row shape, stage-fold format, stage-standalone fallback, AA text tokens for `#number` + timestamp.
  - `StatusPill.contrast.test.ts` (new, colocated) — 6 per-variant AA-contrast checks + a "every variant has a documented pair" check.
- **Gotchas**:
  - jsdom does NOT apply CSS, so `container.textContent` includes `sr-only` content; the "no visible workflow-profile text" assertion walks every `<span>` and filters out `sr-only` ones manually instead of relying on container `textContent`.
  - `borderLeftColor` is exposed as `rgb(r, g, b)`, not `#hex`. The test converts the expected `getPriorityStripColor` hex via `hexToRgbString` for comparison.
  - Test-only helper `runningAgentStatusFor(issueNumber)` registers an `ActiveAgentInfo` for the issue; the existing default `mockAgentStatus` (empty activeAgents) means tests for the "Running" stage fold need to opt in.
  - `formatStageFoldSuffix` is small enough to live inline; the `STATUS_PILL_LABEL` map needs `Record<NonNullable<StatusIndicator>, string>` (not `Partial<...>`) so the lookup return type is non-optional.
- 129 kanban-board tests + full 243-file (3769 tests) web suite still green. `tsc -b` clean.

## T-005 — Cross-cutting desktop + mobile regression verification

T-005 is the integration REVIEW task for the spec scenario "Existing board behaviors remain functional across desktop and mobile layouts". It depends on T-001..T-004 and verifies the integrated whole, not new implementation. Summary of work:

- **Green typecheck**: `npm run typecheck -w packages/web` runs `tsc -b` clean (zero errors).
- **Green test suite**: `npm run test:run -w packages/web` passes 243 test files (3773 tests, 1 skipped) at 15.6s — 4 more tests than the pre-T-005 baseline (3769).
- **New test coverage for Done-column collapse**: T-001..T-004 collectively pinned filtering, sorting, Show/Hide cancelled, Needs-Attention, and the strip / chip colors, but the `StageColumn` limit-5 collapse ("N more" / "Show less") was not directly covered. Added a new `describe('Done column collapse - desktop limit-5 + expand')` block in `kanban-board-query.test.tsx` with 4 tests:
  1. `limits the desktop Done column to the first five issues and exposes an N more toggle` — pins the limit and the toggle label.
  2. `expands the desktop Done column to show every issue when the toggle is clicked` — pins the expand path and `Show less` label.
  3. `does not collapse the Done column when it has fewer than six issues` — pins the no-op below the limit.
  4. `renders the Archive / Archive-all-done controls in the desktop Done column footer` — pins the footer (5 archived / view / Archive all done) since the spec scenario "Archive and Archive-all-done" was not directly covered before. The per-card archive button is on each `IssueCard` (`data-testid="archive-button"`) when `showArchiveButton` is set; that's exercised transitively by all Done-column tests that render Done cards.

  These tests are deterministic: each issue gets a distinct `updatedAt` (one day apart) so the priority-tie → updatedAt-desc tiebreaker gives a predictable sorted order (#107, #106, ..., #101), and the collapsed view is the 5 most recent. The "5 archived" text is matched with a regex (`/5 archived/`) because the "📦" emoji splits `getByText`.

- **Containment chain (T-002) still pinned**: `kanban-board-containment.test.tsx` already asserts `min-w-0` on SidebarInset `<main>`, KanbanBoard root, and the kanban-board-row, and parses App.tsx's wrapper to confirm `min-w-0 flex-1 min-h-0` is on the content wrapper. No `overflow-x-auto` is set on the page shell (`App.tsx`, `sidebar.tsx`), so the page itself never scrolls horizontally — the only horizontal scroll is the board row (desktop) or the tab strip (mobile), both of which are local to their container.
- **Desktop / mobile interaction coverage map** (each line points to the test that pins it):
  - **Filtering** (priority, key=value labels, search, AND across keys): `Board Query State - Filtering` (10 tests), `Label filtering beyond first eight labels` (5 tests).
  - **Sorting** (global SortToggle drives all columns): `Board Query State - Sorting` (3 tests) + `Single sort control - per-column sort buttons removed` / `changing the global sort drives the sort order of every column` (5 tests).
  - **Done-column collapse** (NEW, this task): `Done column collapse - desktop limit-5 + expand` (4 tests). Mobile doesn't collapse because it shows a single column at a time and scrolls vertically.
  - **Show / Hide cancelled** (desktop): `cancelled toggle lives inside the Cancelled column and supports bidirectional show/hide`. (mobile): `Mobile cancelled tab count is independent of showCancelled` (verifies the in-list toggle and the tab badge count).
  - **Archive / Archive-all-done** (desktop): new `renders the Archive / Archive-all-done controls in the desktop Done column footer` (this task) pins the footer; the per-card `archive-button` data-testid appears transitively in all Done-column tests. Mobile Archive is per-card (same `archive-button` data-testid), so the existing IssueCard rendering covers it.
  - **Needs-Attention banner**: `Needs attention summary - user-action wording` (10 tests) covers approval / interrupted / blocked / integration-failed / completed-excluded / non-existent-banners. The banner is the desktop `NeedsAttentionSummary` component; on mobile the same banner is rendered above the tab strip (per `KanbanBoard.tsx:549`), so the desktop tests confirm the wiring.

- **Gotchas**:
  - `sortIssues` priority-tie tiebreaker is `updatedAt desc` then `number desc`. To get a deterministic order in Done-collapse tests, give each issue a distinct `updatedAt` (one day apart) — the most recent 5 stay visible after the `slice(0, 5)`.
  - The "📦 5 archived" footer text splits across the emoji + a regular span, so `getByText('5 archived')` fails; use a regex `/5 archived/`.
  - The mobile `SortToggle` lives behind the `mobile-filter-toggle` disclosure (default `mobileFiltersOpen = false`), so the "exactly one global SortToggle" assertion holds with the panel closed. The same testid `sort-priority` is reused inside the panel — `getAllByTestId('sort-priority')` returns 2 after the disclosure opens.
  - The Done-column collapse is desktop-only: `StageColumn.tsx` renders inside the `hidden md:flex` board row, so the `DONE_COLLAPSE_LIMIT = 5` rule never applies on mobile. The mobile path (`md:hidden flex flex-col`) renders a single selected column's full issue list with `overflow-y-auto`, which is the intended UX.
