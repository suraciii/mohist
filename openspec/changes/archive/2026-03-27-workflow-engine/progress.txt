## 2026-03-27T08:00:00Z - T-008: Implement local merge on approve

**Status**: Completed

**What was done**:
- Updated `cli/commands/issue.ts` approve command to check issue stage before approving
- When issue is in `waiting-review` stage:
  1. Fetches issue details via `GET /api/issues/:number` to get `projectPath`
  2. Executes `git merge --no-ff mo/issue-{N}` locally in projectPath using `execSync`
  3. On success: calls `POST /issues/:number/approve` then `POST /issues/:number/cleanup`
  4. On merge conflict: displays error with resolution instructions, does NOT call server API
- For non-waiting-review stages: uses existing server API flow (unchanged)
- Added `execSync` import from `child_process`

**Learnings**:
- Server-side cleanup route (`POST /issues/:number/cleanup`) was already implemented in T-005, so no server changes needed for T-008
- `execSync` with `stdio: 'pipe'` prevents merge output from polluting CLI, while still throwing on non-zero exit (conflict)
- If server approve fails after successful merge, user is given `git reset --hard HEAD~1` instructions to revert
