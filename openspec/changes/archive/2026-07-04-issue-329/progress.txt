## Codebase Patterns

- `ConfigService` exposes a JSON-flavored schema (key -> (type, defaultValue)). All writes go through `SetAsync` which validates against the schema via `_schema.ContainsKey`. Removing a schema key immediately closes that write path; existing on-disk `Mohist:Config:<key>` entries still load via `ReadConfigFile` + `GetConfigValue` — schema membership is a write-time guard, not a read-time one.
- Tests seed config by either `SetAsync(key, value)` (preferred, goes through validation) or by writing `_configPath` JSON directly with `"""{ "Mohist": { "Config": { ... } } }"""`. Use the latter when the key is intentionally not in schema (e.g. simulating legacy `model`-only configs after the schema removal).
- `JsonElement`-backed dictionary values: after `JSON.Deserialize<Dictionary<string, object?>>`, scalar fields come back as `JsonElement`, not `string`. `Assert.Equal("gpt-4o", dict["model"])` will say "Values differ" with identical strings — cast via `.ToString()` first or assert against the JSON path.
- `Validate` is `(type, value)` driven off `_schema`; legacy keys removed from the schema also drop their type-driven validation, but `Validate` is not the surface under test for this task.
- Server tests use xUnit `[Trait]` decorators `Traits.Speed.Unit` + `Traits.Sut.System` for the ConfigService specs — keep them on new tests.

## Task T-003 Notes (Consolidate the five verb HTTP methods into one generic send)

- Added a single private `SendAsync(HttpMethod method, string path, object? body) -> Task<HttpResponseMessage?>` in `MohistCliApi`. It builds a `HttpRequestMessage(method, path)` once, attaches `JsonContent.Create(body, options: JsonOptions)` only when `body is not null`, calls `_http.SendAsync(request)`, and centralizes the `HttpRequestException -> ServerUnavailableMessage + return null` path. Returning `null` from `SendAsync` is the "server unavailable, exit 1 was already written to stderr" signal — every verb method now does `using var response = await SendAsync(...); return response is null ? 1 : await PrintResponse/EnvelopeAsync(response);`.
- All ten verb methods are now thin 3-line forwarders (`PrintGetAsync` / `PrintPostAsync` / `PrintPutAsync` / `PrintPatchAsync` / `PrintDeleteAsync` and the `PrintWithOutputAsync` / `PrintPostWithOutputAsync` / `PrintPutWithOutputAsync` / `PrintPatchWithOutputAsync` / `PrintDeleteWithOutputAsync` variants). Each is `SendAsync(...)` + the existing `PrintResponseAsync` / `PrintEnvelopeAsync` dispatch — no per-verb try/catch and no per-verb `HttpRequestMessage` / `JsonContent.Create` boilerplate survives. `grep -nE '_http\.(GetAsync|PostAsJsonAsync|PutAsJsonAsync|SendAsync|DeleteAsync)' packages/cli/Mohist.Cli/MohistCliApi.cs` now returns only the out-of-scope callers (PrintProjectListAsync / PostAndReadAsync / GetDataAsync / PrintRunnerShowAsync / PrintSystemInfoAsync / PostDataAsync) and the inside-SendAsync `_http.SendAsync(request)` line itself.
- `PrintSystemInfoAsync`'s command-level `HttpRequestException -> RenderSystemInfoDegradedAsync + exit 0` recovery is intentionally NOT folded in (per task). Its local `try { _http.GetAsync("/api/system/info") } catch (HttpRequestException) { ... }` block stays in place.
- `PrintGetSafeAsync`'s `try/catch (HttpRequestException)` is now unreachable but left in place to preserve the public surface (no command call sites use it; leaving it alone keeps blast radius minimal). `GetDataSafeAsync` is unrelated and untouched.
- New `MohistCliApiSendAsyncSpecs` (20 specs) at `packages/cli/tests/Mohist.Cli.Tests/MohistCliApiSendAsyncSpecs.cs`:
  - 5 specs asserting `PrintGet/Post/Put/Patch/DeleteAsync_ServerUnreachable_WritesServerUnavailableMessageAndExitsOne` (the bare-verb network-failure path that previously threw — now exits 1 with `ServerUnavailableMessage` on stderr). These directly cover the new spec scenario "Network failure prints the server-unavailable message" for all five bare verbs.
  - 5 specs asserting `Print/PrintPost/PrintPut/PrintPatch/PrintDeleteWithOutputAsync_ServerUnreachable_WritesServerUnavailableMessageAndExitsOne` (the already-handled paths — regression coverage that the consolidation didn't break them).
  - 5 specs asserting the verb methods serialize bodies and reach the server with the right method: `PrintPostAsync` / `PrintPutAsync` / `PrintPatchAsync` / `PrintDeleteAsync` (`ServerReachable_*` group) and `PrintGetAsync_ServerReachable_ExitsZeroOnSuccessEnvelope`.
  - 2 specs asserting `PrintPostAsync_NotFoundEnvelope_ExitsFour` / `PrintDeleteAsync_BadRequestEnvelope_ExitsOne` to confirm 404 + 400 exit-code mapping (via `FailureExitCode`) is unchanged for the verb paths.
  - 2 specs asserting `PrintWithOutputAsync_JsonMode_ServerReachable_PrintsJson` / `PrintPatchWithOutputAsync_JsonMode_ServerReachable_PrintsJson` to confirm the WithOutput variants still route to `PrintEnvelopeAsync` -> `PrintResponseAsync`.
