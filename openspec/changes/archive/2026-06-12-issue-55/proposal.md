## Why

Workflow task outputs are durable evidence for planning, review, repair, and integration decisions, but Mohist currently exposes them mostly as mutable worktree files. Recording immutable task-produced artifacts now closes the history gap in check and repair loops, where later runs rewrite paths such as `review.md` and hide the reports that drove earlier workflow decisions.

## What Changes

- Add `WorkflowArtifact` as the product, API, storage, DTO, and UI language for immutable outputs recorded from workflow task runs.
- Support task-level `artifacts.files` in workflow YAML as the formal workflow artifact capture declaration, separate from action `with.expect` completion inputs.
- Keep `mohist/acp-agent` expectations available through `with.expect.files` and `with.expect.markers`, including marker expectations that accept `oneOf` values such as `<promise>PASS</promise>` or `<promise>FAIL</promise>`.
- Add runner-to-server artifact upload and binding so files from the runner workspace are persisted before task results become visible in workflow history.
- Expose issue-scoped workflow artifact queries for latest-by-path, path history, task-run artifacts, and immutable artifact content.
- Show artifacts on issue workflow task rows and add a latest-artifacts index, including directory artifacts as one browsable collection instead of flooding the top-level view.
- Preserve every artifact version generated by repeated task runs, such as multiple `ai-review` reports across check repair loops.

## Capabilities

### New Capabilities

- `workflow-artifacts`: Defines immutable workflow artifact recording, upload binding, latest/history/task-run queries, content retrieval, and directory artifact behavior.

### Modified Capabilities

- `workflow-definition`: Adds task-level `artifacts.files` metadata and clarifies that `with.expect` remains action input rather than the generic workflow artifact declaration surface.
- `workflow-agent`: Preserves acp-agent completion expectations and extends marker expectations to support target paths with `oneOf` accepted marker values.
- `workflow-run`: Records task-produced artifacts during task result binding and exposes produced artifacts on task runs in workflow history.
- `http-api`: Adds issue-scoped workflow artifact list and content endpoints.
- `web-ui`: Adds latest artifact and per-task artifact history views to the issue page.

## Impact

- Backend domain and persistence gain `WorkflowArtifact` records, pending upload rows, filesystem-backed content storage, and `WorkflowArtifactRecorded` events.
- Runner collects declared and dynamic artifacts from the workspace, enforces path safety and directory limits, uploads content with multipart form data, and reports upload ids with task results.
- Workflow result binding validates uploads, fails required missing artifacts through normal task failure handling, and makes bound artifacts visible in read models.
- API and web clients gain artifact DTOs, immutable content retrieval, latest grouping, path history, task-run filtering, and directory browsing support.
- Default workflow YAML can repeat paths in `with.expect` and `artifacts.files` where completion validation and artifact recording intentionally overlap.
