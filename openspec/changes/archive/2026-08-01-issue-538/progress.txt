## Codebase Patterns

- `WorkflowRunStore.StageRunAsync` is the runtime funnel for both run save overloads. Projection writes must stay on its `DbContext` so `State`, active-work columns, and task-map rows share the `SaveChangesAsync` transaction.
- `WorkflowRunWorkProjectionBuilder.Build` is the single calculation point for all-stage task membership and active-work identity. A future state upgrader should call this builder rather than reproduce the traversal.
- Projection reads use `AsNoTracking` plus scalar `Select` expressions. Loading `WorkflowRunRow` is not suitable for projection reads because it also selects the large `State` column.
- Migration tests that intentionally roll back to an older schema must use explicit column reads instead of materializing the current `WorkflowRunRow` model.

## T-002

- Added `WorkflowRunWorkProjectionDataUpgrader`: it preflights every WorkflowRun with the current model and shared `WorkflowRunWorkProjectionBuilder`, compares both projection shapes, then writes only mismatches in one transaction using 500-row query batches.
- Projection backfill updates only `ActiveWorkId`/`ActiveWorkerId` and `WorkflowRunTaskMap`; it leaves `State` and shadow `ETag` unchanged. Terminal runs with historical tasks and empty projections are included; a second run has no candidates.
- Database initialization invokes the backfill after `WorkflowRunStateDataUpgrader`, before the remaining initialization work, so projection reads are available before service startup.
