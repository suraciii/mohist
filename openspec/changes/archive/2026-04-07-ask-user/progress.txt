### T-004: Implement ask_user tool — 2026-04-06T12:00:00Z

**Status:** Completed

**Implementation:**
- Created `packages/cli/src/tools/ask-user.ts` with `createAskUserTool` factory and `resolveQuestion` export
- Module-level `pendingResolvers` Map stores `{ resolve, timer }` entries keyed by question ID
- Factory accepts `{ questionRepo, eventBus, issueId?, projectId?, timeoutMs? }`
- Default timeout: 24h (`24 * 60 * 60 * 1000`)
- On execute: creates question in DB, emits `question_asked`, returns blocking Promise
- On timeout: marks question expired in DB, emits `question_answered` with expired message, resolves with default message
- `resolveQuestion(id, answer)` exported for API handler to call — clears timer, removes from map, resolves Promise
- Tool ID: `ask_user`, parameter: `{ question: string }`
- Typecheck passes

**Learnings:**
- Used `Tool.define` pattern consistent with `spawn-coder.ts`
- Module-level Map (not instance-level) allows `resolveQuestion` to be imported separately by API routes — this is the key design for sharing the resolver between tool and API without a singleton service
- The `issueId` comes from context (set at wiring time in server/index.ts), not from tool parameters — consistent with spawn_coder pattern

### T-005: Create questions API routes — 2026-04-06T13:00:00Z

**Status:** Completed

**Implementation:**
- Created `packages/cli/src/api/questions.ts` with three endpoints:
  - `GET /api/questions?issueId=xxx` - List questions for an issue, ordered by created_at DESC
  - `GET /api/questions/:id` - Get single question detail, returns 404 if not found  
  - `POST /api/questions/:id/reply` - Reply to a question with validation:
    - Validates answer is provided and is a string
    - Returns 404 if question doesn't exist
    - Returns 409 if question is not in pending status
    - Updates DB via QuestionRepo.answer()
    - Calls resolveQuestion() from tools/ask-user to unblock agent
    - Emits question_answered event via EventBus
    - Logs resolution status (warns if no resolver found, which can happen on timeout/restart)

- Updated `packages/cli/src/server/state-manager.ts`:
  - Added QuestionRepo import
  - Initialized questionRepo in constructor
  - Added getQuestionRepo() getter method

- Updated `packages/cli/src/server/index.ts`:
  - Added import for createQuestionRoutes
  - Mounted questions router at /api/questions

**Design Decisions:**
- Used existing `resolveQuestion()` export from tools/ask-user.ts to resolve the Promise
- Reply endpoint emits question_answered event after successful DB update and Promise resolution
- Added appropriate error handling for edge cases (non-existent question, already answered)

**Learnings:**
- The pattern of exporting a standalone `resolveQuestion()` function from the tool module works well for API route integration
- StateManager acts as the dependency injection container, providing repos to routes
- Questions API follows same error response format as other API routes (ApiResponse wrapper)
