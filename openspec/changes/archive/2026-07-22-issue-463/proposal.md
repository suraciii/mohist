## Why

Three independent cross-layer inconsistencies break what users see during and after a follow-up, violating the invariant that one event carries consistent field names, subscription membership, and status semantics across runner, server, and web: the runner emits and the server recognizes follow-up terminal events that the web never subscribes to, so completions/failures silently vanish before reaching the UI; the resolved-model event uses different type names and field names between the OpenCode and Pi runtimes, so Pi sessions never surface their actual model; and a follow-up user input is rendered as a fresh round on the web while the server intentionally excludes it from the session's active-time computation, so the page shows new activity while the session is reported inactive.

## What Changes

- Deliver follow-up terminal events (`session.followup_completed`, `session.followup_failed`) to the web by adding them to the web's canonical transcript event subscription set, and route them to handlers that update session state when a follow-up completes or fails.
- Unify the resolved-model event across runtimes so both the OpenCode and Pi runtimes emit a single server-recognized model-resolution signal carrying one consistent field (`resolvedModel`), make the server read that field consistently in both live-state application and transcript-summary projection, and align the web `model.resolved` live-event contract to the same field, so the web always shows the resolved model name. The OpenCode runner path is already consistent and is not altered.
- Make follow-up user input's activity semantics agree between server and web so a rendered follow-up round and the session's reported active/inactive status can no longer disagree. The mechanism is a design decision (refresh active time on the server, or stop treating follow-up input as a new round on the web), and it must preserve the existing recovery invariant that an idle follow-up lease does not extend the active window, so Compact/Reset remain available immediately after a rejected follow-up.

## Capabilities

- `agent-session-followup-terminal-visibility`: The web subscribes to and reacts to follow-up terminal events so the in-flight follow-up round converges to completed or failed (and the session status is refreshed from the server) when a follow-up finishes or fails, instead of those events being dropped by the server delivery filter.
- `agent-session-model-resolution-event`: The resolved-model event carries one consistent type and field (`resolvedModel`) across the OpenCode and Pi runtimes, server live state, transcript summary, and the web (read model and live-event contract), so the resolved model name is visible for every runtime.
- `agent-session-followup-activity-state`: Follow-up user input has a single activity-state semantics shared by the server's active-time computation and the web's round rendering, so the page and the reported session status agree.

## Impact

- **Web event subscription and routing** (`packages/web/src/shared/lib/canonical-event-types.ts`, `packages/web/src/app/providers/handle-event.ts`): the canonical transcript event set and the dispatch/routing table gain follow-up terminal types and handlers; the subscription/routing compile-time guards must stay satisfied.
- **Web transcript and session display** (`packages/web/src/widgets/session-transcript/*`, `packages/web/src/widgets/coder-session/ui/SessionCard.tsx`, `packages/web/src/entities/agent/model/types.ts`): follow-up terminal handling, the `model.resolved` live-event contract aligned to `resolvedModel`, model-name rendering, and the activity/round rendering path change; follow-up round rendering or status derivation is adjusted for the activity-state agreement.
- **Runner** (`packages/runner/src/runtime/pi/projector.ts`; OpenCode path unchanged): the Pi runtime emits the unified model-resolution signal instead of the `status`/`model` shape the server currently drops.
- **Server session grain and transcript projection** (`packages/server/.../AgentSessionGrain.cs`, `TranscriptEventSummaryProjector.cs`, `TranscriptAccumulator.cs`): model field reading is aligned between live-state application and summary projection; follow-up input activity handling changes according to the chosen mechanism while keeping the recovery invariant asserted by `AgentSessionRecoveryGrainSpecs`.
- **Tests** across `packages/web`, `packages/runner`, and `packages/server`: new and updated coverage for terminal delivery, per-runtime model-name visibility, and follow-up activity-state agreement, with no real network, process, or wall-clock dependencies.
