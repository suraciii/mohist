# Issue 388 — install/update double-entry convergence (T-001)

## Codebase Patterns

- `MohistCliCommands.RunAsync` is the universal test entry point. Production callers leave `installer`/`updater` null; tests inject fakes. Originally only `IOtelQueryExecutor?` was injectable; extended to also take `IServiceInstaller?` and `SourceCodeUpdater?` so install/update specs can be hermetic (no real systemd/Task Scheduler/source rebuilds).
- The default `IServiceInstaller` factory `OperatingSystem.IsWindows() ? WindowsScheduledTaskInstaller : SystemdServiceInstaller` was extracted into `BuildDefaultInstaller` so the platform check still happens lazily when `installer` is null.
- `FakeServiceInstaller` was extended with `Calls`, `InstallServerCalls`, `InstallRunnerCalls` lists. `FakeSourceCodeUpdater` is a new recording fake. Both are `internal sealed` (InternalsVisibleTo already covers the test assembly).
- `CliTestHarness.Create` is a public surface used by ~100 specs. To avoid breaking its tuple shape, a new internal `CreateInternal` was added that returns the same 6-tuple plus a `FakeServiceInstaller`; `Create` and `CreateSync` strip the 7th element before returning.
- `SourceCodeUpdater` was `internal sealed partial class` with non-virtual methods. Made the class non-sealed and the four entry points (`UpdateAllAsync`, `UpdateCliAsync`, `UpdateServerAsync`, `UpdateRunnerAsync`) `virtual` so `FakeSourceCodeUpdater` can override them. All five partial-class declarations needed the same edit (MohistCliCommands.Update.cs/Finalize.cs/Stages.cs/Operations.cs/Outcome.cs).

## Test Patterns

- `CliInstallUpdateSingleEntrySpecs` follows the issue-387 `Legacy*` shape from `CliRootCommandShapeSpecs.cs`: call `MohistCliCommands.RunAsync` on a deleted path, assert `exitCode != 0` AND `installer.Calls`/`updater.Calls` empty.
- Anchored negative assertions (`\n  install `, `\n  update `) used in help-output checks because the literal substring `install` appears inside `uninstall`. Raw `Assert.Contains("install")` / `DoesNotContain("install")` produce false positives on the help table.
- Verb-root unchanged behavior pinned by reading `InstallServerCalls[0]` / `InstallRunnerCalls[0]` and asserting field values match the flag passthrough.
- Update verb-root tests assert the recorded call list equals `new[] { "UpdateAllAsync" }` etc. (single entry) — pinning both that the method ran AND that no other entry points fired.

## Docs

- `docs/cli-reference.md`: dropped the `mo runner install` line in the Runner code block, `mo server install` / `mo server update` lines in the Server code block, the `> 命令路径迁移` note, and the gap-table row tracking the convergence. Cleaned the surrounding prose to remove lingering "无 `mo server install/update` 并存" reference (the spec forbids these strings from the doc). Renamed the gap section to just "## 实装差距" since the only remaining line is "no gaps".
- `CliReferenceDocsSpecs.forbiddenLegacyPathRows` extended with `mo server install`, `mo server update`, `mo runner install`, and an explicit `Assert.DoesNotContain("命令路径迁移", doc)` to pin the migration-note removal.

## Gotchas

- `SourceCodeUpdater` is sealed and methods are non-virtual — overriding was needed for the test fake. Trivial production impact: five `sealed partial` → `partial` edits and four method modifiers.
- Help-output Contains("install") flips to DoesNotContain look trivial but trip on the substring embedded in `uninstall`. Always anchor help-table assertions on `\n  <name> ` to avoid this class of false positive.
