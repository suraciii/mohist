## Codebase Patterns

- Server persistence uses `MohistDbContext` with explicit row mappings and migration-chain SQLite templates in SpecTests.
- Project-scoped API groups resolve the project through `ProjectResolutionEndpointFilter`; API errors use `ApiResults` and stable `Code` values.
- Agent state is stored as JSON in `AgentRow`; `AgentQuerier.GetByIdAsync` is the existing project/status lookup used for routing-rule validation.
- Event match validation uses `EventMatchExpression.Compile`, whose `MatchDiagnostic` contains offset, line, and column. The API reuses the `invalid_match_expression` code and exposes these fields.

## T-003

- Replaced the wildcard subscription dispatch handler with `RoutingDispatchHandler`; dispatch resolves the envelope project, loads only that project's active ordered rules, evaluates through `RoutingTableEvaluator`, and launches each executable outcome with event/rule trigger labels.
- Renamed launcher idempotency and generic-session trigger metadata from subscription id to rule id, including `AgentSessionQuery`, `AgentSessionRow`, EF mapping, and the session computed-column rename migration.
- Removed the obsolete arbitration unit test and updated service/launcher/session test references to the new names. The legacy subscription resource remains for T-006 removal.
- Runtime expression failures are represented as matched-but-skipped outcomes so dispatch logs them and continues without allowing them to stop table evaluation.
