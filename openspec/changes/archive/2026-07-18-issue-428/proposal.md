## Why

When a session is running, the only live signal on the page is a single streaming dot pinned to the very bottom of the transcript. To know what the agent is doing right now the reader must scroll all the way down and hunt through a wall of rows for the one spinner; the moment they scroll back up to read earlier output, they are blind to current activity and to how long the current step has been running. This issue gives the session page a real-time sense of progress — a live-ticking duration on the running tool row, a persistent "current activity" bar that stays visible regardless of scroll position, a block cursor on text being streamed, and an elapsed timer on the thinking state — so the reader always knows, from any scroll position, what is happening and for how long. It is purely additive presentation: it consumes the row anchor established by #427 (`data-tool-call-id`) and the liveness gate established by #426 (`isRunning`), and changes no data flow, event protocol, or state derivation.

## What Changes

- **Running tool rows show a live-ticking duration.** A tool row whose state is `pending` or `running` displays an elapsed duration derived from its `startedAt` and the current wall-clock, updated every second (e.g. `4.7s`). On transition to `completed`/`failed`/`cancelled` the duration freezes at the finalized `startedAt → completedAt` delta. This relaxes the #427 rule that running rows SHALL NOT display a continuously updating timer; that rule is superseded for the in-progress case only.
- **Persistent "current activity" bar at the transcript bottom.** While the session is alive, a slim status bar is pinned to the bottom of the transcript viewport showing the title of the currently-executing tool call and its live elapsed duration. The bar remains visible at every scroll position. Clicking the bar scrolls the corresponding tool row into view (located via its stable `data-tool-call-id`). When the session is not running, the bar is absent.
- **Block cursor at the end of streaming assistant text.** While the session is alive and an assistant text part is incomplete or actively streaming, a blinking block cursor is rendered at the end of the streamed text, signalling "writing here". This replaces the current trailing dot glyph as the in-stream visual; the liveness gate from #426 still applies.
- **Thinking indicator shows elapsed wait time.** While the session is alive and in the thinking state (no visible content yet, or a reasoning part is open), the thinking indicator displays the elapsed time since the thinking state began, updated every second.
- **No change to data flow or state derivation.** No event-protocol, transcript data-model, liveness-gate, or collection-pipeline change. The session liveness signal (`isRunning`) and the streaming/thinking flags are consumed as-is from the existing data source; this issue does not re-derive or re-gate them.

## Capabilities

- `transcript-live-tool-duration`: How the duration displayed on a tool row behaves across the tool's lifecycle. Requires a running/pending row to render an elapsed duration that ticks every second from the row's `startedAt` against the current wall-clock, and a completed/failed/cancelled row to freeze at the finalized delta. Owns the relaxation of #427's "no live timer on running rows" rule, scoped strictly to the in-progress state.
- `transcript-current-activity-bar`: The persistent bottom-of-transcript status bar that summarizes the currently-executing tool call. Requires it to render only while the session is alive, show the active tool's title and live elapsed duration, remain visible across all scroll positions, and on activation scroll the corresponding tool row (located by `data-tool-call-id`) into view.
- `transcript-streaming-cursor`: The block-cursor visual at the end of an assistant text part that is incomplete or actively streaming. Requires it to render only while the session is alive and the part is open, to be removed once the part completes or the session ends, and to be hidden from assistive tech as a decorative cue.
- `transcript-thinking-elapsed`: The elapsed-time display on the thinking indicator. Requires it to render only while the session is alive and in the thinking state, tick every second from the thinking-state start, and freeze/disappear when the session leaves the thinking state or ends.

## Impact

- **Web (`packages/web/src/widgets/session-transcript/`)** — primary surface, presentation layer only:
  - `ui/tool-views/index.tsx` (`ToolRowView`) — render a ticking duration in the `pending`/`running` state (today the duration is gated behind `!isRunning`); freeze on completion. Reuses the existing `data-tool-call-id`/`data-tool-state` anchors from #427.
  - `ui/AssistantParts.tsx` (`AssistantTextPartView`) — render a block cursor at the end of the streamed text while live (replacing/augmenting the current trailing dot glyph).
  - `ui/SessionTranscriptLayout.tsx` (`ThinkingPlaceholder`) — render an elapsed timer on the thinking indicator.
  - A new current-activity bar component (e.g. `ui/CurrentActivityBar.tsx`) and a small model helper to derive the active tool from `displayTurns` (last `pending`/`running` tool part) plus a `useNow(intervalMs)` ticking hook. The hook MUST be time-injectable per `design/testing.md` (no wall-clock in tests).
- **Web (`packages/web/src/pages/session/ui/SessionDetailShell.tsx`)** — mount the current-activity bar inside the transcript scroll region so it stays visible across scroll positions; thread the existing `isRunning`/`isThinking`/`isStreaming` flags plus `displayTurns` (already on `SessionDataSourceResult`) into the transcript layout. No new data-source fields.
- **Time-injection convention** — the new ticking hooks/utilities must accept an injectable clock (`now()` provider or `vi.useFakeTimers`) so unit specs stay deterministic and fast (unit < 50ms, spec < 500ms per `design/testing.md`); no `while (now < deadline)` or `elapsed < N` assertions.
- **Tests (`packages/web`)** — new unit/spec coverage for: live duration ticking and freeze, current-activity bar visibility/scroll-jump, block-cursor liveness gating, thinking-elapsed ticking. The liveness gate itself is owned by #426 and not re-tested here beyond consumption.
- **Server / Runner / CLI / events / protocol / dependencies**: none.
- **Risk (low)**: purely additive presentation; consumes the existing stable row anchor (#427) and liveness gate (#426) without modifying either; mitigated by keeping all new behavior behind the existing `isRunning` flag and the row's existing `data-tool-call-id`.
