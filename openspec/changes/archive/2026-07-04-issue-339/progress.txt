# Issue-339 (Phase 3b) — Working Memory

## Codebase Patterns

- **TaskProgressPanel projection is in `packages/web/src/widgets/issue-workflow/ui/TaskProgressPanel.tsx:230-244`** — currently drops `sessionName` and `classification`; the mirror in `WorkflowView.tsx:152,165` retains both. The mirrored projection must add `sessionName: task.sessionName`, `classification: task.classification`, and keep the existing `origin` (already carries `uses`).
- **TaskLogPanel props** currently `{ issueNumber, taskId, workflowRunId?, taskStatus? }`. We extend with `sessionName?: string | null`, `origin?: { uses?: string } | null`, `classification?: string | null`. The actual call site is `TaskProgressPanel.tsx:173` — must pass all three.
- **`WorkflowRunSession` shape** (entities/coder-session/model/types.ts:149-170): carries `sessionName`, `status`, `model`, `createdAt`, `startedAt`, `completedAt`, `failureReason`, `eventSummary.resolvedModel`, `usage`. `status` is `string` (free-form). `failureReason` is `string | null`.
- **`useWorkflowRunSessions(workflowRunId)`**: returns `{ sessions, isLoading }`. Query key `['workflow-runs', workflowRunId, 'sessions']`. Lives at `entities/coder-session/model/useWorkflowRunSessions.ts`. Already used by `WorkflowView` so the query is warm on the same page.
- **Agent task identification**: `origin.uses === 'mohist/acp-agent'` + non-empty `sessionName`. Pure ops tasks are `mohist/rebase`, `core/process`, etc. — they don't have `sessionName`.
- **Distinct visual marker**: design D9 says "non-color-only marker with accessible name." The chosen glyph for the marker element is `Diamond` from lucide-react (filled diamond + `aria-label="Session event"`); chips and ops sources use sky/slate. The marker uses distinct color class `border-violet-400/40 bg-violet-400/10` plus a meaningful label prefix like `Model bound` / `Session ended`.
- **Existing timestamp format for ops rows**: `<HH:MM:SS.mmm>`. Milestones reuse the same `formatTimestamp(iso)` to preserve chronology look-and-feel.
- **Source chips stay ops-only** — keep the `sources` memo deriving from `lines`, never from `milestones`.
- **Download export** currently emits `line.text` joined with `\n`. With milestones we emit a per-row line plus an extra `[session] <label>: <detail>` line in timestamp order, kept inside the filtered view (Phase 3a semantics).
- **Test fixtures**: `WorkflowArtifacts.test.tsx:92,118` already uses `uses: 'mohist/acp-agent'`. `useWorkflowRunSessions.test.tsx` mocks both `getWorkflowRunSessions` and `onAgentEvent`. `TaskLogPanel.test.tsx` mocks `getIssueWorkflowTaskLog` and the SignalR `HubConnectionBuilder`.

## Open Decisions (resolved during implementation per design leans)

- Status wording: raw `status` verbatim (e.g. "completed" or "failed") — no label mapping.
- Marker glyph: filled diamond via `lucide-react`'s `DiamondIcon`, `aria-label="Session event"`, plus a `human-friendly icon-only <span>` data-testid `task-log-milestone-marker`.
- failureReason rendering: inline in the `detail` span with `whitespace-pre-wrap` so multi-line reasons are visible without truncation.
- Model milestone: show only `eventSummary.resolvedModel ?? model` (no dual rendering of requested vs resolved).

## Gotchas worth noting for downstream steps

- The `WorkflowRunSession.createdAt` field is non-nullable in the wire type (`string`); the design talks about `createdAt` as a fallback anchor but `startedAt ?? createdAt` is the practical anchor pair. If both are ever missing on a finished session, the model-bound milestone is skipped — but persistence guarantees `createdAt` is set.
- The merged `TimelineRow[]` uses lexicographic ISO timestamp sort with a tie-breaker that places ops lines before milestones at the same timestamp (mirrors "stable concatenation" from D7). Within ops lines, seq order is preserved.
- The `useWorkflowRunSessions` hook must be called unconditionally (Rules of Hooks); we gate the `workflowRunId` argument to `null` for non-agent tasks so the underlying React Query is disabled (`enabled: !!workflowRunId`).
- The DiamondIcon is rendered with `role="img"` + `aria-label="Session event"` so the scoped axe `aria-roles` rule sees a labeled img.
- The download filename stays `task-logs-<taskId>-<isoDate>.txt`; only the payload changed. Phase 3a used `line.text` joined; milestones emit `<timestamp> [session] <label>: <detail>`. Ops lines still export just `text` to stay Phase 3a-compatible.
- For ops task with empty sessionName, `isAcpAgentTask` returns false; for an agent task with empty sessionName, also false. Either way no milestones — and `useWorkflowRunSessions` is short-circuited.
