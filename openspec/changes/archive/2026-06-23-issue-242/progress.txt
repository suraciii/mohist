## Codebase Patterns

- IssueRoutes.Sessions.cs is a `public static partial class IssueRoutes` with `MapIssueSessions(RouteGroupBuilder group)` extension. Pattern: each handler takes `HttpContext ctx` and resolves project via `GetRequiredProject(ctx)`.
- Errors use `ApiResults.Ok(...)`, `ApiResults.NotFound(...)`, `ApiResults.Conflict(...)`, `ApiResults.BadRequest(...)` — returns `IResult`.
- `AgentSessionQuerier` reuses private `FindCurrentSessionAsync(db, projectId, issueNumber, sessionName, ct)` that returns `AgentSessionRecord?`. The record exposes `Row.RunnerId`, `Row.AgentSessionId`, `Session.Status.AgentRuntimeSessionId`, `Session.Status.LastDataAt` (used by `AgentSessionJsonHelper.StatusName`), and labels via `Label(record, key)` (from record's `Labels` dictionary; falls back to `Session.Metadata.Label(key)`).
- `RunnerConnectionTracker` is a singleton with `Register(runnerId, connectionId)`, `Unregister`, `GetConnectionId(runnerId)` returning `string?`.
- SignalR push for runners uses `IHubContext<RunnerHub>` (not `<RunnerHub, IRunnerClient>`). `Clients.Client(connectionId).SendAsync(method, payload)` is fire-and-forget — no throw on missing connection.
- `RunnerHub` is registered with runnerId from query string in `OnConnectedAsync`; the tracker is updated automatically when a runner connects.
- Tests use `MohistIntegrationFixture` (collection `MohistIntegration`). Helper `OpenRunnerSessionAsync` posts to `/api/runner/{runnerId}/sessions/{projectId}/{workflowRunId}/{sessionName}/open` to create sessions. To make a session "active", tests POST to `.../attach` with `agentSessionId`.
- Tests can directly `new RunnerConnectionTracker().Register(runnerId, connId)` but here we'll use the live `RunnerConnectionTracker` singleton via DI.
- StatusName returns "active" iff `AgentRuntimeSessionId != null && LastDataAt != null && (now - LastDataAt) <= 5min`. The `AttachPhysicalSessionAsync` endpoint sets both `AgentRuntimeSessionId` and `LastDataAt` to `now`, so simply calling `/attach` makes the session active.
- HttpClient test extension helpers: `PostOkAsync`, `PostDataAsync<T>`, `GetRawAsync`. POST JSON body: `client.PostAsJsonAsync(path, body)`.

## Task T-001 Notes

- `ResolveFollowupTargetAsync` reuses `FindCurrentSessionAsync`. Returns `FollowupTarget?` — null if session not found; otherwise `(RunnerId from row, WorkflowRunId from label, SessionName from label, IsActive)`.
- Endpoint handler validates text first (400), then calls querier (404), checks IsActive (409), then checks tracker (503), then pushes via `Clients.Client(connId).SendAsync("ReceiveFollowup", new { workflowRunId, sessionName, text })`.
- Return shape: `{ status: "sent" }` per spec.
- Tests: 200 success + body shape; 400 for empty/whitespace/missing; 404 for unknown session; 409 for inactive session; 503 for offline runner.

## Task T-002 Notes

- `FollowupTarget` extends the spec's required fields with `projectId` so the runtime-events POST can be made without `ActionContext` (which is only populated inside workflow work-item execution).
- `FollowupTargetResolver` is a closure passed from `RunnerHost` (the only place that has both `sessionManager` and `sharedAcpConnection`). `SharedAcpConnection` is null at construction time and lazily initialized in `initializeSharedConnection`, so a callback is the only way to read it at handler invocation time.
- The runtime-events POST body for followup carries `kind: "followup"` (consumed by `TranscriptAccumulator.CaptureInput` via `AgentSessionJsonHelper.GetStringProp(payload, "kind")`) plus `source: "followup"` and `role: "user"` so server-side attribution is unambiguous.
- `connection.prompt({ sessionId, prompt: [{ type: "text", text }] })` is fire-and-forget: `void ... .catch(...)` so the SignalR receiver returns immediately even if opencode's runner is mid-turn (its `Runner.ensureRunning` blocks the second prompt caller — the message has already been written to DB by `createUserMessage` before the block).
- `AbortSignal` for the runtime-events POST uses a fresh `AbortController().signal` because the SignalR receiver does not propagate one and we want the event to fire even if the runner is shutting down.
