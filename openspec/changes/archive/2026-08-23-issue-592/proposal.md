## Why

The unified session page (`UnifiedSessionPage` + `widgets/session-transcript`) replaced the earlier issue-scoped coder-session UI, but the superseded layer was never removed. Today `widgets/coder-session` still ships a complete dead component chain (SessionCard family, SessionTimeline, PlanProgressPanel, compaction entries, its own `useSessionTimeline`/`session-timeline-reducer`), `entities/session` still ships SessionEvent chat/compact/timeline view projections whose only consumer is that dead chain, and `entities/coder-session`/`entities/agent` still export issue-scoped and generic session client functions no production code calls. On top of that, `pages/session/data/SessionDataSource.ts` re-declares the data hook's return shape as a hand-written interface that has already drifted — fields no consumer reads plus three fields (`siblingNav`, `siblingSidebar`, `issueTitle`) whose only implementation fills them with constants while the page shell still destructures and renders them.

Beyond the session surface, web carries the same rot in shared UI: an old markdown renderer (`markdown-content.tsx`) with zero production references, a self-built toast system (`shared/ui/toast`) that is mounted in `App.tsx` but never fed — every production toast goes through sonner — three viewport-detection hooks where one suffices, a `MarkdownReader` dragging three never-enabled presentation toggles and their helper modules, and no written convention for how entity queries are written. This dead surface slows every session change, keeps obsolete API shapes alive as if they were alternates, and violates the repo rule of removing obsolete paths instead of keeping them.

## What Changes

- Delete the dead `widgets/coder-session` component chain: `SessionCard.tsx` (ActiveSessionCard / RecentCard / WaitingCard), `model/anomaly.tsx`, `SessionTimeline.tsx`, `PlanProgressPanel.tsx`, `session-health/CompactionTimelineEntry.tsx`, `session-health/CompactionCompactSummary.tsx`, `model/useSessionTimeline.ts`, and `model/session-timeline-reducer.ts`. Keep the still-consumed exports (activity events, usage snapshot, SessionFollowupComposer, SessionRecoveryActions, ContextHealthBar, UsageSnapshotLabel).
- Delete the SessionEvent view projections in `entities/session`: `model/view.ts` (`viewSessionEvents`), `model/view/{chat,compact,timeline,helpers}.ts`, the `SessionEvent` / `SessionView*` type family, and their re-exports (`index.ts`, `@x/session-view.ts`). The live timeline projection (`model/timeline/*`, used by `widgets/session-transcript`) stays untouched.
- Delete session data-layer code with no production consumers: `useCoderSessions`, `useFollowupMutation` + `postFollowup`, `useStopSessionMutation` + `stopSession`, and the issue-scoped client functions `getCoderSessions`, `getAgentSessionMetadata`, `getAgentSessionTranscript`, `getAgentSessionEvents` in `entities/coder-session`; `canRecoverSession` / `deriveSessionActivity` in `sessionActivity.ts`; `buildGenericSessionMetadata.ts` in `pages/session/data`; and the duplicated generic-session summary/transcript client functions and hooks (`getGenericSessionSummary`, `useGenericSessionSummary`, `getGenericSessionTranscript`, `useGenericSessionTranscript`, their query options, `GenericAgentSessionSummaryDto`) in `entities/agent`. Types used only by deleted code are removed with it. These data-layer deletions go beyond the issue's five enumerated groups but are verified production-dead and in the issue's deletion spirit; they are an explicit scope addition, not silent drift.
- Replace the hand-written `SessionDataSourceResult` / `SessionTurnControlHandle` interfaces with the concrete return type of `useUnifiedSessionDataSource` (inferred, not re-declared), so `SessionDetailShell` and tests consume the hook's actual shape and fields without consumers disappear from the contract. Together with the interface, stop returning the three always-empty fields (`siblingNav`, `siblingSidebar`, `issueTitle`) and delete the shell's destructuring and empty-render branches for them (header title slot, narrow-viewport sibling-nav slot, sibling sidebar slot), as the issue's group 3 requires.
- Delete the retired markdown renderer and the self-built toast system: `shared/ui/components/markdown-content.tsx` (+test) has zero production references and goes; `shared/ui/toast/` (`RuntimeToastHost`, its context, test, and index) is unmounted from `app/App.tsx` and deleted — sonner (`Toaster` in `AppContent`) remains web's only toast system, and the test scaffolding that kept the dead host alive (toast-host wrappers, transport-notice probes) is pruned with it.
- Converge viewport detection on one hook: delete `shared/lib/use-narrow-viewport.ts` and `shared/hooks/use-mobile.ts`, repoint `IssueDetailPage` and `shared/ui/components/sidebar.tsx` at `useMediaQuery` (the surviving hook). Strip `MarkdownReader`'s three never-enabled toggles (`showToc`, `showHeadingAnchors`, `showCopyCode`) together with what they drag in: `copy-code-button.tsx`, the table-of-contents component, and the anchor/slugger machinery in `heading-remap.tsx` — base heading-level remapping, attachments, tables, and collapsible mode stay.
- Document the query dual-write convention for entity query clients in `packages/web/AGENTS.md`: every server read is written twice — an exported query-options factory owning the query key and fetch, plus a thin hook wrapping `useQuery` over that factory — with the unified session clients as the reference implementation. Documentation only; older query modules that predate the convention are follow-up cleanup.
- Remove tests that cover deleted code only, and prune slice public APIs (`index.ts`) of the removed exports.
- No user-visible behavior changes, no server/runner API changes, no dependency changes.

## Capabilities

- `session-detail-data-source`: The session detail page's single data path — the unified session data hook whose inferred concrete return type is the contract between `pages/session/data` and `SessionDetailShell`; covers that web has exactly one session-detail data source (unified session summary/transcript + generic followup/turn control) with no parallel hand-written interface, no always-empty fields or their empty-render branches in the shell, and no orphaned issue-scoped or generic session client duplicates.
- `session-transcript-timeline`: The surviving production session presentation projection — session turns and live events reduced to timeline facts, items, and grouped entries (`entities/session/model/timeline` consumed by `widgets/session-transcript`); covers that this is the only session-event projection in web after the SessionEvent chat/compact/timeline view builders and their types are removed.
- `web-client-conventions`: Web's shared client-side conventions — exactly one toast system (sonner), one markdown renderer carrying no dead presentation toggles, one viewport-detection hook (`useMediaQuery`), and the documented entity-query dual-write convention (options factory + thin hook) in `packages/web/AGENTS.md`.

## Impact

- **`packages/web` only.** Touched slices: `widgets/coder-session` (component deletions plus index pruning), `entities/session` (view projection deletion, `@x/session-view.ts`), `entities/coder-session` (hooks, client functions, activity helpers, types), `entities/agent` (generic session summary/transcript duplicates), `pages/session` (data source typing, `buildGenericSessionMetadata.ts` removal, shell branch deletion), `shared/ui` (`markdown-content.tsx`, `toast/`, `markdown-reader/` toggle strip), `shared/lib` + `shared/hooks` (viewport hook convergence), `app/App.tsx` (toast host unmount), `pages/issue-detail` (viewport hook repoint, toast test pruning), plus `packages/web/AGENTS.md` (query convention documentation).
- **Tests:** delete unit/dom tests of removed code (SessionCard, SessionTimeline, session-health compaction views, session view projections, dead hooks and client functions, markdown-content, RuntimeToastHost, MarkdownReader affordance legs, the shell sibling-nav dedup spec — the deleted viewport hooks have no dedicated tests); prune toast-host wrappers/probes in `events-hub.test.tsx`, `IssueDetailPage.test.tsx`, and `tests/live-task-cloud-event.spec.tsx`; `SessionDetailShell` tests switch their `data` prop to the concrete hook return type.
- **APIs/dependencies:** none — server endpoints, runner, and CLI are untouched; deleted web client functions simply stop existing (their server routes remain for other consumers). Sonner stays the toast dependency; the self-built host had no production feeder to migrate.
- **Scale:** whole-file deletions alone total ≈7,100 lines (session chain + view family + data layer + shared-UI parallels) before index pruning and in-place edits, comfortably clearing the issue's ≥2,500-line net-reduction bar.
- **Risk:** low — deletions are provably unconsumed in production; the behavioral surfaces are the session page data contract (stricter: unused and always-empty fields fall away), the unmount of a never-fed toast host, and viewport repointing onto semantically equivalent media queries.
