## Codebase Patterns

- **Runner entity / hooks**: `entities/runner` exports `useRunners()` (`packages/web/src/entities/runner/api/queries.ts:6`), `RunnerStatusRow` (`entities/runner/model/types.ts:20`), and `getRunners`. `useRunners()` reads `projectId` from `useProject()` and sets `enabled: !!projectId`, so the runner query is **automatically suppressed** when no project is selected — components should rely on that rather than short-circuiting manually. Query key is `['runners', projectId]` with a 5s `refetchInterval`.
- **Runner widget shape**: `widgets/runner-status` exports `RunnerList` and `RunnerListCard`. `RunnerList` renders rows inline (id, kind, status badge, scope badge, hostname, heartbeat freshness, capacity `used/total slots`) and its own `RunnerEmptyState` when `rows.length === 0`. It hides capacity when `row.capacity` is null (does **not** show `0/0 slots`). `RunnerListCard` wraps it with a TanStack Query call.
- **Project route scope**: `App.tsx:55` mounts `ProjectRouteScope` under `/:projectName`, with child routes for `issues`, `activity`, `runners`, `settings/...`, etc. `primaryNav` entries in `AppSidebar.tsx` get prefixed with the project name via `useProjectPath()` at render time, so nav items just hold the project-relative `to`.
- **Test runner**: vitest hangs in `vitest run` mode in this repo's default config — use `npx vitest run --no-watch <path>` with `timeout` shell wrapper, or pipe output to a file. `basic` reporter isn't installed; use default reporter or `verbose`.
- **Vitest test environment**: Web tests are jsdom-based and declare it via `// @vitest-environment jsdom` at the top of the file. They expect `@testing-library/jest-dom` and React Query `QueryClientProvider` to be wrapped manually per test.
- **Pre-existing test failures (orthogonal to T-001)**: `MarkdownReader.test.tsx` (4 ResizeObserver teardown failures) and `AgentSettingsSection.test.tsx` (1 field-level validation test). Confirmed by `git stash` baseline run — not caused by T-001 work.
- **CLI `IEnvironmentVariableProvider` seam**: `MohistCliCommands.RunAsync(http, args, output, error, fileSystem, executor, environment, standardInput)` accepts an `IEnvironmentVariableProvider?` parameter (defaults to `SystemEnvironmentVariableProvider.Instance`). It is registered in the built `ServiceProvider` so commands can resolve it via `provider.GetService<IEnvironmentVariableProvider>()`. Server-side tests that build their own `ServiceCollection` (e.g. `SkillsCommandRegistrationSpecs.BuildRootCommand`) do not register it — when adding new commands that resolve it, use `provider.GetService<IEnvironmentVariableProvider>() ?? SystemEnvironmentVariableProvider.Instance` so the missing registration is non-fatal.
- **CLI `MohistCli.Api.RunnerScopeFilter` enum**: lives on `MohistCliApi` so the renderer, command, and tests can all share the same scope vocabulary. Filter strings ("all"/"global"/"project") are parsed in `RunnerCommands.ParseScopeFilter` with `OrdinalIgnoreCase` and the server payload is filtered by `scope.type` (string compare) client-side.
- **TableRenderer color gating**: `TableRenderer.Render(JsonNode?, TableShape, bool colorEnabled = true)` — the `colorEnabled` flag is honored only by `RenderRunnerList`; all other shapes ignore it. The status cell is the only one that embeds ANSI escapes (`\u001b[32midle\u001b[0m`, `\u001b[34mbusy\u001b[0m`, `\u001b[33mstale\u001b[0m`, `\u001b[2moffline\u001b[0m`). When the cell exceeds the column width, `Truncate` cuts raw chars — so the `status` column needs `≥ 16` chars to fit `ESC[2mofflineESC[0m` without truncating the reset. Keep that in mind for any future colored cell.

## Task T-002: CLI: `mo runner list` subcommand with scope filter and color-coded status

- **What was implemented**
  - New `list` subcommand under the existing `mo runner` group (`packages/cli/Mohist.Cli/MohistCliCommands.Server.cs` → `RunnerCommands.BuildList`). Wires `MohistCliCommands.ProjectRefOption()` (`--project`/`--project-id`), `MohistCliCommands.OutputOption()` (`-o table|json`), and a new `--scope all|global|project` option (default `all`). Resolves the project via `api.ResolveProjectIdAsync`, validates the output mode, computes `colorEnabled` from `Console.IsOutputRedirected` AND `NO_COLOR`, then calls a new `api.PrintRunnerListAsync(...)`.
  - New `MohistCliApi.PrintRunnerListAsync(projectId, RunnerScopeFilter scope, string mode, bool colorEnabled)` method (in `MohistCliApi.cs`). This is the dedicated fetch+filter+render flow per design D4: it `GET`s `/api/projects/{id}/runners`, extracts `data.runners`, filters by `scope.type` client-side, and renders. JSON mode emits the filtered array verbatim (empty `[]` for the JSON empty case). Table mode with zero rows prints "No runners connected" + "Start a runner: npx mohist runner" hint.
  - New `MohistCliApi.TableShape.RunnerList` enum entry. `TableRenderer.RenderRunnerList(JsonNode? data, bool colorEnabled)` renders the 7-column table (id, kind, status, scope, capacity, heartbeat, hostname) with color-gated status cell. Capacity renders as `used/total slots` when present and `-` when null (no `0/0` for missing capacity per acceptance). Heartbeat renders a relative age ("3m ago") matching the web's `formatHeartbeatAge`. The status column is the only place ANSI escapes are embedded.
  - `MohistCliApi.RunnerScopeFilter` enum (`All`, `Global`, `Project`) added so the command, API, and renderer share one vocabulary.
  - `RunnerCommands.Build` now resolves `IEnvironmentVariableProvider` from the DI provider with a `SystemEnvironmentVariableProvider.Instance` fallback (so server-side `SkillsCommandRegistrationSpecs.BuildRootCommand`, which builds its own `ServiceCollection` without that service, still works).
  - 16 xUnit tests in `packages/cli/tests/Mohist.Cli.Tests/CliRunnerCommandSpecs.cs` covering: `mo runner --help` lists `list`; default scope returns both global and project runners; `--scope global` filters out project; `--scope project` filters out global; `--project <name>` overrides project; full column set present; missing capacity renders `-` not `0/0`; `NO_COLOR` set → no escapes; `colorEnabled: true` → 4 distinct ANSI codes per status; `-o json` → valid JSON, no color, no borders; empty result → start hint, no empty table; `--scope project` empty JSON → `[]`; server down → standard "Server is not running" + non-zero; invalid `--scope` → error, no API call; no active project → standard error; `colorEnabled: false` via direct API call → no escapes.

- **Files changed**
  - `packages/cli/Mohist.Cli/MohistCliApi.cs` (new `TableShape.RunnerList` enum entry, new `RunnerScopeFilter` enum, new `PrintRunnerListAsync` method, new `RunnerStartHint` constant)
  - `packages/cli/Mohist.Cli/TableRenderer.cs` (new `RenderRunnerList` method + `FormatScope`/`FormatCapacity`/`FormatHeartbeat`/`ColorizeStatus` helpers + ANSI constants; `Render` dispatch extended to accept `bool colorEnabled`)

- **Learnings for future tasks**
  - **Decisions**
    - The dedicated fetch+filter+render flow is in `MohistCliApi.PrintRunnerListAsync`, not the generic `PrintWithOutputAsync`. Per design D4 the generic helper has no pre-render transform step, and scope filtering is a data concern that must run before the renderer sees the array.
    - Scope filtering is purely client-side over `data.runners[i].scope.type`. No new query param, no new endpoint — consistent with the Web page's existing `filterByScope` behavior.
    - `RunnerScopeFilter` lives on `MohistCliApi` (not in the command or renderer) so all three layers reference the same enum and tests can pass it without re-parsing the string.
    - Status derivation stays server-side. The renderer reads `status` as a string, colorizes it, and never re-derives. This satisfies the spec's "shared four-value status taxonomy" requirement.
    - Capacity rendering: `null` capacity → `-`. `RunnerStatusView.capacity` is nullable, and the design notes (Risks) call out that the CLI must mirror the Web's "unavailable rather than 0 used slots" behavior. Confirmed via test.
  - **Gotchas discovered**
    - **`Truncate` cuts ANSI escapes mid-sequence** — `TableRenderer.Truncate(value, softCap)` slices by char count, so a colored status like `\u001b[2moffline\u001b[0m` (15 chars) gets truncated if the column width is ≤14. The status column was bumped from 12 to 16 chars to fit `offline` (the longest) with escapes. If a future colored cell is added, account for the escape length when sizing the column.
    - **`Console.IsOutputRedirected` is always `true` under xunit** — the xunit test runner captures `Console.Out`, so any test of the command-path `colorEnabled` decision will see `IsOutputRedirected == true` and never emit colors. Two test strategies were used: (a) full command-path tests for the `NO_COLOR` case (which is controlled by the env provider and bypasses the redirect check), and (b) direct `MohistCliApi.PrintRunnerListAsync(..., colorEnabled: true)` calls to verify the colored renderer's ANSI emission regardless of `Console` state. The direct-API test is the only one that proves the color codes are present in the table-mode output.
    - **Server tests build their own `ServiceCollection`** — `Mohist.Server.Tests/Specs/Skills/SkillsCommandRegistrationSpecs.BuildRootCommand` constructs a `ServiceCollection` and never registers `IEnvironmentVariableProvider`. Resolving it via `GetRequiredService` crashes those tests. Use `provider.GetService<IEnvironmentVariableProvider>() ?? SystemEnvironmentVariableProvider.Instance` for any new command that needs env access.
    - **`Mohist.sln` does not include `Mohist.Cli.Tests`** — the project is not in the .sln file, so `npm test` (which runs `dotnet test Mohist.sln`) does not run the CLI tests. CLI tests must be invoked separately: `dotnet test packages/cli/tests/Mohist.Cli.Tests`. The build (`dotnet build Mohist.sln`) does pick up the CLI project, so `TreatWarningsAsErrors` lint is enforced via that path.
  - **Patterns / API shapes established**
    - **`MohistCliApi.PrintRunnerListAsync(projectId, scope, mode, colorEnabled)`** — signature. Returns `0` on success, `1` for missing project / server down / scope error. JSON mode emits the filtered array verbatim (always, even when empty `[]`). Table mode with zero rows prints the start hint and returns `0`; table mode with rows delegates to `TableRenderer` with `colorEnabled`.
    - **`TableRenderer.RenderRunnerList` column set** — `id` (IdSoftCap=24), `kind` (12), `status` (16), `scope` (16), `capacity` (14), `heartbeat` (18), `hostname` (TitleSoftCap=60). Headers are the lowercase form. `scope` resolves to `global`, the project name, the project id, or `project` (in that preference order). `capacity` formats as `"<used>/<total> slots"` or `-` when the input is null. `heartbeat` formats as `"<n>s ago"` / `"<n>m ago"` / `"<n>h ago"` / `"<n>d ago"`, or `unknown` when `lastHeartbeatAt` is null/invalid.
    - **`colorEnabled` parameter is plumbed end-to-end**: the command decides based on `Console.IsOutputRedirected` AND `NO_COLOR` env, the API forwards it to the renderer, the renderer only uses it for the status cell. Other cells stay plain. This keeps the gating decision in one place while letting tests control it directly.
    - **Test data fixture shape**: `CliRunnerCommandSpecs.Runner(id, kind, hostname, status, scopeType, capacity, projectId?, lastHeartbeatAt?)` builds a complete `RunnerStatusView`-shaped object so tests cover the same wire format the server emits.
- **Cross-task invariants**
     - The four-status taxonomy (`idle` / `busy` / `stale` / `offline`) is the contract boundary shared with the Web page (T-001) and the server. The CLI renderer must not invent a fifth visual value or re-derive a status from runtime fields.
     - `--scope project` correctness depends on the server's `ListEligibleRunnersAsync(projectId)` invariant that no foreign-project runners leak. The CLI does not double-filter by `projectId`; it trusts the server. (A defensive server test exists at `RunnerRegistrySpecs.ListEligibleRunnersAsync_OtherProjectRunner_IsExcluded`.)
     - The runner start hint text (`npx mohist runner`) is shared with the Web widget and the Runners page. Keep all three in sync if the runner bootstrap command ever changes.
