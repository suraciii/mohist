# Issue #170 — Dashboard Recent Digest progress notes

## Codebase Patterns

- **Test file naming for entity libs**: tests with React/JSX must be `.tsx`. `recent-digest.test.ts` failed typecheck because `makeWrapper()` returns JSX; rename to `.tsx` (matches `completion-snapshot.test.ts` precedent only when JSX is involved — that one stays `.ts` because it doesn't include JSX).
- **Entity lib style** (`entities/issue/lib/completion-snapshot.ts`): pure function + React hook in same file, tests in sibling file. Pure function takes data + `now` for determinism; hook wraps `useIssues` and memoizes.
- **Hook signatures**: `useIssues(params?)` and `useArchivedIssues(params?)` return `{ data?: Issue[], isLoading: boolean, ... }`. `data` is `undefined` until first fetch resolves. Always coerce with `?? []` before passing into pure derivation to keep types clean (`NoInfer<Issue[]> | undefined` is not assignable to `readonly Issue[]`).
- **Widget structure**: `widgets/<feature>/{ui,model}/` + root `index.ts` that re-exports the public API. Existing `widgets/coder-session` exports both a hook (`useActivityCards`) and components from the same `index.ts`. For dashboard-digest we keep it minimal: only components, since the hook lives in entities.
- **Test setup for components consuming queries**: provide `QueryClient`, `QueryClientProvider`, `ProjectProvider` (with `initialProjects` + `initialProjectId`), and `MemoryRouter`. Mock `../../../entities/issue/api/queries` via `vi.hoisted` + `vi.mock` to control `useIssues`/`useArchivedIssues` return shape per test. See `widgets/issue-event-timeline/ui/ActivityDialog.test.tsx` as the canonical pattern.
- **`useProjectPath()` returns**: a callback `toProjectPath('/issues/<n>')` that prepends the project name segment. Tests should assert the path ends with `/issues/<n>` rather than the prefix (which depends on `currentProject?.name`).

## Gotchas

- The completion-snapshot test passes `vi.fn()` directly without `vi.hoisted`. When a mock captures multiple functions and you need them all hoisted, use `vi.hoisted` (we needed this in widget test for `useIssues` + `useArchivedIssues`).
- `useRecentDigest` should NOT report `isLoading: true` when `projectId` is null (queries are disabled → they will never resolve). Return `false` in that branch so the widget doesn't show a permanent spinner.
- Ordering for "most recent first" depends on `hoursAgo(0)` being the freshest. In tests where `number` correlates with `i` and `updatedAt: hoursAgo(i)`, the **smallest** number is the most recent. Don't write `expect(first.number).toBeGreaterThan(last.number)` — that pattern only works when `number` is anti-correlated with recency.

## T-003 fix-tests notes (verify check failures unrelated to #170 scope, but blocking the check)

### Failures observed
- **Web**: `useCompletionSnapshot` and `SnapshotRow` tests fail because the hooks use `Date.now()` (via `deriveCompletionSnapshot(data)` default arg) but the tests assume a hard-coded `NOW` anchor.
- **Runner**: `FirstMaterialization_CloneFailureIsFatal` times out because `git clone --bare https://127.0.0.1:1/...` hits a TCP-level connect timeout (12s+ on Ubuntu 24.04) which exceeds the 10s vitest default.

### Root-cause fixes (no assertion weakening)
- Web: freeze the clock in tests that hit the `useMemo` path of `useCompletionSnapshot` / `SnapshotRow` via `vi.useFakeTimers({ now: new Date(NOW) })` in `beforeEach` + `vi.useRealTimers()` in `afterEach`. The hook's runtime behavior (`Date.now()`) is unchanged — only the test environment becomes deterministic.
- Runner: replace the bad URL with `https://no-such-host.invalid/...` (RFC 2606 / 6761 reserved TLD, must not resolve). DNS failure returns in ~40ms instead of hanging on TCP retry. Test assertion (`/git clone failed/`) is unchanged.

- Runner types: re-add `outputs?: string | null` to `WorkDispatchResponse` so the surviving `dispatch.outputs` reference in `connection.ts:209` typechecks. The field was a no-op removal in `4ff494a9a` (consumer still references it). Alternative would be to delete the `connection.ts:209` line, but that's outside #170 scope.

### T-003 lessons (for future agents)
- When a hook forwards to a pure function that defaults `now = Date.now()`, any test that uses a hard-coded anchor for the "current time" must lock the clock with `vi.useFakeTimers`. The `deriveCompletionSnapshot` pure-function tests pass an explicit `now`; the hook tests don't, so they silently depend on wall-clock alignment.
- For "must fail" network tests in this repo, prefer an RFC-reserved unresolvable TLD (`.invalid`, `.example`, `.localhost`-with-no-resolver) over unreachable IPs — the IP case may retry for the full OS TCP timeout (10s+ on Linux), which is too long for vitest's default 10s `testTimeout`.
- The server's `AgentSessionLabels` table was replaced by computed columns on `AgentSessions` (see migration `20260620185946`). Any test code that still queries `db.AgentSessionLabels` will fail to compile against the current EF model. Use `LabelSourceId` / `LabelSessionName` directly on `AgentSessions`.

## T-004 fix-tests notes (re-failure of FirstMaterialization_CloneFailureIsFatal)

### Re-failure observed
- T-003's `.invalid` URL fix was correct in principle, but the local sandbox runs with `http.proxy=http://127.0.0.1:20172` set in global git config. Git's HTTP transport forwards `.invalid` (and any non-`file://` URL) through that proxy, and the proxy accepts the connection then waits on the upstream that never comes back. Result: `git clone --bare https://no-such-host.invalid/...` hangs for ~10s on a TCP-level proxy stall instead of failing fast with DNS NXDOMAIN. Test times out at vitest's 10s default.

### Root-cause fix
- Switch the URL scheme to `file:///this-path-does-not-exist/this-host-has-no-git-server.git`. Git's `file://` transport is purely local I/O — no proxy, no DNS, no TLS — so `git clone --bare` fails in a few ms with `fatal: '/this-path-does-not-exist/...' does not appear to be a git repository`. WorkspaceManager wraps that stderr as `git clone failed for file:///...: <stderr>`, which still matches the existing `/git clone failed/` regex. No assertion was weakened; the clone-failure surface is the same error kind the test was designed to exercise.

### T-004 lessons (for future agents)
- T-003's lesson on `.invalid` TLDs was correct *for environments without an HTTP proxy*. In sandboxes/CI where `http.proxy` / `https.proxy` is set (here, `http://127.0.0.1:20172` in global git config), any `http://`/`https://` URL — including `.invalid` and other unresolvable hosts — is forwarded to the proxy, which may keep the connection open waiting for an upstream. The reliable cross-environment fix for a "must fail" clone in this repo is a `file://` URL pointing at a nonexistent path: local I/O only, no proxy / DNS / TLS involvement, fails in single-digit ms.
