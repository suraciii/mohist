# Issue 516 T-002 — Slack first-mention thread-history import

## Status
Code complete and tests green. Wrapping up due to interruption warning.

## What landed
- `ISlackApiClient.ConversationsRepliesAsync` (and `SlackConversationsRepliesPage` /
  `SlackConversationMessage` records) on the real `SlackApiClient` and on all
  fakes (unit `RecordingSlackApiClient`, spec `RecordingSlackApiClient`, plus
  the 5 inline fakes in ConnectionDiagnosticSpecs / SlackOwner*Specs /
  SlackSetupVerifierSpecs / SlackConnectionRotateCredentialsSpecs).
  The HTTP call posts `conversations.replies` with channel/thread/cursor/limit
  200/inclusive=false, mirroring the other 7 read APIs the Server already
  issues.
- `SlackProviderOptions`:
  - `StartupContextCharacterBudget` (default 8000)
  - `StartupContextPaginationDepthCap` (default 10 pages × 200 msgs)
  Both bind via `Configuration.GetSection("SlackProvider")`.
- `SlackThreadHistoryReader` (Server-side, `IScopedService`):
  - `ReadAsync(... mentionTs)` paginates `conversations.replies` (depth-capped),
    stops at the mention ts (returns Empty), refuses on Slack error or
    transport failure (returns Refused + reason), returns Empty when no
    messages were collected, otherwise Imported with the ordered visible set.
  - `ApplyBudget(messages, characterBudget)` renders the chronological
    transcript (oldest→newest), drops whole oldest messages first when over
    budget, and surfaces a stable `"N oldest messages omitted"` marker via
    `AgentStartupContextProvenance.TruncationMarker`.
- `SlackThreadLaunchReservationStore.ReleaseAsync(...)` — releases the
  unbound reservation owned by the supplied launch message so a failed
  read followed by a re-mention can proceed (no stale-reservation wait).
- `SlackConnectionRoutes`:
  - New `HandleChannelIngressRequest` fields: `ISecretStore Secrets`,
    `SlackThreadHistoryReader ThreadHistory`, `IOptions<SlackProviderOptions>
    SlackProviderOptions`. The ingress handler injects them and passes them
    through the existing `From(...)` factory.
  - `LaunchChannelRootAsync` takes an additional `AgentStartupContext?
    startupContext` and threads it into `AgentLauncher.LaunchConnectionAsync`
    (which was already wired in T-001 to forward the value to the launch
    chain).
  - The first-mention-in-existing-thread branch (after the existing
    ownBinding / otherBots / reconcile checks) calls
    `ReadThreadHistoryIfAnyAsync`; on Refused it releases the reservation
    and asks the user to re-mention; on Imported it builds the
    `AgentStartupContext` (via `BuildStartupContext`, which uses
    `SlackProviderOptions.StartupContextCharacterBudget`) and passes it as
    the launch startup context; on Empty it launches with `null` (root
    mention path is unchanged).
  - `BuildLaunchAck` emits the dual-marked acceptance reply: imports report
    "Prior thread discussion is being used as background"; truncated imports
    add "the oldest messages were omitted to fit the bound"; the existing
    "Task accepted and queued for execution." / redelivery acks are
    preserved.
  - Empty-mention rejection is preserved on the thread-context path (the
    existing check now sits before the read in the same branch).
  - Root-mention, other-bots-in-thread, and reconcile-match paths still
    launch with `startupContext: null` (no chat-history import on those
    paths).
- Docs `docs/agent-connections.md` and `design/slack-agent-connection.md`
  实装差距 paragraphs updated to mark thread-history import as provided.

## Notes for future readers
- The `SlackThreadHistoryReader` is wired through the `IScopedService`
  convention, so any new assembly with that marker will auto-register.
- The read is intentionally called before the launch reservation so the
  reservation can be released cleanly on refusal — keeps the inbound Slack
  surface stateless about partial work.
- The character budget is configurable so a noisy Slack thread with a
  long-running peer bot does not inflate the Agent's input; the depth cap
  keeps the read bounded even on adversarial workloads.
- The `AgentStartupContext.TruncationMarker` ("N oldest messages omitted")
  is the same string the router puts in the Slack acceptance reply, so the
  two attestations cannot drift.
# Issue 516 — review fixes

Addresses every finding in `openspec/changes/issue-516/review.md`.

## F1+F4 — Reader now keeps prior messages; post-mention messages excluded
- `SlackThreadHistoryReader.ReadAsync` replaced the exact-ts-equality stop
  (which discarded collected messages via `return Empty(...)`) with a
  timestamp boundary: a message is collected when `ts < mentionTs` and the
  read stops at the first message with `ts >= mentionTs`. Prior discussion
  now survives; messages at or after the mention are excluded even when the
  mention itself is absent from the fetched pages.
- Added `TryReadMessageTs` helper (shared by `ApplyBudget`) for tolerant
  Slack-ts parsing; unparseable timestamps are skipped rather than throwing.

## F2 — Depth-cap exhaustion now refuses
- The reader tracks `paginationComplete` separately from `reachedMention`.
  When the pagination depth cap is exhausted without reaching the mention
  and without Slack signaling end-of-pagination, the read returns `Refused`
  ("pagination depth cap reached before the mention") — no `AgentJob`,
  consistent with D5. A thread that ends (nextCursor empty) before the
  mention still imports the visible prior set.

## F3 — Removed dead refuse-path release
- `ReadThreadHistoryIfAnyAsync` no longer calls
  `SlackThreadLaunchReservationStore.ReleaseAsync`: the reservation is
  created later inside `LaunchChannelRootAsync`, after the read, so on the
  refuse path no reservation exists to release. Removed the now-unused
  `ReleaseAsync` store method. Renamed the two spec tests whose names
  implied a reservation was being released.

## F5 — Indentation regression fixed
- `AgentSessionGrain.cs` replay-conflict block restored to method-body
  indentation.

## Test updates
- Unit `SlackThreadHistoryReaderTests`: `StopsAtMentionMessage` →
  `KeepsPriorMessages_StopsAtMention` (now asserts `Imported` with the
  prior message); added `MentionExcluded_PostMentionMessagesDropped`;
