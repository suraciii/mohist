- All three tools follow the established `Tool.define()` pattern with context factory function
- Context interface is `{ projectPath: string }` — generic enough for future sub-agent reuse
- grep-tool has its own file walker (not reusing glob) to support extension filtering inline

## [2026-04-07T13:59:00Z] T-006: Implement explore API routes

**What was done:**
- Created `api/explore.ts` with `createExploreRoutes()` factory function following existing Hono route pattern
- Implemented 5 endpoints:
  - `POST /api/explore` — creates session with projectId + optional title
  - `GET /api/explore?projectId=x` — lists sessions ordered by updated_at desc
  - `GET /api/explore/:id` — returns session with all messages
  - `DELETE /api/explore/:id` — deletes session (cascades messages)
  - `POST /api/explore/:id/messages` — sends user message, returns SSE stream with agent response
- SSE streaming uses `streamSSE` from Hono + Vercel AI SDK's `fullStream` async iterator
- Stream events: `tool_call` (tool name, args, result), `chunk` (text fragment), `done` (with optional issueId)
- Added `ExploreSessionRepo`/`ExploreMessageRepo` to `StateManager` with getter methods
- Added `ExploreService` export to `services/index.ts`
- Registered `/api/explore` route in `server/index.ts`

**Learnings:**
- Vercel AI SDK v6 `fullStream` yields parts with types: `text-delta`, `tool-call`, `tool-result`, `start`, `finish`, `error`, etc.
- `tool-call` part contains the tool invocation, `tool-result` part contains the result — both needed to reconstruct full tool call records
- Used `result.text` (awaited) instead of accumulating `text-delta` parts for the final assistant content — more reliable
- Persisted messages AFTER stream completes (not during) to ensure complete content is stored
- Checked `exploreSessionRepo.findById()` after stream to detect if agent called `create_issue` (which updates session.issue_id via tool)

**Verification:** TypeScript build passes, all 166 tests pass (no regressions).
