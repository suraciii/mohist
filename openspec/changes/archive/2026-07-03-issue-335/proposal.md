## Why

The Issue aggregate's two terminal transitions publish events whose names betray the facts they carry. `Issue.Close()` sets status to `Cancelled`, yet it emits `IssueClosed` (serialized `com.mohist.issue.closed`), while the catalog's `com.mohist.issue.cancelled` is declared but never emitted by any producer. Symmetrically, `Issue.Complete()` sets status to `Done`, yet it emits `IssueWorkCompleted` (serialized `com.mohist.issue.work-completed`), while `com.mohist.issue.completed` is a dead catalog entry. Consumers paper over the lie — projecting `closed` back to `State.Cancelled`, with code comments admitting "the durable facts diverge from the spec text; the implementation follows the facts." This must be fixed now because these misnomers are persisted durable facts: every day they persist, the historical event layer grows more entangled and the backfill to reconcile it grows larger. Domain events must record the truth under a faithful name; the catalog must declare what producers actually emit.

## What Changes

- Add `IssueCancelled`; `Issue.Close()` records `IssueCancelled`, serialized as `com.mohist.issue.cancelled`. **Remove the `IssueClosed` type and the `com.mohist.issue.closed` id.**
- Add `IssueCompleted`; `Issue.Complete()` records `IssueCompleted`, serialized as `com.mohist.issue.completed`. **Remove the `IssueWorkCompleted` type and the `com.mohist.issue.work-completed` id.**
- Make the catalog consistent with producers: the `cancelled` / `completed` constants now have real emitters; the dead `work-completed` / `closed` catalog entries are removed; the serializer routes the renamed types through catalog constants instead of divergent string literals.
- **BREAKING (persisted data only, no API/schema change):** the `IssueEvents.Type` column values for terminal rows change (`...closed` → `...cancelled`, `...work-completed` → `...completed`). A one-time backfill migration (following the `20260629120000_BackfillIssueCompletedAt` raw-SQL precedent) rewrites historical rows so pre- and post-rename data share one vocabulary. No external API, DTO, `IssueStatus` enum value, snapshot model, or grain-state contract changes.
- Sweep every consumer keyed on the legacy terminal type ids to the canonical ids, preserving all downstream effects: epic auto-done & reconciliation subscriptions, inbox projection, stage attribution, stage-population snapshot, metrics querier terminal bucketing, and the web event registry / timeline / outcome handling.
- Explicitly unchanged: the `IssueStatus` enum (`Backlog/InProgress/Done/Cancelled`); snapshot-as-truth (no event sourcing is introduced, and grains do not replay events, so state is unaffected); `EventBridge` (the `com.mohist.*` wildcard subscription is naturally compatible); non-terminal event names (`created` / `labels-changed` / etc., already faithful); and the broader "catalog lists 4 of 13 emitted issue ids" deficit (deferred to a separate change).

## Capabilities

### New Capabilities

- `issue-terminal-events`: The Issue aggregate's terminal domain-event vocabulary and its consistency invariants — `Close()` records `IssueCancelled` and `Complete()` records `IssueCompleted`; the serializer emits the canonical reverse-DNS ids (`com.mohist.issue.cancelled` / `com.mohist.issue.completed`) through catalog constants; the catalog declares exactly the terminal events that producers emit; and the legacy misnomer types/ids (`IssueClosed`, `IssueWorkCompleted`, `...closed`, `...work-completed`) no longer exist anywhere in the codebase.

- `terminal-event-consumption`: The cross-cutting contract that every consumer keyed on terminal event type ids continues to recognize cancellation/completion and preserve its downstream effect — epic auto-done & reconciliation, inbox projection, stage attribution, stage-population snapshot exclusion, metrics querier terminal bucketing, and the web timeline/outcome handling — under the canonical ids, with a backfill migration that rewrites historical persisted event rows so the same behaviors hold on pre-rename data (timeline rendering and terminal bucketing correct across old and new rows).

### Modified Capabilities

None — no living spec currently covers the event vocabulary or these consumer surfaces (the only living spec is `issue-board`, which is unrelated).

## Impact

- **Server — Issue domain** (`packages/server/src/Mohist.Server`): `Issue/Domain/Events/IssueEvent.cs` (the `IssueEvent` union plus the two renamed records), `Issue/Domain/Issue.Transitions.cs` (the two `RecordEvent` calls in `Close()` / `Complete()`). `IssueStatus.cs` is unchanged.
- **Server — event infra**: `Infrastructure/Events/IssueEventSerializer.cs` (`BusType` and `Unwrap` mappings), `Infrastructure/Events/EventCatalog.cs` (drop the dead `work-completed`/`closed` list entries; route the serializer through the `ReverseDns` constants).
- **Server — consumers**: `Events/Subscriptions/EpicAutoDoneHandler.cs` (the two `[Subscription]` literals, the two `ICloudEventHandler<T>` type params, and the `evtType` log strings), `Events/Subscriptions/InboxProjectionHandler.cs` (the subscription pipe plus the dispatch/kind-mapping arms), `Issue/Services/IssueStageAttribution.cs` (the `closed` literal → `EventCatalog.ReverseDns.IssueCancelled`), `Issue/Services/IssueQuerier.cs` (the `WorkCompletedType` / `ClosedType` consts and terminal-bucketing doc), `Events/Hosting/StagePopulationSnapshotService.cs` (the hardcoded lifecycle type literals), `Events/Hosting/EpicReconciliationService.cs` (doc comments).
- **Server — persistence**: a new raw-SQL EF migration rewriting the `IssueEvents.Type` column for terminal rows from the legacy ids to the canonical ids (precedent: `20260629120000_BackfillIssueCompletedAt.cs`). Because Issue is state-stored and grains do not replay events, snapshot integrity is unaffected; the existing `completedAt`-backfill migration's id references become historical-only (its work is already done and `completedAt` is now live-written by `Close()` / `Complete()`).
- **Web** (`packages/web`): `shared/lib/canonical-event-types.ts`, `widgets/issue-event-timeline/model/describe.ts`, `entities/issue/@x/events.ts`, `app/providers/handle-event.ts`, `app/providers/model/reverse-dns-outcome.ts`.
- **CLI / runner**: none.
- **Tests**: sweep all specs referencing `IssueClosed` / `IssueWorkCompleted` / the legacy id strings — `EpicAutoDoneHandlerSpecs`, `EpicReconciliationServiceSpecs`, `InboxProjectionHandlerSpecs` (+ `InboxProjectionHandlerRealtimeHintSpecs`), `StagePopulationSnapshotServiceSpecs`, `IssueStageAttributionSpecs`, `IssueQuerierSpecs`, `IssueMetricsApiSpecs`, `BackfillIssueCompletedAtMigrationSpecs`; plus web `canonical-event-types.test.ts`, `reverse-dns-outcome.test.ts`, `LiveTaskProvider.test.ts`, `live-task-cloud-event.test.tsx`.
- **Risk (medium)**: a persisted event-type rename can split historical from new data if any consumer or the backfill is missed. Mitigated by: snapshot-as-truth (no state replay to break), an exhaustive consumer sweep keyed on one canonical id set, the established backfill-migration precedent, and the explicit no-replay / no-`EventBridge`-change boundary.
