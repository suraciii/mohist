## Gotchas

- `IssueHealth` 不在 `entities/epic` 索引里；要从 `../../../entities/issue` 导入。
- 千万别为了 "更准" 而在 selector 里调 `LinkedIssue.canStart` —— 那会越界到 detail-enrichment 路径，违反 D2 和 spec §"Grouping relies only on existing list read-model fields"。
- `EpicStatus.Idle`/`Running` 选择交给调用方；本 selector 只看 `progress` 三字段。`Paused`/`Done`/`Closed` 由 `EpicListPage` 自己过滤后再喂给 selector。
- `EpicCardBody` 与 `EpicCard` 用 `CardGroup = ActiveGroupKey | 'done' | 'closed' | 'paused'` 双闭包联合；不要把它收成 `string` —— 类型收窄是 `idleEmpty` vs `readyToStart` 在 readyToMarkDone 字段上语义不同的保障。
- jsdom 拿不到真实 layout，mobile no-overflow 必须 stub `documentElement.scrollWidth/clientWidth`（jsdom 默认是 0）后断言相等 —— 设计意图是"宽度相等即不溢出"，因为 jsdom 不会计算宽度差异。
- `[data-slot="badge"]` 是 `@base-ui/react` 的 Badge primitive 自带属性，可直接 query —— 这条对所有 shared/ui/components/badge 渲染都成立。
- 测试 `getByText('1 / 3 completed')` 在多卡场景会重复；要查具体卡用 `closest('[data-slot="card"]')` 收窄；要查"至少存在一个"用 `getAllByText(...).length >= 1`。
- `Start next issue` 按钮在 `disabled=true` 时文本会从 `'Start next issue'` 变成 `'Starting...'`，已用独立用例断言这条。
