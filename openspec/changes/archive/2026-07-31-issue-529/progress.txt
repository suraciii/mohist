## Codebase Patterns

- `OtelQueryRoutesIntegrationSpecs` runs reliably through the built xUnit v3 assembly with `-class`; the project-level `dotnet test --filter` option is ignored by Microsoft Testing Platform in this environment.
- `TraceQuerier.ExecuteBoundedQuery` collects reader field names before materializing rows, so the same `fieldNames` array can be returned for every result path.
- `RecordingHttpHandler` captures `req.Content` after the responder reads it; inside a responder, use `await req.Content.ReadAsStringAsync()` to inspect the request body (the captured `Body` field is on the captured request, not the live `HttpRequestMessage`).
- System.CommandLine rejects unknown options at parse time with a non-zero exit code; no contact to the Server happens.
- `OtelCommands.RunStatusAsync`'s exception path uses `MohistCliApi.ServerUnavailableMessage` for both `HttpRequestException` and `TaskCanceledException` — the new `RunQueryAsync` follows the same pattern.
- `Mohist.Cli` no longer needs `Microsoft.Data.Sqlite` (CLI imports were only used by the deleted SQLite executor). The package reference is left in place since the Server-side workload still shares the same project graph; verify by checking the project still compiles cleanly (it does).
