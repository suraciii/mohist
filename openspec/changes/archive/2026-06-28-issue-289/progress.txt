## Codebase Patterns

- **Runner action persist helper shape**: `context.writeVars` is best-effort,
  immediate, not rolled back on later failure. Existing persist call sites
  wrap it in try/catch and return `{ errorCode: "retry-safe", stage: "persist-name" }`
  on rejection so the retry path re-attempts. See `ArchiveChangeWhenPersistFails_FailsWithRetrySafeBeforeMove`.
- **Archive-name validation**: `validateArchivePrefix(prefix)` at
  `packages/runner/src/actions/openspec.ts:494` rejects empty/whitespace,
  `.`/`..` segments, slashes/backslashes, and absolute paths. Run it on
  every resolved name (new key, legacy fallback, and backfilled basename)
  so the existing unsafe-name rejection still applies.
- **Test fixture pattern**: `archiveContext(workDir, changeDir, variables?, serverConnection?)`
  wires `writeVars` to `serverConnection.patchRunVars` and defaults the latter
  to `vi.fn()`. Tests assert via `expect(patchRunVars).toHaveBeenCalledWith(...)`
  for the new `{ openspecArchiveName: basename }` payload.

## Decisions / Gotchas

- **Migration is best-effort, not eager.** When a retry observes an already
  archived directory (no write site fires), the legacy key is not migrated
  on that retry. Subsequent retries keep reading legacy harmlessly until a
  write site runs (e.g., a future retry that re-moves). Spec scenario
  "Legacy key migrated to openspecArchiveName" is satisfied via the
  before-move and backfill sites.
- **Same basename re-write is idempotent.** When a retry that already
  persisted `openspecArchiveName` re-enters the before-move path (e.g., a
  crash between persist and move with source still present), the action
  writes the same value again. `writeVars` is last-write-wins with the same
  basename, so this is harmless.
- **Backfill picks the actual matched basename.** If `findExistingArchive`
  matches a `-vN` sibling, the backfilled name is that sibling's basename,
  so subsequent retries reuse the same archive (D5 backfill-pick mitigation).
- **Both keys test exercises precedence, not migration.** When both keys
  are present and the new-key archive already exists, the action does not
  write either key — it simply reads the new-key value and proceeds. The
  test name reflects D2 preference only.
