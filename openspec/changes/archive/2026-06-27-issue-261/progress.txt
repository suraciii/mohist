## T-001: Implement project-level AI quality aggregation endpoint

### Decisions
- Followed design decision D2 option B: added `LoadWorkflowRunsAsync` bulk loader in `IssueQuerier` that reads raw deserialized `WorkflowRun` state, keeping `WorkflowStatusMapper` / `CheckStatusView` untouched. `RepairCount` is therefore available without widening the frontend-facing workflow status contract.
- Followed design decision D3: window membership anchored on `IssueEvents.Time` of `com.mohist.issue.work-completed`, matching `GetCompletionBucketsAsync`. Done issues without a matching event do not contribute.
- "Entered a stage" predicate chosen as `StageRun.Initialized == true`. This cleanly distinguishes reached stages from never-reached stages in seeded workflow run states.

### Code patterns
- Querier result types (`QualityMetricsResult`, `QualityMetricsWindow`, `QualityStageReworkAggregate`) are internal records on `IssueQuerier`, mirroring `ApprovalWaitResult`.
- Endpoint partial `IssueRoutes.QualityMetrics.cs` mirrors `IssueRoutes.ApprovalMetrics.cs`: inject `IssueQuerier`, resolve project via `ProjectResolutionEndpointFilter`, return `ApiResults.Ok(BuildResponse(...))`.
- DTOs in `IssueRoutes.Dtos.cs` use nullable `double?` rates + integer denominators (`SampleCount`, `EnteredCount`) for zero-sample distinguishability.
- Tests use JSON-anonymous-object seeded `WorkflowRun` rows with `repairCount` and `initialized` fields; `JSON.Options` (web defaults) maps camelCase properties correctly.

### Gotchas
- `LoadWorkflowRunsAsync` originally typed to `IReadOnlyCollection<IssueReadModel>`; caller must materialize read models, not `IssueInfo`.
- When seeding events in unit tests, `IssueEventRow.Id` must be unique per source; reused the existing max-id pattern from `SeedEvent`.
- The endpoint tests seed events directly via `IssueEventRow` because the integration fixture does not emit domain events automatically.

## T-002: Implement useQualityMetrics hook and QualityPanel component

### Decisions
- Followed `useApprovalWait` / `useCompletionTrend` precedent for the hook shape: `useProject()` → `useQuery` with `queryKey: ['issues','metrics','quality', projectId]`, `enabled: !!projectId`, `staleTime: 60_000`.
- QualityPanel treats the 7-day window as the primary/leading window: if `window7d.sampleCount === 0` (or the hook returns no data), the whole panel renders the established empty-state convention (`<section data-state="empty">` + `<p data-testid="productivity-quality-empty">`). This mirrors `CompletionTrend` and keeps the zero-sample presentation distinguishable from a genuine perfect score.
- The 30-day window is rendered as a secondary comparison window inside the populated panel; if it is zero-sample it gets its own window-specific empty sub-section (`data-testid="productivity-quality-window-30d-empty"`).
- Per-stage emptiness (`enteredCount === 0`) is rendered independently within a populated window as an em-dash (`—`) with a stage-specific testid, without blanking the whole panel.
- Rates are displayed as rounded percentages (e.g. `70%`, `0%`, `100%`) for readability; `null` rates are rendered as `—`.

### Code patterns
- `quality-metrics.ts` mirrors `approval-wait.ts`: exported `fetchQualityMetrics`, `qualityMetricsQueryKey`, and `useQualityMetrics`, plus response/window/stage TypeScript interfaces.
- Barrel export added to `entities/issue/index.ts` alongside `completion-trend` and `approval-wait` exports.
- `QualityPanel.tsx` uses the same card styling as `CompletionTrend` (`rounded-lg border border-border bg-card/50 p-4`) and the same empty-state attributes.
- Tests mock `useQualityMetrics` at the API module path (not the barrel) to avoid pulling in the real hook / query client behavior, matching the `CompletionTrend.test.tsx` pattern.

### Gotchas
- `npm install` was required in this workspace before `tsc` / `vitest` were available; the previous T-001 note about vitest not being installed was resolved by installing the monorepo dependencies.
- The backend returns camelCase JSON (`window7d`, `firstTimeRightRate`, `enteredCount`, `reworkRate`) because the server uses `JSON.Options` (web defaults with camel-case naming), so the frontend interfaces use camelCase.
