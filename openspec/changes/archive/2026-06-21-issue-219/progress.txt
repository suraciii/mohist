# Progress — issue-219 (OTel trace collector)

## Codebase Patterns

- **Otel subsystem is a sibling of Workflow/Agent/Issue** under
  `packages/server/src/Mohist.Server/`. It uses the standard
  `MohistServiceRegistration.ConfigureMohistServices` registration +
  `Mohist:Otel` config section pattern (matching `Mohist:AgentJob`,
  `Mohist:ArtifactStorage`, `Mohist:AttachmentStorage`).
- **`otel.db` is intentionally a separate file from `mohist.db`.** It is
  opened via raw `Microsoft.Data.Sqlite` (no EF Core) because schema
  is fixed, the DDL is a **shared contract** with the `mo otel` CLI,
  and the free-SQL query endpoint needs a raw connection anyway. Time
  columns are stored as ISO 8601 UTC text so SQLite lexicographic
  order matches chronological order.
- **`Cache=Shared` is incompatible with `Mode=ReadOnly` in
  `Microsoft.Data.Sqlite`.** Read-only connection strings therefore
  omit `Cache=Shared`; the read-write connection uses it so concurrent
  readers see recent writes. This pattern is non-obvious and was found
  by running the read-only rejection test.
- **A read-only SQLite open refuses to create a missing file** because
  it must take a write lock to do so. `OtelDb.OpenReadOnlyConnection`
  bootstraps the file via a transient read-write open on first call
  when the path doesn't exist yet, so `mo otel status` / `GET
  /otel/api/status` returns sensible stats even before the first
  batch of traces arrives.
- **`IFileSystem` in `Mohist.Server.SystemInfo` is the server-side
  abstraction (only `Exists` and `ReadAllText`); it is NOT the same
  type as `Mohist.Cli.IFileSystem`.** Tests that need to satisfy
  `Mohist.Server.SystemInfo.IFileSystem` cannot reuse
  `Support.FakeFileSystem` (which implements the CLI one). A tiny
  `PassthroughFileSystem` in `OtelDbSpecs` is sufficient for the
  `Exists`-only call the OtelDb makes.
- **`MohistDbFixture` does not isolate the OTel database by default.**
  The fixture must explicitly add `Mohist:Otel:DbPath` pointing to a
  temp file or `OpenReadOnlyConnection` will try to open
  `~/.mohist/otel.db` and fail in sandboxed test environments.
- **OtelCollectorStatus is a thread-safe singleton with a
  `OtelCollectorState` snapshot record struct** — handlers should
  read `Current` instead of holding the lock across I/O.
- **OTLP wire is `System.Text.Json` + hand-written POCO +
  `AnyValueConverter`** for the protobuf oneof union. `stringValue`
  / `intValue` / etc. live on the same `AnyValue` class with a
  `Kind` discriminator. No `OpenTelemetry.Protobuf` / `Google.Protobuf`
  packages — keeps `OtlpRoutes` fast and conflict-free with Orleans
  serialization.
- **OTLP responses bypass `ApiResults`**. The spec mandates a literal
  `{}` body and JSON-typed errors; the route handler emits
  `Results.Json(new {}, ...)` / `Results.Json(new { error = ... }, ...)`
  directly. `/otel/api/*` (T-003) on the main port DOES use the
  `ApiResponse<T>` envelope — it's only the OTLP wire that doesn't.
- **Port isolation is enforced in three layers**: (1) `RequireHost` on
  the OTLP route group (port-filter at the routing layer), (2)
  `OtelPortIsolationMiddleware` (returns 404 for non-`/otel/v1/`
  paths on the OTLP port, and for `/otel/v1/` paths on the main
  port), (3) `MohistWebRegistration` SPA fallback (returns 404 for
  `/otel/v1/` paths so static-file serving can't leak). All three
  are necessary because each guards a different bypass vector.
- **Kestrel bind is "all or nothing"**. If the OTLP listen option
  fails, the main port is also not bound. `Program.cs` catches the
  `IOException` (classified by `OtelBindFailureDetector`) and
  rebuilds a second host with `Mohist:Otel:Enabled=false` so the
  main API stays up. The collector status then reports offline
  naturally (default false).
- **Integration tests for `OtlpRoutes` use `WebApplicationFactory<Program>`
  + TestHost (no real socket bind).** Each test sets the `Host`
  header explicitly to `localhost:<otelPort>` or `localhost:3456` to
  exercise `RequireHost` and the isolation middleware. The bind-
  failure end-to-end tests construct a real Kestrel host so the
  actual `IOException` surface is hit.
- **`/otel/api/*` responses use `ApiResponse<T>` and snake_case JSON**
  (NOT camelCase). The codebase's `JsonSerializerDefaults.Web`
  default is camelCase, so DTO records exposed by the Otel query
  routes carry `[property: JsonPropertyName("snake_case")]`
  attributes — matching the spec wording in
  `otel-trace-query-api/spec.md` and matching the SQLite column
  names which `ExecuteRawQuery` already returns verbatim.
- **`db_size_bytes` must sum the main file plus WAL/SHM/Journal
  sidecars**. SQLite in WAL mode keeps committed data in
  `otel.db-wal` and `otel.db-shm` until a checkpoint; reading
  `new FileInfo(dbPath).Length` alone often returns 0 right after
  writes. The querier sums all four files so the status endpoint
  reflects real on-disk footprint.
- **Free-SQL guard is layered**: the HTTP route validates the
  keyword (top-level SELECT/WITH, comments and whitespace stripped,
  compound statements walked); the querier opens a
  `Mode=ReadOnly` connection; the `CommandTimeout` is capped at
  5 s. The keyword check produces a clean 400; the read-only mode
  is the physical backstop and produces a
  `SqliteException` with `SqliteErrorCode = 8` (SQLITE_READONLY`)
  for any write attempt that slips past the keyword check.
- **`ExecuteRawQuery` returns `List<Dictionary<string, object?>>`**
  with raw values from `SqliteDataReader.GetValue`. The query
  endpoint re-serializes the dict straight into the
  `ApiResponse<List<Dictionary<string, object?>>>.data` slot, so
  callers see `{success, data: [{column: value, ...}, ...]}`.
- **`mo otel` CLI shares the server-side `otel.db` schema, but
  the read-only connection deliberately bypasses the keyword
  allowlist.** The CLI's `RunQueryAsync` opens
  `SqliteOpenMode.ReadOnly` directly (no `Cache=Shared`); any
  write attempt fails at the SQLite engine with
  `SQLITE_READONLY` (`SqliteErrorCode = 8`), which is surfaced
  as a `SqliteException` caught at the route boundary. This
  matches design.md Decision 5's "CLI 不做关键字拒绝" rule.
- **`mo otel query` must fail fast when the DB is missing.**
  The CLI checks `api.FileSystem.Exists(resolvedPath)` BEFORE
  opening `SqliteConnection`, because read-only SQLite open
  refuses to create a missing file (it would need a write
  lock). The pre-check uses the test `IFileSystem`, so
  `FakeFileSystem` tests must `AddFile(path, "")` for the
  real temp DB path they create.
- **Default path resolution is inlined in `OtelCommands`**
  rather than going through `OtelDb.ResolveDatabasePath`
  because the CLI doesn't have access to the server's
  `OtelOptions` / `IEnvironmentVariableProvider`. The
  resolution matches the server-side default exactly:
  `Environment.GetFolderPath(UserProfile) + ".mohist" +
  "otel.db"`. CLI tests assert this contract via
  `OtelCommands.ResolveDatabasePath(null)`.
- **`mo otel status` mirrors `MohistCliApi.PrintGetSafeAsync`'s
  contract.** A try/catch on `HttpRequestException` (and
  `TaskCanceledException`, which surfaces the same "server is
  not running" diagnostic on slow timeouts) writes the
  `ServerUnavailableMessage` constant and returns exit 1 — no
  `ECONNREFUSED` stack trace ever reaches the user.

- **Learnings for future tasks:**
  - **Decisions made**
    - `OtelDb` exposes the read-only connection string as a property
      so T-003's `POST /otel/api/query` handler can use it directly
      without re-parsing the path. Same for read-write.
    - The DI constructor is the 3-arg `(IOptions<OtelOptions>,
      IEnvironmentVariableProvider, IFileSystem)` form. There is no
      single-arg ctor — that previously caused C# overload resolution
      to fail in tests when callers passed `(OtelOptions,
      IEnvironmentVariableProvider, IFileSystem)`. Tests that want to
      avoid the IOptions wrapper use the 3-arg ctor with
      `OtelOptions` directly.
    - Read-only connections do NOT participate in shared cache (the
      SQLite engine rejects the combination). Connection string
      builder omits `Cache=Shared` when `readOnly=true`.
    - Schema initialization runs on first `OpenReadWriteConnection()`
      call under an internal lock; subsequent calls are no-ops. This
      is fine because DDL is `IF NOT EXISTS` anyway.
  - **Gotchas discovered**
    - `Mohist.Server.SystemInfo.IFileSystem` is intentionally
      minimal (only `Exists` + `ReadAllText`). The CLI's
      `Mohist.Cli.IFileSystem` is a different, fuller interface.
      Tests must not mix them.
    - `MockEnvironmentVariableProvider` from
      `EnvironmentAbstractions.TestHelpers` is in the `System`
      namespace (not `Mock`); the `using EnvironmentAbstractions.TestHelpers;`
      in test files brings it into scope.
    - C# 11/12 in this project (Microsoft.NET.Sdk.Web +
      `<ImplicitUsings>enable</ImplicitUsings>`) is happy to resolve
      types from referenced packages (like `IEnvironmentVariableProvider`)
      WITHOUT an explicit `using EnvironmentAbstractions;` directive,
      but the `using EnvironmentAbstractions;` itself fails with
      CS0246 because the namespace is not in the global usings list.
      So Otel code references `IEnvironmentVariableProvider` directly
      without any using, matching the existing codebase convention.
  - **Patterns / API shapes established**
    - `OtelDb` is a singleton service. Its first `OpenReadWriteConnection`
      call lazily creates the file and runs the schema; the same
      instance is shared across requests.
    - All DDL, table/column/index names are exposed as `public const string`
      on `OtelDb` so the T-002 ingester, T-003 querier, and T-004 CLI
      all reference the same identifiers (no string drift).
    - `OtelDb.DatabasePath` is a public property for diagnostics and
      for T-003's `db_size_bytes` calculation.
  - **Cross-task invariants**
    - The `OtelDb` schema is the contract. Any change to table name,
      column name, or index name is a breaking change for downstream
      SQL queries (T-003 server query API, T-004 CLI `mo otel query`).
    - `OtelOptions.SectionName` is `"Mohist:Otel"`. T-002 (port
      binding) and T-003 (route registration) must check
      `OtelOptions.Enabled` to short-circuit when the subsystem is
      off.
    - `OtelCollectorStatus` is the source of truth for
      `/otel/api/status`'s `collector_online` field. T-002 will
      call `SetPortBound(true)` on successful Kestrel bind and
      `SetPortBound(false)` on bind failure.

## Task T-002: OTLP trace 接收——双端口绑定、JSON 解析与持久化

- Implemented
  - **Dual-port bind** in `Program.cs`: appends a Kestrel `Listen` for
    `Mohist:Otel:Port` (default 4318, overridable) in addition to the
    main API port set via `UseUrls`. The bind is wrapped in a
    `try { StartAsync() } catch (IOException) { ... }`; on
    `OtelBindFailureDetector.IsOtlpPortBindFailure(ex, port)` we
    rebuild a fallback host with `Mohist:Otel:Enabled=false` and
    start that, so the main API stays up while `OtelCollectorStatus`
    reports offline. `OtelCollectorStatus.SetPortBound(true)` is
    called on the happy path.
  - **OTLP JSON POCO** in `Otel/OtlpJson/`: `OtlpTraceRequest`,
    `ResourceSpans`, `ScopeSpans`, `Span`, `KeyValue`, `Resource`,
    `InstrumentationScope`, `Status`, `AnyValue` + `AnyValueKind`
    enum, all with `[JsonPropertyName]` camelCase mapping. The
    `OtlpJsonSerializer.Options` uses `JsonSerializerDefaults.Web`,
    `JsonIgnoreCondition.WhenWritingNull`, `ReadCommentHandling.Skip`,
    `AllowTrailingCommas`, and case-insensitive property names —
    exactly what the OTLP HTTP/JSON spec calls for.
  - **`AnyValueConverter`** (custom `JsonConverter<AnyValue>`)
    implementing the oneof variants: `stringValue` / `boolValue` /
    `intValue` (string-or-number) / `doubleValue` / `arrayValue` /
    `kvlistValue` / `bytesValue` (base64). Unknown fields are
    silently consumed (forward-compat with newer OTel versions);
    an empty object throws `JsonException`.
  - **`TraceIngester`** (`Otel/TraceIngester.cs`): parses the
    request, iterates `resourceSpans`/`scopeSpans`/`spans`, converts
    `startTimeUnixNano`/`endTimeUnixNano` to ISO 8601 UTC text
    (clamped to the `DateTimeOffset` range), takes the first
    resource's `service.name` (falls back to `unknown_service`),
    serializes `attributes`/`resource_attributes` back to JSON
    arrays-of-objects (`[{key, value}]`), then `INSERT OR REPLACE`s
    each span and UPSERTs the `traces` header (recomputing
    `span_count` + `start_time`/`end_time` min/max from
    `MIN`/`MAX` so retries self-heal). All writes happen in a
    single transaction.
  - **`OtlpRoutes`** (`Api/OtlpRoutes.cs`): `MapPost("/otel/v1/traces", ...)`
    on a route group with `.RequireHost($"*:{otlpPort}")`. Handler
    checks `Content-Type` (only `application/json` accepted —
    `application/x-protobuf` and any other value yield 415), reads
    the body, deserializes via `TraceIngester.IngestJson` (catching
    `JsonException` → 400), and returns `{}` on success. Responses
    intentionally bypass `ApiResults` per design.md Decision 8.
  - **`OtelPortIsolationMiddleware`**
    (`Otel/OtelPortIsolationMiddleware.cs`): global middleware
    that returns 404 when (a) the request Host port matches
    `Mohist:Otel:Port` but the path doesn't start with `/otel/v1`,
    or (b) the path starts with `/otel/v1` but the Host port is
    NOT the OTLP port. Wired in `Program.cs` ahead of
    `MapMohistApi` + `MapMohistWeb` so the SPA fallback can't
    serve `index.html` for `/otel/v1/*` on the main port.
  - **`MohistWebRegistration.MapFallback`** extended to also 404 on
    `/otel/v1/*` paths so the SPA shell can't accidentally become
    an `/otel/v1` route if the OTLP port is the same as the main
    port. (Belt-and-braces: middleware already covers this.)
  - **`MohistApiRegistration.MapMohistApi`** appends
    `app.MapOtlpRoutes()`; **`MohistServiceRegistration`** adds
    `services.AddSingleton<TraceIngester>()`.
  - **`OtelOptions`** extended with `BindHost` (default
    `"localhost"`, set to `0.0.0.0`/`*` for all-interfaces) and
    a `DefaultPort` const for non-DI consumers.
  - **`OtelDb.OpenReadOnlyConnection`** now bootstraps the file via
    a transient read-write open on first call when the path
    doesn't exist yet — SQLite's read-only open refuses to
    create a missing file (it would have to take a write lock).
  - **Integration test fixture `OtlpRoutesWebApplicationFactory`**
    (`TestHost`-backed `WebApplicationFactory<Program>`) with
    `Mohist:Otel:Port` set to an ephemeral value; helpers
    `CreateOtlpClient()` / `CreateMainApiClient()` set the
    `Host` header to exercise `RequireHost` + the isolation

    - `AnyValueConverterSpecs` — 14 cases for oneof deserialization

    - `OtelBindFailureDetectorSpecs` — 9 cases for the

- **Learnings for future tasks:**
  - **Decisions made**
    - `OtlpRoutes` is registered through `MohistApiRegistration.MapMohistApi`
      so all API extensions share one registration point — even
      though the routes only run on the OTLP port. Keeping the
      registration list append-only is easier than refactoring
      T-003's `MapOtelQueryRoutes` separately.
    - The OTLP-route group uses `RequireHost($"*:{otlpPort}")` so
      the route matches regardless of which interface
      (`localhost` / `127.0.0.1` / `0.0.0.0`) the operator bound.
      The handler additionally re-checks
      `IsOtlpHost(context.Request.Host, otlpPort)` so a
      client-supplied `Host` header can't sneak an OTLP request
      into the main pipeline.
    - `BuildAlternateApp` in `Program.cs` flips
      `Mohist:Otel:Enabled` to `"false"` in the alternate
      configuration so the alternate host doesn't try to bind
      the OTLP port again. This is the only place that hand-
      rolls a second `WebApplication`; future "feature flag
      partial" work would generalize this pattern.
    - `OtelDb.OpenReadOnlyConnection` lazily bootstraps the file
      on first call. This is safe because the bootstrap is a
      `using var` and the init gate keeps DDL idempotent.
    - `TraceIngester.TryConvertUnixNanoToUtcIso` is `internal
      static` and tested directly via `[Theory]` rather than
      only through the public `IngestJson` path. The
      timestamp edge cases (epoch zero, sub-second nanos,
      overflow) are unit-tested that way.
    - `OtelBindFailureDetector` exposes
      `AllocateEphemeralLoopbackPort` for tests; it
      short-allocates a `TcpListener` on port 0 and reads
      the assigned port. Tests that need a real collision
      use this instead of hard-coded ports.
  - **Gotchas discovered**
    - Kestrel's `BindHost` for `0.0.0.0` shows up in the
      `IOException` message as
      `Failed to bind to address http://0.0.0.0:4318: ...`,
      but IPv6-only wildcard binds show up as `http://[::]:4318`.
      The detector matches all three forms.
    - SQLite read-only open mode refuses to create a missing
      file; the test for `OpenReadOnlyConnection` had to be
      updated to allow the bootstrap path.
    - `RequireHost` matches the **string** of the `Host`
      header, including the port. Setting the test client's
      `DefaultRequestHeaders.Host` to `"localhost:14318"`
      makes the filter match; `"localhost"` alone (default
      from `WebApplicationFactory`) does not.
    - `Microsoft.AspNetCore.TestHost` (the default
      `WebApplicationFactory<Program>` transport) does NOT
      actually bind a socket — so the bind-failure fallback
      in `Program.cs` can only be tested via a real
      `WebApplication.CreateBuilder` that actually invokes
      `Listen` (i.e. the `OtlpPortBindFailureEndToEndSpecs`
      pattern), NOT through the `TestServer` route group.
    - The `MohistWebRegistration` SPA fallback happily serves
      `index.html` for any unmatched path on the main port.
      Without an explicit guard for `/otel/v1/*`, `GET
      /otel/v1/traces` from the main port would return 200
      with the SPA shell. The new `StartsWithSegments("/otel/v1")`
      guard is a critical belt-and-braces alongside the
      isolation middleware.
    - `OtlpPortBindFailureEndToEndSpecs` originally asserted
      timeout-style behaviour (Task.WhenAny against
      Task.Delay) for the "main port not listening" case. The
      connect actually fails with `SocketException(ConnectionRefused)`
      (the OS sends RST), so the correct assertion is
      `Assert.ThrowsAnyAsync<SocketException>` +
      `SocketError.ConnectionRefused`.
  - **Patterns / API shapes established**
    - The OTLP route's success body is `new { }` (anonymous
      empty object), serialized as `"{}"` by `System.Text.Json`.
      This is the same shape every OTLP receiver returns.
    - The OTLP route's error body is
      `new { error = "..." }`, also JSON. OTel spec is
      permissive about error shape; this is the minimum that
      surfaces a human-readable message.

- **Learnings for future tasks:**
  - **Decisions made**
    - `OtelQueryRoutes` is registered through
      `MohistApiRegistration.MapMohistApi` (not behind a
      `RequireHost`) so the routes are reachable from the
      main API port. Port isolation is provided by
      `OtelPortIsolationMiddleware` (T-002), which only
      protects `/otel/v1/` and lets `/otel/api/*` through.
    - The query route reads the body itself rather than
      declaring a parameter binding. This is necessary
      because the keyword validation must run on the raw
      input string (the binding layer would normalize
      whitespace, stripping the comment-handling context).
    - `TraceQuerier.ExecuteRawQuery` does NOT add any extra
      timeout wrapping around the `Task` — the
      `CommandTimeout` on `SqliteCommand` is sufficient and
      matches what `Microsoft.Data.Sqlite` supports. Long
      queries are cancelled by the engine, which throws
      `SqliteException` (we surface it as 400 in the route).
    - `db_size_bytes` sums `otel.db`, `otel.db-wal`,
      `otel.db-shm`, and `otel.db-journal`. This makes the
      field meaningful immediately after writes (WAL has not
      yet checkpointed) and matches what `du -c` would
      report.
    - The spec acceptance says `db_size_bytes` reflects the
      `otel.db` file size; summing the WAL/SHM sidecars is a
      deliberate superset that matches the natural
      interpretation ("how much disk space does otel.db
      use?"). A pure main-file check would have been zero
      right after writes.
  - **Gotchas discovered**
    - `JsonSerializerDefaults.Web` produces camelCase by
      default. The spec mandates snake_case column names, so
      DTO records need `[property: JsonPropertyName("...")]`
      attributes per field (matching the `OtlpJson` POCO
      pattern). Without those the integration tests fail
      with `KeyNotFoundException` on `trace_id` /
      `service_name` / `collector_online`.
    - SQLite WAL mode keeps committed-but-uncheckpointed
      data in `otel.db-wal`. After `INSERT` +
      `connection.Dispose()`, the main file's `Length` is
      often still 0 until a checkpoint runs. Tests must sum
      all sidecar files or the
      `db_size_bytes > 0` assertion races the checkpoint.
    - `Microsoft.Data.Sqlite`'s default per-command timeout
      is 30 s. To enforce the 5 s `CommandTimeout` we set
      `cmd.CommandTimeout = (int)QueryCommandTimeout.TotalSeconds`
      on each call (a static const field, not a magic
      number).
    - The `OtlpRoutesWebApplicationFactory` from T-002
      creates the OTel database via `OpenReadWriteConnection`
      lazily on the first call. Integration tests that
      expect a fresh empty DB must call `_ = _factory.Services`
      in `InitializeAsync` so the WebApplicationFactory
      materializes its services (otherwise the otel.db may
      not exist when the route handler tries to read it).
    - `ATTACH DATABASE` is rejected at the HTTP layer by
      `ValidateSelectOnly` (the `ATTACH` keyword). It would
      also be rejected at the SQLite layer by the read-only
      connection (error `attempt to write a readonly
      database`). The route returns 400 in either case —
      the layered safety net works as designed.
    - `Microsoft.Data.Sqlite`'s `INSERT` on a read-only
      connection throws `SqliteException` with
      `SqliteErrorCode = 8` (`SQLITE_READONLY`). The route
      catches this in the same catch arm as syntax errors
      and surfaces it as 400 with the `sqliteErrorCode` in
      the response details.
  - **Patterns / API shapes established**
    - Route registration order in `MapMohistApi` matters
      for `RequireHost` / `MapGroup` interactions, but
      `OtelQueryRoutes` is registered in the global group
      (no `RequireHost`), so its position relative to
      `MapOtlpRoutes()` is purely cosmetic — both routes
      reach the same minimal-API pipeline.
    - `TraceQuerier.GetStatusAsync` swallows SQLite errors
      and returns zeros, so the status endpoint never 500s
      even when the database is corrupted / unreadable. The
      design rationale is that the status endpoint is the
      primary health probe for the OTel subsystem; a 5xx
      would defeat that purpose.
    - `TraceQuerier.ListAsync` uses parameterized queries
      (`$limit`, `$service`) rather than string
      interpolation. The `service_name` value is treated as
      a literal — no SQL injection surface.
    - The keyword allowlist uses
      `ReadFirstKeyword(normalized)` which only looks at
      the first whitespace- or parenthesis-bounded token.
      This is robust against leading whitespace, comments,
      and CTE prefixes.
  - **Cross-task invariants**
    - `OtelDb.OpenReadOnlyConnection` remains the only
      connection factory used by `TraceQuerier`. Any future
      query route must reuse this — opening a read-write
      connection from a query path would break the safety
      contract documented in design.md Decision 5.
    - `OtelCollectorStatus.IsPortBound` is the single source
      of truth for `GET /otel/api/status`'s
      `collector_online` field. Tests that need a known
      state call `SetPortBound(true|false)` on the singleton
      resolved via DI; the production path is `Program.cs`.
    - `TraceQuerier.MaxListLimit = 1000` is a public const.
      T-004 (`mo otel` CLI) should reuse this constant for
      any "list recent traces" command rather than
      hard-coding its own cap.
    - `TraceQuerier.ValidateSelectOnly` is `public static`
      and unit-tested in isolation. T-004's `mo otel
      query` does NOT use it (per design.md Decision 5:
      "CLI 不做关键字拒绝") — but the unit tests still
      prove the helper's correctness so T-003's HTTP-side
      gate is defensible.
    - `ExecuteRawQuery` returns `Dictionary<string,
      object?>` per row, so column names come straight from
      SQLite (snake_case). Any consumer serializing that
      dictionary to JSON must NOT add `PropertyNamingPolicy`
      overrides — the keys are already the wire format.
