## Codebase Patterns

- Preset resources use a separate `presets/` content root, while asset lookup reuses the packaged sibling-root fallback behavior from `SkillAssetRootResolver`.
- `PresetCatalog` accepts an explicit root for FakeFileSystem tests and returns `PresetCatalogResult` with available names for unknown presets.
- The manifest stores file references; response prompt files are read verbatim so `{{event.*}}` placeholders remain unrendered.

## Verify repair — round 2 (server spec test)

- After the CLI fix above, `npm test` still failed: 1 server spec test (`GenericLaunch_FollowUpRuntimeEvents_AppendNonEmptyTranscriptContent` in `GenericAgentSessionTranscriptAxisSpecs`) failed deterministically when run as part of the full 3006-test suite, but passed in isolation.
- Earlier round-2 hypothesis (dispatch retry grain-timer never fires because `PollOnceAsync` does not advance `FakeTimeProvider`) was wrong — advancing time did not fix it. Re-diagnosed against live grain state.
- Actual root cause: `SessionFollowupApiSpecs` registers a runner (`followup-api-{guid}`) into the collection-wide `RunnerRegistryGrain` but never unregisters it (no `IAsyncDisposable`). The registry is a single global grain shared by every class in the `IntegrationSessions` collection, and `ListEligibleRunnersAsync` ignores project affinity — it returns every registered runner. The leaked `followup-api` runner stays live and idle, so when a later `GenericAgentSessionTranscriptAxisSpecs` test launches an agent job, `AgentJobGrain.TryDispatchAsync` assigns the work to the leaked runner instead of the launching test's own runner. The launching test then polls its own runner, never sees the dispatch, and times out after 50 polls.
- Fix (test-only, no production code touched): make `SessionFollowupApiSpecs` implement `IAsyncDisposable` and unregister its runner on teardown, mirroring the sibling classes `GenericAgentSessionFollowupApiTestSupport` and `GenericAgentSessionCancelApiTestSupport`. The registry now reflects only the currently-running test's runners.
- Reverted the round-2 `PollOnceAsync` time-advance hack from the prior WIP commit (it was treating a symptom of the wrong cause).

## Re-review fix pass (issue-488 review.md findings N1–N3)

- **N1 (Medium) — agent 409-conflict re-resolve used a malformed project id:** `EnsureAgentAsync` sliced the agents URL path (`/api/projects/{id}`) and passed it as `projectId` to `ResolveAgentAsync`, which prepended `/api/projects/` again → a double-prefixed/escaped URL that 404s. Under the concurrent-install race (D3's 409 safety net) install printed `exists, skipped` then errored. Fix: thread the real `resolution.ProjectId` into `EnsureAgentAsync` and pass it to `ResolveAgentAsync`. Added `AgentInstall_AgentCreateConflict_ResolvesExistingAndBindsRulesToIt` — a stateful handler simulates the race (list empty → POST 409 → list returns the agent) and asserts install exits 0, re-resolves via the exact project-scoped agents URL, and both rules bind `agentId` to the re-resolved supervisor. Verified the test fails against the reverted bug and passes with the fix.
- **N2 (nit) — `ManagedAssetKind` validation error was hardcoded by label compare:** `TryValidatePrepared` picked the error string via `kind.Label == Skill.Label` instead of data-driving it. Added `InvalidPreparedMessage` to the `ManagedAssetKind` descriptor (`"no '*/SKILL.md' found"` / `"manifest.json not found"`); `TryValidatePrepared` now reads `kind.InvalidPreparedMessage`. A future asset kind gets its own message for free.
- **N3 (coverage) — three spec scenarios pinned at the narrowest level:**
  - Tail-append: `AgentInstall_CreatesAgentAndRulesInOrder` now asserts the rule POST bodies carry no `before`/`after` keys (anchors would reorder rules).
  - Verbatim placeholders at the HTTP boundary: new `AgentInstall_ResponsePromptPlaceholdersFlowThroughToRuleBodyVerbatim` seeds `{{event.*}}` prompt text and asserts the POSTed `responsePrompt` contains the tokens unchanged (catches accidental sanitization).
  - Partial pre-existence: new `AgentInstall_PartialPreexistence_CreatesOnlyTheMissingRule` — agent + supervisor-approval pre-exist, failure missing → exactly one POST (the failure rule), agent and approval reused unmodified.
