## Codebase Patterns

- Route handlers live in `packages/server/src/Mohist.Server/Api/IssueRoutes.*.cs` as `internal static` partial-class methods. `BuildRebaseTaskWith` lives in `IssueRoutes.Helpers.cs`; the rebase route in `IssueRoutes.Rebase.cs`.
- Helpers that take a `WorkflowRepositoryContext` fixture normally use the fully-qualified namespace (`Mohist.Server.Workflow.Domain.Run.WorkflowRepositoryContext`) inside the signature to avoid a `using` at the top of the file.
- `JsonSerializer.SerializeToElement(with, JSON.Options)` is the standard way to convert a `Dictionary<string, object?>` into the `JsonElement?` shape consumed by `RuntimeTaskInput.With`. The result is a JSON object that the dispatcher hands verbatim to Action input validation.
- `mohist/rebase` Action declares only `baseBranch`, `remote`, `squash`, `message`, `messageFrom` (`packages/runner/src/actions/built-ins.ts:236-242`). Anything else in `with` triggers `Action 'mohist/rebase' received unknown input '<key>'` from `validateActionInput`.
- The rebase route handler reads `runSnapshot` for two responsibilities that must be preserved:
  - line 37-39: returns Conflict `missing_repository_context` if absent (no task queued).
  - line 48-50: defaults `baseBranch` from the snapshot when the operator omits one.
  These are spec requirements 2 and 3 and are intentionally left as-is by T-001; only the mirroring of the snapshot into the Action `with` is removed.
