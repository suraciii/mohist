## T-001: Add filesystem API endpoints (backend)
Completed: 2026-04-06T16:04:00Z

Created `packages/cli/src/api/fs.ts` with two endpoints:
- `GET /api/fs/list?path=...` - directory listing via fs.readdirSync, filters to directories only, excludes hidden dirs (starting with .), returns `{ name, absolute }[]`
- `GET /api/fs/search?query=...&limit=50` - fuzzy directory search via system `find` command with maxdepth=4, path traversal guard ensuring resolved path stays under HOME, returns `{ name, absolute }[]`

Registered routes in `server/index.ts` at `/api/fs`.

Both endpoints follow existing API patterns: factory function (`createFsRoutes`), `ApiResponse<T>` wrapper, try/catch error handling, 400 for validation errors, 500 for internal errors.

Build passes. All 161 tests pass (1 pre-existing failure in cli-commands.test.ts unrelated to this change).

Learnings:
- `~` prefix expansion handled manually via `os.homedir()` replacement
- Path traversal guard: `path.resolve()` then `startsWith(home)` check
- `find` command uses `-iname` for case-insensitive matching
- No service dependency needed - fs.ts is self-contained using Node.js fs/path/os/child_process
