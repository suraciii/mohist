## T-001: AI-quality per-bucket trend

### Codebase Patterns

- **Pre-sized daily boundary idiom**: `GetCompletionBucketsAsync` (IssueQuerier.cs:345) emits 30 trailing UTC days by `Enumerable.Range(0, N).Select(i => today.AddDays(...))`. The trend reuses this verbatim — `today = DateOnly.FromDateTime(now.UtcDateTime.Date)` then `Enumerable.Range(0, 30).Select(i => today.AddDays(-29 + i))`.
- **Nullability rule for empty buckets**: `BuildWindow` (IssueQuerier.cs:720-722) returns null rates when `SampleCount == 0`. The trend mirrors it: `double? firstTimeRightRate = sampleCount == 0 ? null : (double)FirstTimeRightCount / sampleCount;` — empty bucket is distinguishable from a genuine 0%/100%.
- **Single-pass classification**: `ClassifyRuns` returns `(isFirstTimeRight, stageRework)`. The trend reuses both verbatim: FTR numerator = `isFirstTimeRight`; any-stage rework = `stageRework.Values.Any(v => v)` — no second classification path.
- **Ship-time anchoring**: `window30dFrom = now.AddDays(-30); window30dTo = now`. The trend condition `shipTime >= window30dFrom && shipTime <= window30dTo` matches the existing 30d scalar window membership — fold the trend accumulation INTO the same branch as the 30d scalar to avoid duplicate checks.
- **Test helpers**: `SeedIssue(db, project, idSuffix, workflowRunId, status)` for issue rows; `SeedEvent(db, issueId, type, time, workflowRunId)` for events; `SeedWorkflowRunAsync(db, runId, state)` for workflow runs; `QualityRunState(runId, [(stage, [(checkName, title, repairCount)])])` for run state. `IssueQuerier.WorkCompletedType` is `com.mohist.issue.work-completed`.

### Decisions Made

- **Folding the trend into the 30d branch**: rather than two consecutive `if (shipTime >= window30dFrom && shipTime <= window30dTo)` checks, the trend bucket accumulation is nested inside the 30d scalar accumulation. Same condition, no extra branch.
- **Indentation fix**: prior diff had `public async Task<QualityMetricsResult>` at column 0; fixed to 4-space indent under the class.
- **DTO From/To serialization**: used `ToString("o")` (round-trip with offset) matching `BuildWindow`'s format — keeps the trend and window fields consistent.

### Tests

- **Querier**: 8 new cases — pre-sized 30-day shape, per-bucket FTR rate, per-bucket rework-any-stage, multi-stage-counts-once, empty-bucket-null-independent, non-shipped-excluded, ship-time anchoring, additive-and-unchanged-scalars.
- **API**: 3 new cases — trend-alongside-windows, zero-sample-200-with-null, 404.

### Gotchas

- **Pre-existing flaky delivery-time API tests** (DeliveryTimeMetrics_DeliveredIssueWithWorkStart_ReturnsLeadAndCycle and 3 others) fail under parallel test runs but pass in isolation. Unrelated to this change; left alone per the "avoid unrelated refactors" policy.
- **Trend "empty bucket" assertion** must use a single-bucket-aware predicate (`Assert.Single(predicate)` would match 29 buckets in a near-empty project); use the first point directly — it's always 29 days before `now` and zero-count in any fixture without backdated ships.

## T-002: FTR trend line widget with rework overlay

### Codebase Patterns

- **Single-fetch composition**: `useQualityMetrics()` already returns scalars + trend (T-001 wired the additive `trend?` field onto the same response). The widget calls the hook once and pulls `data.trend` — no second fetch, no second query key.
- **Three-state routing via ChartContainer**: `ChartContainer` accepts `status: 'loading' | 'error' | 'empty' | 'resolved'` and renders the appropriate placeholder. Empty-state text is passed as `emptyAction` so each chart names its own next action.
- **Null-bucket line gaps**: `LineSeries.splitSegments` (LineSeries.tsx:15) splits `(LinePoint | null)[]` into sub-paths around `null` gaps. Mapping per-bucket rate to `null` when the bucket has no samples is enough — no need to special-case 0%.
- **Single-axis percentage scale**: both FTR and rework are proportions in [0,1], so a fixed 0/25/50/75/100 percentage axis is honest — no data-driven `niceCeil`, no dual axis (D5).
- **Shape-disambiguated legend**: `ChartLegend` `line` swatch renders a solid polyline + markers, `dashedLine` swatch renders the same path with `strokeDasharray="2 2"`. Using shape (not color) lets color-blind users tell the two series apart — the spec's non-color-legend requirement.
- **Theme token contract**: `stroke-chart-N` / `fill-chart-N` for series colors; `tabular-nums` for numeric labels (inherited via `ChartAxes`); `useReducedMotion` from `LineSeries` controls the opacity transition on paths/markers.

### Decisions Made

- **Trend is optional on the wire**: `trend?: QualityTrendDto` so an old server omitting it leaves the widget in the empty state (the acceptance criterion "graceful degradation against an older server").
- **Overlay toggle is local state, not a URL param**: a single `useState<boolean>(false)` is enough; no need for a query-string or persisted preference for a per-widget view toggle. Disabled when the series carries no rework samples.
- **One ChartInner component for both states**: switching between FTR-only and FTR+rework is a single conditional render of a second `LineSeries` plus a 2-entry legend. The single-axis and tick layout don't change.
- **No fixed y-axis ceiling**: FTR and rework are bounded in [0,1], so a fixed 0/25/50/75/100 percentage tick set is sufficient — no `niceCeil` math, simpler and visually stable.
- **Mount ordering**: `ProductivityZone` now reads `<QualityPanel /> <FtrTrendChart /> <InvestmentPanel />` — FTR-trend sits beside its scalar sibling (`QualityPanel`), per the design.

- **Existing tests regression**: QualityPanel 6/6, CostTrendChart 31/31, ThroughputChart 13/13, CycleTimeChart 12/12, StageDurationChart, CompletionTrend, InvestmentPanel, SnapshotRow, EpicProgressList — all green.

### Gotchas

- **`LineSeries` doesn't render `fill="none"` as an SVG attribute**: it puts `fill-none` in `className` (Tailwind utility). Tests that check the path has `fill="none"` need to assert on the className, not the attribute. `CostTrendChart.test.tsx` does this correctly.
- **`ChartLegend` returns null when `entries.length <= 1`**: with only the FTR series active (overlay off), the legend collapses and there is no `chart-legend` testid in the DOM. This is intentional — the legend's job is to disambiguate the two series, not to label a single series.
- **LSP lag on first build**: the editor flagged implicit-any on `points.find((p) => ...)` and similar before `tsc` ran on the new module. `tsc -b` resolves it cleanly; no real type errors.
- **Mocking `useQualityMetrics`**: the hook is in `entities/issue/api/quality-metrics.ts` (not the barrel index). `vi.mock('../../../entities/issue/api/quality-metrics', ...)` matches the path that the component actually imports from, while still leaving `useQualityMetrics` exposed through the barrel for other consumers.
