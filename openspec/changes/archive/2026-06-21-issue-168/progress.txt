## Codebase Patterns

- FSD widget layout: `widgets/<name>/{index.ts, ui/, model/}`. The `index.ts` is the public API; only files re-exported from it are importable from outside the widget.
- TanStack Query keys are namespaced by entity: `['agent-activity', params, projectId]`, `['agent-status', projectId]`, `['agent-sessions', params, projectId]`. Reuse `useAgentActivity()` directly — adding a separate fetch violates the no-new-query contract for read-only composites.
- Session/issue cards consume the `SessionCard` projection from `widgets/coder-session/model/activity-cards.ts` (`useActivityCards()` → `activeCards`/`statusCounts`/`slotUsage`). This is the canonical shape for session list/card widgets; do not re-project `useAgentActivity` in a new model module.
- Status pill color tokens are reused across surfaces: `bg-blue-100`/`amber-100`/`green-100`/`red-100` for `active`/`waiting`/`completed`/`failed`. The top-bar `shared/ui/StatusBar.tsx` includes runner-badge `children`, so dashboard zones should not import the component itself — reuse only the color tokens.
- Workflow-stage `STAGE_COLORS` (lowercase `build`/`plan`/`review`/`check`/`integrate`) is defined locally in each widget that needs it; lookup is `STAGE_COLORS[card.issueStage.toLowerCase()] ?? 'bg-gray-100 text-gray-700'`. The `kanban-board/model/stage-colors.ts` map is keyed by `IssueStatus` enum (workflow states, not stages) — different map.
- Context-health color comes from `widgets/session-health/ui/ContextHealthIndicator` — it accepts `(contextWindowUsed, contextWindowSize, contextUsagePercent)` and emits `data-testid="context-health-indicator"` with `data-status="green|yellow|red"`. Use it instead of rendering raw percentages.
- Half-width zone rendering: titles and single-line fields use `-webkit-line-clamp: 1` to prevent overflow. Cap list lengths and add a `+N more in <Page>` footer link to avoid unbounded scroll inside a dashboard tile.
- Test pattern for TanStack Query widgets: `vi.hoisted` a `mocks` object, mock the queries module with `vi.mock('@/entities/.../api/queries', ...)`, render with `QueryClientProvider` + `ProjectProvider` + `MemoryRouter`. Test that the rendered query keys only contain `'agent-activity'` to assert no new query is introduced.
- Tests use `data-testid` attributes per element (e.g., `pulse-compact-card`, `pulse-pill-active`, `pulse-capacity-header`). Tests assert on these rather than text matching alone.
- `DashboardZone` wrapper is the canonical mount-point container for the four dashboard slots (`attention`/`pulse`/`productivity`/`digest`). Slot identity (`data-testid`, `data-zone`, `aria-label`) and visual placeholder styling are byte-identical to the original `DashboardZonePlaceholder`. Future zones (Attention/Productivity/Digest) extend via `renderZoneContent(id)` in `DashboardPage.tsx` — return `null` to keep an unimplemented slot as an empty placeholder.
- Vitest must be run via the npm workspace script (`npm run test:run -w packages/web`) or via `npx vitest run` from inside `packages/web/`. Running `vitest run <path>` from the repo root triggers a vitest 1.6.1 fallback that fails all suites with "Vitest failed to find the current suite" — this is a config quirk of the dual-version workspace, not a test failure.
- `vi.mock('../../../entities/agent', ...)` works as a module-level mock for both `useAgentStatus` and `useAgentActivity`; combine it with `vi.hoisted` for `mocks.agentActivity` so test bodies can mutate the mock between assertions.

## Task T-001: Implement dashboard-pulse widget (PulseZone + CompactSessionCard)

- What was implemented
  - `packages/web/src/widgets/dashboard-pulse/index.ts` re-exports `PulseZone` and `CompactSessionCard`.
  - `packages/web/src/widgets/dashboard-pulse/ui/PulseZone.tsx` renders a capacity header (`active/max` + 4 status pills), the active-session card list (capped at 4 with `+N more in Activity` overflow link), and an empty-state affordance. Reads from `useActivityCards()`.
  - `packages/web/src/widgets/dashboard-pulse/ui/CompactSessionCard.tsx` renders a slimmed variant of `ActiveSessionCard`: issue number, stage badge, current task title (with `taskDescription`/`issueTitle` fallback), task progress bar, token·cost usage line, and context-health color. Drops elapsed time, model, activity previews, tool counts, failure category, and anomalies.
  - `packages/web/src/widgets/dashboard-pulse/ui/PulseZone.test.tsx` (10 tests) covers capacity header values, status pills, empty state, card list cap, overflow link text and href, non-active sessions hidden, re-render on data update, and absence of new query keys.
  - `packages/web/src/widgets/dashboard-pulse/ui/CompactSessionCard.test.tsx` (13 tests) covers issue/stage/title display, title fallback chain (title → taskDescription → issueTitle), task progress bar (present and absent), token-only / cost-only / both / neither usage lines, context-health indicator (red threshold + null contextWindowSize), absence of elapsed/model/preview/tool/failure/anomaly text, and STAGE_COLORS for plan stage.
  - All 23 tests pass via `npm run test:run -w packages/web -- dashboard-pulse`; `npm run typecheck -w packages/web` is clean.

- Files changed
  - `packages/web/src/widgets/dashboard-pulse/index.ts`
  - `packages/web/src/widgets/dashboard-pulse/ui/PulseZone.tsx`
  - `packages/web/src/widgets/dashboard-pulse/ui/CompactSessionCard.tsx`
  - `packages/web/src/widgets/dashboard-pulse/ui/PulseZone.test.tsx`
  - `packages/web/src/widgets/dashboard-pulse/ui/CompactSessionCard.test.tsx`

- Learnings for future tasks
  - Decisions made
    - Followed FSD widget layout (`ui/` for components, `index.ts` for public API). Did not introduce `model/` — the widget is purely presentational over `useActivityCards`.
    - Reused the local `STAGE_COLORS` map pattern from `widgets/coder-session/ui/SessionCard.tsx` (lowercase keys, gray fallback). Did not extract to a shared module because that would be an unrelated refactor — the same map is currently duplicated in `SessionCard.tsx` and `CompactSessionCard.tsx`; future task may consolidate.
    - Reused the same pill color tokens (`bg-blue-100/amber-100/green-100/red-100`) as `shared/ui/StatusBar.tsx` but did not import the component (its runner-badge `children` slot is irrelevant inside a zone).
    - `UsageLine` helper omitted when both `totalTokens` and `costAmount` are null, rather than rendering an empty placeholder — matches spec scenario "omits fields whose underlying values are absent".
  - Gotchas discovered
    - `SessionCard.issueStage` is a string like `'Build'`/`'Plan'` (mixed case), but `STAGE_COLORS` is keyed lowercase — always `.toLowerCase()` before lookup or fallback to `bg-gray-100 text-gray-700`.
    - `SessionCard.title` is `s.currentWorkItem?.title ?? s.taskDescription` — it can already be null when both work item and task description are absent, so the card must also fall back to `issueTitle` for non-empty display.
    - `ContextHealthIndicator` returns `null` when context data is missing — wrap it conditionally in the parent (e.g., `card.contextWindowSize != null && card.contextWindowSize > 0 && <ContextHealthIndicator ... />`) so the indicator only renders when there is meaningful data; tests assert `queryByTestId('context-health-indicator')` is null when contextWindowSize is null.
    - The TanStack Query test pattern using `vi.mock('@/entities/agent/api/queries', ...)` with a hoisted `mocks.activity` object is the established convention for this codebase — copy it as-is for any future widget that depends on activity data.
  - Patterns / API shapes established
    - Capacity header testid surface: `pulse-capacity-header`, `pulse-slots`, `pulse-status-pills`, `pulse-pill-{active|waiting|completed|failed}`.
    - Card list testid surface: `pulse-card-list`, `pulse-compact-card` (with `data-issue-number`), `pulse-compact-stage`, `pulse-compact-title`, `pulse-compact-usage`, `pulse-compact-progress`, `pulse-overflow-link`.
    - Empty state testid: `pulse-empty-state`. Zone root testid: `pulse-zone`.
    - Constants: `MAX_VISIBLE_CARDS = 4` lives in `PulseZone.tsx` — easy to tune if product changes the cap.
  - Cross-task invariants
    - PulseZone MUST consume `useActivityCards()` and never introduce a new query key. The T-002 (mount into DashboardPage via `renderZoneContent`) must not change this — it is a wiring task only.
    - The empty-state affordance is rendered inside the card-list area only; the capacity header always renders. T-002 should not collapse the zone when empty.
    - The overflow link target is `useProjectPath('/activity')` — it must remain a link to the Activity page, not an in-zone expansion.

## Task T-002: Mount PulseZone into Dashboard via DashboardZone wrapper and update dashboard-shell tests

- What was implemented
  - `packages/web/src/pages/dashboard/ui/DashboardZone.tsx` — presentational wrapper that renders the slot container with byte-identical attributes (`data-testid="dashboard-zone-<id>"`, `data-zone`, `aria-label`) and accepts optional `children`. Owns the `DashboardZoneId` union type.
  - `packages/web/src/pages/dashboard/ui/DashboardPage.tsx` — replaces `DashboardZonePlaceholder` usage with `DashboardZone`, adds a `renderZoneContent(id)` switch returning `<PulseZone />` for the `pulse` slot and `null` for the other three. Imports `PulseZone` from the existing `widgets/dashboard-pulse` public API (no widget refactor needed).
  - `packages/web/src/pages/dashboard/ui/DashboardZonePlaceholder.tsx` — deleted; replaced by `DashboardZone` (the wrapper covers both filled and empty slot rendering).
  - `packages/web/src/pages/dashboard/ui/DashboardPage.test.tsx` — updated to assert the MODIFIED `dashboard-shell` contract:
    - All four slot identities (`data-zone`, `aria-label`) remain stable.
    - `dashboard-zone-pulse` contains the `pulse-zone` element (i.e., mounts `dashboard-pulse` content).
    - `attention`/`productivity`/`digest` slots render as empty placeholders (`toBeEmptyDOMElement()` and explicit `querySelector('[data-testid="pulse-zone"]')` null checks).
    - Pre-existing assertions (Kanban absence, project empty state, dialog open) preserved.
    - Added a `useAgentActivity` mock alongside the existing `useAgentStatus` mock so `PulseZone` (which calls `useActivityCards → useAgentActivity`) doesn't trigger a real fetch.
  - All 6 updated DashboardPage tests pass; the prior 23 dashboard-pulse widget tests remain green; full suite: 128 files / 1889 tests pass.
  - `npm run typecheck -w packages/web` is clean.

- Files changed
  - `packages/web/src/pages/dashboard/ui/DashboardZone.tsx` (new)
  - `packages/web/src/pages/dashboard/ui/DashboardPage.tsx`
  - `packages/web/src/pages/dashboard/ui/DashboardPage.test.tsx`
  - `packages/web/src/pages/dashboard/ui/DashboardZonePlaceholder.tsx` (deleted)

- Learnings for future tasks
  - Decisions made
    - Kept the `DashboardZoneId` union type in `DashboardZone.tsx` rather than colocating it with `DashboardPage.tsx`, because the wrapper is the natural owner of the slot contract (slot identity = mount-point contract).
    - Made `children` optional and rendered inside the section unconditionally. When `renderZoneContent` returns `null` the slot still renders the placeholder styling (dashed border, min-height) — `toBeEmptyDOMElement()` passes because no children are appended.
    - Single `switch` over `DashboardZoneId` for `renderZoneContent` rather than a registry map. The current four-zone scope is small enough that a switch is clearer; future zones add one `case` each (Attention/Productivity/Digest).
  - Gotchas discovered
    - When the wrapper renders `children` as `{children}` and `children` is `null`/`undefined`, React renders nothing — no whitespace text nodes — so `toBeEmptyDOMElement()` from `@testing-library/jest-dom` passes. Avoid conditionally calling `children` or wrapping in `{children ?? ''}`; pass `children` directly so the slot stays truly empty.
    - The DashboardPage test must mock `useAgentActivity` from `entities/agent` (not just `useAgentStatus`) because `PulseZone → useActivityCards → useAgentActivity`. Forgetting this surfaces as a real fetch attempt during the test, which would either hit the network or fail on an unmocked URL.
    - `vi.mock('../../../entities/agent', () => ({ ... }))` without `importOriginal` still works for ad-hoc mocks — only needed when the production module exports more than the mocked hooks. The dashboard test mocks only `useAgentStatus` + `useAgentActivity`, which is everything `DashboardPage.tsx` consumes.
  - Patterns / API shapes established
    - Slot-mount contract: `<section data-testid="dashboard-zone-<id>" data-zone="<id>" aria-label="<name>" className="rounded-lg border border-dashed …"> {children} </section>`. Stable contract for downstream zone views; any new zone wrapper must keep these attributes.
    - Empty-zone convention: `renderZoneContent(id)` returns `null` for unimplemented slots. The wrapper renders the placeholder appearance when children are null, satisfying both "unimplemented slot renders empty" and "implemented slot renders capability content" in one component.
  - Cross-task invariants
    - The `PulseZone` widget is now mounted by `DashboardPage` at the `pulse` slot. Adding more zones in future tasks MUST go through `renderZoneContent` in `DashboardPage.tsx`, not by editing `DashboardZone.tsx` (the wrapper is identity-only).
    - The slot contract (`data-testid="dashboard-zone-<id>"`, `data-zone`, `aria-label`, dashed-border styling) MUST remain stable across all future zone additions — downstream selectors and accessibility tooling depend on it.
