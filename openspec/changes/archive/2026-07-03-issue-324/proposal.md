## Why

Insights (M1/M2) consolidated every trend chart and the Signal Summary onto `/insights`, but each visualization is locked to its own hard-coded window — cycle/completion/cost/stage-duration at 30d, quality at 7d+30d, cumulative-flow pinned at 90d, agent-usage at 7d. An operator cannot replay a different period: "how was all of last month?" or "the last three months?" is impossible because every chart freezes on the window its endpoint was compiled with. The charts and the Signal Summary verdicts are already co-located; M3 closes the loop by giving that single retrospective space one global time-range control (7d / 30d / 90d) that every signal and chart answers to, so a range switch re-bases the whole page in one motion.

## What Changes

- Add a global time-range selector to `/insights` offering exactly three presets — `7d`, `30d`, `90d` — held as page-level state by `InsightsPage` and propagated down to every chart and the Signal Summary. No custom from/to picker (non-goal).
- Thread the selected range through the eight Insights data hooks — `useCompletionThroughput`, `useCompletionTrend`, `useCumulativeFlow`, `useDeliveryTime`, `useStageDuration`, `useQualityMetrics`, `useAgentUsage`, `useCostRollup` — as a query parameter, and fold it into each hook's `queryKey` so a range switch fetches fresh data and never serves a stale cache from another range.
- Parameterize the server metrics endpoints to accept the range and compute their current **and** previous comparison windows from it: `completion`, `delivery-time`, `stage-duration`, `quality`, `cumulative-flow`, and `agent-usage` (the six AC-named endpoints), plus `approval-wait` for contract uniformity. Omitting the parameter MUST reproduce today's exact fixed windows (back-compat — see Impact for the Dashboard consumers that share these hooks).
- **BREAKING (contract reversal, no DTO field removed):** supersede the cumulative-flow design D6 contract (`CumulativeFlowQuerier.TrailingWindowDays = 90`; `dashboard-cumulative-flow` spec — *"The trailing window SHALL be fixed and SHALL NOT be user-configurable"*). The CFD window becomes range-driven (default 90d preserves today's behavior); the snapshot read path and DTO are unchanged.
- Add a range-aggregation path to agent cost (`/agent/cost`): today it exposes only `today` + all-time `total` + a fixed 30d current/previous windowed figure, with no range dimension. The windowed figure's window becomes range-driven so `InvestmentPanel` and the Signal Summary's investment verdict re-base with the selector. `costPerShip` (all-time) is unaffected.
- Resolve the quality double-window DTO (`Window7d` / `Window30d`) within this change: the lean is to keep the DTO shape intact (non-goal: no existing field removed) and let the range drive the primary (30d-equivalent) window, its previous window, and the 30-day trend, while `Window7d` stays a fixed short-term lens answering a different question. The final call is recorded in design.md.
- `EpicProgressList` (`useEpics`, a live in-progress snapshot with no time window) is exempt from the selector.

## Capabilities

- `insights-time-range`: The global 7d/30d/90d selector on `/insights` — its placement and default selection, page-level state ownership, propagation to all eight chart hooks and the Signal Summary, the per-hook `queryKey` isolation that prevents stale cross-range cache, and the `EpicProgressList` no-window exemption. Frontend-only contract; depends on the two server capabilities below.
- `issue-metrics-time-range`: Server-side uniform `range` parameter accepted by the issue metrics endpoints (`completion`, `delivery-time`, `stage-duration`, `quality`, `cumulative-flow`, `approval-wait`), each computing its current and previous windows from the range, with back-compat fallback to today's fixed windows when the parameter is omitted. Includes the formal reversal of the cumulative-flow D6 "fixed, not user-configurable" contract (`CumulativeFlowQuerier`, `dashboard-cumulative-flow` spec) to range-driven with a 90d default, and the quality double-window decision.
- `agent-cost-time-range`: Server-side range dimension for agent spend — the new range-aggregation path on `/agent/cost` (and `/agent/usage`) so the windowed cost figure and the usage timeseries re-base to the selected range, with back-compat fallback to the current fixed 30d / 7d windows when the parameter is omitted. Distinct seam because agent cost has no existing range parameter (only today + all-time + fixed windowed) and lives in `AgentSessionQuerier`, separate from the issue-metrics read path.

## Impact

- **Server** (`packages/server`):
  - `Issue/Services/IssueQuerier.cs` — `GetCompletionBucketsAsync` / `GetDeliveryTimesAsync` / `GetStageDurationsAsync` / `GetQualityAsync` / `GetApprovalWaitAsync` gain a range input (or day-count) replacing the hard-coded `AddDays(-30)` / `-60` / `-29` / `-59` literals; current+previous windows both scale.
  - `Issue/Services/CumulativeFlowQuerier.cs` — `TrailingWindowDays = 90` becomes the default of a range-derived window; the D6 doc-comments and the `dashboard-cumulative-flow` "not configurable" requirement are superseded.
  - `Workflow/Services/Sessions/AgentSessionQuerier.cs` — `GetCostWindowedAsync` (fixed 30d current/previous) and `GetUsageTimeseriesAsync` (fixed 7d, 7 buckets) accept the range; bucket granularity for 90d usage needs a decision (week buckets vs. 90 daily buckets) recorded in design.
  - Route files `IssueRoutes.{Metrics,DeliveryTimeMetrics,StageDurationMetrics,QualityMetrics,ApprovalMetrics,CumulativeFlow}.cs` and `AgentRoutes.cs` — bind the new `range` query parameter, validate the three presets, and pass it through.
- **Web** (`packages/web`):
  - `pages/insights/ui/InsightsPage.tsx` — holds the selected range in state, renders a new selector control, and passes the range to `SignalSummary` and `InsightsCharts` (which forwards it to each panel/hook).
  - The eight hooks in `entities/issue/api/` and `entities/agent/api/` — accept a range arg, append it to the URL, and fold it into `queryKey`. `EpicProgressList` is untouched.
  - Per-chart window badges added in M2 remain coherent (they already derive from returned `rangeFrom`/`rangeTo`).
- **Shared-hook back-compat:** `useCostRollup` is also consumed by the Dashboard `FactoryStatusHeadline`, and `useApprovalWait` by the Dashboard `AttentionHero`. Per the non-goal (no selector on non-Insights pages), these Dashboard consumers keep calling the hooks without a range, which MUST hit the back-compat default branch — so the default-omitted path reproducing today's windows is a hard contract, not a nicety.
- **Tests:** server spec/unit tests for each parameterized endpoint (range drives window; omit ⇒ fixed default; unknown value ⇒ 400); web tests for selector state, queryKey isolation across ranges, and that Signal Summary + every chart re-base on switch. `npm test` (server) and `npm run typecheck -w packages/web` + `npm run test:run -w packages/web` must pass with no regression to the existing metric specs.
- **Risk** (high, carried from issue): cross-cutting change spanning 6+ server endpoints, two queriers, the cumulative-flow D6 contract reversal, a new agent-cost aggregation path, and 8 frontend hooks — one shared by the Dashboard. Blast radius is wide; the default-omitted back-compat branch is the chief safety line.
