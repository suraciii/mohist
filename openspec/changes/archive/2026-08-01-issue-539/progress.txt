## Codebase Patterns

- `WorkflowQuerier` is conventionally registered as scoped, while cross-request read state must use an `ISingletonService`; conventional singleton registration is `AsSelf()` only, so interface seams need an explicit forward registration in `MohistServiceRegistration`.
- Workflow status specs can use `TestSqliteDatabase.CreateMigrated()` plus `WorkflowDefinitionResolverTestFactory`; the status definition resolver is intentionally run per call.
- `WorkflowRuns.ETag` is an EF shadow property and is queried with `EF.Property<long>(row, "ETag")`; direct test state writes must increment the shadow value when they model a store save.
