## Codebase Patterns

- `TaskLogPanel.tsx` uses `useIssueWorkflowTaskLog` from `entities/issue` (REST snapshot) + `useEventsConnection` + SignalR `OnTaskLogDelta` envelope from `shared/api/events-hub` to live-append. The panel already merges live deltas into the React Query cache via `queryClient.setQueryData(...)` using `mergeTaskLogDelta`, and invalidates on terminal status.
- Existing visual styling: panel root uses `rounded border border-slate-200 bg-white px-2 py-1.5 space-y-1`; header line uses `text-[10px] uppercase tracking-wide text-slate-500`; scroll container uses `max-h-64 overflow-y-auto rounded bg-slate-900 text-slate-100 font-mono text-[11px] leading-snug p-2`; lines render timestamp (`text-slate-500`), `[source]` in `text-sky-300`, then `text` body.
- Phase 1 line model is `{ seq, timestamp, source, text }` — there is intentionally **no level** field. Spec mandates filter dimension is `source`, chips use **neutral slate palette**, NOT `LEVEL_CHIP_COLORS`.
- `LogsPage` (system logs) is the reference interaction pattern: search input + chip multi-select (`Set<LogLevel>` opt-in) + `Blob` export + scroll-aware auto-follow (`userPausedAutoFollow` flag, `distFromBottom > 10` threshold). TaskLogPanel mirrors **the pattern**, not the code (different line models, different chip semantics).
- Test harness in `TaskLogPanel.test.tsx` provides `buildHarness`, `makeLine`, `makePage`, `makeEnvelope`, `mockConnectionBuilder`, `flushAndGetLastConnection`, `renderWithHarness`. Mocks `getIssueWorkflowTaskLog` and `HubConnectionBuilder` from `@microsoft/signalr`.
- `index.ts` re-exports mocks: `vi.mock('../../../entities/issue/api/client', ...)` patches `getIssueWorkflowTaskLog`.

## Decisions

- Source chips use opt-out `disabledSources: Set<string>` (NOT opt-in `enabledSources`) per design D4 — data-driven sources grow during live append, opt-out keeps new sources visible by default.
- `disabledSources` is `useMemo` per render (avoid extra renders on rapid toggle), and chips are derived as `Array.from(new Set(lines.map(l => l.source))).sort()` (lexicographic) per design D3.
- Single compositional `useMemo` over `[lines, disabledSources, searchQuery]` returning filtered array; **both** rendering and download consume this array (WYSIWYG).
- Download filename pattern: `task-logs-<taskId>-YYYY-MM-DD.txt` where date = `new Date().toISOString().slice(0, 10)`.
- Scroll-aware follow: `userPausedAutoFollow` flag from scroll handler (distFromBottom > 10 pauses), follow effect keyed on `filtered.length`.
- Boundary priority: loading > error > lines.length===0 (empty) > filtered.length===0 with split (searchQuery wins over source).

## Gotchas / Non-Obvious

- Phase 1/2 follow effect must NOT regress: even if user scrolled to bottom and filtered view changes, follow should re-engage when pinned to bottom. The new effect simply gates force-scroll on `!userPausedAutoFollow`.
- `subscribedReconnectVersionRef.current` and connection ref logic must be preserved exactly for non-regression (Phase 2 T-004).
- Live append tests reset state — need to ensure new tests don't interfere; use separate `describe` block.
- a11y config in `vitest.a11y.config.ts` excludes `tests/a11y/**` from default config; tests there run with `--config vitest.a11y.config.ts`. Structural axe rules are the same as in `settings-a11y.test.tsx`.
- Download button disabled when `filtered.length === 0`; spy `URL.createObjectURL` to assert Blob + filename.
- For boundary "no-source-filter" message test: must use non-empty lines, disable all sources, with empty searchQuery so search doesn't take priority.
- For scroll-pause test: the follow effect should run only if not paused; we can simulate by setting `scrollTop = smallNumber` with a scroll height > clientHeight + 10. We don't actually need to fire real scroll events — we directly set `userPausedAutoFollow` via test rendering with content taller than viewport... Actually, the cleanest test: render with content, fire a scroll event on the scroll container with offset, verify scrollTop is NOT reset to scrollHeight on subsequent line append.

## After Implementation

- All 37 TaskLogPanel tests (21 existing + 16 new) pass green; all 4074 web tests pass green. Typecheck is clean. a11y suite has 24 tests (21 existing + 3 new) all green.
- Filtered/download UX:
  - `useMemo` over `[lines, disabledSources, searchQuery]` produces `filtered`. Both render and download consume `filtered`.
  - Source chips: data-driven from `lines.map(l => l.source)`, lex-sorted, opt-out `disabledSources`. New sources from live append stay visible by default.
  - Search haystack: `text + source`, both lowercased. Case-insensitive.
  - Download: Blob over `filtered.map(l => l.text).join('\n')`, filename `task-logs-<safeTaskId>-YYYY-MM-DD.txt`. disabled when `filtered.length === 0`.
  - Filename `safeTaskId` replaces unsafe chars with `-` to avoid filesystem surprises.
- Scroll-aware follow: dedicated `useEffect` attaches scroll listener to compute `distFromBottom > 10` and toggles `userPausedAutoFollow`. Follow effect re-keys on `filtered.length` (not raw `lines.length`).
- Boundary priority: `isLoading > isError > lines.length === 0 > (search wins over source)`. Distinct testids for empty/no-search/no-source match for unambiguous assertions.
- a11y: search input has `aria-label="Search log lines"`, chips are `<button type="button">` with text content as accessible name, download is `<button type="button">` with `aria-label="Download execution log"`. Decorative SVGs use `aria-hidden="true"`.
- DOM order: search → download (in same flex row of header) → chips (next row) → scroll body. Test asserts both are keyboard-reachable AND tab-through works.
- Test harness gotchas:
  - `mockedGetIssueWorkflowTaskLog.mockReturnValueOnce` was unreliable across `useQuery` retries; using `mockImplementation` with a stable `page` object works reliably.
  - For the loading/error boundaries, set the mock **before** calling `render` and **do not** use `buildHarness` (which would override the mock).
  - `vi.spyOn(document, 'createElement')` lets us capture `<a download>` click events without triggering real browser download — captures `download` attribute and `href` for assertions.
  - `expect(...).toHaveAccessibleName(...)` from jest-dom checks the accessible name; chips pass because their text content is their accessible name.
  - For "AND composition" test: ensure the only **enabled** source is the one whose match we want. Disabling the wrong chip leaves its line still visible (which would still pass search).
- Phase 1/2 non-regression: existing 21 TaskLogPanel tests still pass without modification. Render, subscription, merge, terminal-state cache invalidation all unchanged.
