## Codebase Patterns
- Event delivery progress for T-001 lives directly on the three event row entities as nullable `DispatchedAt`; existing `List*Async` paths intentionally keep ignoring it so append/list semantics stay unchanged.
- `IEventStore.ListUndeliveredAsync` is implemented as one raw SQLite `UNION ALL` query through `db.Database.SqlQueryRaw<UndeliveredSqlRow>` in `EventStore`, then mapped into the `UndeliveredEvent` record with `EventOrigin`.
- `MarkDispatchedAsync` routes by event source prefix (`/mohist/issues/`, `/mohist/epics/`, otherwise workflow runs) and updates only the matching `(Source, Id)` row; missing rows are treated as no-op.
- The first partial-index usage in the repo is on the three event tables in `MohistDbContext` with `.HasFilter("\"DispatchedAt\" IS NULL")` and explicit names `IX_<Table>_Undelivered`.
- Event-store delivery-progress tests use in-memory shared-cache SQLite plus `EnsureCreated`, not migrations, so T-001 can verify model behavior before the unified migration task lands.
- `IDeadLetterStore` is registered from `AddCloudEventBus()`, which is already called by both `MohistServiceRegistration` and `MohistSiloRegistration`; this keeps dead-letter DI aligned with the event-bus composition point without duplicating registration in both roots.
- `DeadLetterStore.ListAsync` follows the repo's usual newest-N query shape: take descending by time/id to honor limit, then re-order ascending for stable chronological inspection output.
- T-003 adds explicit `IX_WorkflowRunEvents_Type_Time` and `IX_IssueEvents_Type_Time` in `MohistDbContext`; the acceptance test inspects SQLite index metadata after `EnsureCreated` and asserts `EpicEvents` lacks a `(Type, Time)` index.
- T-004 unified migration was scaffolded as `20260708015352_AddEventDeliveryProgressAndDeadLetters`; generated `Up` already used `filter: "\"DispatchedAt\" IS NULL"` for all three partial indexes, but `Down` needed a manual reorder to satisfy the task's expected drop sequence (indexes -> columns -> DeadLetters table).
- After the migration landed, `Migrate()`-based fixtures no longer need the temporary `ApplyEventDeliverySchemaFix`; only the older WorkflowRuns status schema fix remains for tests that still create pre-migration schemas.
- Migration coverage now lives in `EventDeliveryProgressMigrationSpecs`: it queries `sqlite_master.sql` to pin the exact `WHERE "DispatchedAt" IS NULL` predicate, checks `(Type, Time)` indexes exist only on WorkflowRunEvents/IssueEvents, and verifies migrating from `20260707120000_WorkflowWorkerAssignment` up to the new migration applies cleanly.
