## Findings

1. **High - Parent issues can still start a workflow despite the new blocker.** In `packages/server/src/Mohist.Server/Issue/Grains/IssueGrain.cs:145-157`, `StartWorkAsync` calls `TryReuseActiveWorkflowAsync` before checking `HasChildrenAsync` and `ThrowIfStartBlocked`. A parent which previously started a workflow, then returned to Backlog (for example, after cancellation/reopen and stopping its prior run), retains `WorkflowRunId` until `TryReuseActiveWorkflowAsync` clears it. If the old run is still active, the method returns its id at line 150 and bypasses the parent-has-children blocker entirely. This violates the acceptance criterion that an issue with children must not start/continue its own workflow. Evaluate the parent blocker before the reuse fast path, and add a grain/API regression test for a parent with an active retained run.

2. **Medium - `mo issue create` always sends `parentIssueNumber: null`, which breaks mixed-version compatibility stated in the approved design.** `packages/cli/Mohist.Cli/MohistCliCommands.Issue.CrudWrites.cs:126-137` unconditionally adds `parentIssueNumber` to every create payload, even when `--parent` was not passed. The design's migration plan requires older clients to omit the new field; this newer client should likewise omit it when unused so an older server can accept ordinary issue creation. Track whether `--parent` was supplied and only emit the property in that case. Add a CLI payload test for create without `--parent`.

3. **Medium - The parent list filter depends on a title-bearing join rather than the persisted parent key, so it can omit valid children if the parent projection is unavailable.** `packages/server/src/Mohist.Server/Issue/Services/IssueQuerier.cs:206-207` filters `ParentIssueRef`, but that reference is populated only by the inner join at lines 278-293. The contractual filter is `IssueRow.ParentIssueNumber == N`; filtering the persisted projection directly is both the specified behavior and avoids silently losing a child whose stored parent row is unavailable or malformed. Apply the filter before loading/enriching the list (or retain the parent number on the read model) and add coverage that verifies the database key drives `--parent`.
