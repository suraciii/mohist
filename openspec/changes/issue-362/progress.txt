## Codebase Patterns

- EF migrations follow `YYYYMMDDHHMMSS_<Title>.cs` + `.Designer.cs`. Migration id is treated as an immutable identity; the file content is regenerated only when EF detects a model diff.
- `MohistDbContextModelSnapshot.cs` is the canonical "current model" — only its content drives `dotnet ef migrations add` diffs. Designer.cs snapshots of historical migrations are frozen artifacts and never participate in the diff.
- SQLite EF provider can't translate `ORDER BY DateTimeOffset` (only `DateTime`). `WorkflowRunRow.ReadySince` documents this and uses `DateTime?` + VIRTUAL computed column. Pattern: either use `DateTime` for sortable date columns, or drop into raw SQL with `SqlQueryRaw<T>` like `EventStore.ListUndeliveredAsync` (table-derived projection type holds `string` for JSON columns and parses manually).
- Test fakes are duplicated across UnitTests/Support and SpecTests/Support (e.g. NoopEventStore exists in both); the test projects don't reference each other.
- `MigratedSqliteTemplate` (SpecTests/Support) clones the full EF schema once via SQLite online-backup API. New EF migrations must "just work" against it — verified by the new `MigratedSqliteTemplate_AlreadyContainsDeadLettersTable` spec.

## Decisions (T-001)

- DeadLetterRow mirrors the historical shape from ba50c2089 exactly (Origin/Id/Source/EventId/Type/Time/SpecVersion/Subject/DataContentType/Data/ExtensionsJson + FailingHandler/ErrorMessage/ErrorStack/AttemptCount/DeadLetteredAt + DeadLetterId PK). Origin is a `string` (TEXT, maxLength 32) so AgentSession is supported without enum churn — store converts to/from EventOrigin at the IDeadLetterStore seam if/when T-002 wants it.
- IDeadLetterStore includes atomic `SettleAsync`, explicit redelivery start/failure/resolve transitions, and direct write/query/get/delete primitives. QueryAsync returns unresolved rows ordered by (DeadLetteredAt ASC, DeadLetterId ASC).
- DeadLetterStore.QueryAsync uses raw SQL (`SqlQueryRaw<DeadLetterSqlRow>`) with a `(failingHandler IS NULL OR FailingHandler = @filter)` predicate so one query covers both filter modes. Mirrors the historical DeadLetterStore + the GetUndelivered UNION pattern already in EventStore.cs.
- DeadLetterStore.GetAsync uses an EF no-tracking single-row lookup. Recovery state is `Pending`, `Redelivering`, or `Resolved`; resolved rows stay auditable but are excluded from unresolved queries.
- DI registration: `services.TryAddSingleton<IDeadLetterStore, DeadLetterStore>()` in `ConfigureMohistServices`. TryAdd lets tests inject NoopDeadLetterStore (placed in both UnitTests/Support and SpecTests/Support) without disturbing the single host-shared production graph.
- Migrations: `20260709002625_AddDeadLetters` creates the table; `20260711041122_HardenDeadLetterRecovery` adds recovery state and unique `(Source, Id, FailingHandler)`. No DispatchedAt column is added because all four source truth tables already own it.
- Spec tests: DeadLetterStoreSpecs covers Write/Get (with AgentSession origin), monotonic IDs, query order + limit + handler-filter narrowing + empty, unknown GetAsync → null, Noop fake usability. DeadLettersMigrationSpecs covers: all columns, both indexes, migration-applies-cleanly from previous state, migration source contains CreateTable/PK/indexes, model snapshot includes the entity + both indexes, MigratedSqliteTemplate already contains the table+indexes (proves the new migration runs end-to-end).
- Speed=Service (not Unit) on both spec files: they go through the real EF pipeline + MigratedSqliteTemplate, same as AgentSessionEventsMigrationSpecs and EventStoreScopedAppendSpecs.

issue-362 — T-002 working memory

## Codebase Patterns

- Re-confirmed: per-test fakes are duplicated across UnitTests/Support and SpecTests/Support (FakeEventStore and NoopDeadLetterStore each live in both projects). NoOpEventStore is in both projects too (same name).
- `DispatcherGrain` and `DispatcherOptions` live under `Events/Grains/` — Events is NOT in the FeatureDirectories allow-list (Agent/Epic/Issue/Project/Runner/Sessions/Workflow), so the archtest's `FeatureDirectories_ShouldOnlyContainDomainGrainsAndServices` rule does NOT apply to it. No new archtest registration needed.
- Tests use `FakeTimeProvider` for the dispatcher core. Deterministic delivery specs drive `IDispatcherGrain.PulseAsync`; a full-host integration spec reads the real reminder table to verify startup activation without waiting on wall-clock timing.

## Decisions (T-002)

- `EventDispatcherService` is a plain DI singleton (not an interface) injected by `DispatcherGrain`. Tests build it directly with fake store + FakeTimeProvider, so an `IEventDispatcherService` seam is unnecessary for the test surface — the unit specs are the source of truth and they use the concrete class.
- `DispatcherOptions` lives in `Events/Grains/` next to the grain. The service constructor takes `IOptions<DispatcherOptions>` and `ConfigureMohistServices` binds the section once for the host-shared graph.
- `InMemoryEventBus` constructor was widened to require `TimeProvider` (after `IEventStore`). Two constructors stay: parameterless one (for fixtures that wire subscriptions later) and full DI one. Every test fixture that built an `InMemoryEventBus` directly had to pass `TimeProvider.System` (or a `FakeTimeProvider` for unit tests).
- `DispatcherGrain` calls `RegisterOrUpdateReminder` in `OnActivateAsync`; `DispatcherActivationService` activates the fixed key during host startup. `ReceiveReminder` filters by name and ignores foreign reminders.
- `ReminderOptions.MinimumReminderPeriod` lowered to 100ms in BOTH the production silo (`MohistSiloRegistration`) AND the test silo (`GrainTestConfig.ConfigureSilo`). Without this, the in-memory reminder service refuses to register a sub-second period; the production `UseAdoNetReminderService` has the same restriction.
- `RedeliverAsync(deadLetterId)` reconstructs the envelope, persists `Redelivering`, retries only the recorded failing handler, and marks the row `Resolved` after success. A post-handler persistence failure leaves an explicit ambiguous state for idempotent replay.
- Retry is a hand-rolled loop in `InvokeWithRetryAsync` with `DispatcherOptions.HandlerMaxAttempts` cap (default 3). No Polly. No backoff. The cap is configurable so the spec test's `per-handler isolation` scenario can use 2 attempts without overflowing.
- Per-row `DispatchedAt` is set after matching handlers settle. Poison rows use one transaction for handler-keyed dead-letter upserts plus source mark; any settlement failure aborts the batch to preserve FIFO.
- Durable production reactions await required side effects and propagate failures. Hermes and `AgentSubscriptionDispatchHandler` retain their documented best-effort catch-and-log contracts and do not enter retry/DLQ.
- Agent subscription launches write trigger labels before durable submission and derive stable session/job keys from project + event + subscription. AgentJob persists raw AgentConfig JSON, candidate runner, stable work id, retry state, and terminal state; replay never treats session labels as the launch claim.
- Dead-letter API operations are absent on public listeners and require a high-entropy operator credential on loopback listeners. The CLI reads the user-only credential file, responses are no-store and stack/path-redacted, and table output exposes recovery status without terminal controls. Closed-generic Epic handlers create a scope per delivery for `EpicQuerier`.
- RunnerGrain owns atomic agent-job admission: lifecycle changes and admission share one gate, offline runners reject work, and concurrent jobs cannot both consume a one-slot runner.
- Agent jobs use poll reconciliation after admission: accepted work is reoffered until its stable key appears in the runner's reported set. A per-runner poll gate excludes overlapping rounds, Agent admission retries while reconciliation is active, and active Agent work is subtracted before workflow claims.
- Runner persistent state retains the last registration profile. After activation loss, the first poll restores online presence and the registry before reconciling the same durable Agent work; explicit unregister clears the profile.
- Poll admission captures slots inside the Runner grain and holds the admission gate through reconciliation. The route no longer pre-reads capacity, `DispatchService` accepts no caller-provided slots, and capacity updates wait until the admitted poll finishes.
- Inbox projection and `InboxItemPersisted` event append share one database transaction. A failed append rolls the projection back, so dispatcher replay cannot lose the durable hint behind an `AlreadyExisted` early return.
- The inbox/hint transaction is verified with the real `EventStore`: an SQLite trigger aborts the final hint insert after the inbox save, proving zero/zero rollback and exactly-one/exactly-one replay.
- Server and CLI operator credential precedence is environment token, config token, environment path, config path, then the default user-only file. Operator diagnostics redact embedded one-line frames and path substrings in addition to newline-separated stacks.

## Gotchas

- `DispatcherGrain` namespace is `Mohist.Server.Events.Grains`. The `GrainImplementations_ShouldInheritFromGrain` archtest rule picks it up because the type name ends with `Grain` and the namespace matches `Mohist.Server.*.Grains`. Convention-discovered, no explicit registration needed.
- `Closed-generic scan fix` in `AddCloudEventHandlersFromAssembly` is just the swap of the `typeof(ICloudEventHandler<>).IsAssignableFrom(t)` line to a proper `GetInterfaces().Any(IsCloudEventHandlerInterface)` walk — both `ICloudEventHandler` (non-generic) and `ICloudEventHandler<>` (closed-generic) are now discoverable. The `IsCloudEventHandlerInterface` helper is private static at the bottom of the class. No new types, no new DI lifetime.
- `IDispatcherGrain` lives in `Mohist.Server.Events.Grains` so its Orleans proxy generator can be discovered by the silo (`IGrainWithStringKey` convention). No explicit grain class registration in DI is needed.
- `DispatcherFixture` uses `CapturingEventStore` (in the fixture file, not the Support fakes) to track events AND drive the dispatcher's `ListUndeliveredAsync`. It also installs `NoopDeadLetterStore` so `RedeliverAsync` is exercised without EF.
- The host-shared application graph registers `EventDispatcherService` as a singleton; `DispatcherGrain` resolves it by constructor injection. `DispatcherOptions` is bound from the `Mohist:Dispatcher` configuration section.
- `InMemoryEventBus` no longer reads `DateTimeOffset.UtcNow` — both constructors take `TimeProvider` and use `_time.GetUtcNow()` in the typed `PublishAsync<TData>` overload. The two existing constructors are unchanged in argument order except for the new `TimeProvider time` parameter between `IEventStore` and `ILogger`.
