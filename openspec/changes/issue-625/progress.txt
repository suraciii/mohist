# Progress: T-001 implementation (final)

Implemented T-001 end to end on top of the plan-review fixes above.

## Codebase Patterns (established here)
- Lane evidence is additive `TaskRun.Lane` (`VerificationLaneAttempt`): populated at task creation (`TaskRun.MakeTask`) for any DefinitionId in `VerificationLaneCatalog` — lane id, catalog order, configured budget from `with.timeout` (int ms, positive), Pending outcome, and TaskRunId. So a pending lane exists in the same commit that materializes the task.
- Report classification happens at the verification boundary in `WorkflowWorkLifecycle.ApplyTaskReportAsync` via `VerificationLaneClassifier.Classify` (Succeeded->pass unless AddTasks present->fail; Failed with error.code=timeout->timeout; else fail) and persists on the same transition. `TaskReportStatus` stays Succeeded/Failed (no third state).
- `ResolveStageFromBoundSnapshotAsync` (WorkflowDefinitionResolver) is the ONLY stage/lock resolution path for the grain (stage initializer + stage-lock coordinator). Snapshot parsed from in-memory run first; no snapshot + built-in profile -> `RetainedLegacyAggregate` (single verify task build stage); other missing cases fall back to `LoadStageSpecsAsync` (which itself checks the DB snapshot first). It is async (no sync-over-async).
- Ordered dispatch: `WorkflowRun.NextWork` filters the candidate pending task through `VerificationLaneGate.IsClaimableLaneTask` — for lane-enabled runs only the first non-passing lane is exposed; later lanes are blocked while predecessors are non-pass; legacy runs unaffected.
- Stage gate: `WorkflowRun.Stage.TryRequestApproval` now takes the run and refuses to mark the build stage Completed unless `VerificationLaneGate.CanAdvanceBuildStage(run)` (all six lanes durable pass). Non-lane runs always advance as before.
- `WorkflowStatusMapper.MapVerificationLanes` projects all six lanes (pending placeholders for missing) with pass/fail/timeout wire values + diagnostics; null for legacy runs.
- Binding: coordinator serializes the entire effective `WorkflowDefinition` with `WorkflowYamlSerializer.ToJson` into `BoundWorkflowStart.DefinitionJson`; participant persists write-once `WorkflowRun.BoundWorkflowDefinitionJson`; idempotency compares the snapshot string.
