## Why

AgentSession is meant to be a stable, reusable logical conversation, but today one execution's outcome is interpreted as the whole session's terminal state: completion, failure, or cancellation closes the session, the Session page and API derive status from historical end facts, and consumers stop allowing follow-up. Separately, when the underlying Runtime Session is reclaimed, users must manually Reset before any further input works — even though the input was never submitted. Both behaviors break continuous conversation and force redundant Reset cycles. This change implements the already-specified target model (`design/agent-execution.md`, `docs/agents.md`) by removing session terminal semantics and adding safe rebinding when a Runtime Session is confirmed missing.

## What Changes

- **BREAKING** Remove AgentSession terminal states. An execution completing, failing, or being cancelled only returns the session to `idle`; the API, Session page, and command eligibility no longer expose or derive `completed`/`failed`/`stopped`/`cancelled` as a session lifecycle, and no longer scan transcript history to reconstruct status.
- **BREAKING** Remove the `session.closed`, `session.followup_completed`, and `session.followup_failed` transcript events. Introduce `session.activity` (idle/active/unknown transitions) and `session.context_reset` (a binding replacement marker carrying only a reason, no physical session IDs) as the transcript contract for activity and rebinding.
- **BREAKING** Remove physical Runtime Session lineage. The session stores only the current binding; lineage lists, the `PreviousAgentRuntimeSessionId` fact, lineage DTOs, and Web history views are dropped. Rebinding preserves AgentSession ID, source, working directory, transcript, and cumulative usage; Runtime context starts empty and is shown via the single `session.context_reset` fact.
- Add a first-class `idle`/`active`/`unknown` activity state machine owned by the session aggregate, replacing the time-window-derived `active`/`inactive` heuristic.
- Add confirmed-missing Runtime Session recovery: before submitting a new independent input (Workflow task, AgentJob, or idle Follow-up), if the owning Runner deterministically confirms the current Runtime Session no longer exists, Mohist creates at most one empty session on the same Runner, replaces the binding via compare-and-swap, then accepts and submits the input exactly once — without consuming a Workflow recovery budget or creating a new work attempt.
- Keep all other conditions explicit failures that preserve the current binding and never replay input: non-deterministic absence, timeouts, permission failures, corrupt data, unclassifiable responses, unknown submission outcome, requests landing on a different Runner, and `active`/`unknown` activity.
- Apply identical activity, input, rebinding, Follow-up, Cancel, and Reset semantics across OpenCode and Pi, and across Workflow and Agent launch sources; TaskRun/AgentJob/Workflow recovery/retry continue to judge their own work results independently of session activity.

## Capabilities

- `agent-session-activity`: The idle/active/unknown activity state machine owned by the session aggregate; the rule that an execution outcome only returns the session to idle and never creates a terminal session state; and that API responses, command eligibility, and the Session page read current activity rather than reconstructing it from historical end facts, while TaskRun/AgentJob results stay independent of session activity.
- `session-transcript`: The flat, append-only transcript contract — plain input boundaries via `session.input`, activity transitions via `session.activity`, and binding-replacement markers via `session.context_reset`; removal of `session.closed`/`session.followup_completed`/`session.followup_failed`; no per-execution sub-resources, execution IDs, or grouped message history; and the atomic ordering of `session.context_reset` before the next `session.input`.
- `runtime-binding-recovery`: The single current-binding model with compare-and-swap replacement; confirmed-missing recovery that creates at most one empty session across TaskRun, AgentJob, and idle Follow-up entries; the exhaustive set of non-recovery conditions that preserve the binding and refuse replay; Reset and runtime-change as the same binding-replacement path; rejection of stale expected bindings and late events from superseded physical sessions; and the invariant that rebinding preserves AgentSession identity, source, working directory, transcript, and cumulative usage while Runtime context restarts empty.

## Impact

- **Server domain & grain** (`packages/server/src/Mohist.Server/Sessions/`): replace time-window status derivation (`AgentSessionJsonHelper`, `AgentSessionQuerier.ReadTerminalStateAsync`) with a persisted activity state machine; remove `RuntimeSessionLineage`/`RuntimeSessionLineageEntry` and `PreviousAgentRuntimeSessionId` (`AgentSession.cs`, `AgentSession.Transitions.cs`); extend compare-and-swap binding replacement (`EnsureExpectedRuntimeSession`, `RebindRuntimeSession`, `AttachPhysicalSession`) to the missing-recovery path across `BeginSessionCommandAsync`, Follow-up, and task/AgentJob submission.
- **Server API & read models** (`Api/AgentSessionFollowupRoutes.cs`, `AgentSessionCancelRoutes.cs`, `AgentSessionRecoveryRoutes.cs`, `AgentSessionReadModels.cs`, `AgentSessionDtoMapper.cs`): drop lineage DTOs, drop `runtime_session_missing` hint-to-Reset behavior on the recovery path, and expose activity instead of derived terminal status; the `409 runtime_session_missing` semantics change from "caller must Reset" to automatic recovery (where conditions hold) or a binding-preserving failure.
- **Runner** (`packages/runner/src/runtime/`): the runtime adapters already report `missing-session` deterministically (`opencode/runtime.ts`, `pi/runtime.ts`); wire the resolve→create→replace ordering into task dispatch (`executor.ts`), AgentJob execution (`agent-job-executor.ts`), and idle Follow-up (`followup-handler.ts`), ensuring input is submitted only after the server confirms the new binding.
- **Transcript event catalog** (`TranscriptEventTypes.cs`, `EventCatalog.cs`, `canonical-event-types.ts`): add `session.activity` and `session.context_reset`; remove `session.closed`, `session.followup_completed`, `session.followup_failed`, and the `compaction`/lineage-based reset markers that currently stand in for context reset.
- **Web UI** (`packages/web/src/pages/session/data/`, `entities/coder-session/model/`, `widgets/`): replace the three duplicated status mappers that read `completedAt`/`session.closed` with activity-based derivation; remove the runtime-session history view and lineage consumption.
- **Persistence**: a schema migration drops lineage storage and legacy event rows; transcript content from prior physical sessions is not migrated or replayed.
- **Tests** (`packages/server/tests/Mohist.Server.SpecTests/`, `packages/runner/`, `packages/web/`): extend coverage to activity transitions, binding compare-and-swap recovery, stale-binding rejection, late-event rejection, and the exhaustive non-recovery failure set, using injected fakes and no wall-clock timing.
