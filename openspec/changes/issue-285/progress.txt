### Key Decisions (followed design.md D1/D2/D3)

- InboxSubscriptionStore mirrors ProjectWorkflowProfileManager's load-by-projectId / null-synthesizes-default / mutate / SaveChanges shape

- Migration timestamp 20260629003200 follows 20260629003151_AddInboxItemsTable

### Gotchas
- The Designer.cs for a migration reflects the FULL model (all entities), not just the new one. Both .Designer.cs and ModelSnapshot.cs contain the same BuildTargetModel content; the Designer differs only in the [Migration] attribute and partial class name.

## T-002 — Subscription-gated inbox projection

### Files Modified

- `packages/server/tests/Mohist.Server.Tests/Specs/Events/Inbox/InboxProjectionHandlerRealtimeHintSpecs.cs` — added `DisabledKind_PublishesNoHint`

### Key Decisions (followed design.md D4)
- Subscription gate inserted after issue resolution and before `InboxItemDraft` creation (~line 138), exactly as D4 prescribes
- Early return skips both `inboxStore.InsertAsync` and the `IEventPublisher.PublishAsync` hint — no insert, no hint
- Missing subscription row → `InboxSubscriptionState` default (all-enabled) → gate passes → MVP behavior preserved
- No in-process cache; each projected event reads subscription fresh from store
- Test DI scope must explicitly register `InboxSubscriptionStore` (the production scope uses `AddMohistConventionalServices` auto-registration via `IScopedService` marker; the test harness builds its own scope manually)
