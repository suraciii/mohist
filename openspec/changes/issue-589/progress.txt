## Codebase Patterns

- WorkflowRun state is persisted transactionally with Workflow events through WorkflowGrain.CommitAsync. CommitAsync([]) persists a state-only transition without appending events.
- Task attempts keep their dispatch identity on TaskRun.Id, WorkId, and WorkerId. Reports must not use the mutable current AgentSession metadata as an identity source.
- IWorkflowGrain test doubles live in RunnerWorkflowStatusRouterSpecs and must be updated when the grain interface grows.
- Server test source changes require synchronizing the SpecUnitMigration ledger, validator, and provenance source-tree file count and digest.

## T-002

- The first unknown Agent result observation persists its absolute deadline with the injected TimeProvider and emits an observable unconfirmed-result event. The `agent-result-settlement` reminder reconciles persisted unknown, blocked, terminal, and explicitly stopped settlement states on both ticks and activation.
- Unknown and blocked work is fenced from new dispatch, desired redelivery, retries, stage reruns, and runtime task insertion while the Runner's reported in-flight or awaiting-ack key continues to consume capacity.
- Expiry writes blocked task, stage, and run events without a failure transition. An authoritative report remains eligible for the original running attempt and clears the settlement only after snapshot and reminder cleanup succeeds, so failed cleanup is repairable on activation.
- Explicit stop commits task cancellation and run stop together, then retries snapshot deletion, reminder removal, and stage-lock release through idempotent stop replay or activation. Later reports and observations for that cancelled attempt are stale.
- Reminder registration and removal failure specs use an overridden grain seam to prove the committed settlement is repaired on activation. The final Server-test source-tree baseline is files=836, digest=4e8fb8268b1cb7cfc56489f7a76eb018616572df11876392a5e8243669d3d687.
