## Codebase Patterns

- `SessionPage.tsx` already has `setupSessionPage` + `renderWithQueryClient` mocks for `useCoderSessions`, `useIssue`, `getAgentSessionMetadata`, `getAgentSessionTranscript` (tests/SessionPage.test.tsx:25-58). The mock for `getAgentSessionTranscript` reads `sessionPageMocks.turns ?? []` and returns `{ turns, partCount, lastActivityAt }` — tests can drive both metadata and transcript through these hooks.
- `navigator.clipboard` is faked at module load (tests/SessionPage.test.tsx:60-63) and `Element.prototype.scrollTo` is faked in `beforeEach`/restored in `afterEach` (lines 65-79, 108-110). Use these for any new SessionPage tests rather than re-mocking.
- The transcript hook `useSessionTranscript` (`packages/web/src/widgets/session-transcript/model/useSessionTranscript.ts`) initializes state with `useState(initialState)` where `initialState = useMemo(() => initialTurns ?? [], [])`. On first render `initialTurns = transcriptResponse?.turns ?? EMPTY_TURNS`; until the transcript query resolves, `turns` from the hook is `[]`. A `useEffect([initialTurns, isRunning])` calls `setTurns(initialTurns ?? [])` (line 138) once the query resolves, so the main transcript branch only renders after the second render. Tests that assert "main branch" state must `findByText` for a marker that depends on `displayTurnCount = detail.metadata.turnCount = transcriptResponse.turns.length` (e.g. `'2 turns'`) instead of `findByText('Issue #123')`, otherwise the assertion runs during the brief empty-branch render.
- `convertLegacyToAgentMetadata(detail)` (tests/SessionPage.test.tsx:81) hard-codes `sessionName: legacy.sessionId` when synthesizing `AgentSessionMetadata`; tests that care about a specific `<h1>` text cannot rely on overriding `metadata.sessionName` and must instead target `metadata.title` or another stable field. Prefer asserting on the stage badge / status badge / issue title (`getByText('Build')`, `getByText('Completed')`, `getByText('Test Issue')`) rather than the `<h1>` text.
- The local `SessionHeader` function lives in `SessionPage.tsx:267`, not in `widgets/coder-session/ui/SessionHeader.tsx`. There is also a widget-level `<SessionHeader>` (different component, used in issue-detail / session cards). Issue-243 work targets the local one only.
- `SessionTranscriptLayout`'s outer `<div className="flex flex-col h-full">` wrapper is gone after T-001 — the parent (`SessionPage.tsx:769-777`) is now the scroll container (`flex-1 overflow-y-auto`). The layout itself is just the `data-scrollable=""` inner region. Future tasks adding the toolbar / TOC / keyboard hook should mount into the layout, not the parent.
- `SessionPage` already pulls in `<SessionFollowupComposer>` at the bottom of the main branch (line 779). The followup composer has a `[data-composer-input]` attribute that the future `useTurnKeyboardNav` (T-005) can use to bail out on j/k/g/G.
- `packages/web/src/widgets/session-transcript/ui/AssistantParts.render.test.tsx` is co-located with `AssistantParts.tsx` (the `.render.test.tsx` suffix) — the convention for new widget render tests in this directory. `tests/*.test.tsx` is the convention for higher-level SessionPage/integration tests. Co-locate new `TurnList`-level tests with the source file.
- The shared `formatTime` helper at `packages/web/src/shared/lib/format-time.ts` is `toLocaleString()` (date + time), NOT `toLocaleTimeString()`. The transcript's local `formatTime` in `AssistantParts.tsx:7` (and the new one in `TurnList.tsx:7`) is `toLocaleTimeString()` (time only). They are different functions; T-002 specifically references the AssistantParts-style local helper. Don't accidentally import the shared one.

## T-002 Decisions

- D2: Added a one-line `TurnHeader` (`TurnList.tsx:55-73`) above `PromptBlock` inside `TurnItem` showing the 1-based turn index and a clock time. Layout: a right-aligned (`flex justify-end`) `text-xs text-gray-400` row that visually sits above the right-aligned prompt bubble — small subtle marker, doesn't compete with the prompt bubble's own kind/sentAt header inside it. Inner span: `<span>Turn {index}</span>` (bold `text-gray-500`) + `·` separator + `<time dateTime={startedAt}>{formatTime(startedAt)}</time>`. The `data-turn-index="N"`, `data-turn-index-label="Turn N"`, and `data-turn-timestamp=""` attributes give stable selectors for tests and future TOC/refs wiring. The `<time>` `dateTime` attribute carries the raw ISO from `startedAt` so screen readers + future keyboard nav can read it; `title={startedAt}` exposes the raw ISO on hover. Local `formatTime` (toLocaleTimeString, time-only) is duplicated as a 2-line helper inside `TurnList.tsx` rather than imported — matches the existing `AssistantParts.tsx:7` pattern (the helper is intentionally not shared). `TurnItem` gained an `index: number` prop so the index lives at the iteration site (`TurnList.tsx:23`) and `TurnItem` doesn't recompute it from `turn.id`. No new model field; `DisplayTurn.startedAt` IS the source of truth.
- D2: Did NOT touch `PromptBlock`. It still renders `formatDateTime(prompt.sentAt)` inside the prompt bubble — that's prompt-level context (kind + sentAt in the bubble header) and is conceptually distinct from the new turn-level timestamp rendered above the bubble. The acceptance criterion "the turn header is the single source for the turn-level time" is satisfied by adding exactly one `[data-turn-timestamp]` per turn; the existing prompt-bubble timestamp is contextual to the prompt and was out of scope per the design's "do not render the timestamp inside PromptBlock" instruction.

## T-002 Gotchas

- `compareDocumentPosition` returns a bitmask — `(node.compareDocumentPosition(other) & Node.DOCUMENT_POSITION_FOLLOWING)` is the right pattern to assert "A precedes B in document order". Treat the bitmask as truthy, not as a boolean expression (`expect(mask & Node.DOCUMENT_POSITION_FOLLOWING).toBeTruthy()`), since the raw value is non-zero but not always equal to 4.
- `new Date(iso).toLocaleTimeString()` is locale-sensitive. Inside jsdom the default locale is consistent across the test run, so the test can compare against the same expression it expects the component to compute. Don't hardcode the formatted string in tests; compute it the same way the production code does.
- `<PromptBlock>` uses `.rounded-2xl` on its inner bubble; the test can locate the prompt bubble via `container.querySelector('.rounded-2xl')` (jsdom renders the first match). Avoids brittle class-name coupling to Tailwind utilities not relevant to the timestamp assertion.
