## Codebase Patterns

- `SessionPage.tsx` already has `setupSessionPage` + `renderWithQueryClient` mocks for `useCoderSessions`, `useIssue`, `getAgentSessionMetadata`, `getAgentSessionTranscript` (tests/SessionPage.test.tsx:25-58). The mock for `getAgentSessionTranscript` reads `sessionPageMocks.turns ?? []` and returns `{ turns, partCount, lastActivityAt }` — tests can drive both metadata and transcript through these hooks.
- `navigator.clipboard` is faked at module load (tests/SessionPage.test.tsx:60-63) and `Element.prototype.scrollTo` is faked in `beforeEach`/restored in `afterEach` (lines 65-79, 108-110). Use these for any new SessionPage tests rather than re-mocking.
- The transcript hook `useSessionTranscript` (`packages/web/src/widgets/session-transcript/model/useSessionTranscript.ts`) initializes state with `useState(initialState)` where `initialState = useMemo(() => initialTurns ?? [], [])`. On first render `initialTurns = transcriptResponse?.turns ?? EMPTY_TURNS`; until the transcript query resolves, `turns` from the hook is `[]`. A `useEffect([initialTurns, isRunning])` calls `setTurns(initialTurns ?? [])` (line 138) once the query resolves, so the main transcript branch only renders after the second render. Tests that assert "main branch" state must `findByText` for a marker that depends on `displayTurnCount = detail.metadata.turnCount = transcriptResponse.turns.length` (e.g. `'2 turns'`) instead of `findByText('Issue #123')`, otherwise the assertion runs during the brief empty-branch render.
- `convertLegacyToAgentMetadata(detail)` (tests/SessionPage.test.tsx:81) hard-codes `sessionName: legacy.sessionId` when synthesizing `AgentSessionMetadata`; tests that care about a specific `<h1>` text cannot rely on overriding `metadata.sessionName` and must instead target `metadata.title` or another stable field. Prefer asserting on the stage badge / status badge / issue title (`getByText('Build')`, `getByText('Completed')`, `getByText('Test Issue')`) rather than the `<h1>` text.
- The local `SessionHeader` function lives in `SessionPage.tsx:267`, not in `widgets/coder-session/ui/SessionHeader.tsx`. There is also a widget-level `<SessionHeader>` (different component, used in issue-detail / session cards). Issue-243 work targets the local one only.
- `SessionTranscriptLayout`'s outer `<div className="flex flex-col h-full">` wrapper is gone after T-001 — the parent (`SessionPage.tsx:769-777`) is now the scroll container (`flex-1 overflow-y-auto`). The layout itself is just the `data-scrollable=""` inner region. Future tasks adding the toolbar / TOC / keyboard hook should mount into the layout, not the parent.
- `SessionPage` already pulls in `<SessionFollowupComposer>` at the bottom of the main branch (line 779). The followup composer has a `[data-composer-input]` attribute that the future `useTurnKeyboardNav` (T-005) can use to bail out on j/k/g/G.

## T-001 Gotchas

- `displayTurnCount` is `detail?.metadata?.turnCount ?? turns.length` and `metadata.turnCount` comes from `buildSessionMetadata(..., turnCount = transcriptResponse?.turns.length ?? 0, ...)`. So the header's "N turn(s)" reflects the *transcript* turn count, not the test's `metadata.turnCount` override. Tests must therefore provide `turns` matching the expected count (or accept that the header updates as the transcript query resolves).
- Two renders happen between mount and the main transcript branch showing: `<SessionLoadingState />` (metadata query) → empty branch (transcript query still loading) → main branch (transcript loaded). `findByText('Issue #123')` resolves at the empty-branch render because the header is identical; assert on something transcript-dependent (`'1 turn'`, `'2 turns'`, or the prompt body) to reliably reach the main branch.
- The widget-level `SessionHeader` (different file, `widgets/coder-session/ui/SessionHeader.tsx`) renders compact cards with `showTranscriptLink`; do NOT touch it from issue-243 work. The local function at `SessionPage.tsx:267` is the one this issue modifies.
