## Codebase Patterns

- `MohistCliApi` is the existing command-facing boundary. It owns HTTP request construction and legacy renderers, while `MohistCliCommands.RunAsync` builds the testable command tree with injected streams and fakes.
- `System.CommandLine` parse errors are available from `ParseResult.Errors`; help for the nearest parsed command can be rendered through a second `--help` invocation using the error writer.
- CLI tests use `RecordingHttpHandler`, `FakeFileSystem`, `StringWriter`, and injected `TextReader`; no real server or filesystem is required.

## T-001

- Added `CliInvocation`, `CliResultWriter`, `CliResponseReader`, `CliHintResolver`, `CliTransportAttempt`, terminal/environment seams, and stable exit-code mapping in `CliExecutionContract.cs`.
- Response failures preserve non-blank Server codes, synthesize `http-<status>` for code-less HTTP failures, retain details, and classify mutating transport exceptions as outcome unknown.
- Root parsing now returns usage exit `2` with nearest-command help on stderr and maps cancellation to `130`.
- Confirmation prompts in notification setup are emitted on stderr and are suppressed when stdin is redirected or `MOHIST_PROMPT_DISABLED=1`.
- Existing suite currently has one expected legacy failure because `NotifySetup_ExistingHermesScalar_PromptsBeforeOverwrite` asserts confirmation text on stdout; the new contract requires confirmation exclusively on stderr.
- Fixed root pre-parse false positives for option values by relying on System.CommandLine's parsed command result; all 1,382 CLI tests now pass.
- Production `CliProgram.Main` now uses `MohistCliCommands.RunAsync`, so cancellation, parse errors, terminal state, and environment handling share one root path.
- `CliResponseReader` reads response content without assuming a seekable stream and maps malformed HTTP payloads to an operation failure instead of leaking a JSON exception.
- `MohistCliApi` carries the shared invocation seams; notification overwrite prompts use the injected terminal and environment state and write confirmation diagnostics to stderr.
