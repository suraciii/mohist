## Codebase Patterns

- `TranscriptPartTypes` is the canonical "persisted part type" vocabulary; `RuntimeEventTypes` is the "incoming runtime event" vocabulary. Both share the same string values for the closure event after T-001 (`session.closed`).
- Read-side matchers should reference the constant, never literals — `TranscriptAccumulator.ToTranscriptPartType` already did so, and after T-001 the four formerly-literal sites (AgentSessionQuerier.ReadTerminalStateAsync, SessionTranscriptBuilder, AgentSessionSummaryBuilder ×2) also reference the constant.
- Specs that seed persisted transcript parts for read-side tests now use the constant (or the dot-token literal) instead of `"session_closed"` so they round-trip correctly under the new vocabulary.
- Activity preview (`AgentSessionQuerier.ToPreview`) falls back to `e.Type` when the payload has no extractable text — closure events with `{status, exitCode}` payloads therefore render the *part type* as the visible `LastActivity.Text`, which is why the existing `Assert.Equal("session_closed", card.LastActivity!.Text)` site had to flip to `"session.closed"`.

## Gotchas
- `LoadIssueTitlesAsync` and `IssueTitle` are conceptually "activity-feed" (their only caller is the assembly code path), but `ListCurrentAsync` also uses them to project `AgentSessionInfoDto.IssueTitle`. So they become shared (`internal static`) rather than moving into the assembler — moving them would either force `ListCurrentAsync` to call back through the assembler (violating D2 one-way dependency) or duplicate the SQL projection. Keeping them shared is byte-identical and avoids the back-edge.
- `LoadEventSummariesAsync` is shared for the same reason (used by both `ListCurrentAsync` / `ListAgentSessionsAsync` and the assembler's activity-card projection). Made `internal static`, calls go through `AgentSessionQuerier.LoadEventSummariesAsync`.
- `ToProjection(string, AgentSessionTranscriptPartRow)` is a tiny but shared helper (used by `LoadLatestEventsAsync` in the assembler; used by the transcript summaries in core). Bumped to `internal static` rather than moved because, again, multiple consumers exist; record type `TranscriptEventProjection` was already `internal sealed record` so nothing else had to change.
- The assembler file lives under `Sessions/Services/` and `using Mohist.Server.Sessions.Domain;` is required for `AgentSessionTranscriptSummary` (the DTO collection type used in `LoadEventSummariesAsync`'s return dictionary). The other DTOs (`ActivityCardDto`, `ActivitySummaryDto`, …) are in the `Mohist.Server.Sessions` namespace, not `Sessions.Domain`.
- `ActivityCardDto` carries `agent_{agentId}` issueId for agent-launch sessions vs `issue_{projectId}_{number}` for workflow sessions — verified by `AgentActivityFeedAssemblerSpecs.WorkflowSessionCard_OmitsAgentFields` (workflow card null for agentId/agentName) and `…GenericAgentLaunchSession_ProjectsAgentIdAndIssueTitleFallback` (generic card populated).
- `StatusName(s, Now())` is gated by a 5-min `ActiveRuntimeEventWindow` against `LastDataAt`. Seeding an `AgentSessionStatusSnapshot` without `LastDataAt` produces `inactive` cards even with `AgentRuntimeSessionId` bound — a unit-spec gotcha worth knowing if a future refactor wants to assert `Summary.Active == n` against freshly-inserted sessions.
