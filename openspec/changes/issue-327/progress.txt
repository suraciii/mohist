## Codebase Patterns

- `TranscriptPartTypes` is the canonical "persisted part type" vocabulary; `RuntimeEventTypes` is the "incoming runtime event" vocabulary. Both share the same string values for the closure event after T-001 (`session.closed`).
- Read-side matchers should reference the constant, never literals — `TranscriptAccumulator.ToTranscriptPartType` already did so, and after T-001 the four formerly-literal sites (AgentSessionQuerier.ReadTerminalStateAsync, SessionTranscriptBuilder, AgentSessionSummaryBuilder ×2) also reference the constant.
- Specs that seed persisted transcript parts for read-side tests now use the constant (or the dot-token literal) instead of `"session_closed"` so they round-trip correctly under the new vocabulary.
- Activity preview (`AgentSessionQuerier.ToPreview`) falls back to `e.Type` when the payload has no extractable text — closure events with `{status, exitCode}` payloads therefore render the *part type* as the visible `LastActivity.Text`, which is why the existing `Assert.Equal("session_closed", card.LastActivity!.Text)` site had to flip to `"session.closed"`.

## Gotchas

- The activity-preview renderer's text-fallback to `e.Type` means part-type literal changes leak into `LastActivity.Text` assertions — keep `AgentSessionSpecs.cs:64` aligned with the part-type vocabulary on every flip.
- Test seeds that bypass the runtime-event → accumulator pipeline and write `AgentSessionTranscriptPartRow` directly must use the same vocabulary as the read-side filter or the test will silently lose resolution (e.g. `AgentSessionReadApiSpecs.InsertFailedGenericSessionAsync` previously seeded `session_closed` and would now fail to match `ReadTerminalStateAsync` if not updated).
- The `CorrelationKey` column is opaque (per-call-site) — flipping it for consistency with the type is hygiene, not required for behavior.

## T-002 — Collapse transcript loading + context-ref helpers

Changes:
- `Sessions/Services/TranscriptPartLoader.cs` (new): single `internal static` loader, `LoadAsync(db, sessionIds, ct, partType?)`, returns `(SessionByTurnId, Parts)`. Dedupes session ids, short-circuits empty cases, applies the part-type SQL filter at the DB boundary. Imposes no SQL ordering — callers apply their own `OrderBy` via LINQ so the byte-identical projection is preserved across all five former call sites.
- `Sessions/Services/AgentSessionContextRefs.cs` (new): single `internal static` parser, `TryBuild(record)`, reads the four launch labels (IssueNumber / EpicNumber / Repository / WorkspacePath), parses IssueNumber as int-or-null, returns a nullable `ContextRefs` value tuple (null when all four are empty/whitespace). Both wrapper callers delegate to it.
- `Sessions/Services/AgentSessionQuerier.cs`: rewired five former duplication sites onto the shared loader — `LoadLatestEventsAsync` (LastSeenAt,Id ordering), `LoadEventSummariesAsync` (Sequence ordering), `LoadTerminalFactsAsync` (Sequence,Id ordering + `partType: TranscriptPartTypes.SessionClosed` SQL filter), `GetGenericSessionSummaryAsync` inline projection, `BuildSessionMetadataDtoAsync` inline projection. `LoadTranscriptAsync` (single-session, returns turns+parts for `SessionTranscriptBuilder.Build`) now delegates the parts fetch to the loader while keeping its own turns fetch (the consumer needs both). The two context-ref builders (`BuildAgentSessionListContextRefs`, `BuildGenericSessionSummaryContextRefs`) are now 3-line delegations that map the shared tuple to their own distinct DTO. `Label(...)` access promoted to `internal static` so `AgentSessionContextRefs` can share it.
- `packages/server/tests/.../Sessions/TranscriptPartLoaderSpecs.cs` (new, 7 specs): empty input, dedup, multi-session reshape, missing-turns, part-type filter with matches, part-type filter with no matches, no SQL ordering imposed.
- `packages/server/tests/.../Sessions/AgentSessionContextRefsSpecs.cs` (new, 10 specs): all labels populated, non-numeric issue number → null IssueNumber, epic-only, all absent → null, all blank/whitespace → null, metadata-fallback resolution, round-trips through both `AgentSessionListContextRefsDto` and `GenericAgentSessionSummaryContextRefsDto` (wire-format DTOs distinct, construction logic shared).
