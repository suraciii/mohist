- ProjectRoutes enforces the API contract: repository is required on POST /api/projects; PATCH /repositories/{name} disallows mixing setDefault with metadata and rejects empty patch; DELETE returns 409 for default deletion; 404 for unknown repository with project id; 409 for duplicate name with stable error code "repository_name_conflict".

Gotchas
-------
- BuildAdd returns IsDefault=true when the project has no current default. ApplyAdd in ProjectGrain then clears existing entries' IsDefault to keep validation happy; with no existing entries the loop is a no-op, so this is safe.
- UpdateRepositoryAsync treats a no-change metadata patch as Unchanged (returns _project without persisting) when BuildUpdate reports Changed=false. Empty patch (neither gitUrl nor baseBranch supplied) still raises ArgumentException via BuildUpdate before this short-circuit, so the route's "Provide gitUrl and/or baseBranch" 400 fires correctly.
- SetDefaultRepositoryAsync on the current default short-circuits before mutating the list, so a redundant setDefault call doesn't even rewrite the persisted JSON.
- BaseBranch normalization lives in TryNormalizeBaseBranch: null/empty/whitespace all collapse to "main" without error.

T-003 progress notes
====================

Implementation
--------------
- ProjectRepositoryBootstrap helper: `packages/cli/Mohist.Cli/ProjectRepositoryBootstrap.cs`.
  Returns `Outcome.Success(Result)` with (WorkTreeRoot, RepositoryName, GitUrl, BaseBranch) or `Outcome.Failure(string message)`. All work happens locally; no HTTP is issued on failure.
- Bootstrap steps (matching design D5):
  1. Canonicalize path with `Path.GetFullPath` (rejecting null/blank/whitespace as "--path is required").
  2. Verify the path is a directory and contains `.git`.
  3. `git -C <root> rev-parse --show-toplevel` to resolve the work-tree root.
  4. `git -C <root> rev-parse HEAD` to confirm a reachable commit.
  5. `git -C <root> remote get-url origin`; non-zero exit or blank stdout is rejected.
  6. Try `git symbolic-ref --short refs/remotes/origin/HEAD` and strip `origin/`; if it fails or is blank, fall back to `git symbolic-ref --short HEAD`. A detached/no-branch state is an actionable failure.
  7. Resource name = directory name of the resolved work-tree root.
  8. The path, root, remote alias, and any local checkout data stay in CLI memory; only the resolved declaration is sent.
- ProjectCommands.BuildCreate now requires `--path`; the action delegates to the bootstrap and posts `{ name, repository: { name, gitUrl, baseBranch } }` only on success. A failure writes a single actionable line to stderr and returns exit 1, with no HTTP request.

Codebase patterns
-----------------
- The bootstrap helper uses the existing `ICommandExecutor` seam from `MohistCliApi`; no new process abstraction is introduced.
- `FakeCommandExecutor` gained a `QueueForFile(fileName, exit, stdout, stderr)` helper for ordering scripted Git responses per call. Default behavior (empty queue) remains `(0, "", "")` so existing tests still pass.
- Project creation requests without a successful bootstrap never reach `MohistCliApi.PrintPostAsync`, so the server-side path-rejection layer is the only contract — the CLI never includes the local path in the payload.

Gotchas
-------
- The bootstrap pre-verifies `.git` on the canonicalized path before invoking any git command, so it returns an actionable error fast for non-work-tree directories without consuming git slots in the fake executor.
- Origin/HEAD fallback treats a blank `origin/HEAD` reference (e.g. an unconfigured remote) as "fall back to checked-out branch"; it does not default to `main` like the optional `mo repo add --base-branch` argument does.
- Description strings for `project create` were tuned to avoid containing the substring "repo" — the server-side `ProjectHelp_DoesNotListRepoSubcommand` spec asserts the absence of that literal, so wording like "local Git working tree" is safer than "local Git repository".
