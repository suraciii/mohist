What exists
-----------
- Domain policy: packages/server/src/Mohist.Server/Project/Domain/RepositoryPolicy.cs
  - Validate(list): empty-list / duplicate-name (case-insensitive) / missing-or-multiple default / blank name or gitUrl or baseBranch
  - Normalize(list): one existing default preserved; multiple defaults → first marked wins; no default → first declaration; blank baseBranch becomes "main"
  - CreateInitial(name, gitUrl, baseBranch): IsDefault=true, blank baseBranch → "main"
  - BuildAdd: rejects duplicate (case-insensitive) and blank fields; sets IsDefault based on explicit SetDefault or absence of a current default
  - BuildUpdate: requires at least one of gitUrl/baseBranch; name immutable
  - BuildSetDefault: returns Previous=Next when target is already sole default (idempotent no-op)
  - BuildRemove: rejects default deletion with code "repository_default_deletion_conflict"
- ProjectGrain (Domain/Grains/ProjectGrain.cs) routes Create/Add/Update/SetDefault/Remove through the policy before persisting.
- ProjectInfo.DefaultRepository resolves via Repositories.FirstOrDefault(r => r.IsDefault); no silent list-order fallback.
- ProjectRoutes enforces the API contract: repository is required on POST /api/projects; PATCH /repositories/{name} disallows mixing setDefault with metadata and rejects empty patch; DELETE returns 409 for default deletion; 404 for unknown repository with project id; 409 for duplicate name with stable error code "repository_name_conflict".

Codebase patterns
-----------------
- Pure domain policies live under Project/Domain/ and are exercised by unit tests without grains or web.
- Grains orchestrate DB persistence + policy; never duplicate validation.
- Route handlers map domain outcomes to ApiResults.{BadRequest,Conflict,NotFound,Ok} with stable error codes ("repository_name_required", "repository_name_conflict", "repository_default_deletion_conflict", "repository_patch_mixed_scope", "repository_update_empty").
- ProjectInfo.DefaultRepository returns the flagged default rather than the first list entry; AddRepositoryAsync that adds to a project without any default promotes the new repo via BuildAdd's "anyCurrentDefault==false" branch.

Gotchas
-------
- BuildAdd returns IsDefault=true when the project has no current default. ApplyAdd in ProjectGrain then clears existing entries' IsDefault to keep validation happy; with no existing entries the loop is a no-op, so this is safe.
- UpdateRepositoryAsync treats a no-change metadata patch as Unchanged (returns _project without persisting) when BuildUpdate reports Changed=false. Empty patch (neither gitUrl nor baseBranch supplied) still raises ArgumentException via BuildUpdate before this short-circuit, so the route's "Provide gitUrl and/or baseBranch" 400 fires correctly.
- SetDefaultRepositoryAsync on the current default short-circuits before mutating the list, so a redundant setDefault call doesn't even rewrite the persisted JSON.
- BaseBranch normalization lives in TryNormalizeBaseBranch: null/empty/whitespace all collapse to "main" without error.
