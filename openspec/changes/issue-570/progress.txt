## Codebase Patterns

- WorkflowRun is persisted as JSON through WorkflowRunStore; additive nullable properties on TaskRun and StageRun survive activation without a schema migration.
- Runner presence closeout enumerates running workflow assignments and first calls ObserveAgentRunnerDisconnectedAsync. Only a stale response falls through to ordinary-work interruption recording, preserving AgentResultSettlement arbitration.
- Workflow reminder reconciliation follows the existing AgentResultSettlement pattern: owner grain registers a durable Orleans reminder from the persisted absolute deadline and re-runs the check on activation.
- Workflow status remains Running and TaskRunStatus remains Running while WorkInterruption is present; no Interrupted enum is introduced.

## T-006 Working Notes

- OpenCode generations track active turns as abortable records. Rebuild waits on `generation.drained` only until `quarantineDrainTimeoutMs` (default 60s); force release marks every turn still in the set with the stable `generation-drain-timeout` runtime error, races its whole turn promise, aborts its local signal, resolves the drain, and lets the replacement start. Turns already returned to the host are outside that set and remain eligible for normal journal/report delivery.
- Runtime teardown uses `runtimeShutdownTimeoutMs` (default 30s) as an abandon-and-proceed bound for OpenCode server/undici cleanup and Pi `services.close()`. OpenCode graceful close sends the SDK's SIGTERM first; timeout destroys the dispatcher and performs best-effort process-group SIGKILL when a handle exposes a PID.
- RunnerOptions and CLI expose `QUARANTINE_DRAIN_TIMEOUT_MS` and `RUNTIME_SHUTDOWN_TIMEOUT_MS`; runner and self-host docs describe defaults, forced-failure semantics, and the systemd `MemoryMax` recommendation.
- Focused and full runner verification passed: `typecheck`, `typecheck:tests`, and Vitest 1,643/1,643 across 152 files.

## T-007 Working Notes

- `WorkResourceLimits` is an additive runner configuration type with nullable `memoryMb`, `wallClockMs`, `watchdogIntervalMs`, and `turnBudgetMs`; omitted values resolve to 1024 MiB, 1 hour, 250 ms RSS sampling, and 1 hour respectively. `RunnerOptions` and `AgentJobExecutorOptions` accept the partial deployment shape.
- Action subprocess containment is attached to `CommandLineOptions.resourceLimits`. When `prlimit` is available, `runCommand` preserves the detached child PID/process group and spawns `prlimit --as=<bytes> --data=<bytes> -- <command> <args...>`; otherwise the same child tree is guarded by aggregate `/proc` RSS sampling and a wall-clock timer. The no-option spawn/result path remains unchanged. A separate `resourceContainment` result marker lets built-in process/script actions report `resource-containment` without widening existing timeout/Git contracts.
- `RunnerHost` probes `prlimit` once before admitting work. `MOHIST_DISABLE_PRLIMIT=1` and the exported test setter force the watchdog fallback. Linux integration coverage uses a real memory-burning Node child; unit coverage uses deterministic RSS and ProcessSpawner seams.
- OpenCode resource-budget expiry aborts the turn, marks the current generation for the existing bounded rebuild/quarantine path, and returns the new `resource-containment` runtime error. Pi expiry aborts the turn and bounded-shuts services so the same runtime handle is replaceable on the next host loop. Journal/report ownership remains in `RunnerHost`, so siblings and completed awaiting-ack results retain their identities.

## T-008 Working Notes

- `RunnerHost` keeps the `started` journal fence closed. In-process `inFlight`/`awaitingAck` entries still skip immediately; after restart, a `started` delivery is registered in `inFlight` while reconciliation probes the persisted AgentSession binding, so repeated deliveries cannot execute the work twice.
- `binding-recovery.ts` resolves workflow-agent sessions by the original `workflowSessionName(with, workId)` and generic AgentJobs by their dispatched `agentSessionId`. A live binding with `activeTurn` is adopted through the runtime-specific `reattachTurn` seam; missing or idle bindings complete the journal with a `runner-restarted` interruption fact. Probe/transport uncertainty leaves the `started` fence for a later delivery rather than fabricating an outcome.
- OpenCode adoption watches the existing session status/event stream until idle and reads the terminal assistant message without calling `session.prompt`; Pi adoption reopens the bound session and waits for its existing stream to settle without `prompt` or `steer`. Replayed runtime observations are not promoted independently into a result.
- Fallback reports use wire `unknown` for runtime-backed agent tasks, including AgentJobs, so existing settlement arbitration remains authoritative, and `failed` plus error code/message `runner-restarted` for ordinary work. Journal acknowledgement retires the interruption receipt only after the server returns a durable `Accepted`/`Stale` acknowledgement.
