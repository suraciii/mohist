  same current default when the launch-time AgentConfig snapshot exists.
  Legacy AgentJobInput records without that snapshot use the persisted
  dispatch values only for fields explicitly supplied by the current Agent
  definition; default-resolved fields remain free so a Project-default change
  cannot flip a completed conclusion. New launches still snapshot
  AgentConfigJson, and config-less agents launched via a default keep their
  null snapshot semantics. Unit-test History helper snapshots AgentConfig for
  new-launch cases and covers the legacy fallback.

- The task-first route is registered beside the Agent definition route and
  keeps the definition-first launcher as the only execution pipeline. It
  pre-mints Agent, Session, Input, and Turn identities from the Project/key
  ownership identity and adopts an existing active Agent at that deterministic
  id after a process crash.
- `AgentTaskDefinitionFactory.Build` is the pure derivation boundary. It
  materializes runtime/model/variant, includes reserved built-in names and all
  active/archived Agent names in case-insensitive disambiguation, and uses
  Unicode-rune truncation for prompt-derived names. `CreateAsync` supports

  determinable task validation and Agent definition adoption. The route still
  resolves the candidate workspace name before replay so the existing
  fingerprint contract is preserved, but a rejected task does not create a
  workspace as a side effect.
