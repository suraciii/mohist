### Decisions
- MatchesCurrentDefinition compares resolved tuples on both sides under the
  same current default when the launch-time AgentConfig snapshot exists.
  Legacy AgentJobInput records without that snapshot use the persisted
  dispatch values only for fields explicitly supplied by the current Agent
  definition; default-resolved fields remain free so a Project-default change
  cannot flip a completed conclusion. New launches still snapshot
  AgentConfigJson, and config-less agents launched via a default keep their
  null snapshot semantics. Unit-test History helper snapshots AgentConfig for
  new-launch cases and covers the legacy fallback.
- Readiness StructuralGaps non-object AgentConfig now yields model-missing
  when no default (previously a corrupt string config produced no gap) —
  unreachable via write surfaces, acceptable tightening.
- AgentLauncher.ResolveDefinitionAsync folds the default ONLY when one is
  configured (zero behavior change otherwise) and extracts the definition
  hint from the launch's own `agent.AgentConfig` (raw runtime, variant kept
  without model) — NOT from the snapshot resolver's opencode-fallback output,
  so a default runtime can fill an absent definition runtime.
- LaunchConnectionAsync (Slack) untouched: its dispatch gate is
  AgentReadinessDeriver, a separate static helper unaffected by this change.
- Route write surface: PUT and PATCH /default-execution-config both map to
  replace-on-set (same closed field set); no clear operation in v1.
- Final refinement: `ProjectInfo.DefaultExecutionConfig` is explicitly
  serialized as `defaultExecutionConfig: null` when unset, matching the
  shared GET read contract instead of relying on the global null omission
  policy. Readiness uses resolved-tuple matching for snapshot-backed jobs and
  the documented legacy dispatch fallback for pre-snapshot jobs.
- Verification so far: focused server unit tests, the server build, and the
  server architecture/integration suites passed on the .NET 11 preview SDK.
- Compatibility follow-up: the first rebuilt full-spec run exposed that
  manually seeded/pre-feature AgentJobInput values may lack AgentConfig. The
  readiness matcher now uses the exact resolved tuple for new snapshots and a
