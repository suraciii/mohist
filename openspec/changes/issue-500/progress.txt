## Codebase Patterns

- Specs that re-activate a grain call `await grain.DeactivateForTestAsync(); await Grains.GetGrain<IManagementGrain>(0).ForceActivationCollection(TimeSpan.Zero);` then `TestWait.ForAsync` polling `GetDetailedGrainStatistics()` to confirm the activation has dropped. The `DeactivateForTestAsync` + `ForceActivationCollection` pattern is duplicated across at least 12 spec files.
- `IManagementGrain.ForceActivationCollection` is the existing cluster-wide lifecycle control — using `TimeSpan.Zero` to drop eligible activations immediately. The shared helper should wrap this.
- Direct grain construction (e.g., `new IssueGrain(... services ...) { GrainKeyForTest = "..." }`) is used in `AgentGrainSpecs`, `IssueWorkflowReadPathSpecs`, `IssueGrainEventSaveFailureSpecs`, `IssueCommentEventSpecs`, `EpicAutoDoneSpecs`, `EpicEventLineageSpecs`, `EpicProgressionTestSupport`, `EpicEventPublishTestSupport`, `WorkflowGrainStateSaveFailureSpecs`. The pattern is: construct grain directly, set key, call `OnActivateAsync()` manually. `GrainKeyForTest` falls back to `this.GetPrimaryKeyString()` when empty. Removing it means these tests must be refactored to either: (a) use a real `InProcessTestCluster` activation, or (b) use a narrower collaborator (e.g., direct `IssueStore`).
- `WorkflowGrain.BindProfileForTest` is explicitly out of scope; it stays.
- `MohistServiceRegistration` always registers `IWorkflowProfileProvider` (and 4 other audited services), so making the constructors require them matches the registered behavior.

- Removed `DeactivateForTestAsync` from the eight stub-class implementations that implement `IIssueGrain` or other grain interfaces (issue/event handler test support classes, SignalR router stub).

### Architecture guards

  - `ProductionGrainInterfaces_DoNotExposeDeactivateForTestAsync` — scans the six grain interfaces for any `DeactivateForTestAsync` method.

## T-003 Plan

### Producer contract
- `internal interface IAgentSessionPersistenceCycleReporter { void Report(string sessionId, AgentSessionPersistenceCycleOutcome outcome); }` in `Mohist.Server.Sessions.Grains`. Outcome enum: `Succeeded | TranscriptFailed | StateFailed`.
- `internal sealed class NullAgentSessionPersistenceCycleReporter { public static readonly Instance; void Report => no-op }` — production registration (`MohistServiceRegistration.TryAddSingleton<IAgentSessionPersistenceCycleReporter>(NullAgentSessionPersistenceCycleReporter.Instance)`). Performs no persistence, no scheduling, no allocation. The grain always loads it.
- `internal sealed class AgentSessionPersistenceCycleProbe : IAgentSessionPersistenceCycleReporter` lives in the production assembly (visible via existing `InternalsVisibleTo("Mohist.Server.SpecTests")`). Single global instance per test silo; one TaskCompletionSource per session; Report drains either a pending waiter or queues the outcome so a waiter registered after the cycle completes still observes it. Public surface for tests: `Task<RecordedCycle> AwaitNextCycleAsync(sessionId, timeout)`, `void Reset()`.

### Grain wiring
- Add `IAgentSessionPersistenceCycleReporter persistenceCycleReporter` constructor parameter to `AgentSessionGrain`.
- In `PersistCallback` (only), wrap `FlushAsync`:
  - try { success = await FlushAsync(…) } catch (InvalidOperationException) { outcome = StateFailed; rethrow }
  - outcome = success ? Succeeded : TranscriptFailed
  - reporter.Report(SessionId, outcome) — *before* `DisposePersistTimer()`.
- Reporter must never be invoked from `FlushPendingTranscriptAsync`, `FlushPendingTranscriptEvidenceAsync`, `OnDeactivateAsync`, or `PersistRecoveryAsync`; those are not deferred cycles. Move existing `DisposePersistTimer()` to fire only on `Succeeded` (current code disposes on `success`; both outcomes equivalent).
- Remove `Task FlushForTestAsync();` from `IAgentSessionGrain` and `public async Task FlushForTestAsync()` from `AgentSessionGrain`.
