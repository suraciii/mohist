# Issue #308 progress

## Codebase Patterns

- **Module split strategy**: 11 focused modules + a barrel (`github-pr.ts`) per design D1. Strict DAG, leaves first.
- **Barrel transparency (D3)**: `registry.ts` and the three specs (`create-`, `merge-`, `mark-` github-pr specs) import the public surface from `./github-pr.js`. Internal-helpers compile unchanged when the barrel re-exports the relocated symbols; no spec import-line edit needed.
- **Runner singletons**: still live as top-of-file mutable `let` in `github-pr.ts` (`git`/`gh`). Move to `github-pr-runtime.ts` in T-003.
- **Test injection setters**: `setGitHubPrGitRunnerForTest`/`setGitHubPrGhRunnerForTest` (in github-pr.ts today, runtime in T-003). `setGitHubPrChecksTimingForTest`/`setGitHubPrTransientRetryForTest` (in github-pr.ts today, merge in T-004).
- **ESM + NodeNext + `.js` extensions**: every internal `import` path uses `.js` (e.g. `./github-pr-parse.js`). `import type` for type-only imports.

### Key gotchas
- **`parsePrStatusCheckRollupResult`** was originally file-private. The leaf's `parsePrStatusCheckRollup` (the public API) calls it. We renamed the leaf's private `function` to `export function` (still module-internal in spirit, but reachable from `github-pr.ts`) so `waitForPrChecks`'s internal call site `parsePrStatusCheckRollupResult(checksResult.stdout)` could keep compiling unchanged while satisfying the design's "(±result)" notation. `github-pr.ts` does NOT re-export it, so the public action surface is unaffected.
- **`parsePrList` etc.**: leaf exports them verbatim — no behavioral change. `extractPrNumberFromUrl` and `PrViewState` move with them.
- **TypeScript type-only re-export**: `export type { ... }` is required for `interface`/`type` re-export under `isolatedModules` semantics; value re-export uses `export { ... }`. Mixing the two keeps each symbol in the correct export kind.
- **`import { type PrCheckEntry }` inside `export {...}` block** — TypeScript syntax for re-exporting a type alongside values in a single `export {}` block.
