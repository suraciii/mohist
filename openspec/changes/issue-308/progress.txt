# Issue #308 progress

## Codebase Patterns

- **Module split strategy**: 11 focused modules + a barrel (`github-pr.ts`) per design D1. Strict DAG, leaves first.
- **Barrel transparency (D3)**: `registry.ts` and the three specs (`create-`, `merge-`, `mark-` github-pr specs) import the public surface from `./github-pr.js`. Internal-helpers compile unchanged when the barrel re-exports the relocated symbols; no spec import-line edit needed.
- **Runner singletons**: still live as top-of-file mutable `let` in `github-pr.ts` (`git`/`gh`). Move to `github-pr-runtime.ts` in T-003.
- **Test injection setters**: `setGitHubPrGitRunnerForTest`/`setGitHubPrGhRunnerForTest` (in github-pr.ts today, runtime in T-003). `setGitHubPrChecksTimingForTest`/`setGitHubPrTransientRetryForTest` (in github-pr.ts today, merge in T-004).
- **ESM + NodeNext + `.js` extensions**: every internal `import` path uses `.js` (e.g. `./github-pr-parse.js`). `import type` for type-only imports.

## T-002 — Extract gh failure-text classifier module + add direct unit tests for the matcher matrix

**Done.** Pure leaf module `github-pr-classify.ts` created (75 lines), `github-pr.ts` re-exports the 7 classifier symbols, new `tests/github-pr-classify.spec.ts` covers every phrase in every matcher plus `classifyGhFailure` precedence + empty/blank fallback. All 793 tests green (38 new + 755 unchanged). Monolith went from 1171 → 1114 lines. Zero existing spec file touched.

### Files created
- `packages/runner/src/actions/github-pr-classify.ts` — leaf (depends only on `github-pr-types.ts` for `GitHubPrErrorCode`). Exports `classifyGhFailure`, `classifyPushFailure`, `looksLikeBaseMoved`, `looksLikeProtectionConflict`, `looksLikePrStateConflict`, `looksLikeAuthFailure`, `looksLikeRetrySafe`. Body is byte-identical to the previous `github-pr.ts` definitions (same `toLowerCase()` idiom, same phrase lists).
- `packages/runner/tests/github-pr-classify.spec.ts` — 38 pure-function tests: for each matcher, enumerate every phrase (lowercase + mixed-case to confirm `toLowerCase()`), plus a control set of negative phrases (unrelated error text) and an empty-input check. `classifyGhFailure` gets single-bucket classification tests, full 5-way precedence sweep (table-driven), and pairwise precedence (auth-beats-protection-beats-base-moved-beats-pr-state-beats-retry-safe). `classifyPushFailure` gets delegation + base-moved-via-git-push-output test.

### File modified
- `packages/runner/src/actions/github-pr.ts` — added value-side imports for the 7 classifier symbols + a re-export block mirroring the parse/checks pattern from T-001; removed the relocated definitions. 93-line diff (18 insertions, 75 deletions). 1171 → 1114 lines.

### Key gotchas
- **Barrel re-export pattern (T-001 precedent, continued)**: import the symbols as values (they are used internally by `classifyGhFailure`, `runGhReadWithRetry`, etc.), and add a value `export {}` block. No `type` qualifier needed because all 7 symbols are functions, not interfaces.
- **`classifyGhFailure` precedence table-driven test**: instead of writing 5 long "winning phrase + losing phrase" pairs by hand, a single loop iterates over the 5 buckets and uses a tiny IIFE per case to return the right phrase + the right "loser text containing every lower-priority bucket" — this proves that priority *suppresses* the lower-bucket matches in the same text, not just that the bucket *appears* in isolation.
- **Empty / whitespace-only fallback**: the original `classifyGhFailure` does `if (!text.trim()) return "retry-safe"` *before* any matcher. Verified via dedicated test that whitespace-only stdout, whitespace-only stderr, and whitespace in both still classify as `retry-safe`. This guards against regressions where someone might move the empty-text check below the matcher loop and accidentally let a pure-whitespace `lower.includes("502")` (false-positive) slip through.
- **Test style for pure leaves**: no `afterEach` runner reset needed (no mutable singleton involved); only direct function calls. Mirrors the small-spec style already used by `issue-fields.spec.ts` etc.
- **Why no `import type` for `GitHubPrErrorCode`**: the test asserts classifier return values are typed as `GitHubPrErrorCode` via `expect(...).toBe<GitHubPrErrorCode>("retry-safe")` — this is a generic type argument at the assertion call site, so `GitHubPrErrorCode` must be a value-position type at the import (which it is: `import type` works fine here, and I used it).

Monolith: 1114 → 1095 lines (19 lines moved out).

### Key gotchas
- **Getter vs exported-`let` (D2)**: design explicitly mandates getters, not exported mutable `let`. If we exported `let` and a helper captured the binding at module-load, `setGitHubPrGhRunnerForTest(null)` would never propagate to that helper. The getter is read live on every call, matching the previous behavior where helpers read the live `let` at call time. Pinned by the new `one setGitHubPrGhRunnerForTest call ... singleton identity` test.
- **Single setter, many readers**: previously `git`/`gh` were closure-captured at module load by every helper in the monolith. After the split, those helpers don't see the module-scope binding at all — they take the runner as a parameter. The orchestrator captures the getter's return value *once* per action call and passes it through. This is what "helpers keep runner param signatures, only orchestrators call the getter" means in practice.
- **`resolvePrNumberForMerge` signature change**: it was the *only* helper that read `gh` directly from module scope (line 578 of the pre-T-003 file). To keep the singleton-ownership clean — only orchestrators read module state — I added a `gh: GhRunner` first param. The sole caller (`mergeGitHubPrAction`) was updated to pass the captured `gh`. No test changed.
- **Type-alias shadowing is fine**: the runtime module exports `GitRunner` / `GhRunner` for T-004 / T-005 to import. `github-pr.ts` keeps its own `type GitRunner = typeof defaultGit` / `type GhRunner = typeof runCommand` aliases for its helper-param types. They are structurally identical (both `typeof` the same underlying values), so callers see the same shape. No re-export needed.
- **`runGhPrecheck` accepts `gh` as a param** — design's placement decision (this module is the "git/gh execution context"). A dedicated `github-pr-gh.ts` was an acceptable variant per design Open Questions; we follow the runtime placement (simpler DAG, fewer files).
- **Barrel re-export pattern (T-001/T-002 precedent, continued)**: `github-pr.ts` adds a value `export {}` block for `setGitHubPrGhRunnerForTest` / `setGitHubPrGitRunnerForTest`. The *getters* and `runGhPrecheck` are NOT re-exported — they are internal to the runtime module and the orchestrators (consistent with `combinedGhOutput` etc. being internal to the orchestrator helpers in T-001). The new `barrel re-export from github-pr.js` test pins that only the two setters leak out.
- **`CommandResult` import**: runtime's `runGhPrecheck` only needs `typeof runCommand` for the `GhRunner` type alias — it does not import `CommandResult` (the orchestrator's `runGhReadWithRetry` still needs it and will move with T-004). Kept the type alias local to runtime for the same reason.
