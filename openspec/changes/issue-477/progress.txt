## Codebase Patterns

- WorkflowProfile collection records are custom-only rows keyed by `(ProjectId, ProfileId)`; built-ins remain catalog assets and are merged by `IWorkflowProfileProvider`.
- Reference rows keep one public Profile ID in their owning state and a nullable custom backing key for the restrictive composite FK. Built-in references leave the backing key null.
- `WorkflowProfileDeletionBlockerQuery` is diagnostic; the FK is the final delete/selection race backstop. Terminal Run transitions clear only the backing key and retain public state/history.
- Server spec databases use the existing shared in-memory SQLite model schema. Collection specs use a fixed `FakeTimeProvider`; production writes accept the application `TimeProvider`.
