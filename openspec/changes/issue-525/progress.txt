## Codebase Patterns

- Slack management routes use `AgentQuerier.GetByIdAsync(projectId, agentId)` for bound-Agent reads and `ApiResponse<T>` with camel-cased anonymous response objects.
- `AgentConnectionStore.CreateAsync` validates the active Agent and persists `BotName` verbatim; `WorkspaceTeamId`, `AppId`, and `BotUserId` stay empty until `SlackSetupVerifier` calls `BindSlackIdentityAsync` after verification.
- Pure Agent derivations are static `*Deriver` types under `Agent/Services`, with direct unit tests under `Mohist.Server.UnitTests/Agent/Services`.
- Slack's current manifest contract for `features.bot_user.display_name` is 1–80 characters using only lowercase `a-z`, `0-9`, `-`, `_`, and `.`; `display_information.description` allows up to 140 characters, but T-001 requires a non-blank Agent description to remain unchanged.

## T-002 Notes

- The masked credential input lives at `packages/web/src/shared/ui/components/masked-credential-input.tsx` and is re-exported from `packages/web/src/shared/ui/index.ts` (slice public API) per the FSD rule "新增导出时先改 slice 的 `index.ts`，而不是在调用方加深路径". Consumers can use either `@/shared/ui` or `@/shared/ui/components/masked-credential-input`.
- Implementation reuses the existing `Input` primitive and forces `type="password"` plus `autoComplete="off"`, `autoCorrect="off"`, `autoCapitalize="off"`, `spellCheck={false}`. The `type` prop is removed from the public prop type so no caller can put the field into a cleartext type — masking is enforced at the type boundary, not just by convention.
- No reveal/show toggle is added (and the prop type excludes `type`, so a future PR can't sneak one in through `type="text"`). The form (T-004) is expected to do clear-on-success and body-only transmission; this primitive deliberately does not own those concerns.
- Test placement and pattern: colocated `*.test.tsx` under `components/`, following `alert-dialog.test.tsx` / `button.test.tsx`. Uses `userEvent.type` for the controlled-input path and `screen.getByLabelText` for queries; `screen.getAllByRole('textbox')` does not match password inputs in jsdom, so a previous draft of the "no toggle" test threw — switched to direct label queries.
- Assertions cover the spec's "masked" / "no cleartext path" / "no storage writes" acceptance criteria: `input.type === 'password'`, no `<button>` rendered, body `textContent` does not contain the secret, `localStorage`/`sessionStorage`/`URL` unchanged after typing + unmount, and `Storage.prototype.setItem` spy never sees the secret. Console warn/error spies assert the same — the setup file's blanket mock would otherwise throw, but the local spies give a clearer signal if the component ever logs the secret.
- FSD: `shared/ui/components/masked-credential-input.tsx` imports `@/shared/ui/components/input` and `@/...` paths are resolved inside the same `shared` slice (no slice boundary crosses). `npm run check:fsd -w packages/web` and `npm run check:test-boundaries -w packages/web` both pass after the change.
- Test boundaries: `npm run test:run -w packages/web` passes 5,096 / 5,096 with the five new specs included. `npm run typecheck -w packages/web` is clean.
