## Codebase Patterns

- Quality metrics and stage durations share the effective project profile stage-order concept. `ResolveProjectStageOrderAsync` now uses `IWorkflowProfileProvider`, so persisted custom project profiles are resolved in addition to builtins.
- Quality windows should emit only entered stages. Definition stages are emitted in Definition order; observed stages absent from that Definition retain accumulator insertion order after them.
- The quality spec file is already guarded by the architecture test file-size ratchet. New scenarios belong in a separate focused spec file rather than expanding `IssueMetricsQualitySpecs.cs`.
- EF Core migration history must keep the dropped column in prior migration snapshots; only the current `MohistDbContextModelSnapshot` and the row/config map need to forget it. The Drop migration only needs to DropColumn and AddColumn (default `"{}"`) on its Down.
- `WorkflowRunVariablesStore` exposes both read and write paths. Removing the defaults layer leaves just `Get/Set/Patch` on the explicit `Variables` column; the ETag concurrency and tracked-row read-modify-write shape stay intact.
- `WorkflowGrain` exposes two constructors (Orleans + test-friendly). Both must drop the `WorkflowRunVariablesStore` parameter and the two `EnsureArchiveDefaultAsync(GrainKey)` start-up calls.
- `recoveries` is a top-level YAML key parsed into `WorkflowDefinition.Recoveries` (`IReadOnlyDictionary<string, RecoveryDefinition>`). Parser reuses `BuildRecovery`; the serializer emits a `recoveries:` block beside `stages`/`approval` and round-trips through `FromJson`/`ToJson`.
- `WorkflowQuerier.GetRecoveryAsync(workflowRunId, name)` is the canonical rebase-route lookup surface; `WorkflowProfileManager.LoadTemplateAsync` already resolves the bound profile so the helper is a thin wrapper.
- File-scoped tests can't use `System.IO.File` / `AppContext.BaseDirectory` (banned in `eng/BannedSymbols.Tests.txt`). Reflection-on-type is the only legal way to assert "method no longer exists" on helpers.
