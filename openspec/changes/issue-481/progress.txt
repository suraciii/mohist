## Codebase Patterns

- Cross-domain read assembly belongs in `AgentOps/Services` and uses the `IScopedService` marker for automatic DI registration.
- Project routes resolve `{projectRef}` with `ProjectResolutionEndpointFilter`; handlers read the canonical identity through `HttpContext.GetResolvedProject()`.
- Runner registry visibility is intentionally global even though `RunnerStatusService` accepts a project id; Activity must preserve this as `scope=global`.
- The route-private approval waiting projection was extracted to `ActivityWaitingProjection` so `/agent/activity` and `/activity` share one source and mapping.
- The Activity merge fetches up to the endpoint maximum from each bounded source, sorts the combined entries by time descending then deterministic id, and only then applies the caller limit.
- Microsoft Testing Platform ignores the legacy `dotnet test --filter` property in this project; focused attempts execute the full spec assembly. Test apphosts require `DOTNET_ROOT=/home/szf/.dotnet` in this workspace.
- CLI shared contracts: `MohistCliCommands.ProjectRefOption()` returns `(--project, --project-id-hidden)`; `MohistCliCommands.JsonSelectionOption()` returns the bare-or-selected `--json`. `api.PrintResourceAsync(path, descriptor, selection, humanRenderer)` already handles discovery/invalid/success/data error paths and is the right entry for finite reads.
- `WriteJsonSelectionResult` returns exit code 2 for `JsonSelectionKind.Invalid`, so command bodies can early-return without re-implementing local validation. Local failure paths use `CliExitCode.For(CliExitOutcome.UsageFailure)` (= 2) for clean semantics.
- `TableShape.*` enum entries are mapped to `ResourceCardinality` and field lists in `ResourceOutputCatalog.For`; a new collection entry must be added to both `cardinality` and `fields` switches. Renderer dispatch lives in `TableRenderer.Render` with peer branches per shape — same partial-class convention as `Events.cs`.
- `RecordingHttpHandler` exposes captured requests in `Requests`; tests that want to assert re-readable results must use fresh `StringWriter` instances per call (the shared `output` writer accumulates across two `RunAsync` invocations in the same test).

## T-002

- `mo activity list` is a single root group with one `list` leaf; registered next to `EventCommands` in `MohistCliCommands.Build`.
- `ActivityList` added to `MohistCliApi.TableShape` (Collection) and to `ResourceOutputCatalog.For` with the 13 declared fields; the command-owned descriptor is the source of truth and is reused for both default and `--json` selection.
- The leaf reuses `api.PrintResourceAsync` + `api.RenderTableAsync` rather than `PrintWithOutputAsync`, keeping the field contract command-owned instead of inferred through the global catalog.
- Field selection is parsed before project resolution or HTTP work: bare `--json` enumerates declared fields, invalid field lists hit `WriteJsonSelectionResult` (exit 2). `--limit` is then validated locally (1..200) before `ResolveProject` so neither failure path issues HTTP.
- Added `RenderActivityList` to `TableRenderer.Events.cs` (Activity is a sibling of Event delivery for table rendering, matching the partial-class peer layout). Columns: provenance / scope / kind / time / title / source — `source` collapses to the most relevant identity (`issueNumber` for Issue/waiting, `workflowRunId`/`sessionId` for those kinds, `runnerId` for Runners).
- The command sends `?limit={limit}` after percent-encoding the resolved project id and never touches `/events`, `/agent/activity`, or Runner APIs.
- Specs cover route/query construction, default limit, project override, no-active-project and 1..200 local validation, bare/selected/invalid `--json`, provenance/scope distinction, default table rendering, and re-readable finite results.
