# Issue #323 — Insights M2 chart migration — working memory

## Codebase Patterns

- **Dashboard grid layout** — `pages/dashboard/ui/DashboardPage.tsx` uses a 2-column responsive grid (`md:grid-cols-2`) that already renders two items cleanly. Going from 3 → 2 surviving zones does NOT cause layout regression.
- **DashboardPage zone mounting** — iterates `DASHBOARD_ZONES` (array of `{id, name}`) and mounts each via `<DashboardZone>`. Wrapping the iterand in a single-expression ternary by `zone.id` (instead of a chained ternary chain) is the simpler, narrower shape after removing the productivity branch.
- **DashboardPage empty-state path** — the `!projects || projects.length === 0` branch is the only place `dashboard-empty-state` renders; none of the chart mocks fire there, so tests in the empty-projects branch can keep asserting every zone is absent (including `dashboard-zone-productivity`) unchanged.
- **Colocated tests** — every chart component has a `*.test.tsx` next to it (not in a separate `tests/` dir); relocating the component means moving its test file with it, single command (`git mv`).
- **`../charts` import pattern preserved** — every `pages/dashboard/productivity/*.tsx` imports `'../charts'` (ChartContainer/ChartAxes/etc.) or specific primitives. Keeping `charts/` and `panels/` as siblings under `pages/insights/` (D1) preserves every import byte-for-byte.
- **`<chart>-window` testid convention (from T-002 spec)** — D4 will add `data-testid="<chart>-window"` to six charts in T-002; the chart's existing data-testid was specifically generic (e.g. `productivity-quality` for `QualityPanel`, `throughput-chart` for `ThroughputChart`). The window badge naming must be `<chart-name>-window` to match `ThroughputChart → data-testid="throughput-chart-window"` etc. (T-002 not done yet; assert it does not collide with any existing testid via grep before adding the badge.)

## Gotchas

- **`DashboardZoneId` type narrowing** — removing `'productivity'` from the union in `DashboardZone.tsx` means `DASHBOARD_ZONES` array literal must also drop that id. TypeScript's exhaustiveness in the ternary was a non-issue because the new code uses a non-exhaustive ternary (`zone.id === 'digest' ? <digest> : <pulse>`), but if you ever tighten back, reintroduce exhaustive checks.
- **`git mv` followed by `git rm`** — `git mv` stages the rename; `git rm` of those same paths then needs `-f` (force) because the index has staged entries. Workaround: `git rm -f <path>` after `git mv` works directly.
- **No third `dashboard-digest-empty` slot check** — in the prior "zone content in every slot" test, the third negation (`productivity.querySelector('[data-testid="dashboard-digest-..."]')`) tested that the productivity slot does not contain digest content. After deletion the new test must verify the surviving zones (`pulse` not mounting digest; `digest` not mounting digest-empty/loading/content is wrong — digest IS the digest mount point). Lesson: be careful not to over-add "absence" assertions on the surviving zones that ARE supposed to mount the digest widget.
- **`npm install` not pre-run** — this workspace ships `package-lock.json` but no `node_modules`; first run of any `npm run *` script triggers a `npm install` (took ~4s). Subsequent commands work normally.

## Task T-002 specifics

- **Badge testid naming:** used `<chart-name>-window` exactly as the convention planned (e.g. `throughput-chart-window`, `cycle-time-chart-window`, `cumulative-flow-chart-window`, `stage-duration-chart-window`, `ftr-trend-chart-window`, `cost-trend-chart-window`). Pre-flight grep confirmed no collisions with existing testids (`*-lens-*`, `chart-container-*`, etc.).
- **Badge style:** `inline-flex items-center rounded-md border border-border bg-muted/40 px-2 py-0.5 text-xs tabular-nums text-muted-foreground` — same chip pattern used elsewhere in the codebase (`SystemUpdateOutcomeView`, `SessionRecoveryActions`, `context-ref-chip-*`). The badge lives in the header chrome (alongside the existing `<h3>`, on the right of a `flex justify-between` row) and does not touch chart body, data-fetch, lens toggles, overlays, empty states, or `ChartAccessibility` summaries.
- **Charts with right-side lens toggles (CycleTimeChart, StageDurationChart):** the badge sits to the left of the lens toggle inside a wrapping `<div className="flex items-center gap-2">` so the layout doesn't break.
- **Charts with rework overlay toggle (FtrTrendChart):** the badge sits inside the existing right-side `<div className="flex items-center gap-2 text-xs text-muted-foreground">` so it shares the row with the overlay checkbox. The badge does not include `text-muted-foreground` since it inherits from the wrapper.
- **Empty-state hiding rule:** badge renders only when the chart's existing populated-data guard passes (`hasThroughputData` / `hasPlottablePoints` / `hasSnapshotData` / `hasPlottableStages` / `trend && bucketCount > 0` / `hasUsageData`) — same predicate the chart body uses to render its data, so the badge visibility mirrors the chart body's empty handling. Each colocated test asserts both the populated badge AND that the badge is absent in the empty state.
- **Window source per chart (matches design.md D4):**
  - `ThroughputChart` → fixed `30d` (completion `bucket=day` trailing window).
  - `CycleTimeChart` → fixed `30d` (delivery-time endpoint trailing window).
  - `CumulativeFlowChart` → derived from `data.rangeFrom`/`data.rangeTo`, formatted as `MMM D – MMM D` (e.g. `Apr 2 – Jun 30`). Reuses existing `formatDayLabel`.
  - `StageDurationChart` → derived from `data.window.from`/`data.window.to`, formatted as `MMM D – MMM D`. Added a new `formatStageWindow` helper that parses the ISO datetime prefix and formats via `toLocaleDateString`.
  - `FtrTrendChart` → derived from `trend.from`/`trend.to`, formatted as `MMM D – MMM D`. Reuses existing `formatBoundaryLabel`.
  - `CostTrendChart` → derived from `data.rangeFrom`/`data.rangeTo`, formatted as `MMM D – MMM D`. Reuses existing `formatLabel`. Note: `rangeTo` may be exclusive (one day after the last bucket, e.g. `2026-06-29T00:00:00` for buckets ending `Jun 28`); the badge reflects the endpoint as-is, not the displayed last bucket day — the task explicitly requires the badge to be "derived strictly from the range their endpoint already returns (no invented window)".
- **Function hoisting:** `formatDayLabel` (CumulativeFlowChart), `formatLabel` (CostTrendChart), and `formatBoundaryLabel` (FtrTrendChart) are all function declarations in the same module, so they hoist and can be referenced from the JSX returned earlier in the file. No imports needed.
- **No new types, no DTO changes, no chart-internal logic touched.** Pure additive header chrome per D4; charts' interaction, empty-state, accessibility, lens toggles, overlays, and `ChartAccessibility` summaries all unchanged.
- **Test results:** all six chart test files pass individually (27/27, 28/28, 23/23, 29/29, 27/27, 33/33). Full web test run: 253 files, 3972 passed / 1 skipped (the pre-existing skip). `npm run typecheck -w packages/web` clean.
