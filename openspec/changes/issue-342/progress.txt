# Issue #342 — Detail-page mobile adaptation — progress

## Codebase Patterns

- **Widgets layout**: `packages/web/src/widgets/issue-workflow/` keeps pure decision/state modules under `model/` (e.g. `derive-runtime-decision.ts`) and presentational React under `ui/`. Cross-cutting pure helpers can live at the widget root next to the model.
- **Barrel exports**: `widgets/issue-workflow/index.ts` re-exports every public surface, type, and (where stable) helper. New helpers should be exported from there.
- **Mutation wiring shape**: `RuntimeDecisionSurfaceMutations` defines the eight runtime mutations as `{ mutate, isPending, error }`. Any helper that drives them must accept this shape and not introduce a new abstraction layer (no wrapper hook, no separate facade).
- **Test discipline**: existing `RuntimeDecisionSurface.test.tsx` uses `vi.fn()` + a `mutation()`/`mutations()`/`decision()` helper trio. New unit tests for the pure handlers should mirror that style and avoid rendering React (the handlers are not React components).
- **Typecheck = lint for web**: `tsc -b` under `packages/web` is the lint step (no `lint` script). Treat any type error as a hard failure.

## Decisions / gotchas

- **Body vs. title**: `getStopConsequenceCopy` returns both. The desktop surface renders `body` (preserves test assertions like `'preserve progress'` / `'irreversible'`). The narrow drawer (T-002) will use `title` as a section header and `body` as the consequence sentence.
- **`invokeAction('inspect', ...)` is a no-op**: matches the existing desktop behavior where inspect is rendered disabled with a `title` reason and never wired to a mutation. Future surface can decide whether to mount it at all.
- **Two-step confirm stays in `RuntimeDecisionSurface`**: only the second click (the actual mutation call) routes through `invokeAction('stop', ...)`. The first click still toggles `stopConfirming` locally — that gating is UX, not action wiring.
- **Send-back success callback is passed via `callbacks.onSendBackSuccess`**, not by returning the mutate promise from `invokeAction`. Keeps `invokeAction` a `void` and the desktop form's local state reset (close form + clear text) where it belongs.
- **No narrow-viewport rendering introduced** — desktop surface stays anchored in the header tier per design D1. T-002 will do the page-level conditional split.

## Decisions / gotchas (T-002)

- **Bar height math**: bar wrapper is `pb-[calc(0.5rem+env(safe-area-inset-bottom))]` + inner `p-2` + button `min-h-[44px]`. Total bar height ≈ 68px + safe-area. With `MobileBottomNav` (56px + safe-area) below md, total reserved ≈ 124px + safe-area. `pb-[calc(8rem+env(safe-area-inset-bottom))]` = 128px + safe-area is enough for both the 768-1024px band (no nav) and below md (with nav) — slightly more padding than the no-nav case needs but never less than the with-nav case requires.
- **`translate-y-0` baseline**: kept on the panel so the tw-animate-css `slide-in-from-bottom-full` runs from the off-screen state to the anchored state. `pointer-events-none` on the outer container plus `pointer-events-auto` on the panel keeps the rest of the page interactive while the drawer is open (no dimming scrim, no event-blocking scrim — design D3).
- **Esc-to-close via `document`**: must `stopPropagation()` so the existing `EventTimelinePanel` `keydown` handler does not also act on the same Escape; the only other Escape consumer in the page is the activity dialog, which only listens when it's mounted.
- **Drawer renders into a sibling of the scroll container** (outside `issue-detail-page-container`). This is required because the scroll container clips its overflow region — a `fixed` drawer inside would still be `fixed` to the viewport (CSS is absolute) but a portal/sibling placement makes the intent unambiguous in tests and DOM.
- **No MobileActionBar on send-back as primary in practice**: per the #340 single-primary model and design D1, the narrow bar only surfaces `decision.primary`. For `approval-required` the primary is `approve`, so `send-back` never reaches the bar in the current decision shape. The MobileActionBar nonetheless implements the send-back drawer (unit-tested) so if the primary ordering ever surfaces send-back, the wiring is ready. T-003 (rail) will not change this.
- **`previousFocusRef` cleanup**: the cleanup runs even when `open` is still `true` if a parent re-renders that flips `open` to `false` between effect runs; the cleanup then steals focus back to the trigger, which is the desired UX (drawer closed → focus returns to the bar's primary button).
