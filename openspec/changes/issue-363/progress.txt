  (in-memory) gives the agreement assertion required by the spec.

## Gotchas
- `WorkflowRun.Start(Now())` will throw `InvalidOperationException` if
  the run is not `Created`/`Paused`. The "started without a runner"
  helper (`StartWorkflowWithoutRunnerAsync`) leaves the run in `Pending`,
  which is the correct phase for `PauseAsync`/`StopAsync`/`ResumeAsync`
  control races.
- `StopAsync` throws `InvalidOperationException` when the run is
  already `Stopped`; the catch helper `CatchAsync` makes this
  assertable without exploding the test.
- `PauseAsync` followed by `StopAsync` both succeed from `Pending`:
  Pause moves to `Paused`; Stop is allowed from `Paused`. When fired
  concurrently, exactly one ordering wins but both can succeed — the
  spec asserts only that the final state is one of the two allowed
  serialized outcomes, never on the order.
- `dotnet test --no-build` runs only what's already built; if the
  preceding `npm test` shows warnings about stale builds, the safe
  re-run is `dotnet build <project>` first.
