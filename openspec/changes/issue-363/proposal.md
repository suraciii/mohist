## Why

Issue #362 landed the self-driving durable event dispatcher — events are now delivered at-least-once out-of-stack, with per-handler retry, backoff, and dead-lettering. That removes the original synchronous-callback rationale for the `[Reentrant]` marks on `WorkflowGrain` and `RunnerGrain`, the `RunnerGrain._worksStateWriteGate` semaphore, handler-internal try-catch swallowing, and the `EpicReconciliationService` 10-minute sweep. RunnerGrain reentrancy removal is deferred to a follow-up prerequisite: the multi-call poll lease and reciprocal Runner↔AgentJob waits still depend on broad interleaving, and the poll sequence is owned by `DispatchService`, which this issue explicitly excludes. The epic sweep reevaluates readiness states beyond missed terminal events (link-to-running, terminal-before-link, all-complete-idle); those are preserved by adding a link-time recompute trigger before the sweep is deleted. Separately, `ReconcileAfterTerminalAsync` is a misnomer — the method recomputes epic progress (MarkDone detection + TryStartNext advance) from member state, it does not "reconcile" a discrepancy — and the word collides with the workflow scheduling domain's separate `DispatchService` reconcile. Cleaning this up lets the code say what it means without silently dropping existing progress guarantees.

## What Changes

- Remove `[Reentrant]` from `WorkflowGrain` (`Workflow/Grains/WorkflowGrain.cs:22`), restoring turn-based serialization as the sole state-safety guarantee for that authority grain. RunnerGrain reentrancy removal is deferred to a follow-up prerequisite (see Scope Decisions).
- Remove handler-internal try-catch exception swallowing (`AgentSubscriptionDispatchHandler.HandleAsync`, `HermesIssueNotificationHandler.HandleAsync`) so errors propagate to the durable dispatcher's unified retry/dead-letter path. (The `RunnerWorkflowTerminalStatusHandler` detach was already removed in #362; any remaining prose referencing the old model is cleaned up.)
- Remove `EpicReconciliationService` (`Events/Hosting/EpicReconciliationService.cs`), `EpicReconciliationOptions`, and the `AddHostedService<EpicReconciliationService>()` registration in `MohistServiceRegistration.cs`. The sweep's non-terminal-event readiness behavior (link-to-running, terminal-before-link, all-complete-idle) is preserved by adding a link-time `RecomputeProgressInternalAsync` call after non-wake links to non-terminal epics; draft/prerequisite readiness is covered by durable delivery of the prerequisite's `completed` event.
- Rename the epic progress-recompute chain from "reconcile" to "recompute progress" across the full call path:
  - `IEpicGrain.ReconcileAfterTerminalAsync` → `RecomputeProgressAsync` (grain contract)
  - `EpicGrain.ReconcileAfterTerminalInternalAsync` → `RecomputeProgressInternalAsync` (shared core logic, called from grain entry + `ResumeAsync` + link-time trigger)
  - `EpicReconcileDispatcher` → `EpicProgressRecomputeDispatcher`
  - `EpicCancelledReconcileHandler` → rename to drop "reconcile" (style-aligned with `EpicAutoDoneHandler`)
  - All XML doc comments and `<see cref>` references updated from "reconcile" to "recompute progress"
- Add concurrency characteristic tests covering state consistency for `WorkflowGrain` after reentrancy removal.

## Capabilities

- `grain-turn-serialization`: Authority-state mutations in `WorkflowGrain` rely on Orleans turn-based serialization — no broad `[Reentrant]`. Concurrency tests verify state consistency under this model. RunnerGrain reentrancy removal is deferred to a follow-up prerequisite that resolves the multi-call poll lease and reciprocal Runner↔AgentJob waits without modifying `DispatchService`.
- `handler-error-propagation`: The durable processing stages covered by this change let exceptions propagate to the dispatcher for unified retry and dead-lettering: Agent subscription dispatch, Hermes notification setup/enqueue, and exceptions escaping the awaited runner-status router invocation. Intentionally best-effort UI delivery remains detached and locally handled.
- `epic-progress-recompute`: Epic progress recomputation on member terminal events is named and documented as "recompute progress" (not "reconcile"). The poll-driven safety-net sweep is removed; its non-terminal-event readiness behavior is preserved by a link-time recompute trigger. Durable delivery becomes the reliable trigger in response to member terminal events. The grain method itself is retained — it is the epic's self-driving domain action (MarkDone detection + serial next-issue advance), including the three required semantic triggers: `EpicAutoDoneHandler` (completed events), the renamed cancelled handler, and `ResumeAsync`.

## Scope Decisions

- **RunnerGrain reentrancy removal deferred.** Removing broad `[Reentrant]` from `RunnerGrain` would strand an admitted poll when `UnregisterAsync` or `UpdateAsync` occupies the turn before the poll reaches `TouchPresenceAsync`, `GetInfoAsync`, or `ReconcileAgentJobsAsync`; marking only `EndPollAsync` interleavable does not resolve this. Runner also has reciprocal progress dependencies with `AgentJobGrain` during assignment, reconciliation, result reporting, and closeout. The poll sequence is owned by `DispatchService`, which this issue explicitly excludes. A follow-up prerequisite must resolve both progress problems before RunnerGrain reentrancy and `_worksStateWriteGate` can be removed. This issue removes `[Reentrant]` from `WorkflowGrain` only.
- **Epic sweep readiness behavior preserved by link-time recompute.** `EpicReconciliationService` reevaluates more than missed terminal events: it advances a running epic after a startable issue is linked, and marks done when all members are complete at link time. These behaviors are preserved by adding a `RecomputeProgressInternalAsync` call after non-wake links to non-terminal epics. Draft/prerequisite readiness is covered by durable delivery of the prerequisite's `completed` event. The sweep is deleted after the link-time trigger is in place. No cross-aggregate event->command semantics are changed.
