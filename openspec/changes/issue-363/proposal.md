## Why

Issue #362 landed the self-driving durable event dispatcher - events are now delivered at-least-once out-of-stack, with per-handler retry, backoff, and dead-lettering. That removes the original synchronous-callback rationale for the `[Reentrant]` marks on `WorkflowGrain` and `RunnerGrain`, the `RunnerGrain._worksStateWriteGate` semaphore, handler-internal try-catch swallowing, and the `EpicReconciliationService` 10-minute sweep. The epic sweep reevaluates readiness states beyond missed terminal events (link-to-running, terminal-before-link, all-complete-idle); those are preserved by adding a link-time recompute trigger before the sweep is deleted. Separately, `ReconcileAfterTerminalAsync` is a misnomer - the method recomputes epic progress (MarkDone detection + TryStartNext advance) from member state, it does not "reconcile" a discrepancy - and the word collides with the workflow scheduling domain's separate `DispatchService` reconcile. Cleaning this up lets the code say what it means without silently dropping existing progress guarantees.

## What Changes

- Remove `[Reentrant]` from `WorkflowGrain` (`Workflow/Grains/WorkflowGrain.cs:22`), restoring turn-based serialization as the sole state-safety guarantee for that authority grain. Drop `using Orleans.Concurrency` if no symbol from that namespace remains.
- Remove `[Reentrant]` from `RunnerGrain` (`Runner/Grains/RunnerGrain.cs:33`) and remove `_worksStateWriteGate` (`RunnerGrain.cs:43`). Remove `_pollAdmissionGate` (`RunnerGrain.cs:45`) to eliminate the multi-call poll-lease deadlock: `UnregisterAsync` and `UpdateAsync` no longer block on a poll-admission semaphore. Keep `_pollAdmitted` as a flag for the `AssignAgentJobAsync` business-logic reject. Keep `_lifecycleGate` for `AssignAgentJobAsync` state-mutation protection.
- Mark `GetRuntimeStateAsync` and `AssignAgentJobAsync` as `[AlwaysInterleave]` on `IRunnerGrain` (`GetSlotsAsync` is already `[AlwaysInterleave]`). This prevents a reciprocal deadlock when `AgentJobGrain.TryAssignToRunnerAsync` calls RunnerGrain while RunnerGrain's turn is held by `HandleTimeoutAsync` or `UnregisterAsync` during closeout.
- Move `CloseoutLostAsync()` outside `_lifecycleGate` in `HandleTimeoutAsync` (matching the existing `UnregisterAsync` pattern) so `AssignAgentJobAsync` can acquire the gate during closeout.
- Remove handler-internal try-catch exception swallowing (`AgentSubscriptionDispatchHandler.HandleAsync`, `HermesIssueNotificationHandler.HandleAsync`) so errors propagate to the durable dispatcher's unified retry/dead-letter path. (The `RunnerWorkflowTerminalStatusHandler` detach was already removed in #362; any remaining prose referencing the old model is cleaned up.)
- Remove `EpicReconciliationService` (`Events/Hosting/EpicReconciliationService.cs`), `EpicReconciliationOptions`, and the `AddHostedService<EpicReconciliationService>()` registration in `MohistServiceRegistration.cs`. The sweep's non-terminal-event readiness behavior is preserved by durable, event-driven recompute triggers that replace every readiness transition the sweep covered:
  - **Link-to-running / all-complete-idle**: inline `RecomputeProgressInternalAsync` after links PLUS `EpicIssueLinkedHandler` subscribing `com.mohist.epic.issue-linked` for durable convergence after a crash between link commit and inline recompute.
  - **External prerequisite completes**: `EpicAutoDoneHandler` reverse-looks-up epics whose members depend on the completed issue via `EpicQuerier.GetEpicIdsDependentOnPrerequisiteAsync`. Cancellation recomputes only a direct member epic because prerequisites require completion.
  - **Draft undraft**: `EpicDraftChangedHandler` subscribing `com.mohist.issue.draft-changed` (undraft only).
  - **Prerequisite removed**: `EpicPrerequisiteRemovedHandler` subscribing `com.mohist.issue.prerequisite-removed`.
  - **Command-path start failure**: `TryStartNextAsync` emits `EpicStartAttemptFailed` (persisted atomically with the epic state); `EpicStartRetryHandler` subscribing `com.mohist.epic.start-attempt-failed` re-drives recompute via the durable dispatcher with backoff, replacing the sweep's running-but-idle recovery loop.
- Recovery-critical events (`EpicIssueLinked`, `EpicStartAttemptFailed`) are persisted atomically with the epic state transition via `EventStore.AppendAsync(db, envelope)` into the caller's DbContext, so a crash or failed append between commit and event persistence cannot lose the only convergence signal.
- Rename the epic progress-recompute chain from "reconcile" to "recompute progress" across the full call path:
  - `IEpicGrain.ReconcileAfterTerminalAsync` -> `RecomputeProgressAsync` (grain contract)
  - `EpicGrain.ReconcileAfterTerminalInternalAsync` -> `RecomputeProgressInternalAsync` (shared core logic, called from grain entry + `ResumeAsync` + link-time trigger)
  - `EpicReconcileDispatcher` -> `EpicProgressRecomputeDispatcher`
  - `EpicCancelledReconcileHandler` -> rename to drop "reconcile" (style-aligned with `EpicAutoDoneHandler`)
  - All XML doc comments and `<see cref>` references updated from "reconcile" to "recompute progress"
- Add concurrency characteristic tests covering state consistency for both `WorkflowGrain` and `RunnerGrain` after reentrancy removal.

## Capabilities

- `grain-turn-serialization`: Authority-state mutations in `WorkflowGrain` and `RunnerGrain` rely on Orleans turn-based serialization - no broad `[Reentrant]`. `RunnerGrain._worksStateWriteGate` and `_pollAdmissionGate` are removed; `_lifecycleGate` is retained for `AssignAgentJobAsync`'s interleaved state mutations and each fresh workflow claim's live availability/capacity check. `GetRuntimeStateAsync`, `GetSlotsAsync`, and `AssignAgentJobAsync` are `[AlwaysInterleave]` to prevent reciprocal deadlock with `AgentJobGrain`. `HandleTimeoutAsync` moves closeout outside `_lifecycleGate`. Concurrency tests verify state consistency for both grains. The `DispatchService` poll order remains unchanged.
- `handler-error-propagation`: The durable processing stages covered by this change let exceptions propagate to the dispatcher for unified retry and dead-lettering: Agent subscription dispatch, Hermes notification setup/enqueue, and exceptions escaping the awaited runner-status router invocation. Intentionally best-effort UI delivery remains detached and locally handled.
- `epic-progress-recompute`: Epic progress recomputation on member terminal events is named and documented as "recompute progress" (not "reconcile"). The poll-driven safety-net sweep is removed; its non-terminal-event readiness behavior is preserved by a link-time recompute trigger. Durable delivery becomes the reliable trigger in response to member terminal events. The grain method itself is retained - it is the epic's self-driving domain action (MarkDone detection + serial next-issue advance), including the three required semantic triggers: `EpicAutoDoneHandler` (completed events), the renamed cancelled handler, and `ResumeAsync`.

## Scope Decisions

- **RunnerGrain reentrancy removal.** Removing broad `[Reentrant]` from `RunnerGrain` requires four supporting changes: (1) remove `_pollAdmissionGate` so `UnregisterAsync`/`UpdateAsync` no longer block on a poll-admission semaphore between poll calls; (2) mark `GetRuntimeStateAsync` and `AssignAgentJobAsync` as `[AlwaysInterleave]` so `AgentJobGrain.TryAssignToRunnerAsync` can complete when RunnerGrain's turn is held by closeout; (3) move `CloseoutLostAsync` outside `_lifecycleGate` in `HandleTimeoutAsync` so `AssignAgentJobAsync` can acquire the gate; (4) revalidate Runner registration and capacity under `_lifecycleGate` for every fresh workflow claim. `_lifecycleGate` is retained because `AssignAgentJobAsync` is now interleavable and fresh workflow claims must be linearized with `UpdateAsync` and `UnregisterAsync`. `_worksStateWriteGate` is removed (redundant with turn serialization for non-interleaved `PersistAsync` calls; `AssignAgentJobAsync`'s `PersistAsync` is protected by `_lifecycleGate`). The `DispatchService` poll order remains unchanged.
- **Epic sweep readiness behavior preserved by link-time recompute.** `EpicReconciliationService` reevaluates more than missed terminal events: it advances a running epic after a startable issue is linked, and marks done when all members are complete at link time. These behaviors are preserved by adding a `RecomputeProgressInternalAsync` call after non-wake links to non-terminal epics. Draft/prerequisite readiness is covered by durable delivery of the prerequisite's `completed` event. The sweep is deleted after the link-time trigger is in place. No cross-aggregate event->command semantics are changed.
