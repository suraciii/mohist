## Codebase Patterns

- `RuntimeConsistencyValidator` uses small private snapshot types (`SystemInfoSnapshot`) and `TryGet*Async` helpers to read API payloads; the new runner identity check follows the same pattern with `RunnerIdentitySnapshot` + `TryGetRunnerIdentityAsync`.
- `VerifyRuntimeStageAsync` reports one line per check via `RuntimeCheckResult.Component`; the new component name is `"Runner identity"`.
- Source HEAD is memoized on `UpdateContext.SourceHead`; both server and runner identity checks reuse `TryGetSourceHeadAsync(context)` with no second `git rev-parse`.
- The runner identity check is intentionally Warn-only (D3); it never returns Fail so existing aggregation (`Any(Fail)` / `Any(Warn)`) stays correct.

## Gotchas / Decisions

- The endpoint is `GET /api/runner/identity` with no hostname query (D4); the server defaults to `Environment.MachineName`.
- Existing server-side system tests (`UpdateSpecs.cs`) stub HTTP responses with `SequenceHttpHandler` / `OutcomeCapturingHttpHandler`. Adding the runner identity check caused previously-all-pass tests to become Recovered because the identity endpoint returned empty 200. Fixed by making those handlers return a runner `buildGitHash` that matches the mocked system info `running.gitHash` when `_systemInfoJson` is set.
- When `_systemInfoJson` is null (runner refresh tests), `SequenceHttpHandler` does not intercept `/api/runner/identity`, preserving the existing queued-response behavior for `RunnerRefreshVerifier` tests.

## Tests Added/Updated

- `RuntimeConsistencyValidatorSpecs`: match, mismatch, missing runner hash, source HEAD unavailable, endpoint unreachable.
- `SourceCodeUpdaterVerifyRuntimeSpecs`: full VerifyRuntime orchestration (pass, mismatch warn, dry-run mentions runner identity).
- `UpdateSpecs` server system tests: handlers now include runner identity response so Ready/succeeded expectations hold.
