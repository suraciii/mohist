# Issue-262 Working Memory (T-001 → T-002)

## Codebase Patterns

- The agent route group is `app.MapGroup("/api/projects/{projectRef}/agent").AddEndpointFilter<ProjectResolutionEndpointFilter>()` in `packages/server/src/Mohist.Server/Api/AgentRoutes.cs`. Any new sibling endpoint inherits the 404-via-filter behavior automatically.
- `ProjectResolutionEndpointFilter` requires the resolved `ProjectInfo` to be read via `context.GetResolvedProject()` inside handlers. It also throws if the filter wasn't applied — so handlers must live on the route group, not as raw `app.MapGet(...)`.
- The `AgentSessionQuerier.GetUsageTimeseriesAsync` method (`packages/server/src/Mohist.Server/Workflow/Services/Sessions/AgentSessionQuerier.cs:283`) is the template for cost rollup reads: `ListByLabelsAsync` with `ProjectId` label + `AgentSessionJsonHelper.Usage` + `HasUsage` predicate (`AgentSessionQuerier.cs:323`). The `??=` pattern for first-non-null `CostCurrency` (`AgentSessionQuerier.cs:313`) is reused.
- `IssueQuerier.ListAsync` returns `IssueReadModel` whose `Status` is the lowercase string (`"done"`). The done count is computed in the handler with `Count(i => i.Status == "done")` — verbatim from `StatusRoutes.cs:58`.
- `ApiResults.Ok<T>(data)` wraps responses in `{success, data}` envelope. Tests deserialize with `GetDataAsync<T>` which unwraps via `ApiEnvelope<T>` (`packages/server/tests/Mohist.Server.Tests/Support/ApiTestClient.cs:111`).
- Tests in `packages/server/tests/Mohist.Server.Tests/Specs/Api/AgentUsageTimeseriesApiSpecs.cs` are the closest analogue: same `MohistIntegrationFixture` + `[Collection("MohistIntegration")]` + insert session via `AgentSessionRow` with serialized `AgentSessionJson.JsonOptions`. Issue insertion mirrors `ActivityWaitingApiSpecs.cs` helpers (`InsertBacklogIssueAsync` / `InsertDoneIssueAsync`).
- Frontend metrics hooks (`entities/issue/api/quality-metrics.ts`, `entities/issue/api/completion-trend.ts`, `entities/issue/api/approval-wait.ts`) follow the same shape: `fetch<Metric>` via `projectApiPath`, an exported `<metric>QueryKey(projectId?)` helper, and a `use<Metric>()` that pulls `projectId` from `useProject()` with `enabled: !!projectId` and `staleTime: 60_000`. Tests mock `useQuery` + `useProject` at the module boundary (no network).
- `formatCost(amount, currency)` from `shared/lib/format-compact.ts` returns `""` for null/undefined, `"$0.00"` for real zero, and a prefixed string (`USD ` fallback) for unknown currencies. It is the established helper for display-grade currency rendering and was already imported by `WorkflowSessionsPanel`, `CompactSessionCard`, `SessionCard`, `SessionHeader`, `UsageSnapshotLabel`, and `SessionPage`.

## Decisions / Notes

- `GetCostRollupAsync` returns an intermediate `AgentCostRollupRawData` (totalCost + todayCost only) rather than the full `AgentCostRollupDto`. The done-issues count is composed in the handler from `IssueQuerier` per design.md D2 (no new service class). The `costPerShip` rule (`BuildCostPerShip` helper) is also composed in the handler — keeping the querier focused on per-session aggregation.
- One unbounded `_sessionQuery.ListByLabelsAsync` query is used; todayCost is filtered in memory against `[todayUtc, tomorrowUtc)`. Avoids two SQL roundtrips and matches the in-memory filter pattern the timeseries uses (`AgentSessionQuerier.cs:299-314`).
- `costPerShip.amount = null` is decided by two conditions: `doneIssuesCount == 0` OR `totalCost.Amount is null`. Otherwise amount is `totalCost.Amount / doneIssuesCount` with `sampleCount = 1`. A genuine `totalCost.Amount = 0` therefore yields a real `0` for costPerShip (per spec "Free shipping is a real zero, not an empty sample").
- `AgentCostMetricDto.Amount` is `double?` and `SampleCount` is `int`. Empty metric: `(null, currency, 0)`. Real zero: `(0.0, currency, >0)`. These are distinguishable by `Amount == null` — mirrors the `QualityPanel` `sampleCount === 0` convention called out in design.md D3.
- Frontend `useCostRollup` is co-located with the agent-session data source (`entities/agent/api/cost-rollup.ts`), not under `entities/issue` — only `doneIssuesCount` originates from issues, the cost fields are agent-session usage; per design.md D5.
- The hook's `queryKey` is `['agent', 'cost-rollup', projectId]` (projectId optionally appended) — distinct prefix from the issues metrics namespace so invalidation can target either independently.
- `InvestmentPanel` treats `totalCost.sampleCount === 0` as the empty branch (mirrors `QualityPanel` `window.sampleCount === 0` gating). `doneIssuesCount === 0` does NOT trigger the panel-level empty state — the panel still renders, with cost-per-ship showing `—` (the spec distinguishes the two emptinesses: panel empty = no spend recorded; cost-per-ship empty = undefined ratio).
- A genuine `totalCost.amount === 0` with `sampleCount > 0` renders as `$0.00` via `formatCost` — verified by a dedicated test that distinguishes it from the empty branch.
