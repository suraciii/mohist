# Review: Issue 517

## Findings

1. **P1: Credential rotation accepts an unverified App token.** `VerifyRotationAsync` receives `appToken` but never uses it ([SlackSetupVerifier.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/src/Mohist.Server/Slack/SlackSetupVerifier.cs:86)); it passes only `botToken` to `RunVerificationAsync` at line 95. The available Slack calls also authenticate only with the Bot token ([ISlackApiClient.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/src/Mohist.Server/Slack/ISlackApiClient.cs:9)). A malformed, expired, or unrelated App-level token therefore passes rotation whenever the Bot token is valid, is persisted at [SlackConnectionRoutes.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/src/Mohist.Server/Api/SlackConnectionRoutes.cs:192), and only breaks when the adapter later attempts Socket Mode. Add an App-token validation call that proves the token belongs to the bound Slack App before either secret is stored, and add an actual route-level rejection test for an invalid or mismatched App token.

2. **P1: Disable does not immediately stop an already-running adapter from sending replies.** The new ingress guard protects only `/ingress` ([SlackConnectionRoutes.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/src/Mohist.Server/Api/SlackConnectionRoutes.cs:268)). `/deliveries/claim` still calls `outbox.ClaimAsync` without loading or checking the Connection ([SlackConnectionRoutes.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/src/Mohist.Server/Api/SlackConnectionRoutes.cs:393)), while an established adapter polls that endpoint and posts every claimed delivery to Slack ([adapter.ts](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/mohist-slack/src/adapter.ts:116)). Discovery only disconnects this runtime on its next refresh, so it cannot provide the required immediate server-side stop. Make delivery claiming reject or withhold records for Disabled Connections, and guard adapter-session renewal as well, then cover disabling an active adapter with a queued or subsequently-produced reply.

3. **P1: The required Web diagnostic surface is absent.** Issue acceptance requires Web diagnostics alongside CLI, and task T-006 requires a Web route, TanStack Query hook, summary, and expandable supporting facts. This change contains no modified `packages/web` product files, so an operator cannot open a Connection diagnostic in Web at all. Implement that route and its data/query layer against `GET /slack-connections/{id}/diagnostic`, including the summary's single next action and all supporting dimensions.

4. **P2: New server "spec" tests do not exercise the API routes they claim to verify.** For example, lifecycle tests replace the ingress endpoint with `RunIngressGuardAsync` ([SlackConnectionLifecycleSpecs.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/tests/Mohist.Server.SpecTests/Specs/Slack/SlackConnectionLifecycleSpecs.cs:425)), and rotation tests similarly reproduce the route body in `RunRotateCredentialsAsync` ([SlackConnectionRotateCredentialsSpecs.cs](/home/szf/.mohist/projects/workspaces/wr_70319ded1dec458599350de7f864eeaf/packages/server/tests/Mohist.Server.SpecTests/Specs/Slack/SlackConnectionRotateCredentialsSpecs.cs:302)). These tests cannot detect a wrong route binding, HTTP status, dependency ordering, or a later divergence from the copied logic. Replace the copied route helpers with tests through the mapped HTTP product entry point for rotation, lifecycle operations, ingress, and diagnostics; retain focused lower-layer tests for the pure/domain behavior.
