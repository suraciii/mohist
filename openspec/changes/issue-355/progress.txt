### Codebase Patterns (carry-forward for T-002 and future issues)

- **`AddJsonFile(path, optional, reloadOnChange)` does NOT take a string path and return it back as the source's `Path`.** For rooted (absolute) input paths, `FileConfigurationSource.ResolveFileProvider()` splits the path: `Path = Path.GetFileName(path)`, `FileProvider = new PhysicalFileProvider(Path.GetDirectoryName(path))`. So locating the just-added source via `builder.Sources.OfType<JsonConfigurationSource>().LastOrDefault(s => string.Equals(s.Path, configPath, ...))` will silently fail to find it. The fix is to use the `AddJsonFile(Action<JsonConfigurationSource>)` overload, which gives the source by reference — much simpler and matches the codebase's "wire callbacks at registration time" style.
- **`System.Text.Json` reads JSONC natively.** `JsonConfigurationFileParser.ParseStream` constructs its `JsonDocumentOptions` with `CommentHandling = Skip` + `AllowTrailingCommas = true` — verified in the framework source. `StripJsoncComments` was solving a non-problem; the deletion is safe.
- **`property.Value.GetRawText()` returns the raw file slice.** If you re-parse it via `JsonNode.Parse` (without `CommentHandling.Skip`), any inline `/* ... */` between sibling keys breaks the inner parse. Pass `JsonDocumentOptions { CommentHandling = Skip, AllowTrailingCommas = true }` to every `JsonNode.Parse` call when the input came from a JSONC file.
- **`OnLoadException` callback signature:** `Action<FileLoadExceptionContext>`. The context exposes `Provider`, `Exception`, and a settable `Ignore`. Set `ctx.Ignore = true` to suppress rethrow (file-system fallback to last-known-good / empty). This is the single seam that covers both startup AND runtime reload fault tolerance — no need for separate paths.
- **`AddMohistConfigFile` early-returns on missing file** (`if (!File.Exists(configPath)) return builder;`). This is in addition to `optional: true`; both are belt-and-suspenders. Removing the early-return would still work (since `optional: true` tolerates missing), but the early-return is faster and preserves the "no source added when file absent" semantic that downstream code may rely on.
- **Tests live under `Specs/SystemSpecs/`** with `[Trait(Traits.Speed.Name, Traits.Speed.Unit)]` + `[Trait(Traits.Sut.Name, Traits.Sut.System)]` for unit-fast tests. New file: `MohistConfigurationExtensionsSpecs.cs` is a plain `IDisposable` class (not `IAsyncLifetime`) because the only IO is synchronous `File.WriteAllText` for setup — matches the lightweight style of other unit specs.
