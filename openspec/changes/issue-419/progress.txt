## Codebase Patterns

- Issue affiliations (Epic, Parent) are stored on the child aggregate via init-only `EpicNumber` / `ParentIssueNumber` properties and projected to `IssueRow`. Affinities are guard-constrained at the aggregate layer (e.g. child cannot join Epic).
- The C# 14 `union` syntax compiles to a base class + per-case records. The base class name shadows the union's case name at the type level: `IsType<UnionCase>(unionValue)` and `OfType<UnionCase>(unionSequence)` both fail at runtime — the analyzer's CA2021 actually flags this statically. Use the `is UnionCase` pattern (or iterate and switch) instead. Existing tests already follow this pattern (`IssueStartReadinessDomainTests.SingleDraftEvent`).
- `IssueLineage.BuildExtensions` and the related event serializers are pure helpers that read only the producing aggregate's state — no DB calls. The `parent` lineage key mirrors `epic`: stamped conditionally on the producing issue, omitted entirely when the affiliation is null.
- `IssueStatus` JSON serialization uses `JsonStringEnumConverter` with `CamelCase` policy: `Backlog → "backlog"`, `InProgress → "inProgress"`, `Done → "done"`, `Cancelled → "cancelled"`. The new `IssueCompositeStatusChanged` event payload uses the same wire strings.

  - `ReopenComposite()` — Cancelled → Backlog, bypasses the repository-existence check (no snapshot argument, no target gate).
  - `RecomputeCompositeStatus(snapshot)` — pure decision method returning the aggregated target status; throws on empty snapshot. Aggregation order: any InProgress child → InProgress; all Backlog → Backlog; any Backlog + terminal mix → InProgress (some work still pending); all Cancelled → Cancelled; mixed terminal with ≥1 Done → Done.
