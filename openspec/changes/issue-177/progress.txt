## Codebase Patterns

- Epic grain uses a `{projectId}:{epicId}` key format parsed via `GrainKey.Split(':')`. The Orleans `Grain` base class can be instantiated directly in unit tests with a `GrainKeyForTest` property pattern (mirrors `AgentGrain.GrainKeyForTest` in `packages/server/src/Mohist.Server/Agent/Grains/AgentGrain.cs:21`).
- For unit testing EpicGrain without Orleans silo: instantiate directly with `new EpicGrain(factory, null!) { GrainKeyForTest = "project_1:epic_1" }`, seed `EpicRow`/`EpicIssueRow`/`IssueRow` directly into in-memory SQLite (Migrate, not EnsureCreated, because the schema has computed columns for `IssueRow.ProjectId`/`Number`/`WorkflowRunId` based on `json_extract`).
- Test database: SQLite `:memory:` + `db.Database.Migrate()` + `TestDbContextFactory` wrapping `DbContextOptions<MohistDbContext>`. See `packages/server/tests/Mohist.Server.Tests/Specs/Agent/Grain/AgentGrainSpecs.cs:203-241`.
- For seeding an Issue into `IssueRow.State` use `IssueStore.Serialize(issue)` (`packages/server/src/Mohist.Server/Infrastructure/Data/Issue/IssueStore.cs:93`). After the migrate creates the schema, computed `ProjectId`/`Number` columns are populated automatically from JSON.
- C# name collision: `Mohist.Server.Issue.Domain` is a namespace AND contains a class `Issue`. Importing both `Mohist.Server.Issue.Domain` and `Mohist.Server.Infrastructure.Data.Issue` breaks `new Issue { ... }` — the compiler picks the namespace. Workaround: use fully-qualified `new Mohist.Server.Issue.Domain.Issue { ... }` and `Mohist.Server.Issue.Domain.IssueStatus.Done` in test code.
- Empty-epic quirk: an epic with no linked issues satisfies `undelivered.Count == 0` (the existing manual `SetStatusAsync("done")` behavior), so `AutoMarkDoneIfReadyAsync` (and resume re-evaluation) on an empty epic transitions to `done`. This is consistent with manual Mark Done, but two existing API specs (`Resume_FromPaused_ReturnsActiveStatusAndClearsReason`, `ResumeRoute_AcceptsEpicNumber`) assumed an empty epic stays `active` on resume — they need a linked backlog issue to exercise the non-ready path.
- `ResumeAsync` re-eval must gate on `wasPaused` (the prior `domain.Status == EpicStatus.Paused` snapshot before the transition), otherwise calling `ResumeAsync` on an already-active epic would still invoke the auto-done check, which is harmless but wasted work and subtly changes the contract. The current `domain.Resume()` is itself a no-op on non-paused, so checking before the call is the right hook.
- `TryAutoMarkDoneAsync` swallows terminal/paused and "undelivered not empty" as no-ops, returning the current DTO. Only on `active` + `undelivered.Count == 0` does it call `domain.MarkDone(...)` (the same domain method the manual path uses, preserving throw semantics on the manual route).

## Gotchas

- `IConfiguration`/`ILogger` and grain deps not used by the methods under test must be passed as `null!` (the grain's `OnActivateAsync` is not called in unit tests because the `Grain` base methods aren't invoked).
- The grain's `Materialize` + `MapToRow` pipeline requires the `EpicRow` to be tracked (no `AsNoTracking` on the load) so that the in-place status update is persisted by `SaveChangesAsync()`. `TryAutoMarkDoneAsync` reuses the tracked row passed in by the caller.
- The grain reads the issue rows by `Number` using a computed column on `IssueRow`. The seed helper must call `IssueStore.Serialize` so the computed columns (`ProjectId`, `Number`, `WorkflowRunId`) resolve from the JSON, otherwise the grain's `BuildLinkedIssueDtosAsync` returns an empty list and the epic auto-dones on any seeded data.

## T-002 outcome

- Added `EpicQuerier.GetEpicIdForIssueAsync(projectId, issueId)` — reverse `issueId → epicId` lookup using the existing `IX_EpicIssues_ProjectId_IssueId` index (defined in `MohistDbContext.cs` for `EpicIssueRow`). Returns `null` when the issue is not linked to any epic so the handler can no-op.
- Added `Mohist.Server.Events.Subscriptions.EpicAutoDoneHandler` (`[Subscription(Type = "com.mohist.issue.work-completed")]`, typed `ICloudEventHandler<IssueWorkCompleted>`). The handler reads `projectid` / `issueid` from the CloudEvent extensions (already published by `IssueGrain.PublishIssueEventsAsync`), resolves the owning epic via the querier, and invokes `IEpicGrain.AutoMarkDoneIfReadyAsync()` on the `$"{projectId}:{epicId}"` grain. Duplicates/out-of-order events are absorbed by the grain's T-001 idempotency.
- Handler placement under `Mohist.Server/Events/Subscriptions/` (top-level alongside `Events/Hub/EventBridge.cs`) — *not* under `Epic/Services/`. Putting it in `Epic/Services` would create a `Services → Grains` cycle (handler uses `IEpicGrain` from `Epic.Grains`) and trigger `DomainInternalLayers_ShouldBeFreeOfCycles`. Top-level placement keeps the Epic slice cycle-free and treats event-bus subscriptions as cross-cutting infrastructure that happens to call into Epic (mirrors how `EventBridge` lives outside any feature folder).
- `EpicQuerier` constructor accepts `IssueQuerier` as `null!` in unit tests when only `GetEpicIdForIssueAsync` is exercised (the method doesn't touch `_issuesQuery`); production DI wires it normally.
- Handler failures are caught + logged at warning level (no rethrow) so a single bad event doesn't poison the in-memory bus; reconciliation sweep (T-003) is the safety net for missed events.
- Tests: 8 new Fake-based specs in `packages/server/tests/Mohist.Server.Tests/Specs/Events/Epic/EpicAutoDoneHandlerSpecs.cs`:
  - last-issue-completes → done (real EpicGrain via fake `IGrainFactory`, end-to-end via DB assertion)
  - unlinked issue → no-op (querier returns null, grain never invoked)
  - partial completion → no-op (epic stays active, grain invoked)
  - duplicate events → converge to done (3 calls recorded, single state transition)
  - paused epic unchanged on event (grain invoked, no auto-done)
  - full bus dispatch via `InMemoryEventBus.PublishAsync` typed subscription path
  - missing `projectid` extension → no-op without error
  - subscription attribute assertion (`com.mohist.issue.work-completed`)
- `dotnet build` clean (0 warnings, 0 errors); `dotnet test` 2575/2575 passed (8 new specs + 2567 prior). Architecture rules pass: handler outside `Epic.*` slice avoids the Services↔Grains cycle.
