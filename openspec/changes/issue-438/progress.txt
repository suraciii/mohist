## Codebase Patterns

### T-001: ModelOptionList + ModelSelect port to cmdk

**Pattern: cmdk context issue with useCommandState**
- `useCommandState` (aka `useCmdk`) must be called from within the `Command` component's React context tree
- Cannot call it at the same component level where `<Command>` is rendered (parent level)
- Fixed by using DOM-based query for `[data-selected="true"][data-model-id]` instead

**Pattern: cmdk onKeyDown interaction**
- cmdk internally calls `props.onKeyDown` for unhandled keys (verified in cmdk 1.1.1 source: `(s=O.onKeyDown)==null||s.call(O,...)`)
- This means `onKeyDown` on `CommandRoot` IS forwarded for non-cmdk keys (ArrowRight, Tab)
- Must guard against chip-initiated events: skip when `event.target.closest('[data-variant-chip]')` exists
- This prevents double-focus bug where CommandRoot handler re-focuses chip[0] after chip keydown advances to chip[1]

**Pattern: Tailwind `**` variant on cmdk elements**
- `**:[[cmdk-group-heading]]:sticky` applies CSS to the heading via descendant selector
- The class is on the group container DOM element, NOT the heading element itself
- Tests should query `[data-slot="command-group"]` for these className assertions

**Pattern: Consumer test fixes**
- `AiSettingsSection.test.tsx`: changed `fireEvent.pointerDown(row)` → `fireEvent.click(row)` (3 places)
- `AiSettingsSection.test.tsx`: changed `screen.getByRole('button', { name: /gemini-2/i })` → DOM query with `data-selected` check
- `IssueModelSelector.test.tsx`: changed `fireEvent.pointerDown(row)` → `fireEvent.click(row)` (2 per-stage places)
- Default-model popover `pointerDown` tests in IssueModelSelector left for T-002

**Gotchas:**
- cmdk's `CommandList` has `no-scrollbar` in the wrapped version; used raw `CommandRoot.List` with custom className including `overscroll-y-contain`
- cmdk's `CommandItem` wrapper has built-in CheckIcon; used raw `CommandRoot.Item` to avoid it
- cmdk's `CommandInput` wrapper has custom InputGroup styling; used raw `CommandRoot.Input` with Tailwind classes
- The `ModelSelectProps` contract preserved exactly; zero prop changes needed at all 4 consumer sites

### T-002: IssueModelSelector default-model popover ported to cmdk

**Approach: Direct cmdk composition (not ModelOptionList wrapper)**
- `IssueModelSelector` has surface-specific extras (loading/error, Override "Use default" row, Recent section, "Override active" note, per-stage overrides) that don't fit the simple ModelOptionList API
- Used cmdk primitives directly (`CommandRoot`, `CommandRoot.Input`, `CommandRoot.List`, `CommandRoot.Item`, `CommandGroup` from wrapper) composing the same way ModelOptionList does internally
- This satisfies the "shared primitive" intent without adding props creep to ModelOptionList

**Pattern: cmdk `filter={false}` broken in cmdk 1.1.1**
- The TS type `CommandFilter` doesn't include `boolean`, and even with a cast, `filter={false}` causes `TypeError: s is not a function` at runtime
- cmdk's internal `te()` function always calls the filter as a function without checking if it's falsy
- Workaround: use `filter={() => 1}` — a pass-through filter that returns 1 for every item, effectively disabling cmdk's built-in filter
- Fuzzysort does the actual filtering externally via `displayedModels`, and those models are rendered as `CommandRoot.Item`s

**Pattern: Controlled `value` on CommandRoot for `aria-selected`**
- cmdk's `CommandRoot.Item` sets `aria-selected` based on `cmdkValue === itemValue` internal comparison
- Must pass `value={configuredModel ?? undefined}` to `CommandRoot` so the currently selected model gets `aria-selected="true"`
- Without this, `aria-selected` is always `false` even when `isSelected` class is applied

**Pattern: "Use default" Override row as CommandGroup+CommandRoot.Item**
- The Override "Use default" button became a `CommandRoot.Item` inside a `CommandGroup` for keyboard navigability and a11y group labeling
- Test queries had to change: `screen.getByRole('button', { name: /Use default/i })` → `document.querySelectorAll('[cmdk-item]')` then find by textContent
- The `CommandRoot.Item` renders as `role="option"`, not `role="button"`

**Deleted:**
- `ModelListItem` component (bespoke, with inline `onPointerDown` selector)
- `handleKeyDown` (bespoke, omitting Escape)
- `highlightedIndex` state
- `searchInputRef`, `listRef`
- `useEffect` resetting highlightedIndex on search change
- `Input` import (replaced by `CommandRoot.Input`)
