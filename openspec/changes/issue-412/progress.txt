# Issue 412 redesign baseline

## Why the previous progress is superseded

The previous T-001..T-007 implementation completed an event-lineage plan built on random
IssueId/EpicId identities, Epic-owned membership rows, copied EpicId snapshots, Workflow binding
states/revisions, and a per-type EventCatalog registry. Repeated check failures exposed failures in
normal cross-aggregate crash windows. The user then confirmed a different domain model, so those
task completion claims no longer describe the accepted target.

The old implementation commits remain in the candidate as migration input. Replacement tasks must
remove or reshape them; they are not accepted progress and no task in the new tasks.json is marked
passing.

## Authoritative redesign

- Master spec commit: `71f2cd7b9 docs: define Issue-owned Epic membership`
- Live Issue #412 title/body updated to the number-only identity and Issue-owned affiliation model.
- Workdir rebased onto `origin/master` at that spec commit.
- New OpenSpec proposal/design/delta specs/tasks replace the old D5 denormalization and binding plan.

Core target:

- Issue identity: (`ProjectId`, `IssueNumber`)
- Epic identity: (`ProjectId`, `EpicNumber`)
- current affiliation authority: Issue.`EpicNumber?`
- Workflow local context: `{ ProjectId, IssueNumber, EpicNumber? }`
- cross-aggregate process: aggregate commit + durable event + idempotent target command
- event keys: `projectid`, `issue`, `epic`, `workflowrunid`, `stage` (plus independent entity ids)
- conformance: real producer-family paths and structural Stage, not a per-type catalog matrix

## Preserved independent repair

Commit `6ef69d923` adds `RejectIfRunReloadRequired()` at the start of `WorkflowGrain.StartAsync` and a
state-save-failure regression. This guard is independent of the superseded lineage protocol and must
survive T-004 cleanup.

## Current candidate debt to remove

The rebased branch still contains old implementation references including:

- random IssueId/EpicId and number alias resolution;
- EpicIssueRow/EpicActiveIssue ownership;
- copied EpicId lineage snapshots;
- AwaitingBinding, WorkflowBindingPending, binding confirmation, and lineage revisions;
- EventCatalog.RequiredAttributes, EnvelopeConformance, and CatalogOnlyTypes;
- issueid/epicid/issueno/epicno producer and fallback paths.

These are expected before new build tasks run. They must not be treated as compatibility requirements.

## T-001 delivered

### Files added / changed

- `packages/server/src/Mohist.Server/Infrastructure/Orleans/ScopedGrainKeyCodec.cs`
  - `IssueKey(ProjectId, IssueNumber)` and `EpicKey(ProjectId, EpicNumber)` strong types.
  - `ScopedGrainKeyCodec.Format/Parse/TryParse` shared between both keys; one source of truth
    for the `projectId:number` grain-key string.
  - `GrainKeyString` decode shape so callers can pattern-match the partition without going
    through `Split(':')` themselves.
- `packages/server/src/Mohist.Server/Infrastructure/Orleans/GrainKey.cs`
  - Adds typed `Issue(projectId, issueNumber)`, `Issue(IssueKey)`, `Epic(projectId, epicNumber)`,
    `Epic(EpicKey)` overloads that route through `ScopedGrainKeyCodec`.
  - Keeps the legacy `Issue(string issueId)` overload as a T-001/T-002 transition shim; no
    obsolete attribute yet (call sites are rewritten by T-002 — adding `Obsolete` now would
    break the build under `TreatWarningsAsErrors`).
- `packages/server/src/Mohist.Server/Infrastructure/Data/Migrations/20260716120000_AdoptScopedIssueEpicIdentity.cs`
  - Idempotent data migration; runs once on startup on top of the existing schema.
  - Backfills `IssueComments.IssueId` from `ProjectId + IssueNumber` (and vice versa when the
    seed had `IssueId = ''`).
  - Backfills `InboxItems.IssueId` from `ProjectId + IssueNumber`.
  - Removes orphan `EpicIssues` and `EpicActiveIssues` rows whose (Project, Number) pair no
    longer resolves to a real Issue / Epic.
  - No runtime aggregate commands touch two aggregates in one transaction; each statement
    operates on one side (Issue side or Epic side).
  - `Down()` is intentionally a no-op — the migration is a one-way projection; restoring from
    a snapshot is out of scope (consistent with the precedent `BackfillIssueEpicAffiliation`).
- `packages/server/tests/Mohist.Server.UnitTests/Orleans/ScopedGrainKeyCodecTests.cs`
  - Codec round-trip, format invariants, `IssueKey` / `EpicKey` typed equality, single-codec
    invariant, defensive input validation.
- `packages/server/tests/Mohist.Server.SpecTests/Specs/Issue/Data/ScopedIssueEpicIdentityMigrationSpecs.cs`
  - Migration spec: same shape as `DatabaseInitializationSpecs` / `EpicIdleRenameMigrationSpecs`.
  - Seeds two projects with overlapping Issue 42 / Epic 7, runs the migration SQL twice, asserts
    canonical references resolve, no duplicates, orphans removed.

### Out of T-001 scope (preserved as T-002..T-008 work)

- Runtime grain activation still keys `IssueGrain` by its legacy `Issue_xxx` random id; call
  sites and `IIdentityResolver` are rewritten by T-002.
- `IssueRow.IssueId` / `EpicRow.Id` random id PKs are retained as legacy columns; EF model +
  column removal belongs to T-002 / T-008.
- `WorkflowArtifactRow.IssueId` does not yet have a `(ProjectId, IssueNumber)` reference —
  T-001's audit found it was the only owner missing `IssueNumber`, and adding the column +
  computed projection belongs with T-005 / T-006 (producer lineage work).
- `WorkflowRunRow.State` JSON annotations `{projectId, issueId, issueNumber, epicId}` stay as
  they are; the migration's data projection only addresses EF-owned rows. T-004 rebuilds the
  Workflow context shape from current Issue state.
