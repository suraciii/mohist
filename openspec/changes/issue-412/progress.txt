## Why the previous progress is superseded

The previous T-001..T-007 implementation completed an event-lineage plan built on random
IssueId/EpicId identities, Epic-owned membership rows, copied EpicId snapshots, Workflow binding
states/revisions, and a per-type EventCatalog registry. Repeated check failures exposed failures in
normal cross-aggregate crash windows. The user then confirmed a different domain model, so those
task completion claims no longer describe the accepted target.

The old implementation commits remain in the candidate as migration input. Replacement tasks must
remove or reshape them; they are not accepted progress and no task in the new tasks.json is marked
passing.

### Constructive details

- `IssueKey` and `EpicKey` are `readonly record struct`s that validate in the primary
  constructor. Blank ProjectId and ProjectId containing the `:` separator throw
  `ArgumentException`. Non-positive numbers throw `ArgumentOutOfRangeException`. The language
  can produce default values, but `GrainKey` and the codec reject them during encoding.
- `ScopedGrainKeyCodec` formats the exact canonical length for `(ProjectId, Number)`: number
  digits are computed up front and the destination span is allocated to that size, so the
  output never contains padding or NUL characters. Number text is invariant-culture
  `int.TryFormat`. `int.MaxValue` (10 digits) round-trips losslessly.
- `TryParse(string?, out string, out int)` validates both halves: separator must be present,
  exactly one separator (separator ambiguity is rejected), neither side may be blank, every
  character of the number side must be `0`-`9`, parsed number must be strictly positive.
- `Parse(string, out string, out int)` is the throwing counterpart used by typed-key callers.
- `GrainKey.Issue(IssueKey)` and `GrainKey.Epic(EpicKey)` are the only public Issue / Epic
  access methods. Reflection-surface test (`GrainKey_DoesNotExposeScalarIssueOverload` /
  `GrainKey_DoesNotExposeScalarEpicOverload`) confirms there is no `(string, int)` Issue or
  Epic overload to bypass typed construction.
- The one necessary comment lives on the `internal` legacy overload and explains only its
  reason and removal task (T-004). Names explain normal behavior.

### Test coverage (46 new tests)

- Round-trip (Format → TryParse → Format yields the original).
- Exact output length: `projectId.Length + 1 + NumberDigits(number)`.
- No NUL padding for short numbers.
- `int.MaxValue` (2_147_483_647, 10 digits) encoded exactly as `p:2147483647` with length
  12; round-trips losslessly.
- Invariant-culture number text (no thousand separators, no decimal).
- Construction rejects: blank ProjectId, separator-containing ProjectId, non-positive
  number (`0`, `-1`).
- TryParse rejects: `null`, empty, `:`, `proj_a`, `proj_a:`, `:1`, `proj_a:notanumber`,
  `proj_a:0`, `proj_a:-1`, `proj_a:+1`, `proj_a:01`, `proj_a:007`,
  `proj_a:1:2` (separator ambiguity), `proj::a:1`,
  `proj_a:1 ` (trailing whitespace), `proj_a: 1` (leading whitespace), `proj_a:1\0` (NUL).
- Cross-Project same-number isolation: `proj_a:42 != proj_b:42` and the typed keys are
  unequal.
- Default `IssueKey` and `EpicKey` values are rejected by `GrainKey` through the shared codec.
- Reflection surface test proves the public GrainKey Issue / Epic surface has no
  `(string, int)` shortcut.
- Reflection surface test proves the random-id `Issue(string)` overload is non-public.

### Current-state Issue owner inventory

- `Issues` is the aggregate root. Its legacy `IssueId` primary key remains only as the T-004

  set it and unbind clears it. Comment-owned and unbound attachments keep it null.

  `ProjectId` + `IssueNumber`. Reconciliation verifies those values against their referenced Issue

  `PrerequisiteNumber`) relation. Reconciliation verifies that both scoped Issues exist.
- Workflow-origin and direct Agent-launch `AgentSessions` already persist Issue context as computed

Managers, queriers, storage-integrity helpers and API projections are access paths over the owners
