# T-001 progress notes

## Codebase Patterns

- The runner Workflow adapter `opencodeAction` already resolves or attaches a Workflow AgentSession binding before calling `runtime.runTurn`. The new transcript reporter wires in only after the binding has a non-null `runtimeSessionId`, so the `session.input` event always carries the current physical binding.
- `RuntimeTurnObserver.onEvent` is called synchronously from `turn.ts` `executePrompt`, which means the reporter must accept events synchronously without awaiting HTTP. The existing `agent-job-executor.ts` shows the pattern: chain `eventWrite` via `.then(...)` so a later rejection does not poison later attempts.
- `session.input` is the canonical cross-source turn delimiter on `AgentSessionGrain`. The grain's `AppendEventsAsync` is the single entry point for both AgentJob (`agentSessionRuntimeEvents`) and Workflow (`workflowAgentSessionRuntimeEvents`) routes, so the persistence fence belongs there, not in the route or in `TranscriptAccumulator`.
- The TranscriptAccumulator accumulates until `_transcript.HasPending` is true; flushes are driven by `FlushAsync` (state + transcript together). For the input fence we only need the transcript portion — extracted as `FlushPendingTranscriptAsync` so the input-fence path cannot accidentally trigger a state-save round-trip.
- `AgentSessionGrainFixture` exposes a fake transcript store that supports `NextException`, so failure-during-input-fence coverage can target exactly the input-boundary flush without dirtying other paths.

## Implementation notes

- Reporter lives at `packages/runner/src/actions/workflow-agent-session-reporter.ts` — Workflow-local; not exposed to AgentJob.
- Input acceptance gate: a single `inputRejected` boolean read by every later upload callback so the chain serializes naturally and rejects later uploads without a separate "skip if rejected" wrapper.
- `controller.signal` is independent of the runner host signal — bounded by a 30 s timeout (`DEFAULT_REPORT_TIMEOUT_MS`), so a stalled upload cannot retain the Action indefinitely.
- `createWorkflowReporter` defensively checks `typeof connection.workflowAgentSessionRuntimeEvents === "function"` so older test fakes that only stub `openWorkflowAgentSession`/`attachWorkflowAgentSession` (e.g., `opencode-action-turn.spec.ts`) keep working unchanged.
- The new Session grain tests use `FakeAgentSessionTranscriptStore.NextException` plus a single explicit `FlushForTestAsync` for observation — no fake-time advance and no scheduler waits, matching the acceptance criterion that correctness does not depend on the 200 ms persistence timer.

# T-002 progress notes

## Codebase Patterns

- The same Workflow `WorkflowAgentSessionReporter` chain from T-001 carries the terminal `session.closed` event naturally: `enqueueClose` appends to `tail` after `enqueueInput` / `enqueueEvent`, so one `await reporter.settle()` drains the whole turn. No extra serialization, no separate upload, no coupling to Workflow work.
- `OpenCodeRuntime.runTurn` failures surface as `{ ok: false, error: { kind, message } }`. The Action only needs the `message` (and the `ok` bit) to map a terminal close; the `kind` value is workflow-side policy, never a Session fact.
- `TranscriptAccumulator.CaptureInput` stores the prompt onto `_promptText` / `_promptKind` rather than emitting an `input` part. The text+tool+close part count per turn therefore does NOT include a `session.input` part — the prompt is observable only via `Turn.PromptText` and the transcript `User` envelope. Spec coverage must distinguish part counts (persisted parts) from turn boundary counts (turn sequences).
- `AgentSessionQuerier.LoadTerminalFactsAsync` and `TerminalFact.FromTranscript` previously ordered `session.closed` parts by `part.Sequence` alone. With multiple turns reusing one AgentSession this picks the part with the largest *intra-turn* sequence, which is the FIRST turn's close (because turn N's `tool`/`text` parts shift its close to `Sequence N+1+tool`), not the LATEST accepted close. The reducer must order by `(turn.Sequence, part.Sequence)` so the most recent turn's terminal observation wins.

## Implementation notes

- `enqueueTerminalClose(reporter, result, binding.runtimeSessionId)` in `opencode.ts` enqueues exactly one close after `runtime.runTurn` returns. It is called BEFORE `await reporter.settle()` and never observes the close upload; close rejection can therefore never change the Action result (the Action result is computed from `result.ok` and `result.error` independently of the close).
- Mapping is symmetric:
  - `result.ok === true`  → `{ status: "completed", exitCode: 0, runtimeSessionId }`
  - `result.ok === false` → `{ status: "failed", exitCode: 1, failureReason: result.error.message, runtimeSessionId }`
- The close's `runtimeSessionId` is `binding.runtimeSessionId` (i.e., the currently-bound physical session), not whatever the assistant mid-turn event projected. If the input was rejected the `reporter` suppresses the close (existing `inputRejected` guard), so the close cannot attach to the previously persisted turn.
- Fix in `AgentSessionQuerier.cs`: `LoadTerminalFactsAsync` and `FromTranscript` order parts by `(turn.Sequence, part.Sequence, part.Id)` instead of `(part.Sequence, part.Id)`. This is a read-side reducer change (no endpoint, no DTO, no schema, no persisted model). Single-turn sessions see byte-identical behaviour because `(turn.Sequence = 1)` ties; multi-turn sessions see the latest accepted close drive `WorkflowSessionDto.Status`.
- Runner test stays under the 800-line file-size budget: the new terminal-close describe block moved to a sibling file `opencode-action-workflow-terminal-close.spec.ts`. It reuses the same `buildRuntime` / `makeFakeConnection` / `baseContext` shape but in its own file (no spec cross-imports).
- Server spec lives in a sibling file `WorkflowSessionTerminalConvergenceSpecs.cs` (Issue-458 / Workflow / Grain). It uses the existing `MohistIntegrationFixture` and `CreateIssueWorkflowAsync` pattern; only one test (one assertion per the T-002 AC) to stay comfortably under the 24,000-byte ratchet.
