## Codebase Patterns

- BranchBar.tsx, PrDeliveryIndicator.tsx, and WorkflowSessionsPanel.tsx use inline English strings (no i18n layer). The PR indicator prefixes the PR number with `Merged via PR #{prNumber}` (consistent with the rest of the app's copy register).
- The session panel `usageText(session)` already returns three honest states: a `totalTokens` summary line, an input/output breakdown, or — when no token figures are present — `'Usage unavailable'`. The aggregate header computes its own summary independently and never falls back to usage-placeholder copy.

## T-001 Implementation Notes

### Surprises / things worth knowing

- The BranchBar.test.tsx had four assertions on the Chinese string `未能检查上游` (3 `getByText` and 1 `queryByText`); all four needed swapping to the English copy `Upstream check unavailable`. Confirmed via ripgrep that no other file in the repo references the literal string in any form.
- The PrDeliveryIndicator.test.tsx had three coupled assertions (`'经由 PR'`, `'#42'`, `'合并'`) in the same `expect(... textContent).toContain(...)` chain. After the copy fix, the indicator's textContent becomes `Merged via PR #42` — kept one `toContain('Merged via PR')` assertion and the PR-number assertion; dropped the standalone `'合并'` assertion since the merged English copy no longer contains a separate substring matching it.
- WorkflowSessionsPanel.tsx had no test for the `'No usage yet'` placeholder (existing tests all provided `usage` data on each session). Added one new test (`renders "Usage unavailable" for a session row with no token figures`) that constructs a session with `usage: undefined` (the helper's default) and asserts the per-row text via `within(row).getByText('Usage unavailable')`. Also asserts `'No usage yet'` is absent to lock the negative.

### Decisions confirmed against spec

- Used `Merged via PR #{prNumber}` (exact wording from the design D1 proposal).
- Used `Upstream check unavailable` (exact wording from D1).
- Replaced `'No usage yet'` with `'Usage unavailable'` per D2 — the design's preferred truthful label.

## T-002 Implementation Notes

### Surprises / things worth knowing

- The BranchBar behind-state rebase button passed three token classes via `enabledClassName` (the `RebaseAction` component takes them as a string). Existing tests asserted those classes directly (`'border-amber-300', 'text-amber-800', 'hover:bg-amber-50'`); updated to the warning-family token strings (`'border-warning-border', 'text-warning', 'hover:bg-warning-subtle'`). Same swap for the negative assertion in the loading-state test.
- TaskLogPanel's light-surface chrome has six distinct surface tokens (panel, header label, truncation badge, search icon, search input, download button, source chips × 2 variants). All eight light-surface palette references swapped cleanly to `bg-card / border-border / text-muted-foreground / text-foreground / bg-background / border-input / bg-warning-subtle / text-warning / focus:border-info / focus:ring-info / placeholder:text-muted-foreground / hover:bg-muted`.

The acceptance criterion explicitly carves this out, and the new `TaskLogPanel.theme.test.tsx` locks it with three assertions (scroll container classes, source-bracket span, timestamp spans).
- TaskLogPanel has no colocated test file; added a new `TaskLogPanel.theme.test.tsx` next to the existing `*.viewing.test.tsx`, `*.merge.test.tsx`, `*.milestones.test.tsx`, `*.liveAppend.test.tsx` suite. - The disabled-chip click test had to be wrapped in `act(async () => { chip.click() })` — the first run failed with "An update to TaskLogPanel inside a test was not wrapped in act(...)" because clicking toggles `disabledSources` state.
- The panel header label color moved from `text-slate-500` to `text-muted-foreground` (the label is OUTSIDE the dark console, in the light-surface chrome header row).
