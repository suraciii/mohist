## Codebase Patterns

- The desktop kanban row (`data-testid="kanban-board-row"`) is a `hidden md:flex flex-row gap-4 overflow-x-auto p-4 flex-1 min-w-0`. Its children are themselves flex items; `StageColumn` already bakes `flex-1` into its class string, so the three core columns absorb the reclaimed slot via `flex-1` without the row needing to know.
- `StageColumn`'s column classes are `flex flex-col min-w-[280px] max-w-[420px] flex-1 rounded-xl border bg-card/50 ...` — the raised `max-w-[420px]` cap keeps the core groups from stretching into unreadable wide blocks at large viewports.
- `filterCancelledFromColumns` is intentionally an identity function (documented seam); visibility is a render-time concern owned by `KanbanBoard.tsx` + `StageColumn`. Cancelled column carries full issue set through the pipeline so tab counts / counts / "n hidden" affordances stay stable.
- State `showCancelled` is local React state. `cancelledCount` (derived from `allColumns`, pre-filter, pre-toggle) is what mobile tab counts and the in-list Show/Hide link read. This is the contract tested by the "Mobile cancelled tab count is independent of showCancelled" describe.

## Gotchas

- The StageColumn class string is on a single line in the source — editing it means re-matching the full string, since conditional whitespace inside the templated class is easy to mistype.
- The DOM-trees-always-render split (desktop `hidden md:flex` + mobile `md:hidden`) means there's always both a desktop row and a mobile column in the document, even if jsdom-class-hidden. Tests that target the desktop board by testid (`kanban-board-row`, `stage-column-*`) still locate the right elements because each testid is rendered exactly once.
- `filterCancelledFromColumns` is an identity seam by design; do not move visibility decisions back into the model — that would break tab counts (already covered by the "cancelled tab count is independent of showCancelled" test).
