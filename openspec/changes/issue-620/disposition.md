  `workspace-unavailable` (`packages/server/src/Mohist.Server/Agent/Grains/IAgentJobGrain.cs:409-418`).

    `unsupported-execution-configuration` → `unsupported_execution_configuration`):

    `permission-required`, `interrupted`, `invalid-input`, `missing-session`,
    `incompatible-runtime`, `turn-failed`.

## MF-2 — Thread follow-up failures record no category — FIXED

Verified against the codebase before fixing:

- The runner's follow-up terminal events set only `failureReason`;
  `failureCategory` is set only for expired manager credentials (`unknown`)
  (`packages/runner/src/server/followup-handler.ts:626-674`,
  `recordFollowupActivity`).
- Follow-up turns never pass through `AgentJobGrain` (follow-up dispatch
  selects turns without a JobId, `AgentSessionGrain.FollowupDispatch.cs:15-16`),
  so server-side reconciliation categories never apply.
- The session-side turn result comes verbatim from the terminal
  `session.activity` payload (`AgentSessionGrain.cs:2667-2675`,
  `ResolveFollowupTurnResult`), so T-003's server-side forwarding alone leaves
  the category null in production and no thread failure could ever show Retry.

Fix applied — explicit producer-side task added:

- New **T-007** in `tasks.json` (runner-side, `packages/runner`): when a
  follow-up turn fails with a runtime error kind, `recordFollowupActivity`
  emits that kind as `failureCategory` on the terminal `session.activity`
  payload, applying the same kind→category mapping the AgentJob path applies
  (shared helper, not a copy). No-kind failures and expired manager
  credentials keep omitting/`unknown` and degrade to no button.
- The Server already consumes the field end-to-end
  (`ResolveFollowupTurnResult` → `turn.Result` → T-003's delivery forwarding),
  so T-007 is purely runner-side plus tests; no server change required.
- New spec requirement `Failed thread follow-up turns record a failure category`
  in `specs/slack-failure-retryability/spec.md` anchors T-007.
- `design.md` updated: Decision 3 gap analysis names the producer-side root
  cause and T-007; Non-Goals carve out (reporting the follow-up error kind is
  in scope; AgentJob reconciliation facts remain unchanged); Risks bullet and
  Migration Plan step 2 (additive field, any deploy order safe) updated.
- `proposal.md` updated: runner impact bullet; `slack-failure-retryability`
  capability description mentions the follow-up fact source; Unaffected line
  adjusted.
