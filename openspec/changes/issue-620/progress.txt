## Codebase Patterns
- AgentSession is an Orleans grain aggregate; target facts are read through IAgentSessionGrain.GetInitialLaunchAsync/ListTurnsAsync/ListInputsAsync. Launch turns are identified by non-empty AgentTurnRecord.JobId, and input provenance is AgentSessionInputProvenance.
- Connection launches flow through AgentLauncher.LaunchConnectionAsync and AgentLaunchCoordinatorGrain. The coordinator adopts pre-minted Session/Input/Turn ids and deduplicates on its idempotency key; the Slack default key is slack:{team}:{conversation}:{messageTs}.
- EF models live in MohistDbContext with row classes under Infrastructure/Data; migrations are timestamped 202609... and the model snapshot is generated. Test fixtures use EnsureCreated for L0 and a migrated SQLite template for integration specs.
- Conventional DI scans IScopedService as self; interface aliases are added manually in MohistServiceRegistration.
- Existing AgentJobFailureReasons constants are in Agent/Grains/IAgentJobGrain.cs: RunnerUnavailable, RunnerLost, ReportTimeout, WorkspaceUnavailable.

## T-002 decisions
- Thread retry accepts a fresh follow-up with `agent-retry:{operationId}`, the operation receipt's pre-minted input/turn ids, the failed input's text/source/provenance, and `ForceNewTurn=true`; this prevents the Session's normal queued-turn coalescing from merging the retry into an unrelated queued turn.
- `BeginFollowupDispatchForTurnAsync(turnId)` shares the existing follow-up dispatch body and guards with `BeginNextFollowupDispatchAsync`; it only changes turn selection. The retry calls the common follow-up dispatcher with the target turn. A busy Session returns no dispatch and leaves the accepted retry queued for the ordinary scheduler.
- Targeted-dispatch specs cover unrelated queued turns, the launch-turn guard, busy-session scheduler order, pre-minted identities, Slack provenance, failed-turn immutability, and pending-operation replay/idempotency.
