## Codebase Patterns

### Runner capacity source of truth

The authoritative runner capacity projection lives in
`packages/server/src/Mohist.Server/Runner/Services/RunnerStatusService.cs`:

- `ProjectRunnerAsync` builds `RunnerCapacityView(UsedSlots, TotalSlots)`:
  - `UsedSlots` = count of `runtime.ActiveWorks` where `OwnerKind == Workflow`
    **distinct by `OwnerId`** (matches `WorkflowGrainSpecs.AssignActiveWorkForTestAsync` setup pattern).
  - `TotalSlots` = `await runnerGrain.GetSlotsAsync()` (persisted on the grain).
- A view with `runtime is null` or `slots is null` returns `Capacity = null`.
- `GetRunnersAsync` returns every runner in the global registry regardless of
  online status; offline runners typically come back with `Capacity = null`.

### Runner online filter

`GetOnlineRunnersAsync` (new in T-001) reuses
`IRunnerRegistryGrain.ListEligibleRunnersAsync` and additionally requires
`runnerGrain.GetRuntimeStateAsync().Status == RunnerStatus.Online`. The status
read is wrapped in try/catch so a missing/deactivated grain is filtered out
without failing the whole call (matches the original
`AgentRoutes.ListAvailableRunnersAsync` semantics). A runner is online as
soon as `RunnerGrain.RegisterAsync` runs (it sets `_status = Online`
unconditionally).

### Aggregate accessor

`GetCapacityAsync` walks `GetOnlineRunnersAsync` views and sums
`(UsedSlots, TotalSlots)` of any view with non-null `Capacity`. This is the
single aggregate accessor that `/agent/status` (and T-002's
`/agent/activity`) consume. No separate capacity service or DTO is
introduced.

### `/agent/status` route rewiring

`Api/AgentRoutes.cs` `GET /agent/status` now:
- Calls `RunnerStatusService.GetOnlineRunnersAsync(project.Id)` once.
- Reads `activeAgents` from `WorkflowActivityQuerier` only for the visibility
  list and the `Running` flag — never for slot counts.
- `AgentStatusResponse.Create` takes the views + a precomputed `RunnerCapacityView`
  from `SumCapacity(runners)`; both the per-runner `Runners[].Active/Max` and
  the top-level `Capacity` derive from the same views, so they are
  guaranteed to agree.
- `LoadPersistedSlotsByRunnerAsync` and `activeSlotsByRunner` are gone.

### Test infrastructure gotchas

- The integration collection (`MohistIntegrationFixture`) shares the global
  runner registry across tests; any test asserting total `Capacity.Active/Max`
  must drain `IRunnerRegistryGrain.ListRunnerIdsAsync()` first to stay
  deterministic — see `AgentStatus_WhenRunnerRegisteredWithoutActiveWork_ReportsIdleRuntime`
  in `RuntimeEntrySpecs.cs` and the divergence spec below.
- `RunnerStatusProjectionSpecs` extends `WorkflowGrainSpecs` and already
  exposes `ClearGlobalRunnerRegistryAsync`, `AssignActiveWorkForTestAsync`,
  `RegisterRunnerForProjectAsync`, `CreateService`, and `TimeAt(...)`
  helpers. Use them when adding capacity tests rather than re-wiring helpers.
- `WorkflowStartInput(Metadata: new WorkflowRunMetadata(...))` works with
  only `projectId` in `Annotations`; `WorkflowGrain.StartAsync` resolves the
  template via `WorkflowProfileManager.LoadStructureAsync`, falling back to
  `IssueWorkflowProfiles.LocalId` if no project/issue profile is set. The
  `SeedRuntimeDivergenceTemplateAsync` helper inserts both
  `ProjectWorkflowTemplates` and `ProjectWorkflowProfiles` rows to make
  startup deterministic.

## T-002 Specific Findings

### `/agent/activity` route rewiring

`Api/AgentRoutes.cs` `GET /agent/activity` now:
- Drops the local `ListAvailableRunnersAsync` lookup that produced the
  `runnerIds` list (it only existed to feed the `+1` heuristic and is no
  longer called by any route — left in place as dead code because T-001
  kept it and removing it is out of scope for T-002).
- Injects `RunnerStatusService` and calls `GetCapacityAsync(project.Id)`
  once; passes the resulting `RunnerCapacityView` into the querier as
  `capacity:`. `AgentSessionQuerier.GetActivityAsync` accepts
  `RunnerCapacityView? capacity` (nullable so the querier stays usable
  in unit tests without the runner service).
- Still calls `BuildWaitingCardsAsync` and threads the result through
  `waiting:` so the waiting count is preserved.

### `AgentSessionQuerier.GetActivityAsync` signature change

- Dropped `IReadOnlyList<string>? runnerIds` (it fed only `runnerIds.Count
  + 1`).
- Added `RunnerCapacityView? capacity` (defaults to `0/0` when null so
  tests that do not exercise the unified source still get a sane
  `ActivitySlotUsageDto`).
- The querier is **session-pure**: it does no capacity math of its own.
  `summary.Slots` is now `new ActivitySlotUsageDto(capacity?.UsedSlots
  ?? 0, capacity?.TotalSlots ?? 0)`.
- `summary.Active` continues to reflect the visible active session card
  count — it is still the visibility signal, just no longer the capacity
  source.
- `RunnerStatusService` is NOT injected into the querier (D4).

### Existing test updates

- No existing `AgentSessionSpecs` test pinned `summary.slots` to active
  session card count or `runnerCount+1`. The only existing assertions on
  `summary` were `Assert.Equal(0, activity.Summary.Active)` (skipped
  `RunnerReport_WhenAgentWorkFailsBeforeTelemetry_ClosesCreatedSession`)
  and `Assert.Equal(1, activity.Summary.Failed)` — neither depends on
  the slot derivation, so neither needed rewording.
- The wire shape `{ active, max }` of `ActivitySlotUsageDto` is preserved;
  only the value derivation changes (proposal D3).

### New divergence spec

`AgentSessionSpecs.AgentActivity_WhenRunnerActiveWorksExceedVisibleSessions_SlotsReflectRunner`
mirrors the T-001 divergence spec for `/agent/status`:
- Drains `IRunnerRegistryGrain.ListRunnerIdsAsync()` so the assertion
  reflects only this test's runner.
- Registers a runner with `slots = 4`.
- Starts two workflow runs, assigns both to the runner, polls twice so
  the runner carries two distinct workflow owners in `ActiveWorks`.
- Calls `/agent/activity` and asserts:
  - `summary.slots.active == 2` (runner active-works count, NOT the
    zero visible AgentSession count).
  - `summary.slots.max == 4` (persisted runner slots).
  - `summary.active == 0` (visible AgentSession count, intentionally
    divergent from capacity to prove the two surfaces are independent).
- Uses `SeedActivityDivergenceTemplateAsync` to seed both
  `ProjectWorkflowTemplates` and `ProjectWorkflowProfiles` rows for
  the synthetic workflow project id (same pattern as T-001's
  `SeedRuntimeDivergenceTemplateAsync`).
