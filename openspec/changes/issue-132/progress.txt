## Design decisions

- Renamed existing `useAgentSessions` → `useGlobalAgentSessions` to free the
  `useAgentSessions` name for the agent-scoped variant (matching D9 / T-001 AC).

- Agent-scoped session list DTO types (`AgentSessionListItemDto`,
  `GenericAgentSessionSummaryDto` etc.) placed in `agent-sessions.ts` alongside
  their client fns — not in `model/types.ts` — to keep the data-access module
  self-contained (consistent with `cost-rollup.ts` pattern).

- `useGenericSessionSummary` and `useGenericSessionTranscript` have dynamic
  `refetchInterval` that polls every 5s while the session is non-terminal /
  has incomplete turns, stops polling on terminal state.

- Followup and cancel mutations accept optional `agentRef` for invalidation of
  the owning agent's session list; `useLaunchAgentSession` always requires it
  since the agent is known at mutation time.

- The existing `getAgentSessions` from `client.ts` (global list) is imported
  as `getGlobalAgentSessions` in queries.ts to coexist with the new
  agent-scoped `getAgentSessions` from `agent-sessions.ts`.

## Gotchas

- `vi.spyOn(globalThis, 'fetch')` must be cleaned up with `vi.restoreAllMocks()`
  in `afterEach` to prevent cross-test pollution in the client-fn URL tests.

- Mutation tests that evaluate `onSuccess`/`onError` callbacks should not invoke
  `mutationFn` unless the underlying client fn is also mocked, otherwise the
  real implementation will hit the network stack and cause unhandled rejections
  in jsdom.

- TypeScript 5+ strict tuple inference in `.filter()` callbacks requires
  widening the callback parameter to `unknown[]` instead of a tuple pattern
  when filtering mock.calls arrays.
