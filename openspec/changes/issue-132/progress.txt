## Design decisions

- `SessionDetailShell` takes `{ data: SessionDataSourceResult }` as a prop
  object (not spread) so it's a proper React component with predictable hook
  ordering. All hooks (useRef, useCallback, useEffect) are placed before any
  conditional return to satisfy React's rules of hooks.

- Data sources return **only data** (no JSX). All component rendering
  (`SiblingNavigation`, `SessionRecoveryActions`, `ContextHealthBar`,
  `CompactionLineageLink`) is done in `SessionDetailShell` or `SessionHeader`
  based on data flags. This keeps tests mockable — existing SessionPage tests
  mock `widgets/coder-session` and `widgets/session-health`, and these mocks
  are respected even when the imports happen inside `SessionDetailShell`.

- For the main transcript view, the recovery bar is rendered ONLY in the
  sticky scroll container (not duplicated in the header). Early-return branches
  (waiting, empty states) render the recovery bar inside the header.

- `useGenericSessionDataSource` sends the back link to the agent profile
  (`/agents/{agentId}`) by default, or to the referenced issue
  (`/issues/{issueNumber}`) when an issue context ref exists — matching the
  spec's OR clause.

## Gotchas

- `SessionDetailShell` must be called as `<SessionDetailShell data={data} />`
  (JSX component), never as `SessionDetailShell(data)` (function call). The
  latter breaks React's hook tracking inside the shell, causing "Rendered more
  hooks than during the previous render" errors.

- All hooks in `SessionDetailShell` MUST precede any conditional early return,
  or React throws "Rendered more hooks" on state transitions. This means
  useCallback/useEffect for scroll management must be at the top of the
  function body alongside useRef.

- Test state leakage between `it()` calls in GenericSessionPage tests requires
  a `beforeEach` that resets ALL mock module variables
  (`mocks.summaryData`, `summaryLoading`, etc.) — `afterEach` + `cleanup()`
  is insufficient because mock closure references survive.
