# Explore 阶段

## 概述

通过对话梳理需求，使模糊的想法变得清晰。

## 触发

Draft 阶段完成（Issue 创建后自动进入）

## 执行引擎

opencode 会话

```
opencode --message "/opsx:explore issue #42"
```

## Agent 行为

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   1. 读取 Issue #42                                              │
│                                                                 │
│   2. 主动提问，澄清需求                                          │
│      - "搜索功能要搜索什么内容？"                                 │
│      - "需要支持关键词高亮吗？"                                   │
│      - "搜索结果要分页吗？"                                       │
│                                                                 │
│   3. 更新 Issue Body（需求逐渐清晰）                              │
│                                                                 │
│   4. 持续对话，直到用户确认                                      │
│                                                                 │
│   5. 不创建 OpenSpec change（还没到 Plan）                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 对话示例

```
Agent: "我来探索一下这个需求"

       "搜索功能要搜索什么内容？"
User:  "文章的标题和正文"

       "需要支持关键词高亮吗？"
User:  "需要的"

       "搜索结果要分页吗？"
User:  "要，每页 20 条"

       "需要搜索历史吗？"
User:  "不需要，先简单点"

       [Agent 更新 Issue Body]

       "需求梳理清楚了，可以开始规划吗？"
User:  "可以规划了"

       → 触发 Plan 阶段
```

## 输出

Issue Body 包含:
- 功能描述（清晰、完整）
- 边界定义（做什么、不做什么）
- 验收标准（怎么算完成）

## Issue Body 结构（Explore 完成后）

```markdown
# 加一个搜索功能

## 状态
exploring → planning (用户确认后)

## 描述
全文搜索功能，支持搜索文章的标题和正文内容。

### 功能范围
- 支持关键词搜索
- 支持关键词高亮
- 支持分页（每页 20 条）

### 不包含
- 搜索历史
- 高级过滤

## 验收标准
- [ ] 搜索框在导航栏
- [ ] 搜索结果按相关度排序
- [ ] 关键词高亮显示
- [ ] 支持分页

## 技术方案
(待 Plan 阶段补充)

## 任务
(待 Plan 阶段补充)

## OpenSpec
(待 Plan 阶段创建)
```

## 转换条件

用户说 "可以规划了" 或类似确认 → 触发 Plan 阶段

## 用户参与

- 高度参与，持续对话
- 回答 Agent 的问题
- 确认需求边界
- 最终确认 "可以规划了"
