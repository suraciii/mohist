# Verify 阶段

## 概述

自动验证 + 人工审查，确保 PR 质量合格。

## 触发

Dev 阶段完成（所有任务完成 + PR 创建）

## 验证层次

```
┌───────────────────────────────────────────────────────────────┐
│                        验证阶段三层把关                         │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│   Layer 1: 自动验证 (CI)                                      │
│   ─────────────────────────────────────                       │
│   • TypeScript 类型检查                                       │
│   • ESLint 代码规范                                           │
│   • 单元测试                                                  │
│   • 集成测试                                                  │
│                                                               │
│   硬性要求: 必须 100% 通过                                     │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│   Layer 2: Agent 审查                                         │
│   ─────────────────────────────────────                       │
│   • 代码质量                                                  │
│   • 设计一致性                                                │
│   • 安全检查                                                  │
│   • 性能考量                                                  │
│                                                               │
│   硬性要求: 无阻塞性问题                                       │
│   参与者: AI Agent (自动修复)                                  │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│   Layer 3: 人工审查 (User Review)                             │
│   ─────────────────────────────────────                       │
│   • 功能正确性                                                │
│   • 用户体验                                                  │
│   • 业务逻辑                                                  │
│   • 最终决策                                                  │
│                                                               │
│   硬性要求: 用户批准                                          │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

## Agent 行为

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   1. 运行 CI (types, lint, tests)                                │
│      失败 → 自动修复 → 重新运行                                  │
│                                                                 │
│   2. Agent Review (代码质量、设计一致性)                         │
│      发现问题 → 自动修复 → 提交 fix commit                       │
│                                                                 │
│   3. 更新 Issue (Review 状态)                                    │
│                                                                 │
│   4. 等待用户 Review                                            │
│                                                                 │
│   5. 用户反馈 → 修复 → 重新等待                                  │
│                                                                 │
│   6. 用户说 "合并" → 合并 PR → Issue 关闭                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Review 流程

```
PR Created
     │
     ▼
┌─────────┐
│ CI 检查  │ ──失败──▶ 自动修复 ──▶ 重新检查
└────┬────┘
     │ 通过
     ▼
┌─────────────┐
│ Agent Review │ ──有问题──▶ 自动修复 ──▶ 重新审查
└──────┬──────┘
       │ 通过
       ▼
┌─────────────┐
│ User Review │ ──有问题──▶ 用户反馈 ──▶ Agent 修复 ──▶ 重新审查
└──────┬──────┘
       │ 批准
       ▼
   PR 合并
       │
       ▼
   Issue 关闭
```

## Agent Review Report 示例

```
🤖 **Agent Review Report**

## CI 检查 ✅
- TypeScript: 通过
- ESLint: 通过
- Tests: 通过 (覆盖率 85%)

## 设计一致性 ✅
- 实现符合 design.md
- API 符合 specs/search/spec.md

## 代码质量 ⚠️
- 建议: SearchService.query() 方法过长，建议拆分
- 建议: 添加更多错误处理

## 安全检查 ✅
- SQL 注入: 已使用参数化查询
- XSS: 已对用户输入进行转义

## 建议
可合并，但建议后续重构 SearchService
```

## 输出

- Review Report
- 修复 commits (如有)
- 合格的 PR

## 转换条件

用户说 "合并" → PR 合并 → Issue 关闭 → Done

## 用户参与

- 中度参与
- 审查 PR
- 提出反馈
- 最终批准合并
