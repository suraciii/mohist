## 探索过程

### 1. 从命名约定开始

**初始问题**: Stage 应该如何命名？

```
ready-for-* 模式:
  ready-for-refinement → ready-for-design → ready-for-implement → ...

vs 状态描述模式:
  exploration → design → implement → ...
```

**关键洞察**:
- `ready-for-*` 混合了"状态"和"触发器"
- 每个状态都暗示"应该执行某个动作"
- 如果动作失败，状态应该是什么？

---

### 2. 发现 Blocker 模式

**用户建议**: `draft` 替代 `ready-for-refinement`

**关键洞察**:
```
draft 不是"触发器"，而是"阻碍条件"
有 draft → 不能创建 PR
移除 draft → 可以创建 PR
```

**演进**:
```
ready-for-* (触发器模式)
    ↓
blocker (阻碍模式)
    ↓
标签 = 阻碍条件
流程 = 逐步移除标签
```

---

### 3. 极简化的核心

**用户洞察**: 
1. `draft` 也是一个 blocker
2. Refinement 和 Design 不会失败，只有 Review 被拒绝

**推导**:
```
如果 Refinement 失败 → 继续在 [draft] 中对话
如果 Design 失败 → 继续在 [need-design] 中重新设计
如果 Review 被拒绝 → 继续在当前标签中

不需要额外的 [need-rework] 标签！
```

**最终结果**: 只需要 3 个核心标签
```
[draft]         需求阶段
[need-design]   设计阶段
[need-review]   审查阶段
```

---

### 4. 用户控制审查级别

**用户要求**:
```
用户要求设计 → 必须用户审查设计
用户不要求 → Agent 自主决定是否需要设计
```

**影响**:
- 简单任务：全自动
- 复杂任务：有人工审查点
- 用户有控制权，Agent 有自主性

---

## 关键决策

### 决策 1: 标签驱动

**选择**: 所有标签都是"阻碍条件"

**理由**:
- 语义统一
- 流程自然
- 不需要额外的状态表示"失败"或"返工"

---

### 决策 2: 3 个核心标签

**选择**: `[draft]` → `[need-design]` → `[need-review]`

**理由**:
- Refinement 和 Design 不存在"失败"
- Review 被拒绝 = 继续停留在当前标签
- 不需要 `[need-rework]`

---

### 决策 3: 用户控制审查级别

**选择**: 用户决定是否要求设计

**理由**:
- 复杂度分级
- 信任机制
- 灵活性

---

### 决策 4: 单 PR 设计

**选择**: 一个 Issue 对应一个 PR

**理由**:
- 历史连续性
- 简化流程
- Review 被拒绝时在同一 PR 上修改

---

## 探索的转折点

### 转折点 1: `draft` 命名

**之前**: `ready-for-refinement`
**之后**: `draft`

**影响**: 暴露了"状态"和"触发器"的混淆

---

### 转折点 2: Blocker 模式

**之前**: 标签表示"当前阶段"
**之后**: 标签表示"阻碍条件"

**影响**: 简化了状态体系

---

### 转折点 3: 无失败状态

**之前**: 需要表示"失败"和"返工"
**之后**: Review 被拒绝 = 继续停留在当前标签

**影响**: 移除了 `[need-rework]` 等额外标签

---

### 转折点 4: 用户控制

**之前**: 固定流程
**之后**: 用户决定审查级别

**影响**: Agent 有自主性，用户有控制权

---

## 设计模式总结

```
┌─────────────────────────────────────────────────────────────┐
│  IssueFlow 核心模式                                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 标签 = 阻碍条件                                          │
│     - 有标签 → 不能继续                                     │
│     - 无标签 → 自动继续                                     │
│                                                             │
│  2. 流程 = 逐步移除标签                                      │
│     - [draft] → [need-design] → [need-review] → done       │
│     - 每个阶段完成后移除当前标签                             │
│                                                             │
│  3. Review 被拒绝 = 继续停留                                 │
│     - 不需要额外的"返工"状态                                 │
│     - 继续在当前标签中工作                                   │
│                                                             │
│  4. 用户控制审查级别                                         │
│     - 用户要求设计 → 人工审查                               │
│     - 用户不要求 → Agent 自主                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
